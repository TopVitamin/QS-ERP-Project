## 一、分析结论与业务边界

自研 ERP 建一套统一的主数据中心，也就是本模块，统一管理商品、供应商、仓库、客户、物流和组织。其中前五类在 ERP 里维护；组织是例外，由金蝶创建、维护并审核，ERP 拉取后只读引用。业务模块引用主数据，不再各自另建同一类档案。

商品只管理成品 SKU。一个可以独立采购、销售、库存和核算的成品规格，对应一个 SKU，不建立 SPU，也不管理原材料、BOM、MRP 和生产物料。

本模块负责定义和维护业务对象及商品配置，与业务模块的边界如下：

- 商品建档时维护初始供应商、初始含税采购价、初始含税销售价和币别，同时给当时已有的采购、销售组织各生成一条对应价格记录。初始供应商只表示初始采购价格归属，不建立供货关系。之后的变价由采购或销售价格调整单处理，详见[价格管理需求分析](../06-价格管理/价格管理需求分析.md)。
- 商品维护库存预警、批次、序列号和保质期配置。库存余额、预警计算，以及实际批次、序列号、有效期的收发记录，由库存模块和第三方 WMS 按确认好的分工负责。配置纳入一期，执行规则另做细化。
- 客户授信由销售模块负责。应收应付、收付款、核销和凭证由金蝶负责，ERP 结算与业财模块只定义业务结果推送和双方的核算边界。
- 接口报文、任务调度和技术重试由系统集成模块负责。

商品 SKU 按一期需要分发到第三方 WMS 和金蝶。领星、聚水潭继续负责 ToC 履约，ERP 通过 SKU 编码或确认后的对应关系识别它们的回传结果，不向这两个系统全量推送商品资料。

供应商只限成品供应商。审核通过且启用后，才能在采购业务里选择；等级不影响采购资格。

一期不管理商品与供应商的供货关系，商品和供应商建档、采购选品都不以建立供货关系为前提。

## 四、功能需求

| 编号 | 功能 | 核心要求 | 仍需确认 |
| --- | --- | --- | --- |
| MD-FR01 | 商品档案 | 维护 SKU 基础信息、品牌、型号与规格、基本单位、多条码、产地、销售等级、尺寸重量、七个图片位、税收分类编码、默认销售税率和非必填开票资料 | 编码生成与修改、条码唯一性、分类调整及评级规则 |
| MD-FR02 | 供应商档案 | 维护成品供应商的分类、等级、多个联系人、多个地址、多个收款账户和默认项、默认币别、结算方式和付款条件选项；支持提交、审核和驳回后重新提交，不管理商品供货关系 | 具体字段、审核责任人、等级评价标准及付款条件选项；已审核资料修改后的重审机制预留 |
| MD-FR03 | 仓库档案 | 维护实体仓、自营或第三方属性，以及归属其下的动态逻辑仓。逻辑仓自主划分并选择库存状态，不限制同一种状态建多个逻辑仓。维护实体仓地址、联系人、第三方仓库、货主和对接配置；实体仓只维护一条联系人。新增逻辑仓引用审核通过且启用的实体仓；已有逻辑仓按自身状态使用，实体仓禁用不级联 | 授权方式、审核责任人及逻辑仓自身禁用条件 |
| MD-FR04 | 客户档案 | 维护五类客户、人工等级、多个联系人、地址、银行信息和默认项、默认币别、结算方式、收款条件选项及单套工商信息；支持审核和驳回后重新提交 | 审核责任人、评级标准、收款条件选项、工商信息适用性及银行资料关联 |
| MD-FR05 | 物流档案 | 维护物流商和服务产品，只有使用状态、不做审核；可以选择具体产品，也可以由仓库指定，自提不用选产品；物流商禁用不影响已有产品 | 下游编码对应、空值传递和物流结果回传协议 |
| MD-FR06 | 外部商品匹配 | 外部履约结果能够匹配到唯一的 ERP SKU。建档后由业务人员在对应模块配置映射，见集成 INT-FR04，不在商品字段清单里预设映射明细 | 具体页面、映射字段及平台、站点、店铺识别范围留到 PRD 和接口设计 |
| MD-FR07 | 数据分发与异常 | 把商品分发到第三方 WMS、金蝶，并记录未匹配或分发失败的数据；内部业务继续、向外部发送单据失败的处理，见《系统集成需求分析》INT-FR04、INT-FR05 | 分发字段及成功标准留到接口设计 |
| MD-FR08 | 状态与引用控制 | 使用状态是启用或禁用；支持查询、新建、编辑、启用和禁用。新业务引用按各档案的使用规则控制：实体仓禁用只限制新增逻辑仓关联，物流商禁用只限制新增服务产品关联。采购选择供应商、新销售业务使用客户，还要审核通过。历史业务保留原来的引用 | 删除、恢复和未完成单据处理规则 |
| MD-FR09 | 价格初始化 | 商品建档时维护初始供应商、初始含税采购价、初始含税销售价和币别。向当前每个采购组织生成该供应商的采购价，向当前每个销售组织生成面向所有客户的销售基准价。新增组织不补建历史商品价格，之后的变价用价格调整单 | 初始价格为空、部分组织初始化失败时的阻断和恢复方式；其余规则见价格管理 PRI-FR01 |
| MD-FR10 | 商品管理配置 | 维护库存预警、批次、序列号和保质期配置，供库存模块及 WMS 使用 | 预警维度与阈值规则、采集环节、配置默认值及变更约束 |

商品的字段见[商品资料字段初稿](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/基础资料/商品资料/商品资料（初稿）.tsv)。规格统一放在一个字段里描述。图片有主视图、左视图、右视图、顶视图、底视图、背视图、全景图，不要求全部必传。商品开票名称、商品开票规格型号、商品税收分类编码都不是必填。生命周期等还标着待确认的字段，不算一期承诺。

供应商档案按以下已确认规则设计：

| 项目 | 规则 |
| --- | --- |
| 分类 | 充电器类、数据线类、移动电源类、综合类、其他；按主要供货品类选择 |
| 等级 | S 级、A 级、B 级、C 级、未评级；人工维护，评价标准后续明确，不自动决定采购资格 |
| 多条资料 | 联系人、地址、收款账户都支持多条；每类最多一个默认项，引用时优先带入默认记录，没有默认项就手动选择，不自动取第一条 |
| 结算资料 | 默认币别；结算方式有电汇、现金、支票等，不另设含义相同的付款方式字段 |
| 付款条件 | 用选项统一表达月结和分阶段付款，并预留后续选项；暂时不拆付款节点、比例明细或独立的账期配置。月结 30 天、下单预付 30% 到货付 70% 只是表达示例，正式选项另定 |
| 审核流程 | 草稿 → 提交后待审核 → 审核通过或已驳回；已驳回的资料修改后重新提交，进入待审核 |
| 使用限制 | 审核状态和使用状态分开；使用状态是启用或禁用，采购只能选审核通过且启用的供应商 |
| 重审预留 | 已审核资料修改后的重审机制先预留，不定义具体修改和重新审核规则 |

### 客户设计确认补充

本轮确认属于目标系统设计，不表示立项时已经存在跨境 2B 业务。

| 项目 | 规则 |
| --- | --- |
| 分类 | 代理商、国内电商 2C 客户、跨境电商 2C 客户、国内 2B 客户、跨境 2B 客户 |
| 等级 | S、A、B、C、未评级；人工维护，评价标准后续明确，不自动决定销售资格 |

| 多条资料 | 联系人、地址、银行信息都支持多条；每类最多一个默认项，优先带入默认项；没有默认项时手动选择，不自动取第一条 |
| 结算资料 | 默认币别、结算方式、收款条件选项；结算方式有电汇、现金、支票等，收款条件选项另定 |
| 工商信息 | 每个客户只有一套，包含企业名称、纳税人识别号、注册地址、注册电话、开户银行和账号；不另设开票资料分组。和银行明细的关联，以及通用 2C、跨境客户的适用性和必填规则待确认 |
| 审核与使用 | 草稿提交后进入待审核，结果是审核通过或已驳回；驳回后修改重新提交。使用状态是启用或禁用，新销售业务只用审核通过且启用的客户 |

具体字段见[客户资料字段初稿](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/基础资料/客户资料/客户资料（初稿）.tsv)；候选和待确认的细节不算全部定稿。

客户授信仍由销售模块负责。仓库主数据提供实体仓、逻辑仓和映射；库存模块基于实际出入库回传维护各逻辑仓的库存，不能只凭建档或采购订单推算库存。

### 仓库结构与单据链路确认

仓库字段初稿见[实体仓资料](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/基础资料/仓库资料/实体仓资料（初稿）.tsv)、[逻辑仓资料](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/基础资料/仓库资料/逻辑仓资料（初稿）.tsv)。实体仓负责联系和对接信息，逻辑仓负责归属和库存状态；没逐项确认的补充字段已标注建议，接口细节保留待确认。

- 实体仓表示实际仓储节点，区分自营和第三方：深圳仓自营，东莞电商仓、FBA 和第三方海外仓由第三方运营。
- 逻辑仓由人工自主命名和划分，每个逻辑仓关联一个实体仓，并选择库存状态（正常品、残次品、待检品）。一个实体仓可以动态增加多个逻辑仓，同一种库存状态也可以建多个。不强制业务类型字段，也不按分类组合限制数量。B2B 正常品仓、电商残次品仓这些都只是命名示例，逻辑仓不等于物理库位。
- 实体仓维护地址、联系人、联系电话、第三方仓库编码、第三方货主标识和对接配置；授权方式按对接系统确定，可以关联授权配置。逻辑仓共用实体仓资料，不重复维护。实体仓只维护一条联系人和联系电话，不设多联系人和默认项。
- 实体仓、逻辑仓都需要草稿提交审核，审核状态和启用或禁用的使用状态分开。新增逻辑仓只能关联审核通过且启用的实体仓。实体仓禁用只阻止新增逻辑仓引用，不影响已有逻辑仓、已有数据或它们的业务，不级联禁用。已有逻辑仓按自身的审核状态和使用状态判断业务资格，不再校验父实体仓是否启用。
- 库存归属依据业务原单判断：能关联 ERP 原单时，沿用原单指定的逻辑仓，即使回传是仓库主动推送也不重新分配；外部发起又没有 ERP 原单时，依据回传信息和配置规则判断逻辑仓。判断依据不足时，不能随便选一个逻辑仓记账。外部 ToC 结果的异常阻断、修复重试和完结保护见[销售与履约需求分析](../04-销售与履约/销售与履约需求分析.md) SAL-FR12，其他业务异常细节另做确认。
- 深圳自营仓由 ERP 直接对接仓库作业系统。国内电商采购单由 ERP 推送聚水潭，再由聚水潭转交第三方仓；货物实际送达第三方仓，发货由聚水潭调用仓库执行。领星采用类似的 SaaS 中转思路，具体仓库和单据对应关系由接口设计明确，不推定各仓接口完全相同。
- ERP 接收直连仓或 SaaS 回传的实际出入库结果，在对应逻辑仓记录库存增减并支持查询，覆盖自营仓和第三方仓。ToC 出库回传也会让对应逻辑仓的库存减少，不再沿用“第三方或 ToC 只做业财归集、不扣 ERP 库存”的旧限制。
- 采购订单下发不是实际入库，不能直接增加库存；库存以确认后的实际出入库结果为依据。外部仓期初及后续变动见[库存与仓储需求分析](../03-库存与仓储/库存与仓储需求分析.md) INV-FR02～INV-FR04，ToC 生效、异常及完结保护见[销售与履约需求分析](../04-销售与履约/销售与履约需求分析.md) SAL-FR09、SAL-FR12。具体映射、期初数量与截点、幂等标识及差异核对仍待设计，只有部分回传单据不能保证完整的库存余额。
- 本次确认不等于全量库存双向同步、跨仓统一调度或自建 WMS；ERP 不接管 ToC 抓单、打单和仓内作业。库位这类仓内细节的查询范围还没确认。

### 组织设计确认补充

组织指公司层面的经营主体，单公司和多公司都要支持。金蝶是组织的唯一来源，创建、维护和审核都在金蝶做。ERP 只主动拉取金蝶已审核的组织，只读展示和引用；不在 ERP 里新增、编辑、提交审核或启停组织。组织的层级、类型、工商信息、联系信息、银行信息和使用状态，都以金蝶为准。

单据按业务选择采购组织、销售组织、库存组织；每个逻辑仓关联一个不可修改的库存组织，多组织共用一个实体仓时分别建逻辑仓，不混记库存。详见[组织需求调研](../10-组织/组织需求调研.md)、[组织需求分析](../10-组织/组织需求分析.md)。原五类的本地维护和启停规则不套用到组织。
