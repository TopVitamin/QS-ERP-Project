## 一、分析结论与业务边界

组织指公司层面的经营主体，单公司和多公司都要支持。

金蝶是组织的唯一来源，创建、维护和审核都在金蝶做。ERP 只主动拉取金蝶已审核的组织，只读展示和引用；不在 ERP 里新增、编辑、提交审核或启停组织。组织的层级、类型、工商信息、联系信息、银行信息和使用状态，都以金蝶为准。

组织菜单提供层级浏览、查询、列表和详情。ERP 不新增部门、渠道、店铺档案，也不会因为接入了组织就承诺内部结算、复杂审批或权限引擎。组织的上下级关系不自动决定财务账套，也不自动决定结算关系。

## 二、原始诉求处理

| 诉求 | 处理 |
| --- | --- |
| 多公司业务归属 | 支持按业务分别选择采购、销售、库存组织 |
| 金蝶维护审核 | ERP 只拉取已审核的记录，本地不做审核流程 |
| 多组织共仓 | 逻辑仓上增加库存组织，不同组织分别建逻辑仓 |

## 四、功能需求

- ORG-FR01：ERP 主动从金蝶拉取已审核的组织，接收组织身份、上级、类型、工商信息、纳税人身份、联系方式和银行信息等，还有组织的使用状态。金蝶里还没审核的组织不会被导入。ERP 不另做审核，也不提供手工创建、修改或启停的入口。非必需字段缺失时，不会挡着组织先同步进来使用；等金蝶补齐之后，ERP 跟着同步更新。本期只覆盖“金蝶审核后拉取使用”这条主流程。禁用、撤销审核这类少见情形暂时不展开，但也不能因为不展开，就说金蝶不支持这些操作。
- ORG-FR02：各业务按需要选择采购组织、销售组织、库存组织。组织的状态和业务资格都在金蝶配置，ERP 同步过来。本期用经营组织就能支持采购、销售和库存管理，不单独设计复杂的资格组合。各业务的组织字段各自保留，但不会因此推定跨组织交易怎么做；同组织调拨和跨组织买卖的边界，引用库存模块的规则。
- ORG-FR03：每个逻辑仓关联一个库存组织；不同组织共用一个实体仓时，各自建自己的逻辑仓。仓库回传结果时，先匹配原单或按规则定位到逻辑仓，再通过逻辑仓确定库存组织，不能只看实体仓就把不同组织的库存合在一起。逻辑仓上的库存组织定下来之后不允许修改。

每个组织有一套工商信息、一条联系信息和多个银行账户，默认项都来自金蝶。每个组织最多只能有一个默认账户；没有默认账户时由业务手工选择，ERP 不去改金蝶的默认标记。

非必需信息缺失时，按 ORG-FR01 先同步、后补齐。默认项冲突这类异常放到接口设计阶段处理，不在 ERP 另开一个本地修改入口。

## 五、一期范围与模块依赖

| 模块 | 分工 |
| --- | --- |
| 系统集成 | 拉取金蝶已审核组织，识别来源标识，处理更新和失败 |
| 采购、销售、结算 | 引用业务组织，做单据校验和业财归属 |
| 仓库、库存 | 逻辑仓关联库存组织且不允许修改；不同组织的库存按逻辑仓隔离 |
| [价格管理](../06-价格管理/价格管理需求分析.md) | 引用组织的纳税人身份；新组织不自动复制历史商品价格，用价格调整单建价，详见 PRI-FR09 |
| [公共能力](../08-公共能力与系统管理/公共能力与系统管理需求分析.md) | RBAC；具体权限留到后续 PRD 设计 |

字段见[组织资料（初稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/基础资料/组织资料/组织资料（初稿）.tsv)。这些字段是业务定义，不代表金蝶的实际接口字段；默认为只读，实际取值和必填项先不预设。

## 六、验收标准

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| ORG-AC01 | 拉取金蝶审核通过和未审核的组织，查看 ERP 里能做什么操作 | 只新增已审核的组织；组织资料和状态都只读，没有本地新增、编辑、审核、启停入口；之后的更新以金蝶为准 |
| ORG-AC02 | 在采购、销售等单据上引用组织 | 业务单据上的组织字段引用同步过来的组织档案；能用的组织支持采购、销售和库存管理，资格来自金蝶，ERP 不再配一套资格 |
| ORG-AC03 | 在同一个实体仓下给两个组织分别建逻辑仓，再查询库存 | 每个逻辑仓只归属一个库存组织，两边可以分开查询，不会因为共用实体仓而混记；想把逻辑仓换到另一个库存组织时，系统不允许修改 |
| ORG-AC04 | 先同步一个缺非必需字段的已审核组织，再到金蝶补齐字段并重新同步 | 组织可以先拉进来使用，之后只读资料跟着更新，不需要在 ERP 本地补录；纳税人身份等字段按金蝶的源资料更新 |
