## 一、分析结论与业务边界

组织表示公司层面的经营主体，支持单公司及多公司。金蝶是唯一创建、维护和审核来源，ERP仅主动拉取金蝶已审核组织并只读展示、引用；不提供本地新增、编辑、提交审核或启用／禁用。层级、类型、工商、联系、银行及使用状态均以金蝶为准。

组织菜单提供层级浏览、查询、列表及详情；不增加部门、渠道、店铺主档，不因组织加入就承诺内部结算、复杂审批或权限引擎。上下级关系不自动决定财务账套或结算关系。

## 二、原始诉求处理

| 诉求 | 处理 |
| --- | --- |
| 多公司业务归属 | 支持按业务选采购、销售、库存组织 |
| 金蝶维护审核 | ERP拉取已审核记录，无本地审核流程 |
| 多组织共仓 | 逻辑仓增加库存组织，不同组织分别建逻辑仓 |

## 四、功能需求

- ORG-FR01：ERP主动拉取金蝶已审核组织，接收组织身份、上级、类型、工商、纳税人身份、联系、银行及使用状态；未审核组织不能作为新组织导入。ERP不另做审核，不提供手工创建、修改或启停入口。非必需字段缺失不阻止先同步使用，金蝶补齐后 ERP 再同步更新。本期围绕审核后拉取使用的主流程，禁用及撤销审核等少见情形暂不展开，不据此声称金蝶不支持这些操作。
- ORG-FR02：各业务按需要选择采购组织、销售组织、库存组织等。组织状态和业务资格由金蝶配置并同步；本期可用经营组织支持采购、销售及库存管理，不单独设计复杂资格组合。保留各业务组织字段，不由此推定跨组织交易方案；同组织调拨及跨组织买卖边界引用库存模块。
- ORG-FR03：每个逻辑仓关联一个库存组织；不同组织共实体仓时分别建逻辑仓。库存回传需匹配原单或规则得到逻辑仓，再由逻辑仓确认库存组织，不能仅按实体仓合并不同组织库存。逻辑仓的库存组织不允许修改。

每组织一套工商信息、一条联系信息、多条银行账户，默认项来自金蝶；每组织最多一个默认账户，无默认账户时业务手选，ERP不修改默认标记。非必需信息缺失按 ORG-FR01 先同步、后补齐；默认项冲突等异常在接口设计阶段处理，不在 ERP 增设本地修改入口。

## 五、一期范围与模块依赖

| 模块 | 分工 |
| --- | --- |
| 系统集成 | 金蝶已审核组织拉取、源标识识别、更新及失败处理 |
| 采购／销售／结算 | 业务组织引用、单据校验和业财归属 |
| 仓库／库存 | 逻辑仓关联库存组织且不允许修改，按逻辑仓隔离不同组织库存 |
| [价格管理](../06-价格管理/价格管理需求分析.md) | 引用组织纳税人身份；新组织不自动复制历史商品价格，通过价格调整单建价，详见 PRI-FR09 |
| [公共能力](../08-公共能力与系统管理/公共能力与系统管理需求分析.md) | RBAC；具体权限在后续 PRD 设计 |

## 六、验收标准

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| ORG-AC01 | 拉取金蝶审核通过和未审核组织，查看本地操作 | 只新增已审核组织；资料和状态只读，无本地新增、编辑、审核、启停；后续更新以金蝶为准 |
| ORG-AC02 | 在采购、销售等业务引用组织 | 对应组织字段引用同步档案，可用组织支持采购、销售及库存管理，资格来自金蝶，不在 ERP 再建资格配置 |
| ORG-AC03 | 同一实体仓下为两个组织分别创建逻辑仓并查询库存 | 每逻辑仓唯一归属库存组织，可分别查询，不因共用实体仓混记；尝试更换库存组织时不允许修改 |
| ORG-AC04 | 同步缺少非必需字段的已审核组织，再在金蝶补齐并同步 | 可先拉取使用，再更新只读资料，不要求 ERP 本地补录；纳税人身份等按源资料更新 |
