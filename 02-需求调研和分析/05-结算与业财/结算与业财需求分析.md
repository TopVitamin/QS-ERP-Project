## 一、分析结论与业务边界

一期结算与业财不建设财务核算模块，只定义 ERP 哪些实际业务结果进入金蝶，以及双方职责边界。ERP 向金蝶逐单推送以下七类已审核结果单：

1. 采购入库单。
2. 采退出库单。
3. 销售出库单。
4. 销退入库单。
5. 其他入库单。
6. 其他出库单。
7. 直接调拨单。

结果单在 ERP 里生成、状态变成“已审核”之后自动推送。订单、申请单、通知单、草稿和未审核的结果单都不推送，推送前也不增加财务二次审核。每张 ERP 结果单单独推送，不按日期、客户、供应商、店铺或组织汇总。

金蝶负责应收应付、收付款、预收预付、核销、凭证、总账和存货成本核算，ERP 不生成这些财务单据或台账。平台账单、收退款、佣金、仓储履约费和最终结算回款，继续由财务线下处理后在金蝶记账，不经 ERP 归集对账。

“系统集成中心—业财结果单据”负责七类结果单的推送记录和结果展示，具体功能归[系统集成需求分析](../07-系统集成/系统集成需求分析.md)；本模块不重复设计推送页面、接口报文、任务调度和技术重试。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 只把业务结果单推送金蝶 | 纳入一期，限定为七类已审核结果单 | ERP 负责供应链业务，金蝶负责财务核算 |
| ERP 管理应收应付或收付款 | 不纳入 | 应收应付、收付款、核销及凭证都由金蝶处理 |
| 结果单逐单进入金蝶 | 纳入，不做汇总推送 | 保持 ERP 原结果单与金蝶接收业务的一一对应 |
| 推送失败后修复重试 | 纳入异常处理边界 | 实际业务已经发生，接口失败不能回滚库存或另造结果单 |
| 成功后发现异常重新推送 | 作为技术运维场景处理 | 金蝶原单人工删除后，技术人员修复后重推 ERP 原结果单，不建设常规业务操作流程 |
| 库存类结果传递成本价格 | 不纳入 | 其他出入库、直接调拨不传成本价格，由金蝶进行月度存货成本核算 |
| 记录并展示金蝶单号 | 不要求 | 页面关注 ERP 原单及推送结果，异常定位使用推送记录和技术日志 |

## 四、功能需求

### FIN-FR01：结果单范围与推送触发

采购入库单、采退出库单、销售出库单、销退入库单、其他入库单、其他出库单和直接调拨单，在 ERP 生成并且已经审核后自动推送到金蝶。七类以外的新结果单按后续业务需要追加，不预先扩展。

每张 ERP 结果单单独发起推送。来源结果单携带的商品、数量、组织、仓库、业务日期、业务类型和适用的交易信息直接用于推送；“业财结果单据”不是重新选择或修改原单信息的入口。

### FIN-FR02：金额与成本边界

采购入库、采退出库、销售出库和销退入库，向金蝶传递 ERP 结果单已有的数量及交易信息。ToC 成交优惠后金额和退货金额继续沿用来源结果，不使用 ERP 销售价目表重算；其他采购、销售金额按各自来源业务单据确定。

其他入库、其他出库和直接调拨不向金蝶传递成本单价或成本金额。金蝶按自己的存货核算规则做月度成本核算，ERP 不回算也不维护金蝶的成本结果。具体币别、含税字段、税费字段和目标字段仍然要接口核验。

### FIN-FR03：推送结果与异常运维边界

推送失败只改变推送结果，不回滚 ERP 已生效的结果单、库存变化或其他业务结果。失败记录保留在原结果单对应的推送记录中，问题修复后继续针对原结果单处理，不新建业务单或结果单。

推送成功后如果发现异常，可以由人工先在金蝶删除错误单据，再由技术运维人员通过技术手段更新、调整状态或重新推送 ERP 原结果单。这项能力属于异常运维，不是普通业务人员的常规反审核、修改或重推流程。具体权限、操作方式、接口去重和日志，由系统集成和运维方案设计。

ERP 页面不要求记录和展示金蝶单号，但要能区分推送结果，并保留必要的推送时间、失败原因和处理日志。金蝶返回内容、成功判定和重复提交协议，待实际接口核验。

### FIN-FR04：财务核算边界

ERP 不生成或管理应收单、应付单、收款单、付款单、预收预付、核销、凭证和总账，也不维护客户应收、供应商应付、账期、到期提醒或财务对账台账。这些能力和存货成本核算，都由金蝶负责。

平台账单、仅退款和其他收退款、佣金、仓储履约费和最终结算回款，由财务线下处理后在金蝶记账，本期不进入 ERP 业财结果范围。

## 五、一期范围与模块依赖

| 分类 | 范围或依赖 |
| --- | --- |
| 本期包含 | 七类已审核结果单逐单推送、交易金额与库存成本边界、推送失败不回滚、技术运维异常处理边界 |
| 本期不包含 | 应收应付、收付款、预收预付、核销、凭证、总账、存货成本核算、平台账单及费用回款对账 |
| 采购 | 生成采购入库单、采退出库单并提供来源业务信息 |
| 销售 | 生成销售出库单、销退入库单；ToC 金额沿用来源结果 |
| 库存 | 生成其他入库单、其他出库单、直接调拨单；库存类结果不传成本价格 |
| 主数据与组织 | 提供商品、仓库和来源结果单已携带的业务组织；组织不在推送记录中重新选择 |
| 系统集成 | 提供“业财结果单据”查看入口，负责接口映射、推送记录、失败信息和技术运维能力 |
| 金蝶 | 接收业务结果并处理应收应付、收付款、核销、凭证、总账和月度存货成本核算 |

## 六、验收标准

下面这些是业务验收示例，不代表金蝶接口已经完成联调。

| 编号 | 关联功能 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| FIN-AC01 | FIN-FR01 | 分别生成并审核七类结果单；另保留一张未审核结果单 | 七类已审核结果逐单进入推送，未审核结果不推；订单、申请和通知单不进入推送 |
| FIN-AC02 | FIN-FR01 | 同一日期、组织或往来单位产生多张结果单 | 每张 ERP 结果单单独推送，不按日期、组织、客户、供应商或店铺汇总 |
| FIN-AC03 | FIN-FR02 | 推送采购、销售结果及其他出入库、直接调拨结果 | 前四类带来源交易信息；后三类不传成本价格，月度成本由金蝶核算 |
| FIN-AC04 | FIN-FR03 | 已审核结果单已改变库存，但推送金蝶失败 | ERP 结果单及库存保持生效，只记录推送失败；不新建业务单或结果单 |
| FIN-AC05 | FIN-FR03 | 金蝶已接收后发现异常，人工删除金蝶原单并由技术人员修复、重推 | 仍使用 ERP 原结果单处理，金蝶最终只保留一张有效单据；异常过程有必要记录 |
| FIN-AC06 | FIN-FR04 | 检查 ERP 业财范围及 ToC 平台结算场景 | ERP 不生成应收应付、收付款、核销或凭证，不归集平台账单、费用和回款 |

### 组织归属

结果单使用来源原单已经携带的组织信息，不在“业财结果单据”中人工选择或修改。组织由金蝶维护审核，ERP 只读同步；详见[组织需求分析](../10-组织/组织需求分析.md)。具体接口字段及映射由系统集成设计确认。
