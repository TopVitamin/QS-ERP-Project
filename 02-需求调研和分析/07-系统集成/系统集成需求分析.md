## 一、分析结论与业务边界

系统集成中心承接 ERP 与外部系统的数据交换、推送结果及异常单据查看。业务单据、生效时点、库存及金额规则以所属模块为准，本模块不另建一套业务规则。

自营仓采用直连仓储作业系统的路径，第三方仓可经聚水潭／领星中转。ERP 向仓库下发的执行指令，采购、退货及 B2B 销售沿用已确认的通知链路，独立站及其他出入库由订单、申请单直接承担；外部系统对应的单据名称后续映射，不把“采购单中转”解释为额外驱动一次仓库执行。物流选择及实际结果沿用主数据规则，一期不直连物流商取面单，不接管 ToC 履约与仓内作业，不扩展全量库存双向同步。

需求及演示阶段可使用 Mock 表达已确认流程；接口字段、协议及实际能力后续补充，Mock 不表示真实接口已验证。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 主档建立后配置外部对应关系 | 对应模块由业务人员维护映射 | 不把外部配置作为主档创建前提 |
| B2C 单据同步、异常修复后继续处理 | 引用销售及库存规则 | 保留来源、避免重复履约与记账 |
| 集中查看金蝶推送结果 | 系统集成中心提供只读业财结果单据 | 不成为原业务编辑入口 |
| 推送失败集中可见，SKU 分发失败不阻止内部业务 | 中心展示异常，下游推单时报错 | 区分内部业务与外部接收结果 |
| 接口无法取得结果或未覆盖订单 | 支持人工确认或导入补充 | 不要求一期接口覆盖所有情形 |

## 四、功能需求

| 编号 | 功能 | 核心要求 |
| --- | --- | --- |
| INT-FR01 | 业务数据交换 | 承接第五章列出的通知、实际结果、订单、物流及库存快照交换；处理结果遵循来源业务模块 |
| INT-FR02 | B2C 来源结果及异常恢复 | 引用销售 SAL-FR09～SAL-FR12，接收原订单及实际结果，保留来源拆分，执行匹配阻断、去重与完结保护；库存归属沿用原单或主数据映射规则，不任意选仓 |
| INT-FR03 | 业财结果单据 | 展示采购入库、采退出库、销售出库、销退入库、其他入库、其他出库、直接调拨的原单及推送状态、时间、失败原因和必要处理记录；只读，不人工改选组织或修改原单，不要求展示金蝶单号 |
| INT-FR04 | 外部映射与商品分发 | 商品、仓库及货主等档案建立后，由业务人员在对应模块配置外部映射；具体入口后续设计，不由此新增货主独立主档范围。SKU 按主数据规则分发至 WMS、金蝶；未成功分发不阻止内部业务继续，向下游推单时由失败反馈进入异常处理 |
| INT-FR05 | 集中异常查看 | 外部推送失败统一在系统集成中心展示异常单据或对应失败记录；具体页面与其他同步异常的展示形态留到 PRD，不扩展为所有异常均可由普通用户修改或重推 |
| INT-FR06 | 人工确认与导入补充 | 仓库接单、执行结束或取消结果无法自动取得时，由相关人员人工确认实际结果；不能将申请或 ERP 关闭视为仓库取消成功。Shopify 接口未覆盖的订单可人工从 Shopify 导入 ERP，类型按实际对接范围确定，仍遵守对应业务及导入审核规则 |
| INT-FR07 | 金蝶组织拉取 | ERP 主动拉取金蝶已审核组织，资料及业务资格只读引用；非必需字段缺失可先同步，金蝶补齐后再更新。规则引用组织 ORG-FR01～ORG-FR03 |

INT-FR03 按[结算与业财需求分析](../05-结算与业财/结算与业财需求分析.md)由已审核结果单自动逐单推送。失败不回滚 ERP 业务或库存，修复后继续原结果单，不另建业务单。成功后发现异常，可先人工在金蝶删除错误单据，再由技术运维修复、调整状态并重推原结果单；这些不是普通业务用户的页面操作。必要推送记录不因一期暂缓完整操作日志而取消。

## 五、一期范围与模块依赖

| 模块 | 已确认交换范围及依据 |
| --- | --- |

| [采购](../02-采购业务管理/采购业务管理需求分析.md) | 采购收货通知、采退发货通知下发及实际入库、出库结果回传 |

| [公共能力](../08-公共能力与系统管理/公共能力与系统管理需求分析.md) | RBAC、导入审核原则及技术配置；不在本模块重新定义业务审核 |

## 六、验收标准

以下为需求验收示例，可先用 Mock 演示，未执行真实接口验证。

| 编号 | 关联功能 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| INT-AC01 | INT-FR01 | 按第五章分别模拟通知下发、实际结果、取消和库存快照 | 各链路遵守所属业务验收；通知不当作实际出入库，取消申请不当作取消成功，快照比对不自动调账 |
| INT-AC02 | INT-FR02 | 模拟销售 SAL-AC15、SAL-AC16、SAL-AC19～SAL-AC21 的来源样本 | 保留来源关联与拆分；失败阻断，修复后继续；重复结果不重复记账，已完结结果不被覆盖 |
| INT-AC03 | INT-FR03 | 生成七类已审核结果并查看中心 | 逐单展示原结果及推送结果，无人工改组织或业务信息入口 |
| INT-AC04 | INT-FR03 | 模拟推送失败及成功后异常 | 不回滚业务或库存，不另造结果单；由技术运维处理原记录，保留必要结果及处理记录 |
| INT-AC05 | INT-FR04 | 建档后配置外部映射；模拟 SKU 分发失败后继续业务并推下游 | 可后配映射；内部业务不因 SKU 分发失败被提前阻断；下游失败可见，不表示下游已接收 |
| INT-AC06 | INT-FR05 | 模拟不同外部系统推送失败 | 系统集成中心可查看对应异常单据或失败记录 |
| INT-AC07 | INT-FR06 | 模拟无法自动取得仓库结果、Shopify 某类订单未对接 | 支持人工确认实际结果、人工导入订单；不绕过对应业务校验及适用的提交审核流程 |
| INT-AC08 | INT-FR07 | 模拟金蝶已审核组织缺少非必需资料，补齐后再次同步 | 可先拉取只读使用，后续更新；组织资格及库存归属符合 ORG 验收 |
