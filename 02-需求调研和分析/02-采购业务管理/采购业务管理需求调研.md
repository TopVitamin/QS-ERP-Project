## 一、调研范围与资料来源

本轮覆盖成品采购需求测算、采购订单、采购收货、采购退货、仓库执行和财务ERP对接。以本轮用户确认为新增依据，仓库及逻辑库存沿用[商品与主数据需求调研](../01-商品与主数据/商品与主数据需求调研.md)里的仓库确认结论。

本轮明确一期不设采购申请，也不做自动采购需求测算、供应商在线协同和采购订单变更单。预付定金和预付款仍然存在，但暂时在线下处理。下面会区分当前业务做法和目标系统诉求，不把目标规则写成已经发生过的事实。

## 二、当前角色与系统分工

| 参与方 | 本轮确认的业务做法 |
| --- | --- |
| 采购部门、采购员 | 总部采购统一用Excel、BI数据人工测算需求，确定采购数量和供应商；在线下跟进供应商，再把结果维护进ERP |
| 供应商 | 商品引入和寻源时就确定了合作供应商，一个商品通常只有一个供应商；供应商通过邮件、微信等线下方式确认订单、反馈发货信息 |
| 仓库 | 按通知单执行收货或退货出库；不合格品按各仓的要求现场拒收，或入库后再退货 |
| 财务 | 预付定金和预付款暂时在线下处理；财务ERP接收实际结果单的目标分工见下文 |

“一般一个供应商”是业务特点，不代表已经确认系统强制一个SKU只能绑定一个供应商。供应商不登录一期ERP，所谓协同录入，是线下沟通后由采购代录进系统。

## 三、核心场景与业务问题

以下为用户确认的业务场景与处理需求，没有另外编造问题频率或损失数据。

| 场景 | 业务情况及需要解决的问题 | 证据状态 |
| --- | --- | --- |
| PUR-S01 | 采购人工测算后直接输出采购订单；采购申请使用少，一期无需单独设置 | 本轮确认 |
| PUR-S02 | 供应商分批发货，由采购代录采购收货通知单；一张订单可有多张通知单，一张通知单只收货一次 | 本轮确认 |
| PUR-S03 | 分批发货出现少收，本次执行结束后需要回补可下推数量，补发另建通知单 | 本轮确认 |
| PUR-S04 | 供应商缺量或延期，需要调整交期或终止，同时保留已审核的数量与价格 | 本轮确认 |
| PUR-S05 | 不合格品可能拒收或入库后退货；退货可关联原入库单，也可无来源手填，允许分批执行 | 本轮确认 |
| PUR-S06 | ERP管业务执行，财务ERP接收采购入库和采退出库结果；预付款暂时在线下处理 | 本轮确认 |

## 四、原始业务诉求

| 诉求方向 | 用户确认的原始诉求 | 目标处理入口 |
| --- | --- | --- |
| 直接采购 | 采购人工测算后直接创建并审核订单，不做采购申请；审核后才对外确认 | 分析PUR-FR01 |
| 分批收货 | 供应商分批发货，由采购代录收货通知；一张订单可有多张通知，每次执行回传一次；少收回补可下推数量，补发另建通知；不超通知量收货 | 分析PUR-FR02 |
| 交期与终止 | 已审核订单保留原数量与价格，只调整交期；支持手工关单和到期自动关单，宽限参数待定 | 分析PUR-FR03 |
| 采购退货 | 不合格品可拒收或入库后退货；退货可关联原入库或无来源，支持分批执行与终止 | 分析PUR-FR04、PUR-FR05 |
| 结果衔接 | 库存按实际出入库结果记账，并向推送财务ERP；订单、退货单和通知不推送；预付款线下处理 | 分析PUR-FR06 |

目标规则、数量规则、取消与关闭条件以及验收，统一见[采购业务管理需求分析](采购业务管理需求分析.md)，本文不再重复。前期讨论里的“采购发货通知单”，统一改用“采购收货通知单”这个名称。

## 五、需要重点确认的边界

- 自动关单已定：宽限为承诺交期或退货截止日期后T+2自然日，每天北京时间0:00跑批；采购退货审核后仅可调整退货截止日期。
- 退货数量已定：关联入库时累计不超过原入库实收，办理中的退货也计入额度；无来源每行大于0，审核仍校验可用库存。
- 外部系统的单据映射、逻辑仓识别及回传失败、重复回传的处理。
- 财务ERP结果单映射、金额及税费规则；推送结果单不等于已经定义财务应付确认规则。
