## 一、分析结论与业务边界

一期由采购部门结合 Excel、BI 数据人工测算后直接创建采购订单，不设采购申请。供应商在商品引入和寻源时就已确定，一个商品通常对应一家供应商，但不因此强制 SKU 与供应商只能一对一。采购员指定本次采购数量和供应商。

供应商通过邮件、微信等线下方式确认订单、反馈发货和延期信息，采购人员代录进 ERP；一期不建设供应商在线协同。业务主链为：

- 采购订单 → 采购收货通知单 → 采购入库单。
- 采购退货单 → 采退发货通知单 → 采退出库单。

采购和退货都支持审核、分批执行、缺量回补、取消、手工关单和到期自动关单。取消是整张订单不再执行，关闭是停止新增通知；关闭之后不允许反关单，也不允许新增通知单，已经生成的通知单继续执行和回传。库存按实际出入库结果变化，订单关闭不代表所有通知单都执行完了。

金蝶只接收采购入库单、采退出库单这两类实际结果单；预付定金和预付款继续在线下处理。以上是一期目标需求，不代表外部系统接口或财务核算规则已经验证。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 总部统一测算，采购申请使用少 | 直接创建采购订单，本期不做采购申请 | 减少不需要的前置环节，替代早期背景中的申请链路 |
| 后续希望自动测算采购需求 | 本期仍人工测算，自动测算后续考虑 | 当前不建设计划模型 |
| 供应商在线下反馈，由采购维护系统 | 采购代录通知单、交期等信息 | 不引入供应商门户 |
| 分批、少供、延期及不再供货 | 通知单分批执行，缺量回补，调整交期或关单 | 已审核采购订单保留原数量和价格，不做变更单 |
| 退货可有来源或无来源 | 支持关联入库带出信息及手工填写 | 覆盖两种业务方式，具体可退约束待确认 |
| 财务只接实际业务结果 | 仅推采购入库及采退出库结果 | 采购订单、退货单和通知单由 ERP 管理，预付款线下处理 |

## 四、功能需求

### PUR-FR01：采购订单

采购员直接建单并提交审核，达到“已审核”后才可发给供应商。一张订单只有一个承诺交期、一个仓库，交期或仓库不同就要拆单。已审核的订单只能调整交期，不能修改价格和数量，也不建设采购订单变更单。

采购订单并列维护三个状态字段，分别记录不同信息：

| 状态字段 | 取值 | 用途 |
| --- | --- | --- |
| 审核状态 | 草稿、待审核、已审核 | 控制编辑、审核，以及能否安排收货 |
| 业务状态 | 正常、已取消、已关闭 | 控制是否继续办理，不另设作废状态 |
| 收货状态 | 未收货、部分收货、全部收货 | 按各行累计实际入库数量自动计算 |

```plain
审核：草稿 → 提交 → 待审核 → 审核通过 → 已审核
       ↑              │
       └──审核退回─────┘

业务：正常 → 取消 → 已取消
         └→ 手工关闭或到期自动关闭 → 已关闭

收货：未收货 → 部分收货 → 全部收货
         └────一次收足────→ 全部收货
```

三个字段各记各的：一张订单可以同时为“已审核＋部分收货＋已关闭”。“正常”表示没有取消、也没有关闭，不代表还没完成；全部收足后保持“正常＋全部收货”，不再重复增加“已完成”状态。审核退回后回到草稿并保留退回意见；取消、关闭保留原审核状态及操作历史，不把已审核订单退回草稿。

| 条件 | 主要功能及限制 |
| --- | --- |
| 草稿＋正常 | 编辑、提交、取消；删除仅作为清理草稿的可选功能 |
| 待审核＋正常 | 审核通过、退回、取消；取消同时终止待审核流程，不允许删除 |
| 已审核＋正常 | 调整交期、关闭；满足取消条件时可取消，不允许删除；价格和数量不可修改 |
| 已审核＋正常＋有可下推数量 | 创建采购收货通知单，支持分批 |
| 已取消 | 查看历史，不再办理 |
| 已关闭 | 查看、追溯；已有有效通知继续办理，不新增通知，不可反关单 |

采购订单先选择供应商和币别，再选择 SKU；不按该供应商是否已有价格过滤可选商品。系统按“供应商＋SKU＋币别”带入当前采购价，没有匹配价格时允许手工填写。草稿改价、改币别清价、零价提醒、提交校验及锁定，统一按[价格管理需求分析](../06-价格管理/价格管理需求分析.md) PRI-FR04、PRI-FR05 执行。

### PUR-FR02：采购收货通知与数量控制

采购根据供应商的线下发货反馈代录采购收货通知单，创建后由系统自动推送到订单对应的仓库执行。一张订单可以生成多张通知单；一张通知单只执行一次收货，结束后回传实际结果，形成采购入库单。补发需要新的通知单。

同一订单商品明细的数量控制规则是：

**可下推数量＝订购数量－已结束通知单的实收数量－未结束通知单的通知数量。**

安排收货时占用额度，通知单结束后，少收的部分回补。不同 SKU 的数量不能互相抵用。订单关闭后不管还剩多少，都不能再安排收货。采购退货不会恢复原采购订单的补货额度，补货需要新建采购订单。

通知单一创建就占用额度；推送失败、待收货、取消中的通知仍然占用，不会因为发送失败或申请取消就提前释放。通知取消成功后才释放额度；收货完成后，用实际数量替代原来的通知占用，缺量部分回补。

订单收货状态按各行累计实收自动计算：所有行都收足才显示“全部收货”，一点实收都没有显示“未收货”，其余显示“部分收货”；不同 SKU 的数量不能互相抵用。

一张通知单只接收一次最终收货结果，需要补收的另建通知单。通知单不设“部分收货”状态，已收货后不能往原通知追加收货。

仓库最终回传实收为 0 并结束本次执行时，按零收处理：通知单取消，显示“实收 0／整批未收”，不生成零数量采购入库单，释放全部通知占用额度，并保留最终回传和确认记录供追溯。通知单取消后，订单仍按自身状态继续办理。还没收到最终结果时，不能把实收未知当作零收。

不允许超过通知单数量收货。超出部分如果还在未关闭原订单的可下推额度内，另建通知单；超过订单数量就另建采购订单。不合格品按仓库规范现场拒收，或入库后再走采购退货。

### PUR-FR03：采购交期、取消与关单

供应商延期，由采购在线下确认后维护订单承诺交期。采购可以手工关闭无法继续供货的订单，订单也可以超过承诺交期加宽限时间后自动关闭；宽限时间的具体值和配置范围待确认。

在途也可以关单，不要求通知单全部结束。关闭不可撤销，已经生成的通知单仍可收货回传，但禁止新增通知单。系统不判断没录入的线下发货事实；关单后发现漏录，通过线下协调、新建采购订单等方式补救，不在原单上补录。

取消与关闭的分工：

- **取消是整张订单都不再执行；关闭只是不再安排剩余采购，已经生成的通知单继续执行。** 两者都不把已审核的订单退回草稿，也不可撤销。
- 订单无实际入库，且没有仍需执行的通知单时，允许取消。
- 待推送或明确推送失败的通知，可以随订单一起取消。
- 存在推送中、待收货或取消中的通知时，不直接取消订单，先处理通知并取得必要的仓库确认。
- 已有实际入库的订单不能取消整单，只能关闭余量。
- 关闭不按触发方式拆状态：手工关闭和到期自动关闭都记为“已关闭”，另外记录关闭方式（手动关闭、到期自动关闭）、关闭原因、关闭时间、关闭操作人（用户或系统）；没关闭时这些信息留空。
- 已取消、已关闭的订单不能再编辑、提交、审核或新增通知单；已关闭的订单仍可接收已有通知的实际结果。

### PUR-FR04：采购退货与出库

退货可以关联采购入库单，带出 SKU、原入库价格、数量等信息；来源缺价或没有来源时，可以手工填写，或主动查询当前采购价快速填充，查询结果在草稿阶段仍然可以修改。提交后价格和税率锁定，取价和校验按价格管理 PRI-FR05、PRI-FR07 执行。带出数量的可修改范围和可退上限待确认，不默认整单全退。

一张退货单只对应一个供应商、一个出库仓库。提交审核确认后，才向供应商传递并生成采退发货通知单，由系统自动推送仓库；实际出库回传后形成采退出库单，并扣减库存。

支持分批执行和数量回补：同一商品的可下推数量，等于退货单数量减去已结束通知单的实际出库数量和未结束通知单的通知数量。每张通知单一次出库结束后，少出的部分回补额度；实际出库为 0 时按零出处理，通知单取消，不生成零数量采退出库单。

### PUR-FR05：退货取消与关单

退货单设置退货截止时间，支持手工关单和到期自动关单，宽限时间具体值待确认。关闭后不可反关单，也不可新增采退发货通知单；关闭前已经生成的通知单继续出库回传。关闭不会取消仓库已有的执行，未安排的部分不再继续执行并释放对应预占；已经生成的通知单结束后，按实际出库消耗预占、释放少出部分。后续仍需退货必须新建采购退货单。

取消是整张退货单都不再执行，和只停止新增通知的关闭不同：

- 无实际退货出库且没有仍需执行的通知时，允许取消退货单。
- 待推送或明确推送失败的通知可以随退货单一起取消；存在推送中、待发货或取消中的通知时，不能直接取消整单，先处理通知并取得必要的仓库确认。
- 已有实际退货出库的退货单不能取消整单，只能关闭余量。
- 取消成功后释放未执行预占；涉及已推送仓库的部分，以仓库取消成功为准，不提前释放。
- 取消与关闭都不可撤销，不能再编辑、提交、审核或新增采退发货通知单；两者都保留原审核状态、操作历史及实际出入库记录。

### PUR-FR06：仓库、库存与金蝶衔接

采购收货通知单按目标仓链路传递：自营仓由 ERP 对接作业系统，国内电商第三方仓经聚水潭中转，领星采用类似的中转思路。采退通知交给仓库执行，外部接收的单据类型和具体映射仍需核实。

实际入库回传后增加库存，采退实际出库回传后扣减库存；订单、通知单的推送本身不增减库存。能关联 ERP 原单时沿用原单的逻辑仓，仓库主动推送也不重新分配；没有 ERP 原单时按回传信息和配置规则判断，依据不足时不得随意选仓记账。

仓库范围沿用[商品与主数据需求分析](../01-商品与主数据/商品与主数据需求分析.md)里的仓库确认结论，替代早期背景中“仅国内仓记账、ToC 回传不扣 ERP 库存”的限制。这个范围不自动包含全量库存双向同步、统一调度和仓内作业接管。

金蝶只推送采购入库单、采退出库单，分批执行按对应的结果单传递，不按整张订单只推一次汇总。采购订单、采购退货单及两类通知单不推送。金蝶目标单据、金额税费及核算规则另行确认，推送结果不等于直接确认应付。

| 主数据 | 成品 SKU、供应商、仓库与逻辑仓 |
| 价格管理 | 提供采购价目表及采购价格调整单；采购订单和退货按价格管理规则取价、改价、校验并保存快照 |
| 仓库执行系统 | 接收通知并返回实际出入库结果，外部类型、映射和异常处理待核实 |
| 库存 | 按原单及回传依据确定逻辑仓，以实际出入库结果记账 |
| 财务、金蝶 | 接收两类实际结果单，预付款线下处理；具体财务规则另行确认 |

本文不定义完整字段、页面、状态机和接口报文，也不因此推断现有原型已经实现这些规则。

## 六、验收标准

下面是基于已确认规则的业务验收示例，不代表已经执行过系统测试。

| 编号 | 关联功能 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| PUR-AC01 | PUR-FR01 | 创建采购订单并审核 | 无需采购申请；审核后才可发给供应商；不同交期或仓库拆单；已审核数量及价格不可修改 |
| PUR-AC02 | PUR-FR02 | 同一 SKU 订购 1,000 件，安排收货 600 件；该通知单实收 580 件并结束，没有其他通知单 | 安排后额度 400 件，结束后回补为 420 件；原通知单不再收货，补发另建通知单 |
| PUR-AC03 | PUR-FR02 | 通知单以外的货物需要接收 | 不超原通知单收货；原订单未关闭且有额度时另建通知单，超过订单数量则新建订单 |
| PUR-AC04 | PUR-FR03 | 订单有未完成通知单，手工关单或达到自动关闭条件 | 禁止反关单及新增通知单，已有通知单仍可收货回传；不能通过补录追认未记录的发货 |
| PUR-AC05 | PUR-FR04 | 分别创建关联入库、来源缺价和无来源退货；审核后计划退 100 件，安排 60 件、实出 50 件并结束 | 关联方式优先带出原入库价格；缺价可查询当前价或手填且草稿可改；提交后价格税率锁定；结束后可下推数量为 50 件 |
| PUR-AC06 | PUR-FR05 | 退货单手工关闭或达到截止时间加宽限时间，有已生成通知单 | 不可反关单或新增通知单；已有通知单继续出库回传；后续退货新建退货单 |
| PUR-AC07 | PUR-FR06 | 下发通知，随后分批回传实际入库或采退出库结果 | 通知下发不增减库存，库存按实际结果在对应逻辑仓变化；只向金蝶传对应入库、采退出库结果单 |
| PUR-AC08 | PUR-FR01 | 选择供应商和币别后录入有价、无价及零价 SKU，再修改币别并提交 | 不按价目表过滤 SKU；有价按供应商、SKU、币别匹配，无价可手填；改币别清空原价格并重取；零价提交需确认，空价或负价被阻断，提交后价格税率锁定 |
| PUR-AC09 | PUR-FR03 | 分别测试无入库且无待执行通知、有推送中通知、已有实际入库三种订单取消 | 无入库且无待执行通知时可取消，待推送或明确失败的通知随单取消；有推送中、待收货或取消中通知时不能直接取消，先处理通知；已有实际入库不能取消整单，只能关闭余量；取消与关闭都不可撤销 |
| PUR-AC10 | PUR-FR02 | 通知 100 件，仓库最终回传实收 0 并结束 | 通知按零收取消并显示实收 0／整批未收；不生成零数量入库单，释放全部通知占用额度，保留回传及确认记录；库存不增加、金蝶不接收零数量结果 |
| PUR-AC11 | PUR-FR04、PUR-FR05 | 分别测试无实出且无阻挡通知、已推送通知、已有实出三种退货单终止场景 | 无实出且无阻挡通知时可取消并释放未执行预占；已推送通知须先取得仓库取消成功；已有实出不能整单取消，只能关闭余量；关闭不撤销已有执行，结束后释放少出部分预占 |
