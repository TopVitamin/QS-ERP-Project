## 一、分析结论与业务边界

一期由采购部门结合Excel、BI数据人工测算后直接创建采购订单，不设采购申请。供应商在商品引入和寻源时就已确定，一个商品通常对应一家供应商，但不因此强制SKU与供应商只能一对一。采购员指定本次采购数量和供应商。

供应商通过邮件、微信等线下方式确认订单、反馈发货和延期信息，采购人员代录进ERP；一期不建设供应商在线协同。业务主链为：

- 采购订单 → 采购收货通知单 → 采购入库单。
- 采购退货单 → 采退发货通知单 → 采退出库单。

采购和退货都支持审核、分批执行、缺量回补、取消、手工关单和到期自动关单。取消是整张订单不再执行，关闭是停止新增通知；关闭之后不允许反关单，也不允许新增通知单，已经生成的通知单继续执行和回传。库存按实际出入库结果变化，订单关闭不代表所有通知单都执行完了。

财务ERP只接收采购入库单、采退出库单这两类实际结果单；预付定金和预付款继续在线下处理。以上是一期目标需求，不代表外部系统接口或财务核算规则已经验证。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 总部统一测算，采购申请使用少 | 直接创建采购订单，本期不做采购申请 | 减少不需要的前置环节，替代早期背景中的申请链路 |
| 后续希望自动测算采购需求 | 本期仍人工测算，自动测算后续考虑 | 当前不建设计划模型 |
| 供应商在线下反馈，由采购维护系统 | 采购代录通知单、交期等信息 | 不引入供应商门户 |
| 分批、少供、延期及不再供货 | 通知单分批执行，缺量回补，调整交期或关单 | 已审核采购订单保留原数量和价格，不做变更单 |
| 退货可有来源或无来源 | 支持关联入库带出信息及手工填写 | 有来源卡原入库可退额度；无来源每行大于0，审核仍校验可用库存 |
| 财务只接实际业务结果 | 仅推采购入库及采退出库结果 | 采购订单、退货单和通知单由ERP管理，预付款线下处理 |

## 四、功能需求

### PUR-FR01：采购订单

采购员直接建单并提交，达到“已审核”后才可发给供应商。一张订单只有一个承诺交期、一个仓库，交期或仓库不同就要拆单。已审核的订单只能调整交期，不能修改价格和数量，也不建设采购订单变更单。

采购订单并列维护三个状态字段，分别记录不同信息（状态明细以04《单据与状态流转》为准）：

| 状态字段 | 取值 | 用途 |
| --- | --- | --- |
| 审核状态 | 草稿、待审核、已审核 | 控制编辑、审核，以及能否安排收货 |
| 业务状态 | 正常、已取消、已关闭 | 控制是否继续办理，不另设作废状态 |
| 收货状态 | 未收货、部分收货、全部收货 | 按各行累计实际入库数量自动计算 |

```plain
审核：草稿 → 提交 → 待审核 → 审核 → 已审核
       ↑              │
       └────撤回───────┘

业务：正常 → 取消 → 已取消
         └→ 手工关闭或到期自动关闭 → 已关闭

收货：未收货 → 部分收货 → 全部收货
         └────一次收足────→ 全部收货
```

三个字段各记各的：一张订单可以同时为“已审核＋部分收货＋已关闭”。“正常”表示没有取消、也没有关闭，不代表还没完成；全部收足后保持“正常＋全部收货”，不再重复增加“已完成”状态。撤回后回到草稿并保留撤回意见；取消、关闭保留原审核状态及操作历史，不把已审核订单撤回为草稿。

| 条件 | 主要功能及限制 |
| --- | --- |
| 草稿＋正常 | 编辑、提交、删除 |
| 待审核＋正常 | 审核、撤回、取消；取消同时终止待审核流程，不允许删除 |
| 已审核＋正常 | 调整交期、关闭；满足取消条件时可取消，不允许删除；价格和数量不可修改 |
| 已审核＋正常＋有可下推数量 | 创建采购收货通知单，支持分批 |
| 已取消 | 查看历史，不再办理 |
| 已关闭 | 查看、追溯；已有有效通知继续办理，不新增通知，不可反关单 |

采购订单先选择供应商和币别，再选择SKU；不按该供应商是否已有价格过滤可选商品。系统按“供应商＋SKU＋币别”带入当前采购价，没有匹配价格时允许手工填写。草稿改价、改币别清价、零价提醒、提交校验及锁定，统一按[价格管理需求分析](../06-价格管理/价格管理需求分析.md) PRI-FR04、PRI-FR05执行。

### PUR-FR02：采购收货通知与数量控制

采购根据供应商的线下发货反馈代录采购收货通知单，创建时选择收货处理方式，默认仓库收货。仓库收货时，创建后由系统自动推送到订单对应的仓库执行，结束后回传实际结果，形成采购入库单。虚拟入库时不推仓库，创建成功后各行实收等于通知数量，系统立即按通知数量生成采购入库单并自动审核，通知变为已收货；虚拟入库不允许缺量或零收。一张订单可以生成多张通知单，各批可以选不同处理方式；一张通知单只执行一次收货。补发需要新的通知单。处理方式写在通知单上，不写在采购订单上。

同一订单商品明细的数量控制规则是：

**可下推数量＝订购数量－已结束通知单的实收数量－未结束通知单的通知数量。**

安排收货时占用额度，通知单结束后，少收的部分回补。不同SKU的数量不能互相抵用。订单关闭后不管还剩多少，都不能再安排收货。采购退货不会恢复原采购订单的补货额度，补货需要新建采购订单。

通知单一创建就占用额度；推送失败、待收货、取消中的通知仍然占用，不会因为发送失败或申请取消就提前释放。通知取消成功后才释放额度；收货完成后，用实际数量替代原来的通知占用，缺量部分回补。

订单收货状态按各行累计实收自动计算：所有行都收足才显示“全部收货”，一点实收都没有显示“未收货”，其余显示“部分收货”；不同SKU的数量不能互相抵用。

一张通知单只接收一次最终收货结果，需要补收的另建通知单。通知单不设“部分收货”状态，已收货后不能往原通知追加收货。

仓库最终回传实收为0并结束本次执行时，按零收处理：通知单取消，显示“实收0／整批未收”，不生成零数量采购入库单，释放全部通知占用额度，并保留最终回传和确认记录供追溯。通知单取消后，订单仍按自身状态继续办理。还没收到最终结果时，不能把实收未知当作零收。

不允许超过通知单数量收货。超出部分如果还在未关闭原订单的可下推额度内，另建通知单；超过订单数量就另建采购订单。不合格品按仓库规范现场拒收，或入库后再走采购退货。

### PUR-FR03：采购交期、取消与关单

供应商延期，由采购在线下确认后维护订单承诺交期。采购可以手工关闭无法继续供货的订单，订单也可以在承诺交期之后第2个自然日的0:00自动关闭（即日期+2天当天0:00）。T+2按自然日计算，不跳过周末。每天北京时间0:00跑批。例如承诺交期为2026-09-20，则2026-09-22 00:00关闭。全部收足的订单不自动关闭。

在途也可以关单，不要求通知单全部结束。关闭不可撤销，已经生成的通知单仍可收货回传，但禁止新增通知单。系统不判断没录入的线下发货事实；关单后发现漏录，通过线下协调、新建采购订单等方式补救，不在原单上补录。

取消与关闭的分工：

- **取消是整张订单都不再执行；关闭只是不再安排剩余采购，已经生成的通知单继续执行。** 两者都不把已审核的订单撤回为草稿，也不可撤销。
- 订单无实际入库，且没有仍需执行的通知单时，允许取消。
- 待推送或明确推送失败的通知，可以随订单一起取消。
- 存在推送中、待收货或取消中的通知时，不直接取消订单，先处理通知并取得必要的仓库确认。
- 已有实际入库的订单不能取消整单，只能关闭余量。
- 关闭不按触发方式拆状态：手工关闭和到期自动关闭都记为“已关闭”，另外记录关闭方式（手动关闭、到期自动关闭）、关闭原因、关闭时间、关闭操作人；手工关闭记操作用户，关闭原因必填；到期自动关闭时关闭操作人和关闭原因都留空。没关闭时这些信息留空。
- 已取消、已关闭的订单不能再编辑、提交、审核或新增通知单；已关闭的订单仍可接收已有通知的实际结果。

### PUR-FR04：采购退货与出库

退货可以关联采购入库单，带出SKU、原入库价格、数量等信息；来源缺价或没有来源时，可以手工填写，或主动查询当前采购价快速填充，查询结果在草稿阶段仍然可以修改。提交后价格和税率锁定，取价和校验按价格管理PRI-FR05、PRI-FR07执行。关联时带出原入库数量，可改小，不能超过剩余可退额度；不强制一次退完。退货单支持草稿删除；退货截止日期手工填写、必填（2026-09-22确认，见04采购退货单PRD）。

关联原入库的退货，累计不得超过该入库单的实际入库数量。退货单审核时占用原入库单可退额度，草稿不占；其他已审核、办理中的退货也计入。取消或关闭释放未退且无通知继续执行的额度，已实际退回部分仍计入累计退货。无来源退货不套用原入库额度，每行数量须大于0；审核时仍须出库仓可用库存足够，不够不能审核。

一张退货单只对应一个供应商、一个出库仓库。提交审核确认后，才向供应商传递并生成采退发货通知单；创建时选择发货处理方式，默认仓库发货。仓库发货时由系统自动推送仓库，实际出库回传后形成采退出库单并扣减库存。虚拟出库时不推仓库，创建成功后各行实出等于通知数量，系统立即按通知数量生成采退出库单并自动审核，通知变为已发货，并消耗对应预占；虚拟出库不允许缺量或零出。处理方式写在通知单上，不写在退货单上。

支持分批执行和数量回补：同一商品的可下推数量，等于退货单数量减去已结束通知单的实际出库数量和未结束通知单的通知数量。每张通知单一次出库结束后，少出的部分回补额度；实际出库为0时按零出处理，通知单取消，不生成零数量采退出库单。

### PUR-FR05：退货取消与关单

退货单设置退货截止日期，支持手工关单和到期自动关单：在退货截止日期之后第2个自然日的0:00自动关闭（即日期+2天当天0:00），与采购订单同一口径，每天北京时间0:00跑批。关闭后不可反关单，也不可新增采退发货通知单；关闭前已经生成的通知单继续出库回传。关闭不会取消仓库已有的执行，未安排的部分不再继续执行并释放对应预占；已经生成的通知单结束后，按实际出库消耗预占、释放少出部分。后续仍需退货必须新建采购退货单。审核后不可修改其他业务内容，仅可调整退货截止日期。

取消是整张退货单都不再执行，和只停止新增通知的关闭不同：

- 无实际退货出库且没有仍需执行的通知时，允许取消退货单。
- 待推送或明确推送失败的通知可以随退货单一起取消；存在推送中、待发货或取消中的通知时，不能直接取消整单，先处理通知并取得必要的仓库确认。
- 已有实际退货出库的退货单不能取消整单，只能关闭余量。
- 取消成功后释放未执行预占；涉及已推送仓库的部分，以仓库取消成功为准，不提前释放。
- 取消与关闭都不可撤销，不能再编辑、提交、审核或新增采退发货通知单；两者都保留原审核状态、操作历史及实际出入库记录。

### PUR-FR06：仓库、库存与财务ERP衔接

采购收货通知单按目标仓链路传递：自营仓由ERP对接作业系统，国内电商第三方仓经聚水潭中转，领星采用类似的中转思路。采退通知交给仓库执行，外部接收的单据类型和具体映射方向已于2026-09-22确认：复用正向同类单据的映射机制，具体单据类型码由接口设计配置。

仓库路径下，实际入库回传后增加库存，采退实际出库回传后扣减库存。虚拟入出库按通知数量生成结果单并自动审核后，同样增减库存。订单、通知单本身不增减库存。能关联ERP原单时沿用原单的逻辑仓，仓库主动推送也不重新分配；没有ERP原单时按回传信息和配置规则判断，依据不足时不得随意选仓记账。

仓库范围沿用[商品与主数据需求分析](../01-商品与主数据/商品与主数据需求分析.md)里的仓库确认结论，替代早期背景中“仅国内仓记账、ToC回传不扣ERP库存”的限制。这个范围不自动包含全量库存双向同步、统一调度和仓内作业接管。

财务ERP只推送采购入库单、采退出库单，分批执行按对应的结果单传递，不按整张订单只推一次汇总。采购订单、采购退货单及两类通知单不推送。财务ERP目标单据、金额税费及核算规则另行确认，推送结果不等于直接确认应付。

六类单据的字段以详细稿为准，初稿仅留档：[采购订单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采购订单（详细稿）.tsv)、[采购收货通知单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采购收货通知单（详细稿）.tsv)、[采购入库单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采购入库单（详细稿）.tsv)、[采购退货单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采购退货单（详细稿）.tsv)、[采退发货通知单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采退发货通知单（详细稿）.tsv)、[采退出库单（详细稿）](../../04-产品设计方案/20260812-ERP项目第一版框架搭建/字段清单合集/采购相关/采退出库单（详细稿）.tsv)。清单按已确认口径收录，未确认的写“待确认”，不算一期承诺；原型里额外出现的采购模式（含委外）、结算供应商、结算期限、业务员、部门等字段，没有本期需求依据，不收录。
