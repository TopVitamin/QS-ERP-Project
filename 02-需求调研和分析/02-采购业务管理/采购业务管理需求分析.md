## 一、分析结论与业务边界

一期由采购部门结合 Excel、BI 人工测算后直接创建采购订单，不设置采购申请。供应商在商品引入寻源时已确定，一个商品通常对应一家供应商，但不据此强制限定 SKU 与供应商只能一对一。采购员指定本次采购数量及供应商。

供应商通过邮件、微信等线下确认订单、反馈发货及延期信息，采购人员代录 ERP；一期不建设供应商在线协同。业务主链为：

- 采购订单 → 采购收货通知单 → 采购入库单。
- 采购退货单 → 采退发货通知单 → 采退出库单。

采购与退货均支持审核、分批执行、缺量回补、手工关单和到期自动关单。关闭后不允许反关单或新增通知单，已有通知单继续执行和回传。库存依据实际出入库结果变化，订单关闭不表示所有通知单已完成。

金蝶仅接收采购入库单、采退出库单两类实际结果单；预付定金、预付款继续在线下处理。以上为一期目标需求，不代表已验证外部系统接口或财务核算规则。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 总部统一测算，采购申请使用少 | 直接创建采购订单，本期不做采购申请 | 减少不需要的前置环节，替代早期背景中的申请链路 |
| 后续希望自动测算采购需求 | 本期仍人工测算，自动测算后续考虑 | 当前不建设计划模型 |
| 供应商在线下反馈，由采购维护系统 | 采购代录通知单、交期等信息 | 不引入供应商门户 |
| 分批、少供、延期及不再供货 | 通知单分批执行，缺量回补，调整交期或关单 | 已审核采购订单保留原数量和价格，不做变更单 |
| 退货可有来源或无来源 | 支持关联入库带出信息及手工填写 | 覆盖两种业务方式，具体可退约束待确认 |
| 财务只接实际业务结果 | 仅推采购入库及采退出库结果 | 采购订单、退货单和通知单由 ERP 管理，预付款线下处理 |

## 四、功能需求

### PUR-FR01：采购订单

采购员直接建单并提交审核，达到“已审核”后才可发给供应商。一张订单只有一个承诺交期、一个仓库，交期或仓库不同需拆单。已审核订单只可调整交期，不可修改价格、数量，不建设采购订单变更单。

采购订单先选择采购组织、供应商和币别，再选择 SKU；不按该供应商是否已有价格过滤可选商品。系统按“采购组织＋供应商＋SKU＋币别”带入当前采购价，无匹配价格时允许手工填写。草稿改价、改币别清价、零价提醒、提交校验及锁定统一按[价格管理需求分析](../06-价格管理/价格管理需求分析.md) PRI-FR04、PRI-FR05 执行。

### PUR-FR02：采购收货通知与数量控制

采购根据供应商线下发货反馈代录采购收货通知单，创建后由系统自动推送至订单对应仓库执行。一张订单可生成多张通知单；一张通知单仅执行一次收货，结束后回传实际结果，形成采购入库单。补发需要新的通知单。

同一订单商品明细的数量控制口径为：

**可下推数量＝订购数量－已结束通知单的实收数量－未结束通知单的通知数量。**

下推时占用额度，通知单结束后少收部分回补。不同 SKU 的数量不能相互抵用。订单关闭后不论剩余数量多少，均不可再下推。采购退货不恢复原采购订单的补货额度；补货需新建采购订单。

不允许超过通知单数量收货。超出部分如仍在未关闭原订单的可下推额度内，另建通知单；超过订单数量则另建采购订单。不合格品依仓库规范现场拒收，或入库后走采购退货。

### PUR-FR03：采购交期与关单

供应商延期由采购在线下确认后维护订单承诺交期。支持采购手工关闭无法继续供货的订单，以及超过承诺交期加宽限时间后自动关闭；宽限时间具体值及配置范围待确认。

在途可关单，不要求通知单全部结束。关闭不可撤销，已有通知单仍可收货回传，禁止新增通知单。系统不判断未录入的线下发货事实，关单后发现漏录时，通过线下协调、新建采购订单等方式补救，不在原单补录。

### PUR-FR04：采购退货与出库

退货可关联采购入库单，带出 SKU、原入库价格、数量等信息；来源缺价或无来源时，可以手工填写或主动查询当前采购价快速填充，查询结果在草稿阶段仍可修改。提交后价格和税率锁定，取价及校验按价格管理 PRI-FR05、PRI-FR07 执行。带出数量的可修改范围及可退上限待确认，不默认整单全退。

一张退货单仅对应一个供应商、一个出库仓库。提交审核确认后，才向供应商传递并生成采退发货通知单，由系统自动推送仓库；实际出库回传形成采退出库单并扣减库存。

支持分批执行和数量回补：同一商品的可下推数量为退货单数量，减去已结束通知单的实际出库数量及未结束通知单的通知数量。每张通知单一次出库结束后，少出部分回补额度。

### PUR-FR05：退货关单

退货单设置退货截止时间，支持手工关单及到期自动关单，宽限时间具体值待确认。关闭后不可反关单，不可新增采退发货通知单；关闭前已有通知单继续出库回传。后续仍需退货必须新建采购退货单。

### PUR-FR06：仓库、库存与金蝶衔接

采购收货通知单按目标仓链路传递：自营仓由 ERP 对接作业系统，国内电商第三方仓经聚水潭中转，领星采用类似中转思路。采退通知仓库执行，外部接收单据类型和具体映射仍需核实。

实际入库回传增加库存，采退实际出库回传扣减库存；订单、通知单推送本身不增减库存。能关联 ERP 原单时沿用原单逻辑仓，仓库主动推送也不重新分配；无 ERP 原单时按回传信息及配置规则判断，依据不足不得任意选仓记账。

仓库范围沿用[商品与主数据仓库确认](../01-商品与主数据/商品与主数据需求分析.md)，替代早期背景中“仅国内仓记账、ToC 回传不扣 ERP 库存”的限制。该范围不自动包含全量库存双向同步、统一调度及仓内作业接管。

金蝶仅推送采购入库单、采退出库单，分批执行按对应结果单传递，不按整张订单仅推一次汇总。采购订单、采购退货单及两类通知单不推送。金蝶目标单据、金额税费及核算规则另行确认，推送结果不等于直接确认应付。

## 五、一期范围与模块依赖

提交与审核权限、允许本人审核及导入沿用原审核流程，统一引用[公共能力需求分析](../08-公共能力与系统管理/公共能力与系统管理需求分析.md) COM-FR01、COM-FR02，不改变本模块业务校验。

| 分类 | 范围或依赖 |
| --- | --- |
| 本期包含 | 采购订单、采购收货通知单、采购入库单、采购退货单、采退发货通知单、采退出库单；上述主链与已确认规则 |
| 本期不包含 | 采购申请、自动采购需求测算、供应商在线协同、采购订单变更单、预付定金和预付款系统流程 |
| 主数据 | 成品 SKU、供应商、仓库与逻辑仓；采购单据选择采购组织等业务所需组织 |
| 组织 | 组织在金蝶维护审核，ERP 同步只读，详见[组织需求分析](../10-组织/组织需求分析.md) |
| 价格管理 | 提供采购价目表及采购价格调整单；采购订单和退货按价格管理规则取价、改价、校验并保存快照 |
| 仓库执行系统 | 接收通知并返回实际出入库结果，外部类型、映射和异常处理待核实 |
| 库存 | 按原单及回传依据确定逻辑仓，以实际出入库结果记账 |
| 财务／金蝶 | 接收两类实际结果单，预付款线下处理；具体财务口径另行确认 |

本稿不定义完整字段、页面、状态机和接口报文，也不据此推断现有原型已实现这些规则。

## 六、验收标准

以下为基于已确认规则的业务验收示例，不代表已执行系统测试。

| 编号 | 关联功能 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| PUR-AC01 | PUR-FR01 | 创建采购订单并审核 | 无需采购申请；审核后才可发给供应商；不同交期或仓库拆单；已审核数量及价格不可修改 |
| PUR-AC02 | PUR-FR02 | 同一 SKU 订购 1,000 件，下推 600 件；该通知单实收 580 件并结束，无其他通知单 | 下推后额度 400 件，结束后回补为 420 件；原通知单不再收货，补发另建通知单 |
| PUR-AC03 | PUR-FR02 | 通知单以外的货物需要接收 | 不超原通知单收货；原订单未关闭且有额度时另建通知单，超过订单数量则新建订单 |
| PUR-AC04 | PUR-FR03 | 订单有未完成通知单，手工关单或达到自动关闭条件 | 禁止反关单及新增通知单，已有通知单仍可收货回传；不能通过补录追认未记录的发货 |
| PUR-AC05 | PUR-FR04 | 分别创建关联入库、来源缺价和无来源退货；审核后计划退 100 件，下推 60 件、实出 50 件并结束 | 关联方式优先带出原入库价格；缺价可查询当前价或手填且草稿可改；提交后价格税率锁定；结束后可下推数量为 50 件 |
| PUR-AC06 | PUR-FR05 | 退货单手工关闭或达到截止时间加宽限时间，有已生成通知单 | 不可反关单或新增通知单；已有通知单继续出库回传；后续退货新建退货单 |
| PUR-AC07 | PUR-FR06 | 下发通知，随后分批回传实际入库或采退出库结果 | 通知下发不增减库存，实际结果驱动相应逻辑仓库存变化；只向金蝶传对应入库、采退出库结果单 |
| PUR-AC08 | PUR-FR01 | 选择供应商和币别后录入有价、无价及零价 SKU，再修改币别并提交 | 不按价目表过滤 SKU；有价按四维匹配，无价可手填；改币别清空原价格并重取；零价提交需确认，空价或负价被阻断，提交后价格税率锁定 |
