## 一、调研定位、范围与事实来源

### 1.1 本文定位

本文是强盛 ERP 一期需求调研的项目级入口，用于回答四个问题：

1. 本轮调研覆盖哪些模块和业务边界。
2. 当前结论来自什么资料，哪些属于现状事实，哪些属于目标设计确认。
3. 各模块已经推进到什么程度，下一步还要补什么证据。
4. 哪些问题跨越多个模块，需要在后续产品、接口或实施阶段统一处理。

本文不复制公司背景、模块业务规则、字段或验收明细。公司与系统背景见[强盛科技公司业务背景信息](../../01-全局背景信息/1.强盛科技公司业务背景信息.md)、[强盛科技 ERP 项目的背景信息](../../01-全局背景信息/2.强盛科技ERP项目的背景信息.md)；模块结论以对应需求分析文档为准。

### 1.2 调研范围

本轮围绕强盛 ERP 一期展开，覆盖商品与主数据、采购、库存、销售、结算与业财、价格、系统集成、公共能力、辅助资料九个模块。

调研关注立项时的业务现状、系统分工、实际场景、问题、原始诉求、证据缺口和待核实事项。以下内容不在本总览中提前设计：

- 页面布局、交互反馈和控件行为。
- 完整字段、状态机、数据库和接口报文。
- 具体账号、角色、权限矩阵和审批岗位。
- 上线切换、历史迁移、初始化数量及真实接口联调方案。

### 1.3 事实来源与使用边界

| 来源 | 在本项目中的作用 | 使用边界 |
| --- | --- | --- |
| `01-全局背景信息` | 说明公司、立项现状、一期定位、系统分工和跨模块约束 | 是项目级事实与范围基线；后续文档不得反向改写其已确认边界 |
| 模块需求调研稿 | 记录当前角色、系统分工、场景、问题、原始诉求和证据缺口 | 只用于还原现状；没有资料支持的内容继续标为待核实 |
| 模块需求分析稿 | 记录已经处理后的目标、一期范围、功能需求、依赖、验收和待决策事项 | 目标设计确认不能被表述成立项时已经存在的现状 |
| 用户讨论形成的设计确认 | 补充虚拟企业一期目标规则 | 必须在文档中明确为目标设计确认，不等于访谈、样表或真实接口证据 |
| 实际样表、系统截图、接口文档和返回样例 | 用于核验现行做法、字段、数据流和外部能力 | 当前尚未取得的资料不能用 Mock、原型或经验替代 |
| `00-草稿对话` | 用于发现历史线索和候选问题 | 不作为范围、规则或字段依据；与正式资料冲突时不采用 |

## 三、统一记录与确认方法

### 3.1 从事实到需求的追溯

模块调研稿使用 `S` 记录场景、`P` 记录问题；模块分析稿将其转化为 `BR` 业务需求、`FR` 功能需求和 `AC` 验收标准。基本追溯关系为：

```plain
现状事实／目标设计确认
    → 场景 S 与问题 P
    → 业务需求 BR
    → 功能需求 FR
    → 验收标准 AC
```

模块前缀沿用现有约定：`MD` 商品与主数据、`PUR` 采购、`INV` 库存、`SAL` 销售、`FIN` 结算、`PRI` 价格、`INT` 集成、`COM` 公共能力、`AUX` 辅助资料。

### 3.2 结论状态

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 已核实的现状事实 | 有正式背景、样表、系统资料或其他可定位证据 | 写入调研稿并标明来源 |
| 目标设计确认 | 一期目标方案已通过本轮讨论确认 | 写入分析稿；需要引用时说明它不是历史现状 |
| 待核实现状 | 当前缺少访谈、样表、接口或操作证据 | 保留问题和所需资料，不用经验补全 |
| 待决策规则 | 会影响范围、业务结果或责任归属，现有资料尚未定义 | 写明影响模块和确认时点，确认后回填权威文档 |
| 后续设计事项 | 字段、页面、接口技术和实施细节 | 进入对应 PRD、接口或实施方案，不在调研阶段展开 |

### 3.3 更新纪律

- 模块内部问题留在模块文档；只有同时影响多个模块或项目范围的问题才进入本总览。
- 同一结论只在负责该规则的文档中完整维护，其他模块使用链接和编号引用。
- 修改已确认结论时，同步检查版本表、追溯矩阵、验收项及依赖它的其他文档。
- Mock 和原型可用于演示流程，但不能据此宣称真实接口、后端事务、并发或生产行为已经验证。

## 四、项目级待核实事项

以下事项不否定已经形成的一期需求主链，但会影响详细产品设计、接口联调、金额和库存验收或上线实施。模块内部待确认项仍以各模块需求分析稿的第七章为准。

| 项目级待核实事项 | 影响范围 | 需要补充的证据或结论 | 最迟确认时点 |
| --- | --- | --- | --- |
| 外部系统真实接口范围、来源单据和结果语义 | 主数据、采购、库存、销售、业财、集成 | 领星、聚水潭、Shopify、WMS、金蝶的接口文档、报文样例、成功判定、映射、重复和异常恢复方式 | 对应接口设计与联调前 |
| 库存起点、上线切换和历史数据处理 | 主数据、库存、销售、采购、集成 | 初始化截点与数量、切换期间业务安排、历史主数据及旧编码迁移范围、核对与回退方案 | 实施方案及上线前 |
| 价税计算和金蝶交易字段映射 | 价格、采购、销售、业财、集成 | 价税精度、舍入和尾差规则；七类结果单的目标单据、币别、含税金额、税费及成功标准 | 字段、财务及接口设计前 |
| 统一编码、账号和权限范围 | 主数据、辅助资料、公共能力及各业务模块 | 编码生成与唯一范围、账号来源、角色、数据范围和对象级操作权限 | 对应系统管理及对象 PRD 前 |
| 基础资料与现行作业证据 | 主数据、价格及依赖模块 | 商品、供应商、客户、仓库、物流、价表、调价和业务单据样例，以及当前维护、审核和交接记录 | 对应详细 PRD 定稿前 |
| 业务量级：各类单据量与频次、涉及仓库规模、用户规模 | 主数据之外的模块均无量级数据 | 补一组粗略量级（可先给区间）。已知粗量级集中在主数据：约 3,500 个成品 SKU、200 多家成品供应商、30 多家 B2B 客户，见《强盛科技公司业务背景信息》 | 对应 PRD 及技术方案前 |

当前没有需要通过本总览重新拍板的新增业务规则。上述事项按各自的确认时点推进：补充现行资料是为了把调研证据做实；接口、实施和系统级细节不挡着需求总览继续完善。
