## 一、分析结论与业务边界

公共能力承接跨模块共用机制，不重新定义业务状态、库存和金额规则。一期采用 RBAC 权限控制；有相应权限可提交、审核，允许审核自己创建的数据。账号来源、具体角色和数据权限留到设计阶段，不按公司组织架构直接推定权限。

完整操作日志不列为一期必做，可后续补充；待办与消息提醒一期不做，保留后续规划。这不取消[系统集成](../07-系统集成/系统集成需求分析.md)已经确认的异常单据、推送结果及必要处理记录。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 有权限即可提交、审核，可以自己审自己 | 采用 RBAC，不强制制单与审核分离 | 先明确业务操作资格，不展开岗位矩阵 |
| 导入数据仍需提交和审核 | 对需要审核的对象保留原流程 | 导入不等于审核通过 |
| 编码、导入导出细节后续再规划 | 编码统一规范；导入导出按具体 PRD | 不提前列全量对象和字段 |
| 操作日志、待办与提醒可后补 | 完整日志不强制一期，提醒后置 | 不扩大一期必做范围 |
| 业务参数先由技术配置 | 技术支持／运维维护代码配置文件 | 后续再开放对应功能模块 |

## 四、功能需求

| 编号 | 功能 | 核心要求 |
| --- | --- | --- |
| COM-FR01 | 权限与提交审核 | 采用 RBAC；有提交权限可提交，有审核权限可审核，允许本人审核本人创建的数据；权限不替代模块已有的状态、库存及金额校验 |
| COM-FR02 | 导入审核原则 | 对原本需要提交审核的对象，导入后仍需提交和审核；辅助资料、物流等原本无审核的对象不因此增加审核。导入不改变对应业务流程 |
| COM-FR03 | 编码规范规划 | 主数据编码及业务单号后续形成统一规范；组织编码等外部权威数据沿用来源。本阶段不预设生成格式、唯一范围或修改规则 |
| COM-FR04 | 参数维护 | 暂由技术支持／技术运维通过代码配置文件维护业务参数；参数含义与取值规则由所属业务模块定义，后续再提供配置功能模块 |

## 五、一期范围与模块依赖

| 范围 | 处理 |
| --- | --- |
| 本期原则 | RBAC、允许本人审核、导入保留适用审核流程、技术配置参数 |
| 后续设计 | 账号建立停用、角色和数据权限；编码统一规范；具体对象的导入导出、错误与批量处理 |
| 后续规划 | 完整操作日志、待办和消息提醒、业务参数配置页面；完整日志不作为一期必做，待办提醒一期不做 |
| 各业务模块 | 定义审核前置条件、状态及参数业务含义，本模块不改变已确认规则 |
| 系统集成 | 保留异常查看、必要推送及处理记录，不因公共日志后置而删除 |

## 六、验收标准

以下为需求验收示例，不代表已执行系统测试。规划类事项在对应设计交付时检查。

| 编号 | 关联功能 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| COM-AC01 | COM-FR01 | 用户具有提交与审核权限，创建满足业务条件的数据后提交并自行审核；再使用无相应权限的用户 | 前者可完成，无相应权限者不能执行对应动作；仍需通过所属模块业务校验 |
| COM-AC02 | COM-FR02 | 导入需审核对象与无审核辅助资料 | 前者不因导入直接生效，仍按原流程提交审核；后者不增加审核流程 |
| COM-AC03 | COM-FR03 | 编制具体主数据或业务单据 PRD | 编码规则关联统一规范；规范未定时明确待定，不将 Mock 编码当作正式规则 |
| COM-AC04 | COM-FR04 | 按模块已确认参数规则配置并验证对应业务 | 由技术支持／运维通过代码配置文件维护，业务采用对应参数；一期不要求参数管理页面 |
