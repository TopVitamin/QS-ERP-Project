## 一、分析结论与业务边界

ERP服务采购、销售、仓储运营、数据分析，以及其他需要库存信息的人员，维护逻辑仓库存，接收出入库结果，处理预占冻结、调拨和库存比对。仓内作业和盘点由WMS或仓库执行，ERP不建盘点单。

仓库结构及档案资格沿用[商品与主数据仓库规则](../01-商品与主数据/商品与主数据需求分析.md)：逻辑仓人工划分、归属实体仓并选择正常品、残次品、待检品，可存在多个相同库存状态逻辑仓；逻辑仓不等于库位。实体仓禁用不级联影响既有逻辑仓业务。虚拟在途归属及调拨见INV-FR03。

自营及第三方实际结果经直连或SaaS回传记入对应逻辑仓，包含ToC；有ERP原单沿用原单逻辑仓，无原单按来源信息和配置映射，依据不足时不随便选仓。该范围不等于全量库存双向同步、接管ToC履约或自建WMS。

采购、销售与退货的主链和各自的关闭规则，分别沿用[采购业务管理需求分析](../02-采购业务管理/采购业务管理需求分析.md)、[销售与履约需求分析](../04-销售与履约/销售与履约需求分析.md)。本模块规定共用的库存规则，以及新增的库存业务，不把其他出入库、调拨的一次执行限制推广到采购、销售。单据分层、一次回传、超量拒绝及结果单审核的共用规则见[强盛ERP的单据分层设计](../../01-全局背景信息/5.强盛ERP的单据分层设计.md)。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 多部门使用库存 | 维护即时、预占、冻结、可用库存及查询 | 支持查看余量、业务使用及分析 |
| 采购尚未入库 | 不在库存中记录或展示 | 未形成实际库存 |

| 跨仓补货、库存状态转移 | 直接调拨或分步式调拨 | 区分即时转移与运输在途 |
| 盘点、样品、赠送、报废等变化 | 其他入库、其他出库，以业务类型区分 | 不逐项新建专用单据；业务类型：其他入库＝盘盈、样品回收、借出归还、退料、赠品入库，其他出库＝盘亏、样品领用、赠送、报废、借出（2026-09-23确认） |
| 其他收发与调拨可能缺量 | 一期不分批，按实际数量一次结束 | 余量不再安排第二次，未使用的预占释放 |

| 库存不足 | 阻止报错 | 不允许负库存 |

## 四、功能需求

### INV-FR01：库存规则与查询

**可用库存＝即时库存－预占库存－冻结库存。** 即时库存是ERP库存账上的实物数量，不代表任何时刻都和仓库实物一致。预占、冻结只锁定数量，不直接减少即时库存。

ERP支持逻辑仓库存查询，为采购、销售、仓储运营、数据分析等提供信息。采购未入库数量不在库存模块记录或展示；采购订单、收货通知下发不增加库存，实际入库才增加。余额查询的列、占用来源的查看方式还没逐项确认，不据此扩展成完整报表。一期提供库存流水页：按逻辑仓、商品、时间查询，能从流水点进对应结果单。展示列随库存流水字段清单；查询权限随库存模块详细设计，本期不定岗位。

### INV-FR02：外部仓期初与初始化边界

库存账需要先有一个库存起点，不能从零开始只累计上线后的销售结果。上线时另外做一次初始化，之后按实际变动记账；本轮不设计期初导入、截点和切换校验。这个编号保留下来，供既有的引用继续使用；初始化的实施和验收放到后续切换方案里落实。

### INV-FR03：FBA 备货、分步式调拨与在途

深圳向东莞、FBA、海外仓等备货属于仓间调拨，不是消费者销售。调拨用于仓与仓之间的库存转移，不能用调拨替代买卖；不据此扩展头程物流管理。

调拨由ERP创建并调度。领星、聚水潭作为本项目下游执行方，不作为调拨发起方；这是项目分工，不作为外部产品能力验证结论。

分步式调拨单（两步式调拨）审核时预占调出仓库存，链路如下：

1. 先生成调出通知单，由系统自动推送调出仓。
2. 根据实际调出结果生成直接调拨单：调出仓减少、虚拟在途仓增加；消耗实出对应预占，释放未发余量预占。
3. 根据实际调出数量生成调入通知单并由系统自动推送调入仓，不按原计划量提前下发。
4. 根据实际接收结果生成另一张直接调拨单：在途仓减少、接收仓增加。

使用归调出仓管理的通用虚拟在途仓。A仓已经发出、B仓还没收到的货，仍然归A仓的在途；在途档案怎么挂到实体仓上，留到主数据详细设计。

不支持分批执行，允许大于0的少发、少收，每端一次执行结束。回传数量超过指令数量时拒绝整次回传。少收差异保留在途，由人工用其他出库从在途逻辑仓扣减（在途差异的业务类型取「盘亏」，2026-09-23确认），不自动抹平、不补建原单批次。主单执行结束不等于差异库存已经处理完。

实际调出必须大于0。仓库回传实际调出为0时，按零出处理：取消该分步式调拨单，不生成调出对应的直接调拨单、在途、调入通知或第二张直接调拨单，不改变库存，也不推进分步式调拨主单；取消后释放未执行预占，保留回传及确认记录。

实际调入同样必须大于0。仓库回传实际调入为0时拒绝整次回传并报错，调入通知单保持等待，不按零收取消。仓库改成大于0后再回传。

调入通知收到仓库最终回传并生成第二张直接调拨单后，分步式调拨主单自动完结。主单完结表示两端的执行链都完成了，不代表少收造成的在途差异已经清理。

| 示例：计划调拨100件 | 数量变化 |
| --- | --- |
| 审核 | 调出仓预占100 |
| 实际调出90 | 调出仓即时减90，在途加90；消耗预占90，释放余下10 |
| 通知接收 | 按90件生成调入通知 |
| 实际调入88 | 在途减88，接收仓加88；生成第二张直接调拨单后主单自动完结，剩余2留在途后续处理 |

### INV-FR04：仓库主动回传与盘点结果

仓库或SaaS反馈的其他实际库存变动，都要纳入ERP，不只限于销售和退货。商品、仓库和业务类型映射正常、通过库存校验之后，直接生成其他入库或其他出库结果单并自动生效，不补建申请、通知，也不要求对已经完成的盘亏先做预占。

盘点由WMS或仓库执行，ERP不建盘点单。盘盈形成其他入库单，业务类型是盘盈；盘亏形成其他出库单，业务类型是盘亏。品质调整按INV-FR07处理，不机械地转成其他收发。

各来源实际支持哪些变动类型、接口长什么样，都还没有核验，不能声称所有报损、盘点、品质类型都有接口。没有原单、归属依据不足时，不能随便选逻辑仓；负库存按INV-FR09阻止。

### INV-FR05：预占与冻结

销售、采购退货、分步式调拨，以及ERP发起的其他出库等正常业务，在审核时预占；可用库存不足时不能审核占库。实际出库时，即时库存和这项业务对应的预占同时扣减，通知下发不再次占库。计算时要同步反映对应预占的消耗，不能把正常已经预占的出库误判成库存不足。

冻结用于人工控制或异常处理，只能用可用数量，不重复冻结已经预占或已经冻结的数量。比如即时100、预占60、冻结10，可用就是30，最多还能新增冻结30。一期由仓储运营手工冻结、解冻，不做异常自动冻结。

一期不按正常品、待检品、残次品限制业务用途，只要有足够的可用库存，就能办理相应的出库；从发现品质问题到转仓之间的这段短暂过程，不另外设计临时冻结控制。

### INV-FR06：ERP 发起的其他出入库

- 其他入库申请单（审核后直接推送仓库）→ 其他入库单。
- 其他出库申请单（审核后直接推送仓库）→ 其他出库单。

因为一期不分批、一次执行就结束，申请和执行一一对应：申请单审核后直接推给仓库执行，不再单独生成通知单。样品领用、赠送、报废等用业务类型区分，不分别建立专用结果单；业务类型：其他入库＝盘盈、样品回收、借出归还、退料、赠品入库，其他出库＝盘亏、样品领用、赠送、报废、借出（2026-09-23确认）。出库申请审核时预占，入库申请和推送不增加库存，都按实际结果记账。

一期不支持分批，允许缺量，按仓库实际出入的数量一次执行结束，申请自动完结，不把余量回补给原单再次执行。出库剩余的预占自动释放。比如申请100、实出90，即时和预占各扣90，再释放预占10。回传数量超过申请数量时，拒绝整次回传并报错，与[《强盛ERP的单据分层设计》](../../01-全局背景信息/5.强盛ERP的单据分层设计.md) §8.2 一致。

不提供手动关闭，也不设置到期自动关单；申请单只等仓库回传一次结果，回传后自动完结，这和到期自动关单不一样。仓库回传零收或零出时，按零收或零出取消这张申请单，不生成零数量的结果单。要中止业务只能用取消：还没推给仓库的部分，可以直接取消并释放预占；已经推给仓库的部分不能直接释放，要等实际结果或仓库取消成功的反馈之后再处理，不能把ERP里的取消当成仓库已经取消。完整的取消条件和状态，留到详细设计。

### INV-FR07：直接调拨与品质调整

直接调拨单是一步式调拨：确认实际调整后，来源逻辑仓减少、目标逻辑仓增加，不经过在途。支持同一个实体仓里正常品、待检品、残次品等逻辑仓之间的调整。直接调拨单只在ERP内部处理，不推给仓库或其他外部执行系统，也不生成通知单；人工创建的直接调拨单按提交审核处理，审核通过后直接记一减一增，不涉及预占。

品质调整有两种来源：仓库主动完成后回传ERP，按回传生成自动审核的直接调拨单，不补做预占；ERP主动调整时，人工创建直接调拨单，审核通过后直接扣减来源逻辑仓、增加目标逻辑仓，不经过在途，也不下发仓库通知。

销售退货按预先指定的逻辑仓收货，发现品质变化后再调拨，沿用销售SAL-FR05；不按现场品质擅自改原退货入库的归属。直接调拨单只在ERP内部处理，按实际调整记一减一增，不涉及分批、缺量和预占。

### INV-FR08：仓库库存比对

提供库存比对看板或查询列表，查询仓库侧的“实体仓＋SKU＋库存状态”数量。仓库没有ERP逻辑仓的概念，ERP把同一实体仓、同一SKU、同一库存状态的逻辑仓即时库存汇总后再比较，展示双方数量和差异，不逐个逻辑仓比。

比对的是即时库存，不用扣掉预占、冻结之后的可用库存；虚拟在途不计入实体仓在库的实物比对。比如两个正常品逻辑仓是60和40，ERP汇总成100，仓库正常品是98，就展示ERP多2；不能据此判断哪个逻辑仓少了2，也不自动分摊改账。

共用一个实体仓的多个外部货主怎么对应，仍需核验，不混同于逻辑仓映射。每天自动比对一次，具体钟点由技术配置。比对不会自动触发库存调整。

### INV-FR09：负库存阻断与异常边界

不允许出现负库存。审核预占、冻结，以及实际结果记账，都需要校验；如果处理后即时库存或可用库存是负数，就阻止这次生效记账并报错，不采用先记负数再处理的方案。

比如即时100、预占95，收到盘亏10之后，会变成即时90、可用 −5，这时必须阻止，不自动释放已有订单的预占。异常修复和重新处理的方式，待详细设计。

外部ToC已经确认的匹配失败挂起、修复重试、去重和完结结果保护，继续引用[销售与履约需求分析](../04-销售与履约/销售与履约需求分析.md) SAL-FR12；不能丢掉既有的保护，也不能因为ERP失败就重新触发已经完成的仓库履约。其他库存业务的异常保存、冲销更正和部分成功恢复，还没有逐项定义，不擅自套用完整的状态机。

### INV-FR10：金蝶结果传递

本模块向金蝶传递其他入库单、其他出库单、直接调拨单。分步式调拨中，实际调出、调入分别生成的直接调拨单，分别传递；申请单、通知单和分步式调拨主单不推送。

采购、销售和退货的结果，按各模块已经确认的范围传递，不在这里重复定义。金蝶的接收类型、金额成本和接口映射另行确认，推送不等于核算方案已经完成。
