## 一、调研范围与资料来源

本轮覆盖 B2B 接单与发货、销售退货、独立站直连履约、ToC 出入库结果归集及金蝶衔接。

- 现状依据：[公司业务背景](../../01-全局背景信息/1.强盛科技公司业务背景信息.md)、[系统定义与上下游链路](../../01-全局背景信息/3.强盛ERP的定义和上下游链路.md)。
- 新增依据：本轮用户对业务做法、一期目标及后续方向的逐项确认。目标要求不当作历史运行事实。
- 共用边界：[商品与主数据](../01-商品与主数据/商品与主数据需求分析.md)、[组织](../10-组织/组织需求分析.md)。采购讨论仅作为提问参照，不自动套用其规则。
- 具体目标规则、数量示例和验收统一见[销售与履约需求分析](销售与履约需求分析.md)，本文保留来源、场景及原始诉求。

## 二、当前角色与系统分工

| 参与方 | 当前做法 | 来源 |
| --- | --- | --- |
| B2B 销售与客户 | 微信、电话等线下谈妥后记录成交结果；大单先报价、签合同 | 本轮用户确认的业务做法 |
| B2B 销售与金蝶 | 金蝶承接基础销售、出库，非标准交接依靠线下沟通和表格 | 01 公司背景，立项现状 |
| 领星、聚水潭及渠道仓 | 承接各自 ToC 订单及履约，补发换货等也在对应 SaaS 处理 | 01 公司背景及本轮用户业务说明 |
| 国内平台店铺 | 京东、淘宝、天猫、拼多多等是强盛入驻开店的销售渠道；“自营”指自己经营，不是向京东批量供货 | 本轮用户澄清背景叫法 |
| Amazon | 暂只有 FBA，提前备货至亚马逊仓库，由亚马逊发货 | 本轮用户业务说明 |
| 独立站业务与仓库 | Shopify 订单尚无统一系统承接，人工协调深圳仓或海外仓 | 01 公司背景，立项现状 |
| 财务 | 多系统导出后归集对账 | 01 公司背景 |

销售负责人审核、ERP 自动归集、独立站接口拉单等是本轮目标分工，见分析稿，不表示现状已经如此执行。

## 三、核心场景与业务问题

| 场景 | 业务情况或诉求 | 证据状态 |
| --- | --- | --- |
| SAL-S01 | B2B 线下成交后录单，大单报价、合同在线下完成；SAL-P01：背景中基础单据不能完整承接业务交接 | 背景及本轮确认；本轮不沿用早期随时改量改价的目标设想 |
| SAL-S02 | 客户要求一次或分批发货，地址可不同；现场自提也必须凭单，仓库可能缺量执行 | 本轮确认 |
| SAL-S03 | 接单需要保留库存，缺货可以先建单；缺量、关单后要正确处理余量 | 本轮目标诉求 |
| SAL-S04 | 订单可能取消或结束，通知仓库后不能仅由 ERP 单方面认定取消 | 本轮目标诉求 |
| SAL-S05 | 有来源和无来源退货、少退、补发换货，以及退回商品品质处理 | 本轮确认 |
| SAL-S06 | 独立站需要直接拉单，确认仓库物流后整单履约，并反馈发货及取消结果 | 背景及本轮目标诉求 |
| SAL-S07 | ToC 在外部执行，ERP 需要归集实际销售出库、退货入库结果 | 背景及本轮目标诉求 |
| SAL-S08 | 财务需要实际出入库结果，ERP 不承担退款执行；平台账单等线下处理，在金蝶手工记账 | 本轮用户说明及目标分工 |
| SAL-S09 | 国内平台入驻销售与 FBA 备货／消费者发货需要区分；外部仓库存需有期初、在途及后续变动依据 | 本轮业务说明及目标诉求 |
| SAL-S10 | 匹配失败不能审核，库存不足不能扣减；异常修复后应可继续，完结结果不能更新 | 本轮目标诉求，非已发生故障记录 |

以上不另行编造问题频率、损失或效率指标。

## 四、原始业务诉求

| 来源场景 | 用户确认的诉求 | 处理入口 |
| --- | --- | --- |
| SAL-S01 | ERP 只记录成交结果，不管报价合同；B2B 约定不随履约改量改价，信用先提醒；具体客户价、客户等级价和基准价的取价规则由价格模块统一处理 | 分析 SAL-FR01；价格分析 PRI-FR03、PRI-FR05 |
| SAL-S02、SAL-S03 | 一单一仓一交期，通知可分批且地址可不同；审核占库，实出减少占用，缺量回补可下推数量 | 分析 SAL-FR02 |
| SAL-S04 | 可以结束余量、到期关闭；订单结束不再打开，通知取消须仓库确认 | 分析 SAL-FR03、SAL-FR04 |
| SAL-S05 | 退货先审核再通知收货，允许少退、不超通知收货；优先沿用原出库价格，缺价可查询当前价或手填；补发新建销售订单 | 分析 SAL-FR05、SAL-FR06；价格分析 PRI-FR07 |
| SAL-S05 | 退货按选定逻辑仓接收，品质不符先收再用调拨单转仓 | 分析 SAL-FR05；调拨执行由库存模块细化 |
| SAL-S06 | 自研接口拉取已付款订单；一期人工批量选仓、选物流，审核通过后由系统自动推送订单至仓库；不拆单、不缺量发货 | 分析 SAL-FR07 |
| SAL-S06 | 换仓换物流保留原订单，取消审核后调整；消费者取消自动尝试，仓库拒绝则人工拦截 | 分析 SAL-FR08 |
| SAL-S06 | 后续按条件自动选仓、选物流及自动审核占库；退货能对接的接入，ERP 处理实物退货 | 分析 SAL-FR07、SAL-FR08；自动化为后续方向（审核后自动推送已纳入一期） |
| SAL-S07 | “要记录原始订单，以及我们最终出库的那张单”；售后由 SaaS 处理，来源两张单就接两张 | 分析 SAL-FR09 |
| SAL-S08 | 金额沿用来源；仅退款不做供应链单据；平台账单等线下、金蝶手工处理；结果暂时一一对应推金蝶 | 分析 SAL-FR10 |
| SAL-S09 | 国内平台都是入驻开店；Amazon 暂只有 FBA | 分析 SAL-FR11 |
| SAL-S09 | 外部仓需要期初，FBA 备货需要在途，“反馈的其他的变动我们也同步” | 库存分析 INV-FR02～INV-FR04 |
| SAL-S10 | 匹配不全卡在审核；库存不足生成失败并提示异常，不允许负库存；补齐后可重试或继续 | 分析 SAL-FR12 |
| SAL-S10 | 已完结结果不能更新，推金蝶后不能回改；有新单就按新单处理 | 分析 SAL-FR12 |

本轮补充：接口未覆盖的 Shopify 订单可人工导入 ERP，具体类型随对接范围确定；权限及本人审核原则引用公共能力分析稿。目标规则见销售分析及集成 INT-FR06，不推定真实接口覆盖范围。上述为目标诉求；取价、占库与数量、取消与关闭等目标规则统一见[需求分析](销售与履约需求分析.md)，本稿不再复述。

## 五、需要重点确认的边界

主链已确认，不代表字段、状态机和接口已完成。剩余重点是自动完成判定、T+2 日历口径、独立站拉单后的修改、退货接口范围、来源接口与金蝶映射；本轮 ToC 异常阻断及恢复原则已收口，统一见分析稿第七章。

背景中的“B2B 灵活改量改价”“ToC 回传不扣 ERP 库存”等早期目标，按分析稿本轮确认执行。独立站允许取消审核调整仓库物流，不推广为 B2B 撤回审核规则。退货调拨诉求不代表完整调拨模块已经设计完成。
