## 一、分析结论与业务边界

本文按用户最终确认整理；讨论中的举例不作为真实业务数据，未确认的提议不作为一期承诺。

三类销售分开处理：B2B在ERP建单、审核、分批通知；独立站由自研接口拉取Shopify已付款订单，在ERP人工审核、整单履约，订单直接推送给仓库执行；其他ToC继续由聚水潭、领星抓单及履约，ERP接收实际结果。

ERP负责的业务主链如下；独立站不再单独生成销售发货通知单；外部ToC单据按SAL-FR09、SAL-FR11接收：

- B2B：销售订单 → 销售发货通知单 → 销售出库单。
- 独立站：独立站订单（单独菜单）→ 销售出库单（订单审核后直接推送仓库执行）。
- 销售退货单 → 销退收货通知单 → 销退入库单。

上述ERP主动履约链路审核占用库存，实际出库减少账面库存及订单占用。订单结束不可重新打开；关闭不等于取消，已有通知单可继续执行。销售模块向金蝶仅推送销售出库单、销退入库单，包括外部ToC结果；其他库存变动不由此推定金蝶单据类型。

本轮B2B约定固定、审核后不改量改价，替代早期背景的灵活改量改价目标；ToC回传的实际结果让对应逻辑仓库存发生变化，沿用主数据最新范围，不沿用早期“ToC不扣ERP库存”的限制。

## 二、原始诉求处理

| 原始诉求 | 处理结论 | 理由 |
| --- | --- | --- |
| 线下谈妥、大单报价签约 | ERP记录成交结果，不管理报价合同流程 | 保留线下商务流程 |
| 欠款、信用控制 | 一期只提醒，不限制发货 | 客户类型、等级授信配置后续补充 |
| 分批、缺量、自提 | B2B支持分批缺量，自提也必须有单 | 按客户要求交付且保留仓库执行依据 |
| 订单变动、取消、关闭 | B2B不改已审核的数量和价格；取消、关闭分开控制 | 防止提前释放正在执行的库存 |
| 独立站整单履约 | 单仓、不拆单、不分批缺量 | 与B2B区分 |
| 审单规则自动处理 | 一期人工选仓、选物流与审核，审核通过后自动推送；条件与动作自动化后续建设 | 自动推送已纳入一期；自动选仓、选物流及自动审核占库仍为后续方向 |
| ERP主动办理的退货与补发 | 实物退货独立执行，补发换货新建销售订单 | 不恢复原销售订单额度；外部ToC见SAL-FR09 |
| 外部ToC履约和售后 | SaaS处理业务，ERP保留原始订单及实际结果，按来源单据拆分归集 | 保留追溯，不接管履约 |
| ToC金额与平台结算 | 结果金额沿用来源；平台账单等由财务线下及金蝶手工处理 | 不用ERP价目表重算，不扩展平台对账 |
| 结果异常与恢复 | 匹配、库存等异常阻断；人工补齐后继续处理；已完结结果不可改 | 防止负库存及重复记账 |

## 四、功能需求

### SAL-FR01：B2B 建单与审核

线下谈妥商品、数量、价格后创建订单；大单先在线下报价签合同，ERP仅记录成交结果。销售负责人审核销售订单及销售退货单，不增加财务强制放行环节。欠款、信用额度相关问题只提醒，不限制发货；按客户类型、等级配置授信额度是后续方向。

B2B销售订单按“具体客户价 → 客户等级价 → 所有客户基准价”的顺序匹配所选SKU和币别；都没匹配上时允许人工填写。草稿改价、改币别清价、零价提醒、提交校验及价格税率锁定统一按[价格管理需求分析](../06-价格管理/价格管理需求分析.md) PRI-FR03～PRI-FR05执行。

B2B已审核订单不允许改量改价，不追溯调整已发货部分，允许调整交期。录错时按SAL-FR04取消后新建，不撤回审核修改。一张订单一个仓库、一个交期，不同仓库拆销售订单。

### SAL-FR02：占库、分批通知与实际出库

库存不足可创建订单，但审核报错，不能完成审核占库。审核通过时占用订单库存。销售订单维护成交约定的发货方式、发货地址与物流服务产品；销售按客户要求一次或分批创建通知单，仓库必须沿用订单，通知单默认继承订单约定，分批发货时地址或物流可按本次覆盖；创建时选择发货处理方式，默认仓库发货。仓库发货时，通知单创建后由系统自动推送仓库，不需要人工再点一次推送。虚拟出库时不推仓库，创建成功后各行实发等于通知数量，系统立即按通知数量生成销售出库单并自动审核，通知变为已发货，并减少即时库存、消耗对应预占；虚拟出库不允许缺量或零出。处理方式写在通知单上，不写在销售订单上。现场自提仍走仓库发货：必须先有订单及通知单，仓库不得无单放货。独立站仍由订单直接推送仓库，本期不增加虚拟出库。

B2B允许缺量出库，一张通知单一次执行结束，少出部分回补可下推量，补发另建通知单。同一SKU、不存在取消或关闭等释放动作时：

- 订单剩余占库＝审核占用数量－累计实际出库数量。
- 可下推量＝订单数量－已结束通知单实际出库数量－未结束有效通知单通知数量；已取消通知单不占可下推量。

通知下发不再次占库，也不扣账面库存。实际出库才减少账面库存及对应订单占用；少出回补的是可下推量，不是重新占库。关闭后即使有余量也不能再安排。

| 示例：订单1,000件，无其他通知单 | 剩余占库 | 可下推量 |
| --- | --- | --- |
| 审核通过 | 1,000 | 1,000 |
| 通知600件，尚未出库 | 1,000 | 400 |
| 实出600件并结束 | 400 | 400 |
| 若实出580件并结束 | 420 | 420 |

### SAL-FR03：B2B 关闭与占库释放

支持手动关闭，以及在交期、退货截止日期之后第2个自然日的0:00自动关闭（即日期+2天当天0:00），允许调整对应日期；T+2按自然日计算，不跳过周末。每天北京时间0:00跑批。B2B订单发货状态变为全部发货时立即自动关单，关闭方式记「全部履约自动关闭」，关闭操作人和关闭原因都留空；手工关闭时关闭原因必填。不另设已完成状态。独立站不适用到期自动关单，也不套用全部履约自动关单。关闭后不可重新打开。独立站订单单独放在「独立站订单」菜单，不并入B2B销售订单。

关闭保留原订购数量和实际结果，禁止新增通知单；已有通知单继续执行。只释放还没安排成通知单的那部分占库，保留执行中通知单对应占用，结束后释放少出余量。例如占库1,000件、通知600件未出库时关闭，先释放400件；通知最终实出580件，扣减其实际出库占用后再释放未发的20件。

### SAL-FR04：销售订单与通知单取消

| 条件或操作 | 规则 |
| --- | --- |
| 没有通知单，或者所有通知都还没推送、推送失败 | 允许取消销售订单，相关通知单一起取消，释放相应占库 |
| 存在推送中，或已推送仓库且未取消的通知单 | 不允许直接取消销售订单 |
| 通知已获仓库取消成功，无实际出库且无其他阻挡通知 | 允许取消销售订单，不因曾经推送过而永久禁止 |
| 向仓库申请取消通知 | 等待WMS结果，不能立即标记已取消或提前回补数量 |
| 仓库确认取消成功 | 通知变为已取消；订单开放时恢复可下推量、保留订单占库；订单关闭时释放该部分占库，不恢复下推资格 |
| 仓库拒绝取消 | 恢复取消前状态，例如推送成功，继续执行 |

取消保留历史记录，不删除已发生业务。销售出库结果单不属于上述取消对象。

### SAL-FR05：销售退货创建与收货

支持关联原销售出库单的溯源退货，以及无来源手工创建。溯源优先带出商品、数量和原出库价格；来源缺价或无来源时，可手工填写或主动查询当前销售价快速填充，查询结果在草稿阶段仍可修改。提交后价格和税率锁定，取价及校验按价格管理PRI-FR05、PRI-FR07执行。审核后不可修改其他业务内容，仅可调整退货截止日期。审核后才生成销退收货通知单；创建时选择收货处理方式，默认仓库收货。仓库收货时由系统自动推送仓库，实际入库形成销退入库单并增加库存。虚拟入库时不推仓库，创建成功后各行实收等于通知数量，系统立即按通知数量生成销退入库单并自动审核，通知变为已收货；虚拟入库不允许缺量或零收。处理方式写在通知单上，不写在退货单上。退货单支持草稿删除；退货截止日期手工填写、必填（2026-09-22确认，见04销售退货单PRD）。

一张退货单一个收货仓，通知单沿用。溯源退货不允许切换原单仓库；无来源退货可指定收货仓，不要求与历史发货仓一致。退货时事先选定逻辑仓，实际只进入该逻辑仓；发现品质问题可先收，再用调拨单转入其他逻辑仓，不按现场品质直接改入库归属。调拨执行由库存模块细化。

### SAL-FR06：退货额度、缺量与结束

溯源退货累计不得超过原实际出库数量。退货单审核时占用原出库单可退额度，草稿不占；其他已审核办理中的退货也计入额度控制。取消或关闭释放未退且无通知继续执行的额度，已实际退回部分仍计入累计退货。例如原出库100件，审核退60件、实际收50件后关闭且无未结束通知，仍可再申请退50件。无来源退货不套用原出库额度，每行数量须大于0；销售退货是收货增加库存，审核时不按可用库存卡数量。

一张通知收货一次结束，允许少收，不允许超过通知数量接收。可下推量为退货单数量，减去已结束通知实收数量及未结束有效通知数量；取消的通知不占额度。例如退货100件、通知60件、实收50件结束后，还能再安排50件。仓库回传实收为0时按零收取消该通知单，不生成零数量销退入库单。

退货支持手动关闭、B2B截止时间之后第2个自然日0:00自动关闭和调整截止时间；关闭后不可新增通知，已有通知继续收货。退货取消参考销售订单及通知单的控制：未推送或推送失败的通知随退货单取消；存在推送中、已推送且未取消的通知时，不直接取消退货单。已推送通知须经仓库确认取消成功，拒绝则恢复取消前状态。取消成功且无实际入库、无其他执行中通知时，可取消退货单。通知取消后，退货单仍开放则回补可下推量、保留原出库单可退额度占用；退货单已关闭则释放相应可退额度，不允许继续安排。补发或换货新建销售订单，不恢复原销售订单的可下推量。

### SAL-FR07：独立站接入与一期履约

自研接口对接Shopify，仅拉取已付款订单。支持深圳仓直发和海外仓发货；一期由业务人员勾选订单，批量选仓、选物流，人工审核时占库。库存不足审核失败，保留待处理，补货或人工调整仓库后重新审核。审核通过后由系统自动推送订单至仓库执行，不再需要人工勾选批量推送；因一单一仓、整单履约，订单与本次执行一一对应，订单直接承担执行指令，不再单独生成销售发货通知单。

独立站一单一仓，不拆成多张订单跨仓发货，不分批、不缺量发货。仓库无法足量发出时整单不发，继续保留占库，等待人工处理；收到仓库明确、最终的整单零执行结果时，按零出取消该销售订单并释放占库，实发数量为0、差额等于订购数量，不生成零数量销售出库单、不推金蝶，并保留最终回传及确认记录。原单终止，不能在原单上改仓、改物流后重审。仓库有货后再发：从原单复制生成新单，按独立站流程重新选仓、审核、推送；也可以等消费者取消。新单用新的ERP单号，仍挂同一个Shopify来源单号。以上不改变聚水潭、领星内部履约方式。发货后把发货结果和运单号同步回Shopify。

独立站订单金额沿用Shopify，ERP不能改，不按B2B价目表取价。

Shopify来源订单变化时，先看上游是改了原单还是另开了新单。原单改了再拉一次：尚未审核的ERP单据按本次拉取覆盖商品、数量、地址和金额；已经审核的不覆盖，由ERP再创建一张新单，同样挂该Shopify单号。上游另开新单的，按新单拉取，生成新的ERP单据。已审核的原ERP单据不因此自动取消。

审核后自动推送仓库已纳入一期；后续方向为条件与动作配置：自动选仓、选物流、自动审核占库。完整自动化链路不列为一期必做，具体条件和动作后续设计。

### SAL-FR08：独立站调整、取消与退货

换仓或换物流保留原ERP订单：未推送仓库时取消审核、释放占库，修改后重新审核；已推送仓库时必须等仓库确认取消成功，再释放占库并调整。取消审核用途为“终止订单”时记为已取消；用途为“调整后重新执行”时回到草稿，页面可显示为“待提交”，原订单可继续编辑仓库、物流等允许调整内容。修改后重新提交审核算一次新的仓库执行，和上一次区分开；上一次的执行记录、取消用途和回执都保留，迟到的回传只能关联上一次执行，不能推进新执行。此例外不推广为B2B撤回审核修改。

消费者取消请求触发自动尝试取消，取消的等待与恢复原则沿用SAL-FR04，处理对象为订单推送：未推送仓库的可直接取消；已推送仓库的先申请取消并等待确认，不能提前向Shopify认定取消成功。仓库拒绝时恢复取消前状态并继续正常发货；仍要停止发货由人工介入拦截。

独立站退货能对接的通过接口接入；接口未覆盖的Shopify订单可人工导入ERP，具体类型按实际对接范围确定，见集成INT-FR06；ERP沿用实物退货链路，不执行退款。不将“仅退款”计为库存增加。

### SAL-FR09：ToC 结果归集与库存归属

聚水潭、领星负责的国内及跨境ToC，其正向履约、退货、补发、换货均由对应SaaS处理，再同步自研ERP。Shopify独立站仍按SAL-FR07、SAL-FR08直连ERP，不因本轮ToC讨论改变其已确认方案。

ERP保留原始平台订单、实际出库单及其关联，逐笔归集实际结果，不只接日汇总销量。原始订单用于追溯，不因此提前接单占库或重新触发履约。售后单据按来源系统实际拆分接收：SaaS形成两张单，ERP也接收两张，不自行合并；是否能关联同一次售后取决于来源信息，不补造关联。外部补发不套用ERP主动履约的新建销售订单规则。仅退款不生成供应链单据、不影响库存，财务路径见SAL-FR10。

销售出库及退货入库实际结果回传后，通过匹配和库存等校验则自动审核、生效、记库存并进入金蝶推送，不增加常规人工审核。实际出库减少对应第三方逻辑仓库存，不重复扣自营仓；实际退货入库增加对应逻辑仓库存。原单及无原单的库存归属沿用[商品与主数据需求分析](../01-商品与主数据/商品与主数据需求分析.md)，异常阻断与恢复见SAL-FR12。

外部仓期初、FBA备货在途及其他库存变动见[库存与仓储需求分析](../03-库存与仓储/库存与仓储需求分析.md) INV-FR02～INV-FR04；此范围不等于全量库存双向同步、跨渠道统一调度或仓内作业接管。

### SAL-FR10：物流及金蝶衔接

销售物流沿用[商品与主数据需求分析](../01-商品与主数据/商品与主数据需求分析.md)：非自提选具体物流服务产品或“由仓库指定”，自提不选产品；ERP传递选择并接收运单及轨迹，不直连物流商取面单，物流商禁用不影响已有启用产品。空值及下游编码协议待确认。

销售单据引用客户、商品、仓库、物流等主数据。客户资格、通用2C客户及其他主数据使用规则沿用主数据文档。

销售侧向金蝶仅推销售出库单、销退入库单，覆盖B2B、独立站、其他ToC；销售订单、销售退货单和通知单不推。两类结果单暂按逐单一一对应推送，不按日期、店铺汇总。金蝶字段对照本期不编，对照表由财务联调时给出。

外部ToC的成交优惠后金额、退货金额沿用SaaS结果，不用ERP销售价目表重算；缺少必要金额按异常处理，不自行补价。仅确认金额来源，不代表币种、税费等字段及核算规则已定义。

本轮渠道的平台账单、收退款（含仅退款）、佣金、仓储履约费及最终结算回款，由财务线下处理并在金蝶手工记账；本期不经ERP归集对账。结果推送不等于已定义收入或应收确认规则，也不将此结论扩展为B2B等其他业务的完整结算方案。

### SAL-FR11：渠道交易模式

京东、淘宝、天猫、拼多多等国内电商平台都按强盛入驻、自行经营店铺并向消费者销售处理。“自营”指强盛自己经营店铺，不按强盛向京东批量供货的模式设计。各平台实际接入能力另行核验，不因渠道列入就推定接口已接通。

Amazon暂仅覆盖FBA：强盛提前备货到亚马逊仓库，亚马逊执行消费者订单发货。备货送仓属于库存转移，不是消费者销售出库；不纳入商家自行发货或向Amazon批量销售的其他交易模式。

### SAL-FR12：外部结果异常、重试与完结保护

| 情形 | ERP处理原则 |
| --- | --- |
| 商品或逻辑仓无法匹配 | 单据不能审核通过，挂起，不记库存、不推金蝶 |
| SaaS实际出库成功，但ERP对应逻辑仓库存不足 | ERP生成结果单失败，提示异常单据，本次扣减失败，不形成负库存、不推金蝶；不得把SaaS成功视为ERP成功 |
| 人工补齐映射或其他必要内容、解决阻塞原因 | 可对原异常记录重试或继续处理，通过后再记库存、推金蝶，不另造一笔业务 |
| 异常恢复涉及仓库环节 | 需要下发仓库的单据可重试推送；SaaS已履约的结果回传只继续ERP后续处理，不重新触发仓库出入库 |
| 来源重复回传或人工重试 | 已成功处理的单据不得重复记账、重复形成金蝶业务单据；具体去重标识及部分成功恢复机制待接口设计 |
| 来源要求更新已完结结果 | 原结果不可更新，已推金蝶后也不能回头修改；不采用跟随来源直接修改或自动冲销原结果的方案 |
| 后续来源形成新单 | 作为新单按其业务含义校验、处理及推送，不覆盖原结果；新单类型及映射须按来源核验，不预设负数冲销方案 |

本节明确业务边界，不定义完整状态机。“完结”的具体状态字段、异常保存形态及处理权限留到详细设计；尚未完结单据的来源变更协议仍需核验，不套用已完结结果规则推定全部更新行为。
