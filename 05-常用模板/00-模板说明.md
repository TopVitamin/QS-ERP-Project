# 常用模板说明

这几份是方法，不是业务结论。换项目时，换模块名、单据名和数量名就能用。做哪个阶段就读哪份，先看通用规则那份。

本仓库写文档时，仍以各目录的 `AGENTS.md` 和《业务设计和应用设计的边界》为准。模板和目录内文件打架，听目录内的。方法里写「可以合并」「可以简化」的地方（域很薄时并章节、没有外部接口时只写内部补录），是给通用层留的灵活度，不代表本项目照此执行。

| 文件 | 回答什么 |
| --- | --- |
| [文档通用规则（通用模板）-V1](文档通用规则（通用模板）-V1.md) | 结论放在哪、引用怎么写、还没定的怎么标、写完怎么查、文字怎么顺 |
| [需求调研与分析文档方法（通用模板）-V1](需求调研与分析文档方法（通用模板）-V1.md) | 现状怎么记、目标结论怎么给 |

后面三份的骨架、深度要求和检查项可以沿用。带「示例」标记的对象类型、数量名和单据分层只在《应用设计四篇骨架（通用模板）-V1》里，那是某类系统的一种拆法，不要当目标项目的结论抄走。

评审办法、写作纪律、结论状态的标法都在《文档通用规则（通用模板）-V1》里；三份方法文档不重复整套规则，只保留各层特有的落地提醒。
