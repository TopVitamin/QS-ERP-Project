# 常用模板说明

这几份是方法，不是业务结论。换项目时，换模块名、单据名和数量名就能用。做哪个阶段就读哪份，先看通用规则那份。

本仓库写文档时，仍以各目录的 `AGENTS.md` 和《业务设计和应用设计的边界》为准。模板和目录内文件打架，听目录内的。

| 文件 | 回答什么 |
| --- | --- |
| [文档通用规则（通用模板）-V1](文档通用规则（通用模板）-V1.md) | 结论放在哪、引用怎么写、还没定的怎么标、写完怎么查、文字怎么顺 |
| [需求调研与分析文档方法（通用模板）-V1](需求调研与分析文档方法（通用模板）-V1.md) | 现状怎么记、目标结论怎么给 |
| [业务设计文档方法（通用模板）-V1](业务设计文档方法（通用模板）-V1.md) | 业务应该怎样运转 |
| [应用设计四篇骨架（通用模板）-V1](应用设计四篇骨架（通用模板）-V1.md) | 系统怎样支撑业务 |

后面三份的骨架、深度要求和检查项可以沿用。文中标了「示例」的对象类型、数量名、单据分层，是某类系统的一种拆法，不要当目标项目的结论抄走。

评审办法、写作纪律、结论状态的标法都在《文档通用规则（通用模板）-V1》里，三份方法文档只留了指向它的话。

字段清单、模块 PRD、原型标注还没抽到这里。本仓库的字段列格式见 `04-产品设计方案/AGENTS.md`。
