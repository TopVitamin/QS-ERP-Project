# 常用模板说明

本目录提供ERP项目的方法与文档模板，优先满足人的阅读、判断和评审需要，AI辅助整理与生成。模板结构可以复用，业务内容须按当前需求填写。做哪个阶段就读哪份，先看通用规则。

本仓库写文档时，仍以各目录的 `AGENTS.md` 和《业务设计和应用设计的边界》为准。模板和目录内文件打架，听目录内的。方法里写“可以合并”、“可以简化”的地方（域很薄时并章节、没有外部接口时只写内部补录），是给通用层留的灵活度，不代表本项目照此执行。

### 如何选用和裁剪

- 有状态流转、上下游单据衔接的业务模块（采购订单、销售订单、通知单等）优先用 V2 模板；主 PRD 写业务契约与状态矩阵，页面细节在 Demo PRD。
- 主PRD以功能说明为中心。新建模块写完整范围；调整类需求写清前后差异及影响，不重写整个模块。
- 主数据模板支持基础维护，审批和外部同步等按需展开，不要求全部具备。
- 页面少、交互较简单时用一份Demo PRD；页面复杂、差异较多时拆分，不按规则条数设硬门槛。
- 骨架先供快速审查，须按 V2 模板画出 **6 列栅格**与**标签在上/控件在下**结构；具体交互、校验、反馈及必要尺寸由 Demo PRD 和 09 原型说明。
- 本套模块PRD模板不设置权限章节或权限矩阵。状态下允许哪些业务动作，仍需按业务规则说明。
- 上下游协同、上线准备、复杂状态等章节按需保留，不适用就删除，不保留空架子。
- 简单内容用短段或短表，复杂内容再分节、配图。示例须替换或标明，定稿删除填写提示，未决事项明确保留。
- 公共UI规范引用实际文件与版本；显示文案写具体，错误后如何修正或继续写清，不只写“按规范”。

正式产物放入项目规定目录：主PRD与TSV属于产品设计资料，页面骨架和Demo PRD随原型设计资料维护。系统架构四篇已有的流程、对象和状态设计在主PRD中引用，避免重复维护。
