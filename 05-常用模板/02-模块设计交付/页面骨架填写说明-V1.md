# 页面骨架填写说明

> 模板版本：V1.1
> 本说明供编写页面骨架时查阅，不复制到模块正式文档。正式交付使用[《页面骨架模板-V2》](页面骨架模板-V2.md)（当前 V2.1）。

## 骨架写什么

页面骨架用于快速确认页面、分区、字段位置、基本控件、按钮和示例值。字段名称、分组和顺序以字段清单 TSV 为准；业务动作和状态条件以主 PRD 为准；校验时机、反馈、Mock 和交互细节写在 Demo PRD。

骨架**不重复**主 PRD 的业务规则，也**不堆**多选/排序/分页等交互细节——这些交给 Demo PRD 和 09 原型。

## 文档结构（V2.1）

每份模块骨架建议按以下层次组织：

| 章节 | 写什么 |
| --- | --- |
| 文档说明 | 与主 PRD、Demo PRD、TSV 的分工；各页「图前 / 图中 / 图后」结构 |
| 绘制约定 | 引用本说明与UI公共说明；只补本模块特有约定 |
| 各页面 | 图前：用途 + 关键要素；图中：ASCII 线框；图后：**补充说明**（无序列表） |
| 待确认问题 | 只记影响布局或入口的未决项 |
| 骨架检查 | 交付前自检清单 |

### 补充说明怎么写

图后只写图中看不出的内容：

- 省略了哪些列或Tab，完整清单在哪。
- 哪些按钮、区块随状态变化，条件引用主PRD的哪条规则。
- 哪个布局重点容易被误读，需要一句补充。

不重复列出线框里已有的字段、按钮和分区；没有补充时写“无”，无需凑齐上述三类。

### 关键要素怎么写

只写**影响分区或入口**的块，例如页头操作、核心筛选维度、关键业务列。不要把多选/单选、默认排序、批量栏细项写进关键要素——这些不是业务范围，是页面约定。

## 布局规则

| 区域 | 画法 |
| --- | --- |
| 查询区、表单、详情只读区 | 6 列；标签在上，控件或值在下；普通字段占 1 列，备注等多行文本占 3 列 |
| 备注字段 | 按TSV行序排入栅格；当前行剩余至少3列时接在前一字段后，不足3列则换行。不固定从第2列开始 |
| 明细表格 | 不使用 6 列栅格；列名与 TSV 明细字段一致 |
| 弹窗 | 字段不超过 3 个时单列纵向；字段较多时使用 6 列 |
| 状态与操作信息 | 编辑页、详情页在标题旁展示状态；操作信息只放详情页底部 |

关联选择的示例值按 Code-Name 展示；详情空值写 `-`。具体样式、分页、列设置和 Toast 以[《原型开发说明》](../../09-产品原型/原型开发说明.md)及[UI布局公共说明](UI布局公共说明.md)为准。

## 页面顺序与页头约定

分区顺序、列表页头操作、详情页“返回列表”位置均见[《UI布局公共说明》](UI布局公共说明.md)。业务按钮是否出现按主PRD，具体顺序在骨架图中体现；只画一种状态时，在补充说明中列出其他状态的差异。导入、导出、新增和批量业务操作均须有本期范围依据。

## 画法与检查

- 页面、弹窗和抽屉用 ASCII 线框画出分区。
- 查询区、表单和详情区保留6列，标签与值分两行；未用列标“（空）”，不写“标签：值”横排。
- 跨3列字段只在起始列画标签和控件，后两列标“（续占）”，表示同一个控件的宽度，不能误画成三个字段。
- 组内按TSV行序和字段占列数排列，剩余列放不下下一个字段时换行；图中使用实际字段、控件、标题和按钮文案。
- 只画本期存在的页面、弹窗和动作。未确定内容写「待确认」。
- 有 09 原型时，页头按钮顺序、收起过滤位置、详情页头单行布局须与原型一致；布局与原型不一致时按项目页面约定核对；若涉及字段或业务动作，仍回查TSV与主PRD，不能由原型反向新增规则。

交付前跑一遍模板中的「骨架检查」清单。
