# 产品设计方案 · 写作须知

适用范围：`04-产品设计方案/`。这里放正式设计产物（字段清单、PRD、流程图）；需求规则依据在 02，业务设计依据在 03，页面行为在 09。

`系统架构和流程/` 四篇的方法、深度标准和逐条自查见[应用设计四篇骨架（通用模板）-V1](../05-常用模板/应用设计四篇骨架（通用模板）-V1.md)。本项目固定用四篇，不按模板里的系统形态裁剪；字段列格式和本目录其余规则见下文。

## 目录与版本

- 新版本建日期目录：`YYYYMMDD-版本名`；旧版本目录保留，不覆盖。
- 字段清单合集按业务分组（如 `基础资料/`、`采购相关/`）；分组下按对象建文件，主数据对象还可以再建子目录。先出初稿，再补详细稿。

## 字段清单（TSV）

- UTF-8、制表符分隔；表头固定，不改列序、不合并单元格；一行一个字段。
- 初稿 5 列：字段所属分组、字段名称、字段类型、字段来源、字段说明/描述。
- 详细稿 13 列：字段所属分组、字段名称、字段类型、字段来源、必填性、新增页、编辑页、列表展示、可筛选、详情展示、字段说明/描述、取值说明、备注。
- 字段类型沿用既有写法：文本、数值、金额、日期、日期时间、枚举、布尔、关联选择、关联明细、多行文本、图片、用户引用、系统记录。
- 字段类型是闭集，不另造近义写法（如「选择」「整数」「关联」「配置引用」「文本明细」）：字典数据与档案引用用「关联选择」，字段自带的固定选项用「枚举」，整数等数字统一用「数值」，纯文本用「文本」，多值且一行一条用「多行文本」。
- 字段名称用业务中文名，与 02 用语一致；关联资料写「xx资料」，枚举把选项列全。
- 未确认的内容不猜：单元格写「待确认」，不要留空或填入假设；来源不明的写「待确认」。

## 文档（PRD / 说明）

- 结构沿用 02 的写法：结论与边界 → 追溯矩阵 → 功能需求 → 范围与依赖 → 验收标准 → 待决策事项。
- 头部保留版本表（版本 / 本次变化 / 状态），每次改动补一行；不在正文里写变更过程。
- 每个结论能指到来源（01/02 文档或用户确认），链接用相对路径。

## 边界

- 不写需求论证（放 02）、不写页面交互与实现（放 09）。
- `系统架构和流程/` 用《系统与模块地图》《系统流程与单据交互》《实体对象关系》《单据与状态流转》四篇骨架，不套模块 PRD 模板；PRD 只写功能需求和验收，引用这四篇，不重画流程和状态。
- 字段或枚举调整若与 02、03 结论冲突，先改 02，再同步 03，最后改 04。
