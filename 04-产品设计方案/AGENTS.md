# 产品设计方案 · 写作须知

适用范围：`04-产品设计方案/`。这里放正式设计产物（字段清单、PRD、流程图）；需求规则依据在02，业务设计依据在03，页面行为在09。

`系统架构和流程/` 四篇的方法、深度标准和逐条自查见[应用设计四篇骨架（通用模板）-V1](../05-常用模板/01-阶段方法/应用设计四篇骨架（通用模板）-V1.md)。本项目固定用四篇，不按模板里的系统形态裁剪；字段列格式和本目录其余规则见下文。

## 目录与版本

- 新版本建日期目录：`YYYYMMDD-版本名`；旧版本目录保留，不覆盖。
- 字段清单合集按业务分组（如 `基础资料/`、`采购相关/`）；分组下按对象建文件，主数据对象还可以再建子目录。先出初稿，再补详细稿。

## 字段清单（TSV）

字段清单直接使用TSV，不再另写Markdown字段清单。

- UTF-8、制表符分隔；表头固定，不改列序、不合并单元格；一行一个字段。
- 初稿5列：字段所属分组、字段名称、字段类型、字段来源、字段说明/描述。
- 详细稿13列：字段所属分组、字段名称、字段类型、字段来源、必填性、新增页、编辑页、列表展示、可筛选、详情展示、字段说明/描述、取值说明、备注。
- 详细稿的页面列取值：新增页、编辑页用“是／只读／否”（只读指在页面上出现但不可编辑）；列表展示、可筛选、详情展示用“是／否／待确认”。页面行为以09原型为准，原型没有的页面按02／03的业务要求判断，仍没依据的写“待确认”。必填性用“是／否／条件必填／不适用（系统赋值）”；原型与口径不一致的地方，在备注里写清并汇总到09的待改项。
- 字段类型沿用既有写法：文本、数值、金额、日期、日期时间、枚举、布尔、关联选择、关联明细、多行文本、图片、用户引用、系统记录。
- 字段类型是闭集，不另造近义写法（如“选择”、“整数”、“关联”、“配置引用”、“文本明细”）：字典数据与档案引用用“关联选择”，字段自带的固定选项用“枚举”，整数等数字统一用“数值”，纯文本用“文本”，多值且一行一条用“多行文本”。
- 字段名称用业务中文名，与02用语一致；关联资料写“xx资料”，枚举把选项列全。系统记录类维护字段统一用「最后更新人」「最后更新时间」，不用「更新人」「更新时间」，见《6.强盛ERP的编码规则和通用字段规则》第三节。
- 字段分组、名称、来源、含义、取值及页面使用信息放TSV；完整枚举写清，条件必填要说明条件或指向具体规则。
- 关联选择类主数据（供应商、客户、仓库、商品等）在页面展示时默认按 Code-Name（`{编码} {名称}`）拼接，规则见《6.强盛ERP的编码规则和通用字段规则》2.3；字段清单拆成独立编码列、名称列的除外。
- 未确认的内容不猜：单元格写“待确认”，不要留空或填入假设；来源不明的写“待确认”。

### 与其他交付物的分工

- 复杂计算、联动、跨字段约束在主PRD说明，TSV备注引用文件和规则编号；页面校验时机及反馈在Demo PRD说明。
- 主PRD、页面骨架和Demo PRD使用同一字段名；必要信息可就近展示，字段事实以TSV为准。发现不一致时回查并同步，不由页面自行创造字段。
- 新增/编辑采用弹窗时，TSV中的新增页、编辑页仍表示对应维护场景；查看弹窗对应详情展示，备注中注明容器形式。

### 交付前自查

检查表头、列数、取值、空单元格和跨文档字段名称。不适用按本节允许取值填写，未确定内容保持“待确认”。

## 文档（PRD / 说明）

- 结构沿用02的写法：结论与边界 → 追溯矩阵 → 功能需求 → 范围与依赖 → 验收标准 → 待决策事项。
- 头部保留版本表（版本 / 本次变化 / 状态），每次改动补一行；不在正文里写变更过程。
- 每个结论能指到来源（01/02文档或用户确认），链接用相对路径。

### 页面骨架与 Demo PRD

- 字段名、枚举、列表列、筛选项与 TSV 详细稿一致；列顺序按 TSV「列表展示=是」「可筛选=是」排列，不在 Demo PRD 另造字段。
- 关联选择类主数据（供应商、客户、仓库等）在列表、详情、下拉、筛选已选值中默认按 Code-Name（`{编码} {名称}`）展示，见《6.强盛ERP的编码规则和通用字段规则》2.3；TSV 将编码、名称拆成独立列的除外。
- 含税类单据明细的价税字段默认顺序：含税单价、税率、不含税单价、价税合计、税额、金额；其中**金额指不含税金额**，**价税合计指含税总额**；单头汇总字段同名，见《6.强盛ERP的编码规则和通用字段规则》第三节「价税字段命名」。
- 布局与控件样式引用[《UI布局公共说明》](../05-常用模板/02-模块设计交付/UI布局公共说明.md)和09 AGENTS；骨架画字段位置，Demo PRD 写校验、联动与文案。详情页的关联单据、操作信息（制单信息／操作日志胶囊 Tab）按 UI 公共说明与 09「详情页标准接线」画，不在骨架里另造平铺「维护信息」卡片。
- 列表批量操作栏：默认只写「已选中计数」与列设置；导入导出在页头。主数据 Demo PRD 可写批量提交审核、启用禁用、删除等；业务单据一期以行内操作为主，批量栏不写删除、取消、关闭等业务按钮，勾选列注明是否仅配合导出「已勾选」。
- 状态类筛选：业务单据列表的并列状态维度（审核状态、业务状态、收货/发货状态等）默认**多选**；未选等同全部，选中多项 OR 匹配。见[《UI布局公共说明》](../05-常用模板/02-模块设计交付/UI布局公共说明.md)。

## 边界

- 不写需求论证（放02）、不写页面交互与实现（放09）。
- `系统架构和流程/` 用《系统与模块地图》《系统流程与单据交互》《实体对象关系》《单据与状态流转》四篇骨架，不套模块PRD模板；PRD只写功能需求和验收，引用这四篇，不重画流程和状态。
- 字段或枚举调整若与02、03结论冲突，先改02，再同步03，最后改04。
