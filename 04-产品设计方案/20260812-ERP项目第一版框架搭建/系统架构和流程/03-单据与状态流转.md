### 审核操作怎么叫

待审核时，审核人对单据的处理分正向与不同意两类；**有没有独立的「已驳回」状态，决定不同意时叫「驳回」还是「撤回」**。

| 对象类型 | 审核状态链（摘要） | 草稿时操作 | 待审核·正向 | 待审核·不同意 | 意见字段 |
| --- | --- | --- | --- | --- | --- |
| 主数据（供应商、客户、实体仓、逻辑仓等；一期驳回不录入意见） | 草稿 → 待审核 → 审核通过／**已驳回** | 提交 | 审核通过 | **驳回** | 驳回意见（一期不录入） |
| 价格调整单 | 草稿 → 待审核 → 已审核／**已驳回** | 提交 | 审核 | **驳回** | 驳回意见 |
| 业务安排单、结果单等（**无已驳回态**） | 草稿 → 待审核 → 已审核 | 提交 | 审核 | **撤回**（回到草稿） | 撤回意见 |

说明：**审核通过**与**驳回**是两个概念，只用于有独立驳回态的对象；无驳回态时，不同意只能**撤回**到提交前（草稿），不叫驳回。各节状态图与操作表按上表执行；主数据 PRD 与字段清单 owner 各自小节。主数据（供应商、客户、实体仓、逻辑仓）审核通过后需要修改的，先反审核回到草稿，再修改并重新提交审核。

## 二、状态与操作：三层主单（以采购订单为例）

**审核状态**（只走审核流程，与业务状态独立）：

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 待审核: 提交
    待审核 --> 草稿: 撤回
    待审核 --> 已审核: 审核
    已审核 --> [*]
```

**业务状态**（控制还能不能继续办，与审核状态组合出现）：

```mermaid
stateDiagram-v2
    [*] --> 正常
    正常 --> 已取消: 取消
    正常 --> 已关闭: 关闭（手工或到期）
    已取消 --> [*]
    已关闭 --> [*]
```

**收货状态是计算列**（未收货／部分收货／全部收货），不参与流转；全部收足也不会自动关闭订单。

| 状态 | 可执行操作 | 前置条件与校验 | 结果与联动 |
| --- | --- | --- | --- |
| 草稿、正常 | 编辑、提交、删除 | 数量大于0；单价非空非负；供应商启用；零价需确认；删除须未被下游引用 | 提交 → 待审核；删除 → 记录消失 |
| 待审核、正常 | 审核、撤回、取消 | — | 审核 → 已审核，可下推；撤回 → 草稿并留撤回意见；取消同时终止审核 |
| 已审核、正常 | 调整交期 | 只改承诺交期；数量和价格不可改 | 交期更新，其余不变 |
| 已审核、正常 | 创建收货通知 | 有可下推数量 | 通知创建即占用额度 |
| 已审核、正常 | 关闭 | 手工关闭无额外条件；到期关闭为承诺交期后T+2自然日，每天0:00跑批 | → 已关闭；不再新增通知，已有通知继续执行 |
| 已审核、正常 | 取消 | 没有实际入库，且没有仍需执行的通知 | → 已取消；释放未执行占用 |
| 已关闭 | 查看、追溯 | — | 不能反关单 |
| 已取消 | 查看历史 | — | 不可撤销 |

**收货状态是计算值**：按各行累计实收自动算成未收货／部分收货／全部收货，不参与流转，全部收足也不会自动关闭订单。

**B2B销售订单的差异**：审核时校验可用量并占库；关闭只释放还没安排出去的占库，保留执行中通知的占库；发货状态变为全部发货时立即自动关单，关闭方式为全部履约自动关闭，关闭操作人留空；取消要先处理已交给仓库的通知，仓库拒绝则恢复继续发货。采购全部收足不自动关单。

**采购退货单、销售退货单的差异**：审核时占用可用库存（采购退货）或原出库可退额度（溯源销售退货）；无来源退货每行大于0、不套原单额度，采购退货审核仍校验可用库存。关闭释放未下推预占；取消要求无实出（或退回）且没有阻挡通知；已实出只能关闭余量。销售退货审核后只能调整截止时间，其他内容不改。采购退货单、销售退货单按退货截止时间后T+2自然日的当天0:00自动关闭（已全部退足的退货单不自动关闭），与采购订单同一口径。

**分步式调拨单的差异**：业务状态取值与三层主单一致（正常／已关闭／已取消）；两端执行完成、主单自动完结时记「已关闭」（页面展示文案可用「已完结」）；实际调出为0按零出取消，记「已取消」。

## 三、状态与操作：执行指令单（以采购收货通知单为例）

```mermaid
stateDiagram-v2
    [*] --> 待推送
    待推送 --> 推送中: 系统自动发送
    推送中 --> 待收货: 发送成功
    推送中 --> 推送失败: 明确失败
    推送失败 --> 推送中: 自动重试或人工重试
    待推送 --> 已取消: 取消
    推送失败 --> 已取消: 取消
    待收货 --> 取消中: 申请取消
    取消中 --> 待收货: 仓库拒绝
    取消中 --> 已取消: 仓库同意
    待收货 --> 已收货: 回传实际数量
    待收货 --> 已取消: 回传零收
    已收货 --> [*]
    已取消 --> [*]
    [*] --> 已收货: 虚拟入库创建成功
```

虚拟入库／虚拟出库不经过待推送、推送中、待收货／待发货：创建成功即已收货／已发货，并生成对应结果单。上图实线仍是仓库路径。

| 状态 | 可执行操作 | 前置条件与校验 | 结果与联动 |
| --- | --- | --- | --- |
| 待推送 | 取消 | — | → 已取消，释放全部通知占用额度 |
| 推送中 | 等待，不重复发送 | 结果不确定时先核实仓库是否收到 | 不重复发送、不提前释放额度 |
| 推送失败 | 等待自动重试；人工重试、取消 | 确认仓库未接收才能取消；自动重试最多3次，间隔由技术配置 | 自动或人工重试 → 推送中；3次仍失败保持推送失败；取消 → 已取消并释放额度 |
| 待收货 | 接收回传；申请取消 | 实收不超过通知量；按来源行回写 | 回传 → 已收货并生成入库单；申请取消 → 取消中 |
| 取消中 | 等待仓库结果 | 仍需处理可能到达的实际结果 | 仓库同意 → 已取消；拒绝 → 待收货；期间到达的实际结果按真实结果完成 |
| 已收货 | 查看实收、缺收、关联入库单 | — | 终态，不再往原通知补收；虚拟入库创建成功即进入本状态 |
| 已取消 | 查看历史 | — | 终态；订单开放时可重新下推 |

**销售发货通知单、销退收货通知单、采退发货通知单、调出／调入通知单复用同一套状态**，只把“收货”换成“发货”，按业务替换名称。采购收货、B2B销售、采购退货、销售退货四条链路复用处理方式：收货类通知选仓库收货／虚拟入库，发货类通知选仓库发货／虚拟出库。调出／调入通知单本期不增加处理方式。差异：销售与退货通知申请取消后订单开放时恢复下推额度；调入通知由实际调出量生成，不按原计划量提前下发；调入通知的零调入属异常，不按零收取消通知单，须人工处理（见第九节）。

## 四、状态与操作：结果单（以采购入库单为例）

```mermaid
stateDiagram-v2
    [*] --> 已审核: 回传校验通过，自动审核
    [*] --> 草稿: 人工创建或人工确认
    草稿 --> 待审核: 提交
    待审核 --> 草稿: 撤回
    待审核 --> 已审核: 审核
    已审核 --> [*]
```

| 状态 | 可执行操作 | 前置条件与校验 | 结果与联动 |
| --- | --- | --- | --- |
| 草稿 | 编辑、提交 | 人工形成结果时 | — |
| 待审核 | 审核、撤回 | 数量、来源行完整 | 审核 → 已审核并记账 |
| 已审核 | 查看来源、库存结果、推送记录 | 已审核才记账、才推送 | 库存生效、回写来源单据；推送失败不回滚；重推在系统集成中心 |

仓库回传校验通过后自动生成并自动审核。虚拟入出库按通知数量生成的结果单同样自动审核，不打开结果单无来源人工建单入口。人工确认实际结果仍走草稿 → 待审核，采购入库须沿来源通知。

**金蝶推送状态独立记录**：未推送 → 推送中 → 推送成功／推送失败；明确失败后系统自动重试最多3次，仍失败在系统集成中心重推原单，不另建业务单，也不在结果单列表行内重推。

## 五、状态与操作：两层单

### 5.1 独立站订单

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 待审核: 提交
    待审核 --> 草稿: 撤回
    待审核 --> 已审核: 审核
    已审核 --> 推送失败: 发送明确失败
    推送失败 --> 已审核: 自动重试或人工重试
    已审核 --> 待发货: 推送成功
    已审核 --> 已取消: 取消审核（终止订单）
    已审核 --> 草稿: 取消审核（调整后重新执行）
    待发货 --> 取消中: 申请取消
    取消中 --> 已取消: 仓库同意（终止）
    取消中 --> 草稿: 仓库同意（调整后重新执行）
    取消中 --> 待发货: 仓库拒绝
    待发货 --> 已发货: 回传整单发出
    待发货 --> 已取消: 回传整单零执行
    已发货 --> [*]
    已取消 --> [*]
```

| 状态 | 可执行操作 | 前置条件与校验 | 结果与联动 |
| --- | --- | --- | --- |
| 草稿、待提交 | 编辑、提交、删除 | 选好仓库和物流 | 删除后记录移除且不可恢复 |
| 待审核 | 审核、撤回 | 库存足够才能审核 | 审核 → 已审核并自动推送 |
| 已审核 | 等待自动重试；人工重试推送；取消审核 | 取消审核：未推送可直接办，已推送要先取得仓库取消成功；仓库推送明确失败后自动重试最多3次 | 终止 → 已取消并释放占库；调整 → 回草稿，重审算新执行 |
| 待发货 | 申请取消 | — | → 取消中，等仓库 |
| 取消中 | 等待 | 到达的实际结果按真实结果处理 | 同意 → 已取消或回草稿；拒绝 → 待发货 |
| 已发货、已取消 | 查看 | — | 终态 |

```mermaid
    已取消 --> [*]
```

与独立站的差异：**没有“取消审核回草稿”这条路**；允许缺量、一次结束、不分批，余量不回补原单；草稿只能删除、不能取消；已审核后的中止只能取消：未推送可直接取消并释放预占，已推送要等实际结果或仓库取消成功。

## 六、数量口径（把公式收在一处）

| 公式 | 适用 |
| --- | --- |
| 可下推数量 ＝ 订单数量 − 已结束通知的实际数量 − 未结束通知的通知量 | 采购订单、B2B销售订单、采购退货单、销售退货单 |
| 订单剩余预占 ＝ 审核占用量 − 累计实际出库量 | B2B销售订单，限尚未发生关闭或取消释放时 |
| 可用库存 ＝ 即时库存 − 预占库存 − 冻结库存 | 所有库存业务 |
| 溯源退货累计可退 ＝ 原实际出库量 − 已退累计 − 办理中占用 | 销售退货 |
| 调拨在途 ＝ 累计实际调出 − 累计实际调入 | 分步式调拨 |

发生关闭或取消释放后，剩余预占还要扣除已释放数量；实际出库消耗与未执行释放不能重复扣减。示例：订单审核预占1,000，通知600后关闭，先释放未安排的400，剩余预占600；通知最终实出580，消耗580并释放缺出的20，剩余预占为0。此时不能按“1,000－580”算成420。依据：[《销售与履约业务设计》§6.1](../../../03-业务分析和设计/02-销售与履约业务设计.md)、《销售与履约需求分析》SAL-FR03、SAL-AC04。

配套规则：通知创建即占用，推送失败、待收货、取消中都不释放；取消成功才释放；结束时以实际数量替代通知占用，缺量回补；关闭后不再安排，已有通知继续执行；不允许负库存，超量回传直接拒绝。

## 七、回写规则

| 结果单 | 回写什么 | 时机 |
| --- | --- | --- |
| 采购入库单 | 通知实收与状态、订单累计实收与收货状态 | 结果单审核通过 |
| 采退出库单 | 通知实出与状态、退货单累计实出、消耗预占 | 同上 |
| 销售出库单 | 通知实出与状态、订单累计实出与发货状态、消耗预占 | 同上 |
| 销退入库单 | 通知实收与状态、退货单累计实退、可退额度占用 | 同上 |
| 其他出入库单 | 申请单完结、释放未用预占 | 同上 |
| 直接调拨单（调出端／调入端） | 调出仓减、在途加／在途减、接收仓加；第二张生成后主单自动完结 | 同上 |

回写是单向的：结果单改来源单据的累计和状态，来源单据不改结果单。

## 八、权限怎么处理

- 能不能执行某个操作，由账号对应的角色权限控制（RBAC）。本文不约定岗位和角色，也不做权限矩阵。
- 需要审核的动作统一走提交与审核流程；没有对应权限，界面上不提供该操作。提交、审核（或审核通过）、驳回、撤回等操作名按第一节「审核操作怎么叫」区分，不因权限模块另造叫法。
- 权限不替代业务校验：库存够不够、金额完整不完整、状态允不允许，仍然按本文和前几节的规则判断。
- 角色、岗位和数据范围在权限配置里定义，具体规则见公共能力模块。

## 九、跨单据联动要点

- 额度：通知创建占用可下推量；取消成功释放；收货完成后以实际替代，缺量回补。
- 占库：销售、采购退货、分步式调拨、其他出库在审核时预占；实际出库消耗对应预占；关闭或取消按各域规则释放。
- 零收零出：按取消执行单处理，不生成结果单、不改库存、不推金蝶。分步式调拨的实际调出和实际调入都必须大于0；零调入属于异常，不按零收取消通知单，通知单无法关闭，需人工处理。
- 关闭与取消：关闭只停止新增安排，已有通知继续执行；取消要整单可撤，涉及仓库的要等回执；两者都不可撤销。
- 主单完结：分步式调拨在收到调入回传并生成第二张直接调拨单后自动完结；完结不代表在途差异已经清理。
- 唯一记账口径：只有已审核结果单改变库存并推送金蝶；订单、通知、草稿一律不记账。
