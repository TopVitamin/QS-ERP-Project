## 2. Demo Mock：模拟回传自动生成（F09）

> 本节为 **仅 Demo，非正式验收** 的行为定义。

### 2.1 正式规则（必读）

正式环境中：

- 路径一：销退收货通知单回传**有实收并结束**后，系统自动校验并生成**已审核**销退入库单，再触发推送财务ERP；虚拟入库在通知创建成功时按通知数量立即生成已审核入库单。**零收不生成**入库单。
- 路径二：外部ToC渠道退货结果按来源拆分接收，商品与逻辑仓匹配、库存校验通过后自动生成**已审核**入库单，直接自动审核，不关联通知、不关联销售退货单。
- 两条路径都不提供人工建单与人工审核；不提供无来源建单。

本节 Mock **仅用于 Demo 原型串联展示**，不属于 AC01～AC13 的正式验收项（主PRD F09）。

### 2.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 销退收货通知单详情 Mock 回传后 | 若实收合计>0，本地自动生成演示用销退入库单（已审核）；实收合计=0 则不生成 |
| 通知选择虚拟入库并 Mock 创建成功后 | 按通知数量生成演示用销退入库单（已审核） |
| 外部ToC结果 Mock 接收后 | 按来源拆分生成 1..N 张演示用销退入库单（已审核），不带来源通知 |

### 2.3 生成规则（本地 Mock）

| 项目 | 规则 |
| :--- | :--- |
| 来源类型 | 路径一=销退收货通知；路径二=外部ToC |
| 来源 | 路径一：当前销退收货通知单及关联销售退货单；路径二：当前外部原始订单 |
| 审核状态 | 已审核 |
| 推送财务ERP状态 | 未推送（Demo 可配置数秒后模拟推送成功/失败） |
| 收货仓库 | 路径一沿用通知仓库；路径二沿用映射结果 |
| 业务日期 | 取实际收货时间的日期部分 |
| 明细 | 路径一按通知各行实收数量（虚拟入库=通知数量）；路径二按渠道回传数量 |
| 价格 | 路径一沿销售退货单交易价格；路径二沿用来源结果金额 |
| 单号 | 按 XTRK 编码规则生成 fictitious 编号 |
| 库存与回写 | 路径一：退货单累计实退增加、通知实收与状态更新、可下推量与可退额度按主PRD规则变化；路径二：只记库存 |
| 标注 | 界面标注「演示数据」或「Mock」 |

### 2.4 不做的事

- 不代替正式仓库接口回传与渠道结果接收
- 不在 Mock 中自动完成真实推送财务ERP
- 不把 Mock 行为写入主 PRD 正式验收
- 不生成零数量销退入库单

## 3. 异常与失败文案（Demo 呈现）

| 场景 | 呈现方式 | 文案/说明 |
| :--- | :--- | :--- |
| 推送财务ERP失败 | 详情单据信息区展示失败原因 | 示例：`财务ERP接口超时，请至系统集成中心重推原单。`（示例文案） |
| 路径二商品或逻辑仓匹配失败 | 不生成本模块单据 | 集成侧异常列表展示；不记库存、不推财务ERP |
| 重复回传已成功结果 | 无新单、无提示变化 | 幂等，不重复记账（SAL-AC21） |

## 4. 验收场景（Demo）

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| Mock 通知回传 | 销退收货通知 Mock 回传有实收 | 本地出现已审核销退入库单；通知详情关联单据可跳转 |
| Mock 零收 | 销退收货通知 Mock 零收 | 不生成入库单 |
| Mock 虚拟入库 | 通知 Mock 选虚拟入库并创建成功 | 按通知数量生成已审核入库单 |
| Mock 外部ToC | Mock 接收渠道退货结果 | 按来源拆分生成入库单，无来源通知 |
| 本模块无重推 | 打开销退入库单详情 | 无重推财务ERP按钮、无任何业务确认弹窗 |
