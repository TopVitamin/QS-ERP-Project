## 一、业务弹窗

本模块列表/详情不提供重推金蝶确认框。自动重试（正式环境）：推送明确失败后系统自动重试，**最多3次**；间隔由技术配置。3次仍失败则保持「推送失败」，到系统集成中心针对原单重推。

## 二、Demo Mock：模拟回传自动生成

### 2.1 正式规则（必读）

正式环境中，采购收货通知单回传有实收并结束后，系统自动校验并生成**已审核**入库单，再触发金蝶推送。零收不生成入库单。**不提供无来源人工建单。** 已交给仓库、接口拿不到结果时，人工确认实际结果沿用 INT-FR06，入口不在本 Mock。

本节 Mock **仅用于 Demo 原型串联展示**，不属于 AC01～AC08 的正式验收项（主PRD F09）。

### 2.2 Mock 触发时机

| 时机 | 行为 |
| --- | --- |
| 收货通知详情 Mock 回传后 | 若实收>0，本地自动生成演示用采购入库单（已审核） |

### 2.3 Mock 生成规则（演示数据）

| 项目 | Mock 规则 |
| --- | --- |
| 生成条件 | 来源通知状态=已收货；实收合计>0；尚无关联入库单 |
| 单头 | 沿通知带入来源、供应商、币别、仓库；业务日期=实际入库时间日期部分 |
| 明细 | 实际入库数量=通知实收；价税沿来源订单 |
| 审核 | 创建即为已审核 |
| 金蝶 | 从「未推送」开始；可模拟自动重试3次 |
| 联动 | 更新来源采购订单累计入库、收货状态；库存 Mock 增加 |

### 2.4 Mock 不做的内容

- 不代替正式 WMS 回传与校验逻辑
- 不提供无来源人工建单页面
- 不把 Mock 推送当作金蝶正式验收
- 不在本模块演示系统集成中心重推

### 2.5 与收货通知 Mock 的关系

收货通知 Mock 回传见[《采购收货通知单前端Demo版PRD_弹窗与Mock》](../../采购收货通知单/前端Demo版PRD/采购收货通知单前端Demo版PRD_弹窗与Mock.md) §二。有实收结束后应继续生成本章演示入库单，串联采购主链。
