## 2. 提交相关弹窗（F03）

**触发入口**：新增/编辑页、列表、详情「提交」；可用条件均为**审核状态=草稿 + 业务状态=正常**（主 PRD §6.4）。

**校验前置**：打开任何提交弹窗前，先按主 PRD R04 与[新增编辑页 §4.4](采购订单前端Demo版PRD_新增编辑页.md)校验当前单据。未通过则 Toast 或字段提示阻断，**不进入**下列弹窗。列表/详情提交已有草稿时，校验口径与表单页一致。

**弹窗顺序**：先零价确认（如有）→ 再提交确认。

```
列表 / 详情 / 新增·编辑页
         │
    点「提交」
         ▼
  新增编辑 §4.4 校验
         │
    ┌────┴────┐
  失败       通过
    │          │
    ▼          ▼
 Toast      存在零价明细？
 阻断          │
           ┌──┴──┐
          否      是
           │       │
           │       ▼
           │   §2.1 零价确认弹窗
           │    取消 │ 确认继续
           │       └──┬──┘
           └────┬────┘
                ▼
         §2.2 提交确认弹窗
          取消 │ 确认提交
               ▼
        待审核 + Toast「已提交」
```

### 2.1 零价确认

| 项目 | 内容 |
| :--- | :--- |
| 出现条件 | 任一明细行含税单价 = 0 |
| 弹窗标题 | 确认使用零价？ |
| 正文 | 第 {N} 行含税单价为 0，请确认业务约定。多行零价时正文列出各行或合并为「存在零价明细，请确认业务约定。」 |
| 确认按钮 | 确认继续 |
| 取消按钮 | 取消 |
| 确认后 | 进入 §2.2 提交确认弹窗 |

### 2.2 提交确认

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 确认提交采购订单？ |
| 正文 | 提交后进入待审核状态，数量和价格将在审核后锁定，审核前仍可撤回修改。 |
| 确认按钮 | 确认提交 |
| 取消按钮 | 取消 |
| 确认后 | 审核状态→待审核；Toast「采购订单已提交」；刷新当前页或列表 |

| 来源页 | 确认后页面表现 |
| :--- | :--- |
| 新增/编辑页 | 停留本页并变为只读待审核态，或返回列表（以实现为准，须可连续演示） |
| 列表 / 详情 | 刷新；行内/页头操作变为审核、撤回等 |

## 3. 状态变更弹窗（F04、F06）

下列弹窗均在**二次确认**后执行。入口可用条件见主 PRD §6.4 与各页页头/行内矩阵；条件不满足时**不展示按钮**，无需弹窗阻断。

**阻断类失败**（不满足业务规则、未进入成功流）：取消/关闭若触发 R09 等规则，直接 Toast，例如「存在执行中的收货通知，请先处理后再取消」。全部收足订单不展示关闭、调整交期入口（R12）。

**通用弹窗结构**（无表单项时省略中间输入区；见 §3.2～§3.5 各节表格）：

```
┌──────────────────────────────────────────┐
│  {弹窗标题}                          [×] │
├──────────────────────────────────────────┤
│  {正文说明}                               │
│  ┌────────────────────────────────────┐  │  ← 有必填项时，如撤回意见、
│  │ {多行文本 / 日期选择}                 │  │     关闭原因、新承诺交期
│  └────────────────────────────────────┘  │
├──────────────────────────────────────────┤
│                    [取消]  [确认{动作}]   │
└──────────────────────────────────────────┘
         │ 取消              │ 确认
         ▼                   ▼
    关闭弹窗，停留      执行业务 + Toast + 刷新页面
```

**入口与阻断关系**（按钮不满足条件时直接不展示，不弹窗）：

```
页头 / 行内「{操作}」
         │
    主 PRD §6.4 允许？
         │
    ┌────┴────┐
   否        是
    │          │
    ▼          ▼
 不展示    R09 / R12 等
 该按钮      业务阻断？
              │
         ┌────┴────┐
        是         否
         │          │
         ▼          ▼
      Toast     打开 §3.x 弹窗
      阻断
```

### 3.1 审核

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「审核」 |
| 可用条件 | 待审核 + 正常 |
| 弹窗标题 | 确认审核？ |
| 正文 | 审核后订单可发给供应商，数量和价格不可再修改。 |
| 必填项 | 无 |
| 确认按钮 | 确认审核 |
| 取消按钮 | 取消 |
| 确认后 | 审核状态→已审核；记录审核人、审核时间；Toast「采购订单已审核」；刷新页面。Demo 可接续 §4 Mock 引导弹窗 |

### 3.2 撤回

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「撤回」 |
| 可用条件 | 待审核 + 正常 |
| 弹窗标题 | 撤回采购订单 |
| 正文 | 请填写撤回意见 |
| 必填项 | 撤回意见（多行） |
| 确认按钮 | 确认撤回 |
| 取消按钮 | 取消 |
| 确认后 | 审核状态→草稿；保存撤回意见；Toast「采购订单已撤回，请修改后重新提交」 |

### 3.3 调整承诺交期

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「调整交期」 |
| 可用条件 | 已审核 + 正常；收货状态≠全部收货（R12） |
| 弹窗标题 | 调整承诺交期 |
| 正文 | 仅修改承诺交期，数量和价格不变。 |
| 必填项 | 新承诺交期（日期） |
| 确认按钮 | 确认 |
| 取消按钮 | 取消 |
| 确认后 | 更新承诺交期；Toast「承诺交期已更新」 |

### 3.4 关闭订单

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「关闭」 |
| 可用条件 | 已审核 + 正常；收货状态≠全部收货（R12）；另须满足 R10 |
| 弹窗标题 | 关闭采购订单 |
| 正文 | 关闭后不可撤销，不能再新增收货通知；已有通知继续执行。 |
| 必填项 | 关闭原因（多行） |
| 确认按钮 | 确认关闭 |
| 取消按钮 | 取消 |
| 确认后 | 业务状态→已关闭；记录关闭方式=手动关闭及关闭人、时间；Toast 见列表/详情 PRD |

### 3.5 取消订单

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「取消」 |
| 可用条件 | 待审核或已审核 + 正常；已审核时须满足 R09 |
| 弹窗标题 | 取消采购订单 |
| 正文 | 取消后整单不再执行，不可撤销。 |
| 必填项 | 取消原因（多行） |
| 确认按钮 | 确认取消 |
| 取消按钮 | 取消 |
| 确认后 | 业务状态→已取消；记录取消人、时间；释放未执行占用（R09）；Toast 见列表/详情 PRD |

### 3.6 离开未保存（表单页）

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 新增/编辑页点「取消」或路由离开，且存在未保存修改 |
| 弹窗标题 | 离开当前页面？ |
| 正文 | 离开后未保存的内容将丢失。 |
| 确认按钮 | 确认离开 |
| 取消按钮 | 取消 |
| 确认后 | 返回列表或上一页 |

表单页错误展示与文案口径见[新增编辑页 §4.6、§8](采购订单前端Demo版PRD_新增编辑页.md)。

## 4. Demo Mock：审核后生成收货通知（F07）

### 4.1 正式规则

按 PUR-FR02，**审核通过不会自动生成采购收货通知单**。采购员在收到供应商线下发货反馈后，手工创建通知单并填写本次通知数量。

本节 Mock **仅用于 Demo 原型串联**，不属于 PUR-AC01～AC11 正式验收（主 PRD F07、AC10）。

### 4.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 列表/详情「审核」成功后 | 弹出 Mock 引导弹窗（Demo 开关可配置，默认开启） |

```
§3.1 审核成功（已审核）
         │
    Demo Mock 开关？
         │
    ┌────┴────┐
  关闭       开启（默认）
    │          │
    ▼          ▼
 Toast      §4.3 引导弹窗
 结束      ┌────────────────────────────────────┐
            │ 采购订单已审核                      │
            │ 正式流程需手工创建收货通知…          │
            │ [稍后手工创建]  [生成演示通知单Mock] │
            └────────────────────────────────────┘
                    │              │           [×]
         稍后手工创建│              │生成演示通知单
                    ▼              ▼
              关闭弹窗         §4.4 本地创建
              可点「下推」      通知单(Mock)
              走正式流程            │
                                   ▼
                            订单占用 / 可下推量更新
                            （可接续收货通知 Mock 回传）
```

### 4.3 引导弹窗

| 项目 | 内容 |
| :--- | :--- |
| 标题 | 采购订单已审核 |
| 正文 | 正式流程需按供应商发货反馈手工创建收货通知。Demo 可一键生成本次演示用通知单，便于查看主链。 |
| 主按钮 | 生成演示通知单（Mock） |
| 次按钮 | 稍后手工创建 |
| 关闭图标 | 关闭弹窗，仅刷新订单状态 |

### 4.4 生成规则（本地 Mock）

点击「生成演示通知单（Mock）」时，在本地 Mock 存储创建一条**采购收货通知单**草稿：

| 项目 | 规则 |
| :--- | :--- |
| 来源 | 当前采购订单 |
| 收货仓库 | 沿用订单收货仓库（逻辑仓） |
| 单据状态 | 待推送 |
| 明细 | 按订单每个 SKU 一行；通知数量 = 当前可下推数量（演示简化，不代表实际分批） |
| 单号 | 按通知单编码规则生成 fictitious 编号 |
| 占用 | 订单在途通知数量增加；可下推数量相应减少 |
| 推送 | Demo 不调用真实仓库；可配置数秒后模拟「待推送→待收货」 |

界面标注「演示数据」或「Mock」角标，与手工创建的通知单区分。

### 4.5 不做的事

- 不代替正式「创建采购收货通知单」页的数量录入与校验
- 不在 Mock 中自动审核订单或自动推送金蝶
- 不把 Mock 行为写入主 PRD 验收标准

### 4.6 与正式下推的关系

关闭引导弹窗后，可通过列表/详情「下推通知单」进入正式创建流程，见[《采购收货通知单前端Demo版PRD_新增编辑页》](../../采购收货通知单/前端Demo版PRD/采购收货通知单前端Demo版PRD_新增编辑页.md)。

下游「模拟仓库回传」见[《采购收货通知单前端Demo版PRD_弹窗与Mock》](../../采购收货通知单/前端Demo版PRD/采购收货通知单前端Demo版PRD_弹窗与Mock.md) §二。

## 6. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| 提交 | 完整草稿点提交 | 校验通过→（零价确认）→提交确认→待审核 |
| 提交阻断 | 含税单价为空提交 | Toast 阻断，不进入待审核 |
| 零价 | 零价明细提交 | 先零价确认，再提交确认 |
| 撤回 | 待审核点撤回 | 必填撤回意见→草稿 |
| 审核 | 待审核点审核 | 已审核；Mock 开启时出现 §4 引导弹窗 |
| Mock 生成 | 点生成演示通知单 | 本地出现 Mock 通知；订单占用/可下推量变化 |
| Mock 关闭 | Demo 配置关闭 Mock | 审核后仅成功提示，不弹 §4 引导 |
| 导入演示 | 列表点导入(Mock) | 打开向导并提示仅为演示，不产生正式订单 |
| R09 阻断 | 有执行中通知时取消 | Toast 阻断，不进入取消成功流 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。
