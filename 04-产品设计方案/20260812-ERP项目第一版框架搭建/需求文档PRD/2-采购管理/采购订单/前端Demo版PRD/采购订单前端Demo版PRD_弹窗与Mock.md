# 采购订单前端Demo版PRD·弹窗与Mock

> 用途：定义采购订单相关的确认弹窗，以及Demo环境专用的收货通知Mock行为。
> 定位：页面与交互设计文档。业务规则引用[《采购订单主PRD》](../采购订单主PRD.md)；正式业务不以本章Mock为准。
> 版本：V0.4｜日期：2026-09-20｜状态：初稿，待评审。

关联资料：[《采购订单主PRD》](../采购订单主PRD.md)（§6.4、§6.5、§8；F03/F04/F06/F07）、[《采购业务管理需求分析》](../../../../../../02-需求调研和分析/02-采购业务管理/采购业务管理需求分析.md) PUR-FR02。

列表、详情、新增编辑页触发的弹窗在本文件统一定义，其他页面 PRD 引用本章，不重复维护文案。弹窗可用条件须服从主 PRD §6.4。

## 一、提交确认弹窗

### 1.1 触发入口

| 入口 | 可用条件 |
| --- | --- |
| 新增/编辑页「提交」 | 草稿+正常（§6.4） |
| 列表/详情「提交」 | 同上 |

### 1.2 提交前校验（在打开弹窗前或弹窗内确认前执行）

| 校验项 | 失败文案示例 | 处理 |
| --- | --- | --- |
| 单头必填 | 请选择供应商／请填写承诺交期／请选择收货仓库 | 阻断，定位字段 |
| 明细至少一行 | 请至少添加一行商品明细 | 阻断 |
| 采购数量 | 第N行采购数量必须大于0 | 阻断，定位明细行 |
| 含税单价空或负 | 第N行含税单价不能为空／不能为负 | 阻断 |
| 零价 | 第N行含税单价为0，确认继续？ | 二次确认后可继续 |
| 供应商资格 | 所选供应商不可用 | 阻断 |

校验依据主PRD R04；通过后进入确认弹窗。

### 1.3 确认弹窗

| 操作 | 弹窗标题 | 正文 | 确认按钮 | 取消按钮 | 确认后的处理 |
| --- | --- | --- | --- | --- | --- |
| 提交 | 确认提交采购订单？ | 提交后进入待审核状态，数量和价格将在审核后锁定，审核前仍可撤回修改。 | 确认提交 | 取消 | 审核状态→待审核；提示「采购订单已提交」；刷新当前页/列表 |

### 1.4 提交成功后页面表现

| 当前页 | 表现 |
| --- | --- |
| 新增/编辑页 | 可选停留并变为只读待审核态，或返回列表 |
| 列表/详情 | 刷新，行操作变为审核/撤回 |

## 二、其他业务弹窗

| 操作 | 弹窗标题 | 正文 | 必填项 | 确认按钮 | 确认后处理 |
| --- | --- | --- | --- | --- | --- |
| 审核 | 确认审核？ | 审核后订单可发给供应商，数量和价格不可再修改。 | 无 | 确认审核 | 审核状态→已审核；记录审核人、审核时间；触发Mock引导（见第三节，可选） |
| 撤回 | 撤回采购订单 | 请填写撤回意见 | 撤回意见（多行） | 确认撤回 | 审核状态→草稿；保存撤回意见；提示「已撤回，请修改后重新提交」 |
| 调整交期 | 调整承诺交期 | 仅修改承诺交期，数量和价格不变；**收货状态=全部收货时不提供入口**（R12） | 新承诺交期（日期） | 确认 | 更新承诺交期；提示「承诺交期已更新」 |
| 关闭订单 | 关闭采购订单 | 关闭后不可撤销，不能再新增收货通知；已有通知继续执行；**收货状态=全部收货时不提供入口**（R12） | 关闭原因 | 确认关闭 | 业务状态→已关闭；记录关闭方式=手动关闭及关闭人、时间 |
| 取消订单 | 取消采购订单 | 取消后整单不再执行，不可撤销。 | 取消原因 | 确认取消 | 业务状态→已取消；记录取消人、时间；释放未执行占用（R09） |
| 零价确认 | 确认使用零价？ | 第N行含税单价为0，请确认业务约定。 | 无 | 确认继续 | 继续提交流程 |
| 离开未保存 | 离开当前页面？ | 离开后未保存的内容将丢失。 | 无 | 确认离开 | 返回上一页 |

取消/关闭失败（如R09不满足）时不打开成功流，直接提示原因，例如「存在执行中的收货通知，请先处理后再取消」。全部收足订单不展示关闭、调整交期入口（R12），无需弹窗阻断。

## 三、审核通过后 Mock：演示用收货通知

### 3.1 正式规则（必读）

按 PUR-FR02，**审核通过不会自动生成采购收货通知单**。采购员在收到供应商线下发货反馈后，手工创建通知单并填写本次通知数量。

本节 Mock **仅用于 Demo 原型串联展示**，不属于 PUR-AC01～AC11 的正式验收项（主PRD F07、AC10）。

### 3.2 Mock 触发时机

| 时机 | 行为 |
| --- | --- |
| 列表/详情「审核」成功后 | 弹出 Mock 引导弹窗（可配置 Demo 开关，默认开启） |

### 3.3 Mock 引导弹窗

| 项目 | 内容 |
| --- | --- |
| 标题 | 采购订单已审核 |
| 正文 | 正式流程需按供应商发货反馈手工创建收货通知。Demo 可一键生成本次演示用通知单，便于查看主链。 |
| 主按钮 | 生成演示通知单（Mock） |
| 次按钮 | 稍后手工创建 |
| 关闭 | 关闭弹窗，仅刷新订单状态 |

### 3.4 Mock 生成规则（演示数据）

点击「生成演示通知单（Mock）」时，Demo 在本地 Mock 存储中创建一条**采购收货通知单**草稿，规则如下：

| 项目 | Mock 规则 |
| --- | --- |
| 来源 | 当前采购订单 |
| 收货仓库 | 沿用订单收货仓库 |
| 单据状态 | 待推送 |
| 明细 | 按订单每个SKU生成一行；**通知数量=当前可下推数量**（演示简化，不代表实际分批） |
| 单号 | 按通知单编码规则自动生成 fictitious 编号 |
| 占用 | 订单在途通知数量立即增加；可下推数量相应减少 |
| 推送 | Demo 不真实调用仓库；可选在3秒后模拟变为「待推送→待收货」供继续演示 |

Mock 单在界面标注「演示数据」或「Mock」角标，与正式手工创建的通知单区分。

### 3.5 Mock 不做的内容

- 不代替正式「创建采购收货通知单」页面的数量录入与校验（正式能力在收货通知PRD定义）
- 不在 Mock 中自动审核订单或自动推送金蝶
- 不把 Mock 行为写入主PRD验收标准
- 不把列表「导入」当成正式建单能力

### 3.6 「稍后手工创建」

关闭 Mock 弹窗后，用户可通过列表/详情「下推通知单」进入正式创建流程，见[《采购收货通知单前端Demo版PRD_新增编辑页》](../../采购收货通知单/前端Demo版PRD/采购收货通知单前端Demo版PRD_新增编辑页.md)。

### 3.7 导入向导（仅 Demo）

一期正式不提供采购订单导入。列表页头「导入」打开向导仅用于演示界面，**不写入正式采购订单**，也不进入主PRD验收。向导内应提示「本操作为演示，不会生成正式订单」。

## 四、演示验收（弹窗与Mock）

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 提交 | 完整草稿点提交 | 校验通过→确认弹窗→待审核 |
| 提交阻断 | 空价明细提交 | 阻断并提示，不进入待审核 |
| 撤回 | 待审核点撤回 | 必填撤回意见→草稿 |
| Mock开启 | 审核 | 出现Mock引导弹窗 |
| Mock生成 | 点生成演示通知单 | 本地出现一条Mock通知；订单占用/可下推量变化 |
| Mock关闭 | Demo配置关闭Mock | 审核后仅提示成功，不弹Mock |
| 导入演示 | 点页头导入 | 打开向导并提示仅为演示，不产生正式订单 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口行为。
