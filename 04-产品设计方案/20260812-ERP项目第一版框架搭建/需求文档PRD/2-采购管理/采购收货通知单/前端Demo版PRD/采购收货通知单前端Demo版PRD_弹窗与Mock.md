## 一、业务弹窗

### 1.1 取消通知单

| 项目 | 内容 |
| --- | --- |
| 触发入口 | 列表/详情「取消」 |
| 可用条件 | 待推送、推送失败（§6.4） |
| 弹窗标题 | 取消采购收货通知单 |
| 正文 | 取消后通知不再执行，不可撤销，并释放订单占用额度。 |
| 推送失败补充 | 推送失败时追加：「请确认仓库尚未接收本通知。」 |
| 必填项 | 取消原因（多行） |
| 确认按钮 | 确认取消 |
| 确认后 | 单据状态→已取消；记录取消原因、取消时间、取消操作人；释放全部通知占用；提示「采购收货通知单已取消」 |

### 1.2 取消通知单（待收货）

| 项目 | 内容 |
| --- | --- |
| 触发入口 | 列表/详情「取消」 |
| 可用条件 | 待收货（§6.4） |
| 弹窗标题 | 取消采购收货通知单 |
| 正文 | 单据已推送仓库，取消需等待仓库回执。取消期间通知仍占用订单额度。 |
| 必填项 | 取消原因（多行） |
| 确认按钮 | 确认取消 |
| 确认后 | 单据状态→取消中；提示「已发起取消，等待仓库回执」 |

仓库回执处理（正式环境由集成层接收，Demo见 §二）：

| 回执 | 结果状态 | 提示 |
| --- | --- | --- |
| 仓库同意 | 已取消 | 采购收货通知单已取消 |
| 仓库拒绝 | 待收货 | 仓库拒绝取消，请继续等待收货 |

### 1.3 重试推送

| 项目 | 内容 |
| --- | --- |
| 触发入口 | 列表/详情「重试推送」 |
| 可用条件 | 推送失败（§6.4）；正式环境须已自动重试满3次仍失败 |
| 弹窗标题 | 重试推送仓库 |
| 正文 | 将重新向仓库发送本通知，请确认失败原因已处理。 |
| 必填项 | 无 |
| 确认按钮 | 确认重试 |
| 确认后 | 单据状态→推送中；提示「已重新推送仓库」 |

正式环境：推送明确失败后系统自动重试，**最多3次**；3次仍失败才保持「推送失败」并出现本按钮。间隔本期不定秒数，由技术配置。Demo 可直接把单据置于推送失败，便于演示人工重试，不模拟间隔。

| 创建/编辑页返回 | 离开当前页面？ | 离开后未保存的内容将丢失。 | 返回上一页 |

## 二、Demo Mock：模拟仓库回传

### 2.1 正式规则（必读）

正式环境中，仓库通过WMS接口回传实收数量与结束标记；零收按 PUR-AC10 取消通知，不生成入库单。

本节 Mock **仅用于 Demo 原型串联展示**，不属于 AC01～AC10 的正式验收项（主PRD F08）。

### 2.2 Mock 触发时机

| 时机 | 行为 |
| --- | --- |
| 详情页「模拟仓库回传」 | 单据状态为待收货（可配置 Demo 开关，默认开启） |
| 创建后自动推送 | Demo 可配置在数秒后自动将待推送→待收货，便于演示 |

### 2.3 Mock 回传弹窗

| 项目 | 内容 |
| --- | --- |
| 标题 | 模拟仓库回传（Demo） |
| 正文 | 各行实收数量不能超过通知数量；超过将自动调整为通知数量并提示。实收少于通知量按缺量结束本次执行。勾选零收则整单按取消结束。 |
| 明细展示 | 表格列与详情页商品明细一致（不含基本单位）：行号、商品编码、商品条码、商品名称、通知数量（只读）、实收数量（可填，默认=通知数量） |
| 输入 | 每行实收数量（默认带出通知数量）；超量自动封顶并提示；确认前须0≤实收≤通知数量；零收勾选框 |
| 主按钮 | 确认回传 |
| 次按钮 | 取消 |

### 2.4 Mock 回传规则（演示数据）

| 项目 | Mock 规则 |
| --- | --- |
| 有实收 | 各行实收≤通知量，且至少一行实收>0；状态→已收货；回写明细实收、缺收=通知量−实收；本地生成演示用采购入库单（见[《采购入库单前端Demo版PRD_弹窗与Mock》](../../采购入库单/前端Demo版PRD/采购入库单前端Demo版PRD_弹窗与Mock.md) §二） |
| 缺量 | 实收<通知量且未勾选零收：按缺量结束，缺收回补订单可下推量 |
| 零收 | 状态→已取消；实收均为0；释放全部占用；不生成入库单 |
| 超量输入 | 实收>通知量时自动调整为通知量，并提示「实收数量不能超过通知数量，已自动调整为通知数量」 |
| 负值 | 实收<0时阻断并提示「实收数量不能为负数」 |
| 订单联动 | 同步更新来源采购订单累计入库、可下推量、在途通知数量、收货状态 |

Mock 数据在界面标注「演示数据」或「Mock」角标。

### 2.5 Mock 不做的内容

- 不代替正式仓库接口的推送、取消回执与异常处理
- 不在 Mock 中自动推金蝶
- 不把 Mock 行为写入主PRD正式验收标准

### 2.6 与采购订单 Mock 的关系

采购订单审核后的「生成演示通知单（Mock）」见[《采购订单前端Demo版PRD_弹窗与Mock》](../../采购订单/前端Demo版PRD/采购订单前端Demo版PRD_弹窗与Mock.md) §三。该 Mock 创建的通知单可继续用本章 Mock 回传串联主链；正式下推创建规则以本文及新增编辑页 PRD 为准。

## 三、演示验收（弹窗与Mock）

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 取消 | 待推送点取消，填原因 | 已取消，订单占用释放 |
| 待收货取消 | 待收货点取消 | 取消中，等待回执 |
| 重试 | 推送失败点重试 | 推送中 |
| 自动重试说明 | 查看推送失败单据 | 正式规则为自动重试3次后才出现人工重试；Demo 可直接模拟失败 |
| Mock回传 | 待收货保持实收=通知量并确认 | 已收货，缺收0，订单数量联动 |
| Mock缺量 | 实收改小于通知量后确认 | 已收货；缺收=差额；订单可下推量回补缺量 |
| Mock零收 | 勾选零收 | 已取消，不生成入库单 |
| 超量调整 | 实收填超过通知量 | 自动调整为通知量并提示 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口行为。
