## 2. 需求背景与目标

### 2.1 背景

B2B销售订单审核通过后，销售人员按客户要求安排本次发货。发货通知单把「本次要发多少、从哪个仓发、发到哪、用什么物流」交给仓库执行，是成交约定与实际出库之间的执行指令。

没有统一的通知单时，仓库不知道本次应发数量和交付地址，销售也难以追踪在途安排与实出差异。

### 2.2 目标

- 从已审核销售订单下推创建通知单，录入本次通知数量，选择发货处理方式（默认仓库发货）；发货方式、发货地址与物流服务产品默认继承订单，分批发货时可按本次交付覆盖；
- 仓库发货：创建后由系统自动推送仓库，不需要人工再点推送；
- 虚拟出库：不推仓库，创建成功后实发等于通知数量，通知变为已发货，系统立即生成已审核销售出库单并扣减即时库存、消耗对应预占；
- 通知创建即占用订单可下推量；取消成功或发货完成后按规则释放或替代占用；
- 一张通知单只执行一次发货，仓库路径缺量通过展示呈现，补发另建通知单；虚拟出库不允许缺量或零出；
- 仓库回传实出后更新通知状态并触发销售出库单生成；虚拟出库在创建时生成（出库PRD定义）。

通知单不直接向推送财务ERP；库存与业财影响由销售出库单承担。

## 3. 需求范围

### 3.1 本期范围

- 销售发货通知单列表、详情；
- 从销售订单下推创建（录入通知数量、发货处理方式、备注；发货方式/地址/物流默认继承订单并可覆盖）；
- 待推送、推送失败时编辑备注（推送成功后不可改）；
- 待推送/推送失败时取消；待发货时取消（进入取消中等待仓库回执）；
- 推送失败时先自动重试最多3次，仍失败可人工重试；
- 单据状态单字段维护（待推送→推送中→待发货/推送失败→已发货/已取消/取消中）；
- 与销售订单可下推量、在途通知数量的联动。

## 4. 单据定位与业务边界

### 4.1 业务作用

| 项目 | 内容 |
| --- | --- |
| 单据层级 | 第2层——执行指令单，表达本次仓库发货要求 |
| 核心职责 | 记录本次通知发多少、从哪个仓发、发到哪、来源哪张销售订单 |
| 单据来源 | 销售订单下推创建；一期唯一方式 |
| 下游单据 | 销售出库单；仓库回传实出并结束后由系统生成 |
| 数量关系 | 一张订单对应多张通知单；一张通知单对应0或1张出库单（零出不生成） |
| 业务终结 | 已发货或已取消为终态；不可撤销；缺量不回原通知补发 |

### 4.2 上下游关系摘要

> 完整流程见[《01-系统流程与单据交互》](../../../系统架构和流程/01-系统流程与单据交互.md)第三节；本文只保留通知侧交接点。

```mermaid
flowchart LR
    A["销售订单<br/>（已审核+正常）"] -->|"下推创建"| B["销售发货通知单<br/>（执行指令）"]
    B -->|"系统自动推送"| C["仓库WMS"]
    C -->|"回传实出"| B
    B -->|"有实出"| D["销售出库单<br/>（结果单）"]
    D -->|"回写"| A
    D -->|"扣减库存"| E["逻辑仓库存"]
```

### 4.3 业务对象关系

| 关系 | 说明 |
| --- | --- |
| 销售订单 : 销售发货通知单 | 1:N；分批创建 |
| 销售发货通知单 : 销售出库单 | 1:0..1；零出不生成出库单 |
| 通知单明细 : 销售订单明细 | N:1；按来源订单行累计占用与回写 |
| 销售发货通知单 : 发货仓库 | N:1；沿用来源订单仓库 |
| 销售发货通知单 : 客户 | N:1；沿用来源订单客户 |
| 销售发货通知单 : 发货地址 | N:1；默认继承订单约定地址，分批发货时可改选其他客户地址 |

### 4.4 本单据不负责的事项

- 通知单不直接向推送财务ERP；财务ERP只接收出库结果单；
- 通知单不修改销售订单的数量与价格约定；
- 已发货通知不能再往原单追加发货；少出部分通过缺出数量展示，补发另建通知单；
- 超通知发货在仓库侧拒发，通知侧通过实出不超过通知量体现；
- 发货方式、地址与物流服务产品默认继承销售订单；分批发货或改地址时可在下推创建页覆盖；

## 5. 核心业务场景索引

| 场景ID | 场景 | 类型 | 说明 |
| --- | --- | --- | --- |
| S01 | 下推创建并一次发足 | 主流程 | 下推→自动推送→待发货→回传实出=通知量→已发货→生成出库单 |
| S02 | 下推创建并少出 | 主流程 | 实出<通知量并结束→已发货+缺出展示→订单可下推量回补缺量 |
| S03 | 仓库零出 | 支线 | 回传实出0→已取消，释放全部占用，不生成出库单 |
| S04 | 推送失败重试 | 支线 | 推送失败→自动重试最多3次→仍失败可人工重试→待发货；失败期间仍占用订单额度 |
| S05 | 推送前取消 | 支线 | 待推送→取消→已取消，释放全部占用 |
| S06 | 待发货取消 | 支线 | 待发货→取消→取消中→仓库同意→已取消 |
| S07 | 仓库拒绝取消 | 支线 | 取消中→仓库拒绝→待发货；期间到达的实际结果按真实结果处理 |
| S08 | 分批发货 | 主流程 | 同一订单多次下推，每次占用对应可下推量；地址/物流默认继承订单，可按本次覆盖 |
| S09 | 虚拟出库 | 主流程 | 下推时选虚拟出库→不推仓库→通知已发货、实出=通知数量→生成已审核出库单 |
| S10 | 自提 | 主流程 | 发货方式选自提，仍走仓库发货处理方式；不选物流服务产品，仓库凭单放货 |

## 6. 状态与操作

状态定义 owner：[《单据与状态流转》](../../../系统架构和流程/03-单据与状态流转.md)第三节。销售发货通知单用**单据状态**一个字段串起推送与执行，不设审核状态，也不设「部分发货」流程状态；缺量通过明细「缺出数量」展示。

### 6.1 状态维度

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 单据状态 | 待推送、推送中、推送失败、待发货、取消中、已发货、已取消 | 控制可执行操作与是否占用订单额度 |

### 6.2 状态取值说明

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| 待推送 | 已创建，等待系统自动发送 | 否 |
| 推送中 | 正在向仓库发送，结果未确定 | 否 |
| 推送失败 | 仓库明确未接收；系统自动重试最多3次，仍失败可人工重试或取消 | 否 |
| 待发货 | 仓库已接收指令，等待回传最终结果 | 否 |
| 取消中 | 已发起取消，等待仓库回执 | 否 |
| 已发货 | 仓库已回传实际数量并结束 | 是 |
| 已取消 | 通知不再执行（含零出取消） | 是 |

```mermaid

    取消中 --> 已取消: 仓库同意

    待发货 --> 已取消: 回传零出
```

| 取消中 | 仓库拒绝 | 仓库回执 | 待发货 | 无 | 继续等待发货 | — |
| 待发货 | 发货回传 | 实出≤通知量（R06） | 已发货 | 自动 | 回写实出、缺出；生成出库单；以实出替代占用、缺量回补订单 | 超量拒绝 |
| 待发货 | 零出回传 | 实出=0并结束（R07） | 已取消 | 自动 | 释放全部占用；不生成出库单 | — |
| 任意非终态 | 销售订单随单取消 | 订单取消且通知为待推送/推送失败 | 已取消 | 随订单 | 释放占用 | — |

## 7. 核心业务规则

### 7.1 创建与下推规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 单号 | 按[《6.强盛ERP的编码规则和通用字段规则》](../../../../../01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)第一节自动生成；前缀 XSFHTZ；保存时分配 | 用户不可编辑 |
| R02 | 来源订单 | 只能来自已审核、业务状态正常、有可下推数量的销售订单 | 订单已关闭/已取消不可下推 |
| R03 | 通知数量 | 每行>0；≤该行当前可下推数量；至少一行有通知数量；不同SKU不互抵；下推创建页默认带出各行可下推数量，可修改 | 创建后不可修改 |
| R04 | 占用 | 通知创建即占用来源订单可下推量，计入在途通知数量 | 推送失败、待发货、取消中仍占用 |
| — | 单头继承 | 来源销售订单、客户、发货仓库、商品明细沿用来源订单；发货方式、发货地址、物流服务产品默认继承订单；用户可改通知数量、本次发货方式/地址/物流与备注 | 不带价格字段 |

数量示例（标明为示例）：订单行 SKU-A 可下推 420 件，下推通知 400 件后，该行可下推变为 20、在途通知 +400；该通知实出 380 并结束后，累计实际出库 +380，可下推回补为 40（20+缺出20）。

### 7.2 推送规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R05 | 自动推送 | 发货处理方式=仓库发货时，通知创建后由系统自动推送仓库，不需要人工触发推送按钮 | 虚拟出库不推送 |
| R14 | 自动重试 | 推送明确失败后系统自动重试，**最多3次**；3次仍失败则保持「推送失败」，可人工重试（F07） | 间隔本期不定秒数，由技术配置 |
| — | 推送中等待 | 推送结果不确定时不得重复发送、不得提前释放占用 | 先核实仓库是否收到 |
| — | 推送记录 | 记录推送时间、推送失败原因；重试成功后仍保留历史失败原因 | 见字段清单 |

### 7.3 发货回写与数量规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R06 | 实出上限 | 实出数量 0～通知数量；按来源订单行回写 | 超通知量拒绝 |
| R07 | 零出 | 仓库最终回传实出0并结束时，通知按零出取消为已取消，不生成出库单 | 须收到最终结果，不能把未知当零出 |
| — | 缺出 | 缺出数量=通知数量−实出数量；发货完成后计算展示 | 不在原通知补发 |
| — | 占用替代 | 发货完成后，以实出数量替代原通知占用；缺量部分回补订单可下推量 | 见 SAL-FR02 |
| R11 | 不超通知发货 | 仓库不得按超过通知量的结果完成本通知 | 有余量另建通知 |
| R13 | 虚拟出库 | 发货处理方式=虚拟出库时，不调用仓库接口；创建成功后各行实出=通知数量、缺出=0，通知变为已发货，系统立即生成已审核销售出库单并扣减即时库存、消耗对应预占；占用被实际数量替代 | 不允许缺量或零出；保存后不可改处理方式；生成失败则整笔回滚，不留下通知；已发货后不能取消 |

### 7.4 取消规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R09 | 直接取消 | 待推送可直接取消；推送失败须在确认仓库未接收后取消 | 释放全部通知占用；订单开放时恢复可下推量 |
| R10 | 待发货取消 | 待发货点「取消」，进入取消中等待仓库回执 | 取消中仍占用；仓库同意才释放 |
| — | 不可撤销 | 已发货、已取消为终态，不可反取消 | — |
| — | 随订单取消 | 销售订单取消时，待推送/推送失败的通知随单取消 | 待发货/取消中/推送中须先处理通知 |
| — | 订单关闭差异 | 通知取消成功后，订单仍开放则恢复可下推量、保留订单占库；订单已关闭则释放该部分占库，不恢复下推资格 | 见 SAL-FR04 |

### 7.5 发货方式与物流规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R15 | 发货方式 | 发货方式=物流配送时，发货地址必填；须选择启用的物流服务产品或「由仓库指定」。发货方式=自提时，不选物流服务产品，发货地址留空；仍须走仓库发货处理方式，仓库凭单放货 | 见《物流资料主PRD》R04 |
| — | 地址选择 | 发货地址从来源客户地址明细选择；下推创建时默认继承销售订单约定地址，可改选其他地址 | 分批发货到不同地址时覆盖 |
| — | 物流继承 | 物流服务产品默认继承销售订单；物流配送时可改选其他启用产品或「由仓库指定」 | 自提不选产品 |
| — | 运单回写 | 实际运单号由仓库或渠道方回传，记在通知单上，不修改物流档案 | 自提通常无运单号 |

### 7.6 字段编辑规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R12 | 可编辑范围 | 仅备注可在待推送、推送失败时编辑；推送成功后（含待发货）整单只读；通知数量、发货方式、地址、物流创建后只读 | 推送中、取消中、终态不可编辑 |

### 7.7 业务生效点

| 业务动作 | 通知单影响 | 库存影响 | 业财/外部影响 |
| --- | --- | --- | --- |
| 下推创建（仓库发货） | 产生待推送通知；占用订单额度 | 无 | 触发向仓库推送 |
| 下推创建（虚拟出库） | 产生已发货通知；实出=通知数量；占用被实际数量替代 | 扣减即时库存和对应预占 | 不推仓库；生成已审核销售出库单并推财务ERP |
| 推送成功 | 单据状态→待发货 | 无 | 仓库开始执行 |

## 11. 异常与一致性

### 11.1 并发操作

| 场景 | 业务处理结果 |
| --- | --- |
| 两人同时对同一订单下推 | 各自校验可下推量；后创建者若额度不足则阻断 |
| 下推同时订单被关闭 | 关闭成功后不可再下推；进行中的下推校验失败并提示 |
| 推送中重复触发重试 | 自动重试与人工重试同时只允许一个作业成功；另一个提示状态已变化 |

### 11.2 幂等与重复处理

| 操作 | 幂等规则 |
| --- | --- |
| 仓库回传 | 同一最终结果不得重复生成出库单或重复计入实出 |
| 取消回执 | 重复到达的同意/拒绝回执只保持一致终态 |

### 11.3 与上下游单据一致性

| 场景 | 处理方式 |
| --- | --- |
| 订单关闭后 | 不可新建通知；已有通知继续执行至结束 |
| 取消中收到实出回传 | 按真实结果完成发货，不以取消申请覆盖已发生事实 |
| 订单随单取消 | 仅待推送/推送失败通知随单取消；其余须先处理 |
