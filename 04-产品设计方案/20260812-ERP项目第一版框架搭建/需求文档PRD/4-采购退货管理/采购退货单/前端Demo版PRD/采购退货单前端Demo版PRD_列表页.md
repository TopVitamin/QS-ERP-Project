## 1. 页面目标与范围

- 页面名称：采购退货单列表页；菜单入口：**采购管理-采购退货单**
- 查看视角：**仅单据视角**（每行 = 一张采购退货单；单据行视角本期不做）
- 作为新增、导入、详情、导出的统一入口
- 一期以**行内操作**为主；勾选列配合页头导出「已勾选」范围
- 功能与状态—操作矩阵见[《采购退货单主PRD》](../采购退货单主PRD.md) §6.4；本页落地F01、F08及列表侧行操作入口

> **本期边界**：
> - 页头**导入、导出**为一期正式能力：导入见 §7（四步向导，主PRD R15、Q08）；导出为异步任务，见 §8。
> - 批量操作栏**不放**批量提交、审核、取消、关闭等业务按钮——单据状态各异，取消/关闭须逐单填原因。
> - 列表行**不提供**「联查」按钮；查看采退发货通知单、采退出库单请通过详情页「关联单据」或对应单据列表跳转。
> - 列表行**提供「删除」**：仅草稿+正常且未被下游引用时可物理删除（主PRD R14、Q02），二次确认，删除不可恢复。
> - 已审核取消按R11：无实际出库且无仍需执行的通知时可取消；待推送/推送失败通知随单取消；有推送中/待发货/取消中通知须先处理并取得仓库确认；**已有实出只能关闭余量，不能取消整单**。
> - **全部退足**（累计实出=退货数量，S07/R13）：仅查看，无下推、取消、关闭、调整截止时间。

## 2. 查询区

> 可筛选字段与顺序以[《采购退货单（详细稿）》](../../../../字段清单合集/采购相关/采购退货单（详细稿）.tsv)「可筛选=是」为准；下表为默认查询方案呈现顺序。
> **type列**：与原型 `FilterControl` 的 `type` 一致，完整规范见[《原型开发说明》](../../../../../../09-产品原型/原型开发说明.md)「查询区通用规则」「FilterControl控件type」。布局、折叠、重置/查询行为不在本文重复定义。

| 查询字段 | type | 匹配 | placeholder / 说明 |
| :--- | :--- | :--- | :--- |
| 创建时间 | `date-range` | 范围 | 不限；按日期比较；默认按创建时间倒序 |
| 单号 | `search` | 模糊 | 请输入采购退货单号 |
| 供应商 | `select` | 精确 | 全部供应商；选项为审核通过且启用的供应商；Code-Name展示 |
| 出库仓库 | `select` | 精确 | 全部仓库；实际选择逻辑仓；Code-Name展示 |
| 来源采购入库单 | `select` | 精确 | 全部；按原采购入库单号选择，未选=全部 |
| 退货截止时间 | `date-range` | 范围 | 不限；按日期比较（原型暂无 `datetime-range`） |
| 商品 | `select` | 精确 | 全部商品；按明细商品选择，选项按Code-Name展示 |
| 审核状态 | `multi-select` | 精确（OR） | 全部；草稿／待审核／已审核；初值 `[]`，未选=全部 |
| 业务状态 | `multi-select` | 精确（OR） | 全部；正常／已取消／已关闭；初值 `[]`，未选=全部 |

查询区交互（收起过滤、重置、查询、空条件默认、查询后回第一页）见《原型开发说明》「查询区通用规则」。查询条件全空时，默认返回最新列表数据（默认按创建时间倒序，主PRD Q07）。

## 7. 导入（一期正式）

一期正式提供列表导入（主PRD F08、R15、Q08；依据[《公共能力与系统管理需求分析》](../../../../../../02-需求调研和分析/08-公共能力与系统管理/公共能力与系统管理需求分析.md) COM-FR02、COM-AC02）。入口为页头「导入」，打开四步向导；**导入不改变业务流程**，生成的单据仍是草稿，须逐单提交审核。本节定义流程与校验，向导内标题、提示、按钮与错误文案见[《采购退货单前端Demo版PRD_弹窗与Mock》](采购退货单前端Demo版PRD_弹窗与Mock.md) §5；向导ASCII见[《采购退货单页面骨架》](../采购退货单页面骨架.md)「弹窗/抽屉」。

### 7.1 四步向导

| 步骤 | 内容 |
| :--- | :--- |
| ① 下载模板 | 下载标准Excel模板（.xlsx），列见 §7.2 |
| ② 上传文件 | 支持 .xlsx；校验文件格式与模板列完整性 |
| ③ 校验预览 | 按保存草稿口径整批校验（§7.3）；全通过时预览拟生成单据数；**任一行失败则整批不导入**，返回逐行错误原因并可下载错误说明 |
| ④ 完成导入 | 生成N张草稿并提示「成功导入N张退货单草稿，请逐单检查后提交审核」；关闭向导并刷新列表 |

### 7.2 模板列

单据序号、供应商、币别、出库仓库、退货截止时间、来源采购入库单号（可空）、备注、商品编码、退货数量、含税单价、税率。

- 同一「单据序号」的行归并为一张退货单；同组单头字段必须一致，不一致报错。
- 无来源退货时来源采购入库单号留空。

### 7.3 校验与结果

| 项目 | 规则 |
| :--- | :--- |
| 校验口径 | 按保存草稿口径（主PRD §7.7、R15）：单头必填（供应商、币别、出库仓库、退货截止时间）；每行商品存在且退货数量>0；价格非空非负（来源单号合法且模板价格留空时按原入库价带入）；供应商审核通过且启用；来源单号须为已审核采购入库单；有来源不超剩余可退额度 |
| 整批策略 | **任一行失败则整批不导入**，返回逐行错误原因，可下载错误说明 |
| 成功结果 | 生成N张草稿（草稿+正常，单号按CGTH规则分配），提示「成功导入N张退货单草稿，请逐单检查后提交审核」 |
| 后续流程 | 导入不改变业务流程，仍须提交审核（COM-FR02、COM-AC02）；零价在草稿级允许，提交时再按R04确认 |
| 同权 | 导入生成的草稿与手工草稿完全同权：可编辑、可提交、可删除（删除见R14） |
| 行数上限 | 不设单次导入行数硬上限 |
| 性质 | 正式能力，进入演示验收（§10.2） |

## 10. Mock数据要求与演示验收

### 10.1 Mock数据覆盖

> 以下为 **Demo Mock** 数据要求，仅Demo，非正式验收依据。

- 列表至少 **10条**单据（去重后）
- 审核状态至少各 **2单**：草稿、待审核、已审核
- 业务状态至少覆盖：正常、已取消、已关闭各 **1单**
- 至少 **1单** 已审核+正常+可下推数量 > 0
- 至少 **1单** 已审核+正常+累计实出 > 0且可下推 > 0（如退100、实出50）
- 至少 **1单** 已审核+正常+全部退足（累计实出=退货数量，S07），用于验证无行内操作
- 至少 **1单** 已审核存在执行中（推送中/待发货/取消中）采退发货通知，用于验证R11取消拦截
- 至少 **1单** 有来源（关联采购入库单）、**1单** 无来源
- 至少 **1单** 草稿，用于验证行内编辑、提交、删除（R14）
- **枚举与口径**：凡字段清单中已定义枚举或格式的，Mock取值**必须落在字段清单范围内**；不得自造清单外文案
