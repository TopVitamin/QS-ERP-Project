## 二、需求背景与范围

客户是销售业务的必选资料。现状是国内电商、跨境电商和2B客户分散在各渠道和表格里，缺少统一身份。本期在ERP建立客户档案，覆盖代理商、国内与跨境2B客户，以及国内电商、跨境电商各一条通用2C客户；通用2C档案只归集业务结果，不按消费者建档。

| 对象 | 用途 | 数据来源 | 由哪里维护 | 被哪些业务引用 |
| --- | --- | --- | --- | --- |
| 客户 | B2B销售的交易对象；通用2C客户用于归集国内电商、跨境电商和独立站业务 | 人工建档与批量导入 | 主数据维护人员提交、资料审核人审核 | 销售订单、销售退货单；独立站与外部电商使用通用2C客户 |

本期做：五类客户的建档与编辑、多条联系人、地址、银行信息及默认项、默认币别、结算方式与收款条件选项、单套工商信息、提交审核与驳回重提、启用禁用、批量导入。

本期不做：按消费者逐一建档、把消费者资料追加到通用2C档案、客户授信（由销售模块负责）、应收应付与收付款核算（由财务ERP负责）、客户门户。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 编码与防重 | 客户编码是唯一识别依据，保存时校验重复并阻止保存；客户名称不允许重复，保存时一并校验并阻止保存 | 编码规则见《6.强盛ERP的编码规则和通用字段规则》第二节（Q01） |
| R02 | 明细与默认项 | 联系人、地址、银行信息都支持多条；每类最多一个默认项，引用时优先带入默认记录 | 没有默认项时手动选择，不自动取第一条；新增明细不自动设为默认 |
| R03 | 通用2C档案 | 国内电商、跨境电商各使用一条通用客户档案；独立站使用跨境电商2C通用客户 | 不按消费者建档，不把消费者资料逐条追加到通用档案（[《强盛ERP全局业务规则与约束》](../../../../../01-全局背景信息/4.强盛ERP全局业务规则与约束.md)第一节） |
| R04 | 分类与等级 | 分类固定五类；等级人工维护，不自动决定销售资格 | 等级固定为S／A／B／C／未评级，系统不校验评价过程（Q04） |
| R05 | 结算资料 | 默认币别、结算方式、收款条件都取自辅助资料 | 结算方式与收款条件由辅助资料维护，上线前补齐实际选项（Q04） |
| R06 | 工商信息 | 每个客户最多维护一套工商信息，包含企业名称、纳税人识别号、注册地址、注册电话、开户银行和账号；不另设开票资料分组。所有客户类型均可不填，各字段选填。工商开户行、账号从银行明细默认项带出，仍可修改或清空 | 见Q04 |
| R07 | 修改范围 | 草稿和已驳回的档案可以修改并重新提交；审核通过后需要修改的，先反审核回到草稿，再修改并重新提交审核，重新审核通过前新单不能引用该条资料 | 见Q03 |
| R08 | 引用与变更 | 改名、调整分类或等级不改历史单据；单据保留当时的客户信息 | 生成单据时从客户资料带出并固化客户名称，取值时点为建单保存时；快照字段与展示位置见各业务单据字段清单 |
| R09 | 删除控制 | 未被任何业务对象引用的客户可以删除；已被引用的不能删除，只能禁用。删除不可恢复，禁用可再启用 | 删除前检查完整引用关系（销售订单、销售退货单、通用2C归集等，见03《主数据准备》的引用关系），不能只查销售单据；见Q05 |
| R10 | 批量维护 | 导入不绕过审核；是否按编码匹配、已存在资料能否更新、空值是否覆盖及错误行处理见Q06。已审核资料的任何修改须遵守R07，不能通过导入直接绕过反审核和重新提交 | 可导入字段、更新范围与冲突处理按导入中心规则确认后实施（Q06） |

### 4.2 F01 客户档案维护

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 新客户开始合作，或通用2C客户需要用于归集渠道业务时建立资料。 |
| 操作与处理 | 在客户列表新增，填写基础信息、结算与收款资料，按需填写工商信息、添加联系人与银行信息明细，保存后进入草稿；草稿和已驳回状态可以编辑并重新提交；审核通过后先反审核回到草稿，再编辑并重新提交审核。列表按审核状态页签查看，支持按关键词（编码、名称、工商企业名称、纳税人识别号）、客户分类、客户等级、默认币别、结算方式、收款条件、使用状态和最后更新时间查询；默认列、可选列及匹配方式见[《客户资料前端Demo版PRD》](客户资料前端Demo版PRD.md)第1节。 |
| 功能规则 | 保存校验：客户名称必填，编码不重复（R01）；分类固定五类（R04）；结算资料取自辅助资料（R05）；工商信息按R06，通用2C档案按R03；其余必填性见《客户资料（详细稿）》。 |
| 成功结果 | 生成一条草稿状态的客户记录，按流程提交审核。 |
| 异常与恢复 | 校验不通过时阻止保存并定位到字段，已填内容保留；通用2C客户的重复校验在保存时执行（含导入），同类档案已存在时阻止保存并提示已有档案。 |

### 4.3 F02 联系人与银行信息明细

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 同一客户有多个业务联系人、多个收货地址或多个银行账户，需要在销售单据与收款时选用。 |
| 操作与处理 | 在新增／编辑页维护联系人、地址、银行信息三条明细，每条支持添加和删除；设置默认项时系统自动取消同组的其他默认。 |
| 功能规则 | 每类最多一个默认项；业务引用优先带入默认记录，没有默认项时手动选择，不自动取第一条（R02）。默认仅影响带出顺序，不代表自动付款。 |
| 成功结果 | 明细随档案保存，详情按分组展示，引用方可以取到默认项。 |
| 异常与恢复 | 明细行必填项不完整时阻止保存并定位到具体行；同一组出现多个默认项的，保存时按最后一次设置生效。 |

### 4.4 F03 提交、审核与驳回重提

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 客户资料建立后需要确认才能用于销售。 |
| 操作与处理 | 草稿或已驳回的档案提交后进入待审核；有审核权限的人员审核通过或驳回；驳回后修改资料重新提交。 |
| 功能规则 | 审核是单级流程，有权限即可提交和审核，允许本人审核本人创建的数据（COM-FR01）；新销售业务只能使用审核通过且启用的客户（MD-FR04）。已审核后修改须先反审核回到草稿，再重新提交审核，重新审核通过前新单不能引用该条资料（R07）。 |
| 成功结果 | 审核通过的档案进入可用范围；驳回的档案保留修改入口。 |
| 异常与恢复 | 一期不录入驳回意见；驳回后修改资料重新提交进入待审核，审核不通过不影响档案继续编辑。 |

### 4.5 F04 启用、禁用与删除

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 客户停止合作、暂停使用，或建档后发现重复、录错。 |
| 操作与处理 | 在列表或详情启用、禁用；删除只对未被任何业务对象引用的客户开放。新建与新导入建档的档案使用状态默认为启用，审核通过后才能被销售选择。 |
| 功能规则 | 新销售业务只能使用审核通过且启用的客户；禁用后新单不能选择，历史单据保留原引用（R08）；被引用的客户不能删除（R09）。等级不改变销售资格（R04）。 |
| 成功结果 | 使用状态变更后立即重新判断新单可选性，历史业务不受影响；重新启用的档案须同时审核通过才恢复可选。 |
| 异常与恢复 | 客户被引用时删除不可用并说明原因；删除后不能恢复。通用2C客户被渠道业务引用后只能禁用，不能删除。 |

### 4.6 F05 批量导入

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 初期建档量大或集中维护客户资料。 |
| 操作与处理 | 在列表页进入公共导入能力；编码匹配、字段更新、空值和错误行规则按Q06确认后执行。 |
| 功能规则 | 导入不改变审核流程，新导入建档的档案仍须提交和审核（COM-FR02），使用状态默认为启用。已审核资料的导入更新不得绕过R07。 |
| 成功结果 | 按Q06确认后的导入规则展示处理结果；新建档案未审核通过前不可供销售选择。 |
| 异常与恢复 | 错误行处理与重新导入方式按Q06确认后的导入中心规则执行。 |

### 4.7 状态与动作

客户有两个状态：审核状态和使用状态，流转规则与供应商一致。

| 状态 | 含义 | 进入条件 | 是否终态 |
| --- | --- | --- | --- |
| 草稿 | 档案已保存，尚未提交 | 新建保存或导入 | 否 |
| 待审核 | 已提交，等待审核 | 提交 | 否 |
| 审核通过 | 资料已确认 | 审核通过 | 否 |
| 已驳回 | 审核未通过，可修改重提 | 驳回 | 否 |
| 启用 | 可被销售引用（还需审核通过） | 新建保存、导入或人工启用 | 否 |
| 禁用 | 停止新增引用 | 人工禁用 | 否 |

| 当前状态 | 动作/事件 | 前置条件 | 结果与业务影响 | 失败处理 |
| --- | --- | --- | --- | --- |
| 草稿／已驳回 | 编辑、提交 | 保存必填项完整（提交校验范围与保存相同） | 提交后进入待审核 | 资料不完整时阻止提交 |
| 待审核 | 审核通过 | 有审核权限 | 审核状态变为审核通过；使用状态为启用时销售可选 | 无 |
| 待审核 | 驳回 | 有审核权限 | 变为已驳回，保留修改入口 | 无 |
| 审核通过 | 反审核 | 有审核权限 | 回到草稿；修改后重新提交审核，重新审核通过前新单不能引用 | 无 |
| 任一审核状态且启用 | 禁用 | 无特殊限制，已被引用也可禁用 | 新单不能选择，历史单据保留引用 | 无 |
| 任一审核状态且禁用 | 启用 | 使用状态为禁用 | 使用状态变为启用；仅审核通过时新单可选 | 审核未通过时不进入可选范围 |
| 任一审核状态 | 删除 | 未被任何业务对象引用 | 记录移除且不可恢复 | 被引用时阻止并提示，可改为禁用 |

| 结算与业财 | 客户结算资料随业务结果推送财务ERP；应收与收款由财务ERP负责 | 结算与业财 | 不重建财务台账 |
| 公共能力 | 提交与审核按RBAC执行，允许本人审核本人创建的数据；导入不绕过审核 | 公共能力 | COM-AC01、COM-AC02 |
| 客户授信 | 不在这里维护；授信由销售模块负责 | 销售 | 本模块不提供授信字段 |

## 六、验收标准与待确认事项

### 6.1 验收标准

| 编号 | 对应功能/规则 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| AC01 | F01、R01 | 使用符合规则的资料新建客户 | 保存成功并进入草稿；编码重复时阻止保存；分类只能从五类中选择 |
| AC02 | F02、R02 | 为联系人、地址、银行信息分别维护多条记录并设置默认项；再删除全部默认项后检查引用 | 每类最多一个默认项；引用时优先带入默认项，没有默认项时手动选择，不自动取第一条（MD-AC15） |
| AC03 | F03、R07 | 驳回待审核客户，修改重提并审核通过 | 状态依次为已驳回、待审核、审核通过（MD-AC16） |
| AC04 | F03、F04 | 分别检查草稿、待审核、已驳回、审核通过未启用和禁用的客户在建销售单时的可选性 | 只有审核通过且启用的客户可选；等级不改变资格（MD-AC04） |
| AC05 | F04、R08、R09 | 禁用已被业务引用的客户后新建销售单；分别尝试删除已被销售单据或其他业务对象引用的客户；将未审核的禁用客户重新启用 | 新单选不到未审核或禁用客户，历史引用保留；任一业务对象已引用时删除被阻止（MD-AC08） |
| AC06 | F01、R03 | 归集国内、跨境电商业务，独立站引用跨境电商2C客户 | 分别使用通用客户，不因消费者增加而创建消费者档案或累计消费者资料（MD-AC14） |
| AC07 | F05、R10 | 导入需要审核的客户数据；再尝试通过导入修改已审核资料 | 导入不直接生效；已审核资料不能绕过R07修改，具体匹配和更新结果按Q06确认后验收（COM-AC02） |
| AC08 | F01、R05、R06 | 维护并重新读取默认币别、结算方式、收款条件和一套工商信息；另以2B客户不填工商信息保存 | 资料保存一致；工商信息最多一套、空值不阻止保存，不出现开票资料分组（MD-AC15） |
| AC09 | F06 | 批量提交审核、审核通过、驳回和删除客户；分别测试审核状态不一致、动作前置状态不满足、存在被引用记录 | 提交仅接受审核状态一致且均为草稿/已驳回的记录；审核通过/驳回仅接受审核状态一致且均为待审核的记录；任一记录状态不符时整批阻止并提示；删除逐条检查引用，任一记录已被引用时整批阻止并说明原因；删除不受审核状态限制 |
