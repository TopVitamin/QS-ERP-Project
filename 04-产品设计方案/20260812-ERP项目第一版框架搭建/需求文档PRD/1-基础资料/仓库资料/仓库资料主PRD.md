## 二、需求背景与范围

仓库是采购入库、销售出库和库存记账的必要资料。现状是多个仓储节点分属不同系统，ERP里没有统一的仓库身份。本期建立实体仓与逻辑仓两级档案：实体仓表示实际仓储节点，逻辑仓在实体仓下人工划分并选择库存状态，库存按逻辑仓记账。

| 对象 | 用途 | 数据来源 | 由哪里维护 | 被哪些业务引用 |
| --- | --- | --- | --- | --- |
| 实体仓 | 实际仓储节点；承载地址、联系人与第三方对接资料 | 人工建档与批量导入 | 主数据维护人员提交、资料审核人审核 | 逻辑仓归属；仓库对接映射 |
| 逻辑仓 | ERP的库存管理归属；采购、销售和库存单据指定逻辑仓 | 人工在实体仓下创建 | 主数据维护人员提交、资料审核人审核 | 采购订单、销售订单、出入库与调拨单据、库存记账 |

本期做：实体仓与逻辑仓建档与编辑、实体仓地址和单一联系人、对接方式与对接资料、逻辑仓库存状态、提交审核与驳回重提、启用禁用、实体仓批量导入。

本期不做：物理库位级的仓内细节管理、库存余额与预占冻结计算、仓库对接的报文与授权参数细节、自研WMS、仓库侧的组织与人员管理。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 编码与防重 | 实体仓编码与逻辑仓编码分别是各自对象的唯一识别依据，保存时校验重复并阻止保存 | 编码规则见《6.强盛ERP的编码规则和通用字段规则》第二节（Q01） |
| R02 | 两级归属 | 每个逻辑仓关联一个实体仓；逻辑仓共用实体仓的地址、联系人和对接资料，不重复维护 | 编辑逻辑仓时不改归属实体仓 |
| R03 | 库存状态 | 逻辑仓必须选择一个库存状态：正常品、残次品、待检品 | 同一实体仓下可以建多个相同库存状态的逻辑仓，不按组合限制数量，不另设业务类型字段 |
| R04 | 引用资格 | 新增逻辑仓只能引用审核通过且启用的实体仓 | 已有逻辑仓按自身的审核状态和使用状态判断业务资格，不再校验父实体仓是否启用 |
| R05 | 非级联禁用 | 实体仓禁用只阻止新增逻辑仓引用，不影响已有逻辑仓、已有数据和它们的业务 | 逻辑仓自身禁用后的未完成业务处理待确认（Q04） |
| R06 | 审核与使用分开 | 审核状态（草稿、待审核、审核通过、已驳回）和使用状态（启用、禁用）分开维护 | 编辑页不修改状态，通过提交、审核、启用、禁用操作变更 |
| R07 | 引用与变更 | 改名、调整地址或联系人信息不改历史单据；单据保留当时的仓库信息 | 历史快照的保存与展示由各业务PRD定义 |
| R08 | 删除控制 | 未被单据或子级档案引用的记录可以删除；被引用的不能删除，只能禁用 | 删除后的恢复与未完成单据处理待确认（Q05） |
| R09 | 批量维护 | 实体仓导入按编码匹配，已存在更新非空字段，不存在新增；导入后仍要提交审核，导入的档案使用状态默认为禁用 | 可导入字段与错误行处理按导入中心规则，待确认（Q06）；逻辑仓是否支持导入待确认（Q06） |

### 4.2 F01 实体仓档案维护

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 新增实际仓储节点，或在合作方式、地址、联系人发生变化时维护资料。 |
| 操作与处理 | 在实体仓列表新增，填写名称、运营类型、地址与联系、对接信息，保存后进入草稿；草稿和已驳回状态可以编辑并重新提交。列表支持按关键词（编码、名称、联系人）、运营类型、对接方式、对接系统和使用状态查询。 |
| 功能规则 | 保存校验：实体仓名称必填，编码不重复（R01）；只维护一条联系人和联系电话，不设多联系人与默认项；对接方式区分直连与SaaS中转，对接系统、第三方仓库编码、货主标识和授权配置按实际对接维护（Q03）。 |
| 成功结果 | 生成一条草稿状态的实体仓记录，按流程提交审核。 |
| 异常与恢复 | 校验不通过时阻止保存并定位到字段，已填内容保留；编码重复提示修改后重试。 |

### 4.3 F02 逻辑仓维护

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 在已启用的实体仓下划分库存管理归属，例如正常品仓、残次品仓、待检品仓。 |
| 操作与处理 | 在实体仓详情页的逻辑仓列表新增或编辑逻辑仓，填写名称、选择库存状态和备注；逻辑仓自身也要提交审核。 |
| 功能规则 | 新增逻辑仓只能引用审核通过且启用的实体仓（R04）；库存状态从正常品、残次品、待检品中选择（R03）；逻辑仓不重复维护地址和对接资料（R02）。 |
| 成功结果 | 生成一条草稿状态的逻辑仓记录；审核通过并启用后成为业务单据可选、库存可记账的归属。 |
| 异常与恢复 | 父实体仓未审核通过或已禁用时，新增入口不可用并说明原因；校验不通过时阻止保存并保留已填内容。 |

### 4.4 F03 提交、审核与驳回重提

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 实体仓和逻辑仓资料建立后需要确认才能用于业务。 |
| 操作与处理 | 草稿或已驳回的档案提交后进入待审核；有审核权限的人员审核通过或驳回；驳回后修改资料重新提交。 |
| 功能规则 | 审核是单级流程，有权限即可提交和审核，允许本人审核本人创建的数据（COM-FR01）；实体仓和逻辑仓分别走各自的审核流程。 |
| 成功结果 | 审核通过的档案进入可用范围；驳回的档案保留修改入口。 |
| 异常与恢复 | 驳回意见随记录保留；审核不通过不影响档案继续编辑。 |

### 4.5 F04 启用、禁用与删除

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 仓库停止使用、暂停使用，或建档后发现重复、录错。 |
| 操作与处理 | 在列表或详情启用、禁用；删除只对未被引用、且没有下级逻辑仓的记录开放。新建与导入的档案使用状态默认为禁用，审核通过后由有维护权限的人员启用。 |
| 功能规则 | 实体仓禁用只阻止新增逻辑仓引用，不级联禁用已有逻辑仓（R05）；已有逻辑仓按自身状态判断业务资格；单据选定的是逻辑仓，逻辑仓归属实体仓（MD-FR03）。被引用的记录不能删除（R08）。 |
| 成功结果 | 新增引用立即受控，已有业务不受影响；重新启用后恢复新增引用。 |
| 异常与恢复 | 记录被引用或实体仓下有逻辑仓时删除不可用并说明原因；禁用不影响已保存业务。 |

### 4.6 F05 批量导入

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 初期建档量大或集中维护实体仓资料。 |
| 操作与处理 | 在实体仓列表页使用导入，按实体仓编码匹配，已存在更新非空字段，不存在新增（R09）。 |
| 功能规则 | 导入不改变审核流程，导入后的档案仍要提交和审核（COM-FR02）；导入的档案使用状态默认为禁用。 |
| 成功结果 | 实体仓批量建立或更新，结果按成功、失败分别可见。 |
| 异常与恢复 | 失败行不写入并给出原因，修正文件后重新导入；错误处理细节按导入中心规则。 |

### 4.7 状态与动作

实体仓和逻辑仓各自有两个状态，流转规则一致。

| 状态 | 含义 | 进入条件 | 是否终态 |
| --- | --- | --- | --- |
| 草稿 | 档案已保存，尚未提交 | 新建保存或导入 | 否 |
| 待审核 | 已提交，等待审核 | 提交 | 否 |
| 审核通过 | 资料已确认 | 审核通过 | 否 |
| 已驳回 | 审核未通过，可修改重提 | 驳回 | 否 |
| 启用 | 可被新增引用（实体仓供新增逻辑仓，逻辑仓供业务单据） | 人工启用 | 否 |
| 禁用 | 停止新增引用 | 新建默认、导入默认或人工禁用 | 否 |

| 当前状态 | 动作/事件 | 前置条件 | 结果与业务影响 | 失败处理 |
| --- | --- | --- | --- | --- |
| 草稿／已驳回 | 编辑、提交 | 资料完整 | 提交后进入待审核 | 资料不完整时阻止提交 |
| 待审核 | 审核通过 | 有审核权限 | 审核状态变为审核通过；启用后进入引用范围 | 无 |
| 待审核 | 驳回 | 有审核权限 | 变为已驳回，保留修改入口 | 无 |
| 审核通过且启用（实体仓） | 禁用 | 无特殊限制 | 新增逻辑仓不能引用该实体仓；已有逻辑仓按自身状态继续 | 无 |
| 审核通过且启用（逻辑仓） | 禁用 | 无特殊限制 | 新单不能选择该逻辑仓，历史单据保留引用 | 未完成业务处理待确认（Q04） |
| 禁用 | 启用 | 审核状态为审核通过 | 恢复新增引用 | 审核未通过时不进入引用范围 |
| 草稿／已驳回，未被引用 | 删除 | 无业务引用，实体仓下无逻辑仓 | 记录移除 | 被引用时阻止并提示 |

## 六、验收标准与待确认事项

### 6.1 验收标准

| 编号 | 对应功能/规则 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| AC01 | F01、F02、R02 | 新建实体仓，在其下自定义多个逻辑仓（含相同库存状态）并提交审核，维护对接资料 | 逻辑仓归属一个实体仓，不强制业务类型或组合唯一；实体仓禁用只阻止新增逻辑仓，逻辑仓共用实体仓联系和对接资料（MD-AC03） |
| AC02 | F02、R03 | 在同一实体仓下建两个库存状态相同的逻辑仓 | 允许创建，命名不同即可；不按状态组合限制数量 |
| AC03 | F03、R06 | 分别提交实体仓和逻辑仓，走审核通过和驳回重提 | 两个对象各自维护审核状态；驳回后可修改重新提交 |
| AC04 | F02、F04、R04 | 用草稿、待审核、已驳回、审核通过未启用、禁用的实体仓新增逻辑仓 | 只有审核通过且启用的实体仓可以新增逻辑仓（MD-AC03） |
| AC05 | F04、R05 | 禁用已有逻辑仓的实体仓，再新增逻辑仓并使用原有逻辑仓 | 新增逻辑仓不能引用该实体仓；原有逻辑仓、数据和业务不受父仓禁用影响（MD-AC18、MD-AC08） |
| AC06 | F01、R02 | 查看逻辑仓详情 | 逻辑仓展示自身字段与归属实体仓，不重复维护地址、联系人和对接资料；实体仓只有一条联系人 |
| AC07 | F04、R08 | 禁用已被业务引用的逻辑仓后新建单据；再尝试删除该逻辑仓和有下级逻辑仓的实体仓 | 新单选不到被禁用的逻辑仓，历史单据保留原信息；删除被阻止 |
| AC08 | F05、R09 | 导入需要审核的实体仓数据 | 导入后仍按提交、审核流程处理，不因导入直接生效（COM-AC02） |
