## 二、需求背景与范围

仓库是采购入库、销售出库和库存记账的必要资料。现状是多个仓储节点分属不同系统，ERP里没有统一的仓库身份。本期建立实体仓与逻辑仓两级档案：实体仓表示实际仓储节点，逻辑仓在实体仓下人工划分并选择库存状态，库存按逻辑仓记账。

| 对象 | 用途 | 数据来源 | 由哪里维护 | 被哪些业务引用 |
| --- | --- | --- | --- | --- |
| 实体仓 | 实际仓储节点；承载地址、联系人与第三方对接资料 | 人工建档与批量导入 | 主数据维护人员提交、资料审核人审核 | 逻辑仓归属；仓库对接映射 |
| 逻辑仓 | ERP的库存管理归属；采购、销售和库存单据指定逻辑仓 | 人工在实体仓下创建 | 主数据维护人员提交、资料审核人审核 | 采购订单、销售订单、出入库与调拨单据、库存记账 |

本期做：实体仓与逻辑仓建档与编辑、实体仓地址和单一联系人、对接方式与对接资料、逻辑仓库存状态、提交审核与驳回重提、启用禁用、实体仓批量导入。

本期不做：物理库位级的仓内细节管理、库存余额与预占冻结计算、仓库对接的报文与授权参数细节、自研WMS、仓库侧的组织与人员管理。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 编码与防重 | 实体仓编码与逻辑仓编码分别是各自对象的唯一识别依据，保存时校验重复并阻止保存 | 编码规则见《6.强盛ERP的编码规则和通用字段规则》第二节（Q01） |
| R02 | 两级归属 | 每个逻辑仓必须关联一个实体仓，所属实体仓必填、不能为空；逻辑仓共用实体仓的地址、联系人和对接资料，不重复维护 | 新增与编辑均可选择所属实体仓，编辑可调整归属；已有库存与未完成单据随逻辑仓挂到新实体仓（Q08）；对接资料仍由实体仓维护，不因逻辑仓改归属而迁移 |
| R03 | 库存状态 | 逻辑仓必须选择一个库存状态：正常品、残次品、待检品 | 同一实体仓下可以建多个相同库存状态的逻辑仓，不按组合限制数量，不另设业务类型字段 |
| R04 | 引用资格 | 新增或重新选择所属实体仓时，只能引用审核通过且启用的实体仓 | 已有逻辑仓按自身的审核状态和使用状态判断业务资格，不再校验父实体仓是否启用 |
| R05 | 非级联禁用 | 实体仓禁用只阻止新增逻辑仓引用，不影响已有逻辑仓、已有数据和它们的业务 | 逻辑仓自身可以禁用，有库存或未完成单据不阻断；新单不能选，已有业务继续（Q04） |
| R06 | 审核与使用分开 | 审核状态（草稿、待审核、审核通过、已驳回）和使用状态（启用、禁用）分开维护 | 编辑页不修改状态，通过提交、审核、启用、禁用操作变更 |
| R07 | 引用与变更 | 改名、调整地址或联系人信息不改历史单据；单据保留当时的仓库信息 | 历史快照的保存与展示由各业务PRD定义 |
| R08 | 删除控制 | 未被任何业务对象引用的记录可以删除；实体仓存在逻辑仓即属于被引用。被引用的不能删除，只能禁用；删除不可恢复，禁用可再启用 | 删除前检查完整引用关系，不能只查业务单据；逻辑仓有库存余额或未完成单据时不允许删除、不允许修改库存状态；见Q05 |
| R09 | 批量维护 | 实体仓与逻辑仓均可导入，导入不绕过审核；编码匹配、已存在资料能否更新、空值覆盖和错误行处理均见Q06 | 新导入建档默认启用但须审核通过才能用于新增引用；已审核资料的任何修改须遵守R10，不能通过导入直接绕过反审核和重新提交 |
| R10 | 修改范围 | 草稿和已驳回的档案可以修改并重新提交；审核通过后需要修改的，先反审核回到草稿，再修改并重新提交审核，重新审核通过前不能供新增引用（实体仓供新增逻辑仓，逻辑仓供业务单据） | 见Q09；提交审核时的字段校验范围与保存相同 |

### 4.2 F01 实体仓档案维护

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 新增实际仓储节点，或在合作方式、地址、联系人发生变化时维护资料。 |
| 操作与处理 | 在实体仓列表新增，填写名称、运营类型、地址与联系、对接信息，保存后进入草稿；草稿和已驳回状态可以编辑并重新提交；审核通过后先反审核回到草稿，再编辑并重新提交审核。列表按审核状态页签查看，支持关键词（实体仓编码、名称、第三方仓库编码）、运营类型、联系人、对接方式、对接系统、使用状态和最后更新时间查询；默认列与可选列见[《仓库资料前端Demo版PRD·列表页》](前端Demo版PRD/仓库资料前端Demo版PRD_列表页.md)。 |
| 功能规则 | 保存校验：实体仓名称、运营类型必填，编码不重复（R01）；只维护一条联系人和联系电话，不设多联系人与默认项；对接方式区分直连与SaaS中转，对接系统、第三方仓库编码、货主标识和授权配置按实际对接维护（Q03）。 |
| 成功结果 | 生成一条草稿状态的实体仓记录，按流程提交审核。 |
| 异常与恢复 | 校验不通过时阻止保存并定位到字段，已填内容保留；编码重复提示修改后重试。 |

### 4.3 F02 逻辑仓维护

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 在已启用的实体仓下划分库存管理归属，例如正常品仓、残次品仓、待检品仓。 |
| 操作与处理 | 在逻辑仓列表或实体仓详情子表新增、查看与编辑逻辑仓；列表可跨实体仓按编码、名称、所属实体仓、库存状态、审核状态、使用状态和最后更新时间查询。新增时从实体仓详情进入则默认当前实体仓，从逻辑仓列表进入则选择所属实体仓；编辑时可以重新选择所属实体仓调整归属；逻辑仓自身也要提交审核。 |
| 功能规则 | 新增或重新选择所属实体仓时只能引用审核通过且启用的实体仓（R04）；库存状态从正常品、残次品、待检品中选择（R03）；逻辑仓不重复维护地址和对接资料（R02）。草稿和已驳回可编辑；审核通过后须先反审核再编辑（R10）。编辑可调整归属，已有库存与未完成单据随逻辑仓挂到新实体仓（Q08）。有库存余额或未完成单据的逻辑仓不允许修改库存状态（R08）。 |
| 成功结果 | 生成一条草稿状态的逻辑仓记录；审核通过并启用后成为业务单据可选、库存可记账的归属。 |
| 异常与恢复 | 不存在审核通过且启用的实体仓时，新增入口不可用并说明原因；校验不通过时阻止保存并保留已填内容。 |

### 4.4 F03 提交、审核与驳回重提

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 实体仓和逻辑仓资料建立后需要确认才能用于业务。 |
| 操作与处理 | 草稿或已驳回的档案提交后进入待审核；有审核权限的人员审核通过或驳回；驳回后修改资料重新提交。 |
| 功能规则 | 审核是单级流程，有权限即可提交和审核，允许本人审核本人创建的数据（COM-FR01）；实体仓和逻辑仓分别走各自的审核流程。已审核后修改须先反审核回到草稿，再重新提交审核，重新审核通过前不能供新增引用（R10）。提交审核时的校验范围与保存相同。一期驳回只变更审核状态，不录入驳回意见。 |
| 成功结果 | 审核通过的档案进入可用范围；驳回的档案保留修改入口。 |
| 异常与恢复 | 驳回后修改资料重新提交进入待审核；审核不通过不影响档案继续编辑。 |

### 4.5 F04 启用、禁用与删除

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 仓库停止使用、暂停使用，或建档后发现重复、录错。 |
| 操作与处理 | 在列表或详情启用、禁用；删除只对未被任何业务对象引用的记录开放，实体仓下存在逻辑仓时不能删除。新建与新导入建档的档案使用状态默认为启用，审核通过后才能被引用。 |
| 功能规则 | 实体仓禁用只阻止新增逻辑仓引用，不级联禁用已有逻辑仓（R05）；已有逻辑仓按自身状态判断业务资格；单据选定的是逻辑仓，逻辑仓归属实体仓（MD-FR03）。被引用的记录不能删除（R08）。 |
| 成功结果 | 使用状态变更后立即重新判断新增引用资格，已有业务不受影响；重新启用的档案须同时审核通过才恢复新增引用。 |
| 异常与恢复 | 记录被引用或实体仓下有逻辑仓时删除不可用并说明原因；禁用不影响已保存业务。 |

### 4.6 F05 批量导入

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 初期建档量大或集中维护实体仓、逻辑仓资料。 |
| 操作与处理 | 在实体仓列表、逻辑仓列表分别进入公共导入能力；匹配、更新、空值与错误行处理按Q06确认后执行。 |
| 功能规则 | 导入不改变审核流程，新导入建档的实体仓仍须提交和审核（COM-FR02），使用状态默认为启用。已审核资料的导入更新不得绕过R10。 |
| 成功结果 | 按Q06确认后的导入规则展示结果；新建档案未审核通过前不能供新增逻辑仓引用。 |
| 异常与恢复 | 错误行处理与重新导入方式按Q06确认后的导入中心规则执行。 |

### 4.7 状态与动作

实体仓和逻辑仓各自有两个状态，流转规则一致。

| 状态 | 含义 | 进入条件 | 是否终态 |
| --- | --- | --- | --- |
| 草稿 | 档案已保存，尚未提交 | 新建保存或导入 | 否 |
| 待审核 | 已提交，等待审核 | 提交 | 否 |
| 审核通过 | 资料已确认 | 审核通过 | 否 |
| 已驳回 | 审核未通过，可修改重提 | 驳回 | 否 |
| 启用 | 可被新增引用（还需审核通过；实体仓供新增逻辑仓，逻辑仓供业务单据） | 新建保存、导入或人工启用 | 否 |
| 禁用 | 停止新增引用 | 人工禁用 | 否 |

| 当前状态 | 动作/事件 | 前置条件 | 结果与业务影响 | 失败处理 |
| --- | --- | --- | --- | --- |
| 草稿／已驳回 | 编辑、提交 | 保存必填项完整 | 逻辑仓编辑可调整所属实体仓（R02）；提交后进入待审核 | 校验不通过时阻止提交 |
| 待审核 | 审核通过 | 有审核权限 | 审核状态变为审核通过；使用状态为启用时进入引用范围 | 无 |
| 待审核 | 驳回 | 有审核权限 | 变为已驳回，保留修改入口；一期不录入驳回意见 | 无 |
| 审核通过 | 反审核 | 有审核权限 | 回到草稿；修改后重新提交审核，重新审核通过前不能供新增引用 | 无 |
| 任一审核状态且启用（实体仓） | 禁用 | 无特殊限制 | 新增逻辑仓不能引用该实体仓；已有逻辑仓按自身状态继续 | 无 |
| 任一审核状态且启用（逻辑仓） | 禁用 | 无特殊限制 | 新单不能选择该逻辑仓，历史单据保留引用；有库存或未完成单据不阻断禁用 | 无 |
| 任一审核状态且禁用 | 启用 | 使用状态为禁用 | 使用状态变为启用；仅审核通过时可供新增引用 | 审核未通过时不进入引用范围 |
| 任一审核状态 | 删除 | 未被任何业务对象引用，实体仓下无逻辑仓 | 记录移除且不可恢复 | 被引用时阻止并提示 |

## 五、上下游影响与协同

| 关联模块/系统 | 变化与交接内容 | 负责方 | 验收结果 |
| --- | --- | --- | --- |
| 库存与仓储 | 库存按逻辑仓记账；单据选定逻辑仓，逻辑仓归属实体仓 | 库存与仓储 | 审核通过且启用的逻辑仓才能被单据选择 |

## 六、验收标准与待确认事项

### 6.1 验收标准

| 编号 | 对应功能/规则 | 条件与操作 | 预期结果 |
| --- | --- | --- | --- |
| AC01 | F01、F02、R02 | 新建实体仓，在其下自定义多个逻辑仓（含相同库存状态）并提交审核，维护对接资料 | 逻辑仓归属一个实体仓，不强制业务类型或组合唯一；实体仓禁用只阻止新增逻辑仓，逻辑仓共用实体仓联系和对接资料（MD-AC03） |
| AC02 | F02、R03 | 在同一实体仓下建两个库存状态相同的逻辑仓 | 允许创建，命名不同即可；不按状态组合限制数量 |
| AC03 | F03、R06 | 分别提交实体仓和逻辑仓，走审核通过和驳回重提 | 两个对象各自维护审核状态；驳回后可修改重新提交 |
| AC04 | F02、F04、R04 | 用草稿、待审核、已驳回、审核通过未启用、禁用的实体仓新增逻辑仓 | 只有审核通过且启用的实体仓可以新增逻辑仓（MD-AC03） |
| AC05 | F04、R05 | 禁用已有逻辑仓的实体仓，再新增逻辑仓并使用原有逻辑仓 | 新增逻辑仓不能引用该实体仓；原有逻辑仓、数据和业务不受父仓禁用影响（MD-AC18、MD-AC08） |
| AC06 | F01、R02 | 查看逻辑仓详情 | 逻辑仓展示自身字段与归属实体仓，不重复维护地址、联系人和对接资料；实体仓只有一条联系人 |
| AC07 | F04、R08 | 禁用已被业务引用、仍有库存的逻辑仓后新建单据；再尝试删除该逻辑仓和有下级逻辑仓的实体仓 | 禁用成功；新单选不到被禁用的逻辑仓，历史单据保留原信息；删除被阻止 |
| AC08 | F05、R09 | 导入需要审核的实体仓数据；尝试以导入更新既有档案 | 新建档案仍按提交、审核处理；既有档案匹配和更新结果待Q06确认后验收，不因导入直接获得引用资格（COM-AC02） |
| AC09 | F02、R02、R04 | 编辑草稿状态的逻辑仓，重新选择另一审核通过且启用的实体仓保存；再尝试选择草稿或禁用的实体仓 | 保存后所属实体仓更新为新选择的实体仓；草稿或禁用的实体仓不能被选择 |
| AC10 | F03、R10 | 审核通过的实体仓与逻辑仓先反审核，修改资料后重新提交并审核通过 | 反审核后回到草稿，可编辑；重新审核通过前不能供新增引用；通过后恢复引用资格 |
| AC11 | F02、R02、Q08 | 编辑已有库存的逻辑仓，将所属实体仓调整为另一审核通过且启用的实体仓 | 逻辑仓归属更新；已有库存与未完成单据随逻辑仓挂到新实体仓；对接资料仍读取新归属实体仓的配置 |
| AC12 | F02、R08、Q05 | 对仍有库存余额或未完成单据的逻辑仓执行删除、修改库存状态 | 删除与修改库存状态均被阻止并说明原因；禁用不受影响，已有业务继续 |
