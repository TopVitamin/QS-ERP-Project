## 3. 状态变更弹窗（F03、F04、F06、F07、F08）

下列弹窗均在**二次确认**后执行。入口可用条件见主PRD §6.4 与各页页头/行内矩阵；条件不满足时**不展示按钮**，无需弹窗阻断。

**阻断类失败**（不满足业务规则、未进入成功流）：可用库存不足时 Toast「可用库存不足，不能审核占库」；状态不匹配时 Toast「当前单据状态为{状态}，不可执行{动作}」；权限不足时 Toast「您暂无{动作}权限，请联系管理员」。

### 3.1 提交

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 新增/编辑页、列表、详情「提交」 |
| 可用条件 | 单据状态=草稿 |
| 弹窗标题 | 确认提交其他出库申请单？ |
| 正文 | 提交后进入待审核状态，出库仓、业务类型与数量不可再修改；审核通过时按可用库存预占，可用不足不能审核；审核前仍可撤回修改。 |
| 必填项 | 无 |
| 确认按钮 | 确认提交 |
| 取消按钮 | 取消 |
| 确认后 | 状态→待审核；Toast「其他出库申请单已提交」；不占库、不改变库存 |

### 3.2 审核

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「审核」 |
| 可用条件 | 单据状态=待审核；出库仓可用库存充足（主PRD R07） |
| 弹窗标题 | 确认审核其他出库申请单？ |
| 正文 | 审核通过后按可用库存预占，系统自动推送仓库；实际出库以仓库回传的结果单为准，实出消耗预占、未出释放。 |
| 必填项 | 无 |
| 确认按钮 | 确认审核 |
| 取消按钮 | 取消 |
| 确认后 | 状态→已审核并自动推送；预占生效；Toast「审核通过，正在推送仓库」；接续 §5 Mock（Demo开关开启时） |
| 失败处理 | 可用不足或处理后将为负时阻断，Toast「可用库存不足，不能审核占库」；状态与库存不变 |

### 3.4 取消

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 列表、详情「取消」 |
| 可用条件 | 单据状态=待审核／已审核／推送失败／待发货 |
| 弹窗标题 | 取消其他出库申请单 |
| 正文 | 取消后本单不再执行，不可撤销；未执行部分的预占在取消成功后释放。已推送给仓库的，需等待仓库确认取消或实际结果，不能单方面认定。 |

## 4. 结果单重推（不在本模块）

```text
其他出库申请单列表 / 详情
         │

         │
         ▼
    本模块无重推按钮
         │
         ▼
  到「其他出库单详情 → 系统集成中心」办理
```

## 5. Demo Mock：模拟仓库回传生成其他出库单（F09）

### 5.1 正式规则（必读）

正式环境中，其他出库申请单审核后按可用量预占并由系统自动推送仓库；仓库执行一次并回传实际出库数量：实出大于0时系统自动生成**已审核**其他出库单，减少对应逻辑仓即时库存、消耗实出预占并释放未出预占，回写申请单实出与状态；实出为0时按零出取消申请单并释放全部预占，不生成结果单、不改变库存。允许缺量、不允许超量（超过申请数量整次拒绝）；处理后即时或可用库存将为负时阻断记账。**申请单不提供手动关闭，也不设到期自动关单。**

本节 Mock **仅用于 Demo 原型串联展示**，不属于主PRD AC01～AC15 的正式验收项（主PRD F09）。

### 5.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 待发货申请单详情点「模拟回传」 | 打开 §5.3 弹窗，录入实出数量；确认后按 §5.4 本地生成演示出库单 |

```text
待发货申请单详情
         │
     Mock 回传实出数量
         │
         ▼
    实出合计 > 0？
         │
    ┌────┴────┐
   否         是
    │          │
    ▼          ▼
 申请单取消   库存校验通过？
 释放预占         │
 不生成结果单  ┌───┴───┐
             否       是
              │        │
              ▼        ▼
           阻断     §5.4 本地创建
         负库存    已审核出库单
                       │
                       ▼
                推送财务ERP状态=未推送
                Demo 可模拟推送进度
```

### 5.3 引导弹窗

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 模拟仓库回传（Demo） |
| 正文 | 按实际出库数量生成演示用其他出库单；正式流程以仓库回传为准。 |
| 必填项 | 回传实出数量（整数，大于0且不超过申请数量） |
| 确认按钮 | 确认回传 |
| 取消按钮 | 取消 |
| 确认后 | 执行 §5.4 本地创建规则 |

### 5.4 生成规则（本地 Mock）

| 项目 | Mock 规则 |
| :--- | :--- |
| 生成条件 | 来源申请单状态=待发货；实出合计>0；实出不超过申请数量；尚无关联出库单；Mock 库存校验通过（不允许负库存） |
| 单头 | 沿申请单带入来源其他出库申请单、出库仓库、业务类型；实际出库时间=当前时间 |
| 明细 | 实际出库数量=录入实出；来源申请行沿来源行 |
| 审核 | 创建即为已审核；审核人留空；创建人、最后更新人显示「系统」 |
| 库存与回写 | Mock 减少出库仓即时库存；消耗实出预占、释放未出预占；回写申请单实出与状态为已发货；未出数量重算 |
| 财务ERP | 生成后从「未推送」开始，由 Demo 模拟推送进度；明确失败时可模拟自动重试3次 |
| 单号 | 按 QTCK 编码规则生成 fictitious 编号 |
| 零出 | 实出为0时：申请单按零出取消并释放全部预占，不生成出库单、不改变库存 |
| 在途仓 | 盘亏走直接记账，不经过本 Mock 的回传步骤；其他出库类型走普通仓库回传 |

界面标注「演示数据」或「Mock」角标，与正式回传生成的出库单区分。

### 5.5 不做的事

- 不代替正式仓库回传与校验逻辑
- 不提供无来源人工建单页面
- 不把 Mock 推送当作财务ERP正式验收
- 不在本模块演示系统集成中心重推；人工确认在本模块申请单详情页办理，随对应模块修订
- 不在 Mock 中制造负库存（主PRD R21）

### 5.6 与结果单 Mock 的关系

本 Mock 生成演示出库单后，可在[《其他出库单前端Demo版PRD_弹窗与Mock》](../../其他出库单/前端Demo版PRD/其他出库单前端Demo版PRD_弹窗与Mock.md)查看结果单侧的推送进度模拟；两侧不重复触发同一张单的生成。

## 6. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| 提交流 | 草稿点提交 | 弹窗 → 待审核；不占库 |
| 审核流 | 待审核点审核，可用充足 | 弹窗 → 已审核；预占生效；自动推送 |
| 审核阻断 | 待审核点审核，可用不足 | Toast 阻断；状态与库存不变 |
| 撤回 | 待审核点撤回，撤回意见为空 | 阻断，提示撤回意见必填；填写后回草稿 |
| 取消（待审核） | 待审核点取消 | 弹窗必填取消原因 → 已取消 |
| 取消（已审核） | 已审核点取消 | 弹窗 → 已取消并释放未执行预占 |
| 取消（待发货） | 待发货点取消 | 弹窗 → 取消中；提示等待仓库确认；不提前释放预占 |
| Demo仓库拒绝取消 | 打开取消中单详情，点「模拟仓库回执」并选「仓库拒绝」 | 申请单恢复待发货，预占继续占用；不调用真实仓库接口 |
| Demo仓库同意取消 | 打开取消中单详情，点「模拟仓库回执」并选「仓库同意」 | 申请单变为已取消并释放未执行预占；不调用真实仓库接口 |
| 重试推送 | 推送失败点重试推送 | 弹窗 → 已审核等待发送；不重复占库 |
| 删除草稿 | 草稿点删除 | 二次确认 → 记录消失 |
| 在途仓盘亏直接记账 | 虚拟在途仓＋盘亏的待审核单点审核 | 弹窗 §3.8 → 已发货；不推送仓库；生成已审核出库单 |
| 在途仓普通出库 | 虚拟在途仓＋报废的待审核单点审核 | 普通审核弹窗 → 已审核并推送仓库；进入待发货，不直接记账 |
| 无关闭/无重推入口 | 任意状态查找关闭、结果单重推 | 无对应按钮与弹窗 |
| Mock 开启 | 待发货详情点「模拟回传」 | 出现 §5.3 弹窗 |
| Mock 生成 | 实出28（申请30），确认回传 | 本地生成已审核出库单28；申请单已发货、未出2；预占消耗28并释放2 |
| Mock 零出 | 实出0，确认回传 | 申请单取消并释放预占；不生成出库单 |
| Mock 超量 | 实出40（申请30） | 阻断并提示不得超过申请数量 |
| Mock 负库存 | 实出导致库存为负 | 阻断并提示不允许负库存 |
| 业务阻断 | 状态不匹配时点操作 | Toast 阻断，不进入成功流 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。
