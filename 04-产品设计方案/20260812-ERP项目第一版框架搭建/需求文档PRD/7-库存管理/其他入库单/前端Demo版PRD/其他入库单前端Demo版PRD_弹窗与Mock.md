### 1.1 本模块不提供的弹窗

本期不提供以下弹窗：

| 弹窗 | 说明 |
| :--- | :--- |
| 重推金蝶确认框 | 金蝶推送失败后在**系统集成中心**针对原单重推（F05）；本模块列表/详情无重推按钮 |
| 提交 / 审核 / 撤回 | 入库单常规由系统自动生成并审核；人工确认实际结果的提交审核入口在系统集成中心（INT-FR06），不在本模块 |
| 取消 / 作废 / 编辑 | 已审核为终态，不可撤销、不可编辑 |

自动重试（正式环境）：推送明确失败后系统自动重试，**最多3次**；间隔由技术配置。3次仍失败则保持「推送失败」，到系统集成中心针对原单重推。

```
其他入库单列表 / 详情
         │
    用户查找重推入口
         │
         ▼
    本模块无重推按钮
         │
         ▼
  到系统集成中心办理（F05）
  须：已审核 + 金蝶推送状态=推送失败
```

## 2. Demo Mock：申请回传生成（F06-A）

### 2.1 正式规则（必读）

正式环境中，其他入库申请单回传实收并结束后，系统自动校验并生成**已审核**入库单，增加对应逻辑仓库存、写库存流水并回写申请单实收与状态，再触发金蝶推送。实收为0不生成入库单，申请单按取消结束。**不提供无来源人工建单。**

本节 Mock 的触发与生成规则统一在[《其他入库申请单前端Demo版PRD_弹窗与Mock》](../../其他入库申请单/前端Demo版PRD/其他入库申请单前端Demo版PRD_弹窗与Mock.md) §5 维护（由申请单详情触发），本模块不重复定义、不重复触发。

### 2.2 本模块的表现

| 时机 | 行为 |
| :--- | :--- |
| 申请单 Mock 回传成功生成入库单后 | 入库单列表出现新记录，状态=已审核、金蝶推送状态=未推送；详情可打开 |
| Demo 推送进度 | 由 Demo 模拟从未推送 → 推送中 → 推送成功；可配置模拟一次推送失败 |

### 2.3 不做的事

- 不代替正式仓库回传与校验逻辑
- 不提供无来源人工建单页面
- 不把 Mock 推送当作金蝶正式验收

## 3. Demo Mock：仓库主动回传生成（F06-B）

### 3.1 正式规则（必读）

正式环境中，仓库先完成盘盈等实际变动后回传，商品、仓库归属与业务类型映射正常且库存校验通过时，直接生成**已审核**其他入库单并生效，不补建申请、通知，也不建ERP盘点单（INV-FR04）。归属依据不足时保留异常，不随便选仓、不记账、不推金蝶。

本节 Mock **仅用于 Demo 原型串联展示**，不属于主PRD AC01～AC12 的正式验收项（主PRD F06）。

### 3.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 其他入库单列表页头「模拟仓库主动回传(Mock)」 | 打开 §3.3 弹窗，选择入库仓库与业务类型、录入商品与数量；确认后按 §3.4 本地生成 |

```
其他入库单列表
      │
  Mock 主动回传
      │
      ▼
 映射与库存校验通过？
      │
 ┌────┴────┐
否         是
 │          │
 ▼          ▼
挂异常     §3.4 本地创建
不记账     已审核入库单
不推金蝶        │
                ▼
         金蝶推送状态=未推送
         Demo 可模拟推送进度
```

### 3.3 引导弹窗

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 模拟仓库主动回传（Demo） |
| 正文 | 按仓库已完成的实际变动生成演示用已审核入库单；正式流程以仓库回传为准，不补建申请单。 |
| 表单项 | 入库仓库（逻辑仓）、业务类型（如盘盈）、来源系统、来源单号、商品与数量（可多行） |
| 主按钮 | 确认生成 |
| 次按钮 | 取消 |
| 关闭图标 | 关闭后不生成任何数据 |

### 3.4 生成规则（本地 Mock）

| 项目 | Mock 规则 |
| :--- | :--- |
| 生成条件 | 商品、入库仓库与业务类型映射正常；数量为正整数；库存校验通过（入库方向不产生负库存） |
| 单头 | 来源类型=仓库主动回传；来源其他入库申请单留空；来源系统、来源单号取弹窗输入；实际入库时间=当前时间 |
| 明细 | 按弹窗录入的商品与数量生成；来源申请行留空 |
| 审核 | 创建即为已审核；审核人留空；创建人、最后更新人显示「系统」 |
| 库存 | Mock 增加入库仓库即时库存；写一条增加方向库存流水 |
| 金蝶 | 生成后从「未推送」开始，由 Demo 模拟推送进度；明确失败时可模拟自动重试3次 |
| 单号 | 按 QTRK 编码规则生成 fictitious 编号 |
| 归属异常 | 演示「归属依据不足」分支时：不生成入库单、不记账、不推金蝶，提示保留异常 |

界面标注「演示数据」或「Mock」角标，与正式回传生成的入库单区分。

### 3.5 不做的事

- 不代替正式接口校验与映射
- 不在 Mock 中自动执行金蝶正式推送
- 不生成无业务类型、无逻辑仓的结果单

## 4. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| Mock 申请回传生成 | 待收货申请单 Mock 回传实收80 | 生成已审核入库单80；申请单已收货、未收20；库存+80 |
| Mock 申请回传零收 | 申请单 Mock 回传实收0 | 不生成入库单；申请单取消 |
| Mock 主动回传 | 列表点「模拟仓库主动回传(Mock)」，选盘盈、数量5 | 生成已审核入库单；来源类型=仓库主动回传；来源申请单为 `-`；库存+5 |
| Mock 归属异常 | 主动回传时不选逻辑仓 | 阻断，提示归属依据不足，不记账 |
| 无重推弹窗 | 在入库单列表/详情查找重推 | 无重推按钮；无重推确认弹窗 |
| 推送失败展示 | 打开推送失败入库单详情 | 展示失败原因；重推须到系统集成中心 |

Demo 验证 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。**本章 Mock 仅 Demo，非正式验收。**
