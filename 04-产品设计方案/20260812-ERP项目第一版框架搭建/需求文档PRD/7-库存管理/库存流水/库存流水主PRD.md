## 一、文档概要

需求类型：新建模块（库存管理-库存流水）。

库存流水是逻辑仓库存每次变动的记录：一行一次变动，标明逻辑仓、商品、事件类型、变动明细（即时、可用、预占、冻结四组的前后与变动）、时间和来源结果单，可从流水点进对应结果单。已审核结果单按明细行记账产生流水；冻结、解冻各生成一条流水，来源单号为空，记录操作人与时间。预占的占用与释放不记流水，通过来源单据与流水关联查看。页面只查看和查询，不提供新增、编辑、删除和导入；导出按导出中心。

## 二、需求背景与范围

库存余额只能回答“现在有多少”，回答不了“这些数量是怎么来的”。业务对账、差异排查和财务交接都需要按时间回看每次变动，并定位到产生变动的那张结果单。库存流水把每次变动集中成一条条记录，与库存查询共用同一库存数据源：查询看当前余额，流水看变动过程。

| 范围 | 说明 |
| --- | --- |
| 本期要做 | 按逻辑仓、商品、时间查询库存变动流水；商品编码与条码的批量查询；展示事件类型、四组变动明细、来源单据类型与单号；从来源单号点进对应结果单；冻结、解冻生成流水；导出按导出中心 |
| 本期不做 | 流水编辑与删除、预占单独占用与释放的流水行（其变化通过来源单据与流水关联查看）、库存调整、期初导入、报表统计与图表、备注列 |
| 适用对象 | 全部逻辑仓（含已禁用逻辑仓、虚拟在途仓）与商品；虚拟在途仓的调拨在途增减同样计入流水；数量按商品基本单位，一期不做单位换算 |

## 三、方案总览与功能清单

库存流水与结果单一一对应：每张已审核结果单按明细行记账，逻辑仓库存每增加或减少一次，产生一条流水；调出、调入等一张结果单可能同时产生多条方向相反的流水，都挂在同一来源单号下。外部电商、仓库回传等来源先形成结果单，流水追溯到结果单后，再沿结果单的来源继续追溯。人工冻结、解冻也各生成一条流水，来源单据类型与来源单号为空，来源以事件类型「冻结」「解冻」表达，操作人与时间随流水留存。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 流水口径 | 库存流水记录逻辑仓库存的每次变动：已审核结果单按明细行记账时产生一条流水；冻结、解冻各生成一条流水。预占的占用与释放只改变可用量，不记入流水，预占变化通过来源单据与流水关联查看 | 《库存与仓储业务设计》§5.1、§5.3；《实体对象关系》§四；冻结、解冻与预占规则见[《预占与冻结主PRD》](../预占与冻结/预占与冻结主PRD.md)；冻结、解冻记流水为2026-09-23确认 |
| R02 | 记账依据 | 只有已审核结果单改变即时库存并产生流水；草稿、待审核结果单，以及订单、申请、通知一律不产生流水；冻结、解冻不改变即时库存，由人工操作直接产生流水 | 《实体对象关系》§八“结果单是唯一记账依据”；《单据与状态流转》§九 |
| R03 | 查询维度 | 按逻辑仓、商品、时间查询；逻辑仓、库存状态多选时按OR匹配，其他条件AND匹配；商品编码、商品条码支持批量查询（换行或逗号分隔，任一命中）；未选条件等同全部 | INV-FR01；批量查询为本模块设计，随评审确认 |
| R04 | 来源范围与事件类型 | 事件类型取值：结果单入库、结果单出库、冻结、解冻。结果单流水的来源单据类型为七类结果单：采购入库单、采退出库单、销售出库单、销退入库单、其他入库单、其他出库单、直接调拨单；外部来源（外部电商、仓库回传）经结果单继续追溯；冻结、解冻流水没有来源单据，来源单据类型与来源单号为空 | INV-FR01、INV-FR10；枚举逐字以《库存流水（详细稿）》为准；事件类型与冻结、解冻来源为2026-09-23确认 |
| R05 | 时间口径 | 变动时间取记账生效时间：结果单流水取结果单记账生效时间，冻结、解冻流水取操作生效时间，精确到秒；时间筛选按日期＋时间范围比较 | 2026-09-23确认；原型暂无 datetime-range 控件，实现时需补（见09《待改项》）；业务日期不单列 |
| R06 | 方向与数量 | 变动方向为增加或减少、变动数量为大于0的整数，用于表达结果单对即时库存的作用；冻结、解冻不改变即时库存，变动方向与变动数量留空；各数量的前后与增减按R11的变动明细四组表达 | QTY_INT；一期数量不允许小数；2026-09-23确认 |
| R07 | 排序 | 默认按变动时间倒序，最新变动在前 | 本模块定义；流水是时间序列，按发生时间倒序查看 |
| R08 | 追溯 | 来源单号可点击进入对应结果单详情；结果单详情页由各对象PRD定义，本模块只定义跳转入口；冻结、解冻流水没有来源单号，不提供跳转 | INV-AC14；结果单对象PRD另行交付 |
| R09 | 只读边界 | 查询类页面不做编辑：不提供新增、编辑、删除和导入；流水由结果单记账和冻结、解冻操作自动产生，不能手工补录或修改 | 《实体对象关系》§八 |
| R10 | 导出 | 导出按导出中心，范围可选全部／当前筛选／已勾选，异步任务；导出列与列表列一致，四组变动明细按 `前 → 后（变动）` 表达 | 《4.强盛ERP全局业务规则与约束》§五；导出中心PRD另行交付 |
| R11 | 变动明细 | 每条流水按即时库存、可用库存、预占库存、冻结库存四组记录变动前、变动数量、变动后；页面与导出按 `前 → 后（变动）` 表达（如 `100 → 90（-10）`），无变化的组显示 `x → x（0）` | 2026-09-23确认；变动数量增加为正、减少为负；预占组的变动反映该事件对预占的影响（出库消耗记负、取消/缺量释放记正）；预占的单独占用与释放不生成流水行（R01），通过来源单据与流水关联查看 |
| R12 | 冻结、解冻流水 | 冻结、解冻各生成一条流水：事件类型为「冻结」「解冻」，来源单据类型与来源单号为空（展示 `-`）；变动时间取操作生效时间，操作人取执行账号，按系统记录保留（本期列表不单列操作人）；原因随系统记录留存 | 2026-09-23确认；不产生独立单据编号（[《预占与冻结主PRD》](../预占与冻结/预占与冻结主PRD.md)R07） |

### 4.2 F01 库存流水列表

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 采购、销售、仓储运营、数据分析人员按时间回看某个逻辑仓、某个商品的库存变动过程，核对数量与来源，并查看冻结、解冻记录。 |

| 异常与恢复 | 查询无结果时展示空状态，不自动补造记录；查询失败提示后保留查询条件；结果单流水都有来源单据，来源单号异常为空的按 `-` 兜底并提示核实；冻结、解冻流水来源单号为空，按 `-` 展示。 |

### 4.5 状态与动作

库存流水是只读记录，没有审核状态和业务状态，也不发生状态流转。流水由结果单记账和冻结、解冻操作自动产生，不能手工改变。查询与导出的权限按RBAC：具备菜单与按钮权限的角色即可操作，页面文档不描述角色与数据范围（2026-09-23确认），权限规则引用[《公共能力与系统管理需求分析》](../../../../../02-需求调研和分析/08-公共能力与系统管理/公共能力与系统管理需求分析.md) COM-FR01、COM-FR02。
