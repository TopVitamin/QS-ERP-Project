# 库存管理交付清单

> 清单版本：V0.4｜更新日期：2026-09-23｜状态：初稿，待评审。

本套件覆盖库存管理一期**已起草**的十二个对象：首批为库存查询、库存流水、预占与冻结；第二批为其他入库申请单、其他入库单、其他出库申请单、其他出库单；第三批为分步式调拨单、调出通知单、调入通知单、直接调拨单（**直接调拨与分步式调拨已起草**）；第四批为库存比对（只读查询视图）。库存查询只查看和查询，并承载仓储运营手工冻结、解冻入口；库存流水按逻辑仓、商品、时间查询，能从流水点进对应结果单；预占与冻结是挂在逻辑仓库存上的数量状态，不单独成单、不单独建页面，冻结、解冻操作并入库存查询；其他出入库按上游对象划分交付四个对象（申请单与结果单各成对象、入库与出库各一份单据），申请单是两层链路的业务安排兼执行指令，结果单是实际结果并推送财务ERP；调拨按上游对象划分交付四个对象（主单、调出与调入通知单各成对象、直接调拨单一份结果单覆盖调出端与调入端），主单是业务安排，两张通知单是执行指令，直接调拨单是实际结果并推送财务ERP。业务规则以[《库存与仓储需求分析》](../../../../02-需求调研和分析/03-库存与仓储/库存与仓储需求分析.md)和[《库存与仓储业务设计》](../../../../03-业务分析和设计/03-库存与仓储业务设计.md)为准；字段与取值以`字段清单合集/库存相关`为准；状态以[《单据与状态流转》](../../系统架构和流程/03-单据与状态流转.md)为准。至此一期库存对象（十二个）全部起草完成。

## 阅读导航

| 读者 | 建议顺序 |
| --- | --- |
| 业务评审 | 库存查询主PRD的数量口径与冻结/解冻规则 → 预占与冻结主PRD的占用、消耗、释放与已定结论 → 库存流水的记录口径 → 其他入库申请单与其他出库申请单的状态、预占与取消规则 → 两个结果单的记账与推送财务ERP口径 → 分步式调拨单主PRD的预占、两端执行与自动完结 → 调出、调入通知单的一次回传与零调出、零调入规则 → 直接调拨单的四类来源与一减一增记账 → 库存比对的即时口径与差异展示 |
| 研发、测试 | 十二个主PRD的规则与验收 → 字段清单详细稿 → Demo PRD |
| 前端实现 | 页面骨架 → Demo PRD → [《原型开发说明》](../../../../09-产品原型/原型开发说明.md) |

## 本轮设计边界

### 第一批

- 库存查询是即时库存视图：每行一个「逻辑仓＋商品」，可用库存＝即时库存−预占库存−冻结库存；不提供新增、编辑、删除和导入，预占不能手工增改；0库存行默认不展示，查询区提供「展示为0的库存数据」勾选框；「预占库存」列提供「查看来源」，行内提供「查看流水」。
- 冻结、解冻由仓储运营在库存查询页行内办理，只能从可用量取；不重复冻结已预占或已冻结的部分；原因必填；一期不做异常自动冻结。预占与冻结不单独成单、不单独编号；预占占用与释放不记流水，冻结、解冻各生成一条库存流水。
- 库存流水记录结果单记账与冻结、解冻：结果单流水来源为七类已审核结果单；草稿、待审核结果单和订单、通知不产生流水；从来源单号可点进结果单；变动时间按记账生效时间，筛选按日期＋时间范围，页面与导出按四组变动明细的 `前 → 后（变动）` 表达。
- 在途仓行按普通行统计并计入流水（即时＝在途数量）；其他入库、其他出库申请单可选在途仓，调拨仓位仍按调拨规则限制；库存查询口径无特殊处理。
- 批量查询：商品编码、商品条码支持多值输入（换行或逗号分隔，任一命中）；逻辑仓、库存状态支持多选。
- 导出按导出中心，范围可选全部／当前筛选／已勾选，含变动明细；查询类不做编辑。
- 权限按RBAC，引用COM-FR01、COM-FR02，不建权限矩阵，页面文档不描述角色与数据范围。

### 第二批

- 其他出入库按上游对象划分交付四个对象：其他入库申请单、其他入库单、其他出库申请单、其他出库单；申请单与结果单各成对象，入库与出库各一份单据，不合并、不硬造第三个对象。
- 申请单是两层链路的业务安排兼执行指令：审核后由系统自动推送仓库，不再生成通知单；一期不分批、允许缺量、一次结束，余量不回补原单。
- 申请单只用一个单据状态字段（草稿、待审核、已审核、推送失败、待收货／待发货、取消中、已取消、已收货／已发货）；草稿只能删除、待审核可撤回；不提供手动关闭、不设到期自动关单，要中止只能取消；已审核未推送或明确推送失败可取消，已推送要等实际结果或仓库取消成功。
- 出库申请审核时按可用量预占；实际出库消耗对应预占并释放未出部分；零出按取消处理并释放全部预占；不允许负库存。
- 结果单由回传或仓库主动回传自动生成并自动审核；零收／零出不生成零数量结果单；超量整次拒绝；记账以结果单为准并写库存流水（口径引用第一批，不重复展开）。
- 结果单不提供新增、编辑、取消或作废；推送财务ERP失败不回滚库存，重推在系统集成中心针对原单办理，业务列表不提供重推按钮。
- 虚拟在途仓例外：其他出库申请单选在途仓时不推送仓库、由系统按确认结果直接记账；其他入库申请单不允许选在途仓。
- 其他出入库不传成本价格，存货成本由财务ERP核算；价税字段不设。
- 权限按RBAC处理：具备菜单与按钮权限的角色即可操作，按钮按权限展示，不建权限矩阵；引用COM-FR01、COM-FR02。第二批权限相关的Q见下表。

### 第三批

- 调拨按上游对象划分交付四个对象：分步式调拨单、调出通知单、调入通知单、直接调拨单；主单、两张通知单、一份结果单各成对象，不合并、不硬造第五个对象。直接调拨单是一份结果单覆盖**分步式调出端、分步式调入端、人工一步式、仓库主动回传**四类来源（前缀统一为ZJDB、菜单一个），不按调出端／调入端拆成两个对象。
- 分步式调拨单是三层链路的业务安排：审核时按计划调拨数量预占调出仓可用库存，生成调出通知单并由系统自动推送；调出、调入各一次执行、不分批；调入通知按实际调出量生成，不按原计划量提前下发；收到调入回传并生成第二张直接调拨单后主单自动完结（业务状态=已关闭，页面文案「已完结」）。
- 调出通知单、调入通知单是执行指令：复用执行指令状态机（调出用「发货」措辞、调入用「收货」措辞），创建后由系统自动推送仓库，推送失败自动重试最多3次，仍失败可人工重试；本期不增加收货／发货处理方式，不走虚拟入出库。
- 数量口径严格按《库存与仓储业务设计》§6与《单据与状态流转》§六：调拨在途＝累计实际调出−累计实际调入；实际调出必须大于0，零调出按零出取消**整张分步式调拨单**并释放未执行预占；实际调入必须大于0，零调入拒绝整次回传、通知单保持等待、不按零收取消；超量整次拒绝；不允许负库存；少收差异留在途，由人工用其他出库从在途逻辑仓扣减（业务类型取「盘亏」，2026-09-23确认），不自动抹平、不补建原单批次。
- 直接调拨单是实际结果：人工一步式走草稿→待审核→已审核，审核通过后在两个逻辑仓之间一减一增；回传与仓库主动回传路径自动生成并自动审核。直接调拨不推送仓库或其他外部执行系统、不涉及预占、不分批、无缺量；来源逻辑仓与目标逻辑仓不能相同，人工一步式不能选虚拟在途仓；来源仓已有预占时按可用量校验，可用为负即阻断（主PRD R05、Q04）。
- 在途仓边界：虚拟在途仓只用于分步式调拨在途记账，不能被调拨单、通知单或人工一步式选为出入库仓；分步式两端结果的在途仓由系统按记账口径写入，不是人工选仓（《库存与仓储业务设计》§4.2）。
- 财务ERP范围：分步式调拨主单、调出与调入通知单都不推送；实际调出、调入分别形成的直接调拨单逐单推送，人工一步式与仓库主动回传的直接调拨单同样推送。直接调拨不传成本价格，存货成本由财务ERP核算；价税字段不设。
- 权限按RBAC处理：具备菜单与按钮权限的角色即可操作，按钮按权限展示，不建权限矩阵；引用COM-FR01、COM-FR02。第三批权限相关的Q见下表。

### 第四批

- 库存比对是**只读查询视图，不成单**：无单据编号、无审核与业务状态、无状态流转；不生成任何出入库或调整单，不改库存、不推财务ERP。
- 一行＝实体仓＋商品＋库存状态；ERP侧数量＝该实体仓下同一库存状态全部逻辑仓**即时库存**之和；不含虚拟在途、不扣预占与冻结；差异数量＝ERP汇总−仓库数量（正数ERP多、负数仓库多、0无差异）；仓库数量来自库存快照。
- 每天自动比对一次，用比对时间（到秒）标识当次；本期按查询列表交付，不做看板；差异只展示，人工查明后另办业务（不自动分摊、不自动改账；INV-FR08）。
