## 2. 需求背景与目标

### 2.1 背景

其他出库申请单交给仓库执行后，需要形成实际出库结果单，作为库存减少、预占消耗和业财交接的唯一依据；仓库先完成盘亏等实际变动时，也需要一个不补申请、不补通知的入口把结果纳入ERP。申请单本身不减少库存，也不向金蝶推送。

没有统一的结果单时，实际出库数量、库存与预占的变化、财务输入无法与业务依据对齐，也无法逐单追溯每次实际出库。

### 2.2 目标

- 两类来源统一收口：其他出库申请单回传实出，或仓库主动回传已经完成的实际变动；
- 常规路径系统自动生成并自动审核；人工确认实际结果沿用INT-FR06，入口在系统集成中心，不提供无来源人工建单入口；
- 审核通过后减少对应逻辑仓即时库存，并消耗来源申请单对应的预占；没有对应预占的仓库主动回传结果不补做预占；
- 负库存阻断：处理后即时库存或可用库存将为负时，阻止本次生效并报错；
- 已审核结果逐单推送金蝶；自动重试最多3次，仍失败在系统集成中心针对原单重推；
- 整单只读：不提供新增、编辑、取消或作废；已审核后不因金蝶推送失败回滚库存与回写。

### 3.1 本期范围

- 其他出库单列表、详情（只读查看）；

## 4. 单据定位与业务边界

### 4.1 业务作用

| 项目 | 内容 |
| --- | --- |
| 单据层级 | 第3层——实际结果单（两层链路的执行结果），记录本次实际出库事实；仓库主动回传时属一层结果单（《单据分层设计》§六、§七） |
| 核心职责 | 记录实际出库多少、出哪个逻辑仓、业务类型与来源；审核后减少库存、消耗预占并推送金蝶 |
| 单据来源 | 其他出库申请单回传实出>0；或仓库主动回传（盘亏等）经校验通过 |
| 下游单据 | 无业务下游；金蝶接收已审核结果 |
| 数量关系 | 一张申请对应0或1张出库单（零出不生成）；仓库主动回传按来源拆分接收 |
| 业务终结 | 已审核为业务终态；不可取消、不可反审核；推送失败不改变已生效库存 |

### 4.2 上下游关系摘要

> 完整链路见[《系统流程与单据交互》](../../../系统架构和流程/01-系统流程与单据交互.md)第8节；本文只保留出库侧交接点。

```mermaid

    A["其他出库申请单<br/>（待发货，已预占）"] -->|"回传实出>0"| B["其他出库单<br/>（结果单）"]
    C["仓库先完成盘亏等变动"] -->|"主动回传，校验通过"| B
    B -->|"审核通过"| D["逻辑仓即时库存减少<br/>消耗对应预占<br/>写库存流水"]
    B -->|"回写"| A
    B -->|"已审核"| E["金蝶"]
```

### 4.3 业务对象关系

| 关系 | 说明 |
| --- | --- |
| 其他出库申请单 : 其他出库单 | 1:0..1；一次回传形成一张结果单，零出不生成 |
| 仓库主动回传结果 : 其他出库单 | 1:N；按来源拆分接收，保留来源系统与来源单号 |
| 出库单明细 : 来源申请行 | N:1（有来源时）；数量沿来源行回写 |
| 其他出库单 : 出库逻辑仓 | N:1；沿用来源逻辑仓（可为虚拟在途仓），仓库主动回传按确认映射识别，不重新分仓 |
| 其他出库单 : 预占 | N:1（按明细行，有来源时）；审核时消耗实出对应预占 |

### 4.4 本单据不负责的事项

- 出库单不安排仓库作业；执行指令由其他出库申请单承担，仓库主动回传的场景仓库已经完成作业；
- 出库单不修改申请单的申请数量、业务类型与仓库约定；
- 已审核后不因金蝶推送失败而回滚库存、预占消耗或删除业务结果；
- 不在原出库单上补出；未出部分在申请单侧体现缺量并释放预占，需要再出另建申请单；
- 超申请量的回传在接收侧整次拒绝，实际出库数量不超过申请数量；
- 品质调整不通过本单处理，走直接调拨（INV-FR07）；
- 不自动清理在途差异：本单只按确认数量扣减在途逻辑仓，差异是否已经处理完由调拨侧判断。

## 5. 核心业务场景索引

| 场景ID | 场景 | 类型 | 说明 |
| --- | --- | --- | --- |
| S01 | 申请回传自动生成 | 主流程 | 待发货申请回传实出>0→校验通过→生成出库单并自动审核→即时库存−、消耗实出预占、释放未出预占→回写申请单→推金蝶 |
| S02 | 申请缺量回传 | 主流程 | 实出<申请数量→按实出记账→未出在申请单侧展示并释放预占→不回补原单 |
| S03 | 申请零出 | 支线 | 不生成出库单；申请单按取消结束并释放预占；库存不变；不推金蝶 |
| S04 | 仓库主动回传（盘亏等） | 主流程 | 无原单→按来源与映射识别归属→校验通过→自动生成并自动审核→库存−→推金蝶；不补申请、不补预占 |
| S05 | 金蝶推送失败重推 | 支线 | 已审核+推送失败→自动重试最多3次→仍失败则在系统集成中心重推原单；库存与回写不回滚；本模块列表/详情无重推按钮 |
| S06 | 负库存阻断 | 异常 | 处理后即时或可用库存将为负→阻止本次生效并报错；不先记负数、不自动释放已有预占 |
| S07 | 归属依据不足 | 异常 | 无法确定记入哪个逻辑仓→保留异常、不记账、不推金蝶→修复后处理原记录 |
| S08 | 接口失败人工确认 | 支线 | 已交给仓库、接口拿不到结果→人工确认实际结果（INT-FR06）→形成出库单并提交审核；入口在系统集成中心 |
| S09 | 重复回传 | 异常 | 不重复生成单据、不重复回写、不重复消耗预占；幂等标识留接口设计 |

## 6. 状态与操作

状态定义owner：[《单据与状态流转》](../../../系统架构和流程/03-单据与状态流转.md) §四。其他出库单用**审核状态**与**金蝶推送状态**两个字段并列维护。

**一期用户界面口径**：回传或仓库主动回传生成的出库单创建即为**已审核**；列表与详情不提供新增，也不提供重推按钮。已交给仓库、接口拿不到结果时，人工确认实际结果走草稿 → 待审核，入口形态见系统集成（待集成PRD），不是本模块无来源建单。

### 6.1 状态维度

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 审核状态 | 已审核（用户可见）；草稿/待审核（模型保留，本期页面入口在系统集成中心） | 控制是否记账 |
| 金蝶推送状态 | 未推送、推送中、推送成功、推送失败 | 跟踪业财推送 |

### 6.2 状态取值说明

**审核状态**

| 状态 | 含义 | 是否终态 | 一期界面 |
| --- | --- | --- | --- |
| 已审核 | 库存已生效、来源已回写 | 是 | 可见 |
| 草稿、待审核 | 人工确认实际结果时使用 | 否 | 入口不在本模块列表；见R09 |

**金蝶推送状态**

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| 未推送 | 尚未发起推送 | 否 |
| 推送中 | 推送作业进行中 | 否 |
| 推送成功 | 金蝶已接收 | 是 |
| 推送失败 | 推送明确失败，可重推 | 否（可重试至成功） |

自动生成的出库单创建时即为已审核，金蝶推送状态从「未推送」开始。仓库回传、申请回传等系统自动生成的结果单，创建人与最后更新人显示「系统」（《6.强盛ERP的编码规则和通用字段规则》第三节）。

## 7. 核心业务规则

### 7.1 创建与来源规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 单号 | 按[《6.强盛ERP的编码规则和通用字段规则》](../../../../../01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)第一节自动生成；前缀QTCK；生成时分配 | 用户不可编辑；结果单不重用单号 |
| R02 | 来源申请单 | 有来源时必须关联一张待发货、或处于取消中且到达实际结果（申请单侧R19）的其他出库申请单；一张申请最多一张有效出库单 | 零出申请不生成；已有出库单不可重复生成 |
| R03 | 申请回传自动生成 | 仓库回传实出并结束，校验通过后系统自动生成并自动审核 | 不经人工建单或人工审核；在途逻辑仓出库按R11直接记账 |
| R04 | 仓库主动回传自动生成 | 仓库已经完成的实际变动（盘亏等）回传，商品、仓库归属、业务类型映射正常且库存校验通过后，直接生成并自动生效；不补建申请、通知，也不要求对已完成变动先做预占 | 归属依据不足时不随便选仓，保留异常（S07） |
| R09 | 人工确认 | 已交给仓库、接口拿不到结果时，可按实际发生情况确认并沿来源申请单形成出库单，走提交审核（INT-FR06） | 不能无来源新建出库单；不能用来替代虚拟出库；无原单场景的补录口径待确认（Q04） |
| — | 单头继承 | 有来源时，来源申请单、出库逻辑仓、业务类型与明细数量沿来源携带 | 用户不可改仓库、数量、业务类型 |

数量示例（标明为示例）：申请A商品100件并审核预占100，回传实出90件并结束，生成90件出库单；申请单已发货、未出10，预占消耗90并释放10。

### 7.2 数量与字段规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| — | 实际出库数量 | 各行实际出库数量＝来源申请行实出数量（有来源时）；仓库主动回传时按回传数量；不超过申请数量 | 创建后不可改；一期数量为整数，不允许小数 |
| — | 零数量 | 不允许零数量出库单 | 零出在申请单侧按取消结束，不进入本单 |
| — | 业务类型 | 沿用来源申请单的业务类型；仓库主动回传按回传类型记录 | 枚举（2026-09-23确认）：盘亏、样品领用、赠送、报废、借出；逐字以TSV为准 |
| R08 | 只读 | 出库单生成后整单只读，不提供编辑入口 | 已审核不可改任何业务字段；备注在自动回传时一般为空 |

### 7.3 回写、库存与预占规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R05 | 负库存阻断 | 结果记账前校验：处理后即时库存或可用库存将为负时，阻止本次生效并报错；不采用先记负数再处理的方案，不自动释放已有订单的预占 | INV-FR09、INV-AC09；恢复方式待确认（Q05） |
| R06 | 回写、记账与预占 | 自动审核通过时：减少对应逻辑仓即时库存、消耗来源申请对应的实出预占、释放未出预占、写库存流水；同时回写来源申请单实出与状态（已发货） | 消耗与释放不重复；没有对应预占的仓库主动回传结果不补做预占（INV-FR04）；流水口径见[《库存流水主PRD》](../库存流水/库存流水主PRD.md)R01、R02 |
| — | 缺出 | 少出部分不在出库单体现；未出在申请单侧展示并释放预占，不回补原单 | 需要再出另建申请单 |
| — | 归属 | 有原单沿用原单逻辑仓；无原单按来源信息与确认映射识别，不能只按实体仓把不同货主库存合并记账 | 《4.强盛ERP全局业务规则与约束》§一；《库存与仓储业务设计》§6.2 |
| R11 | 在途逻辑仓出库 | 出库仓为虚拟在途仓（处理分步式调拨少收差异）时，来源申请单不推送仓库，系统按确认结果直接生成已审核出库单并扣减在途逻辑仓库存；不补做预占（申请单侧R20路径） | 依据INV-FR03、INV-FR04；《库存与仓储业务设计》§4.2；本单只按确认数量记账 |

### 7.4 金蝶推送规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R07 | 推送时机 | 已审核后由系统自动逐单推送金蝶 | 申请单、草稿与未审核结果不推送；本单不传成本价格，存货成本由金蝶核算 |
| R10 | 自动重试 | 推送明确失败后系统自动重试，**最多3次**；3次仍失败则保持「推送失败」，等待在系统集成中心重推 | 间隔本期不定秒数，由技术配置 |
| R12 | 失败重推 | 在系统集成中心针对原单重试，不另建业务单；其他出库单列表/详情不提供重推按钮 | 不回滚库存、预占消耗与回写 |
| — | 业务日期 | 推送金蝶时使用；取实际出库时间的日期部分 | 列表默认按业务日期倒序（《6.强盛ERP的编码规则和通用字段规则》第三节） |
| — | 推送记录 | 记录推送时间、推送失败原因；重推成功后仍保留历史失败原因 | INT-FR03、INT-FR05 |

### 7.5 业务生效点

| 业务动作 | 出库单影响 | 库存影响 | 业财/外部影响 |
| --- | --- | --- | --- |
| 自动生成并审核 | 已审核；带入实际出库数量与来源 | 逻辑仓即时库存减少、消耗实出预占、释放未出预占、写库存流水 | 触发金蝶推送 |
| 金蝶推送成功 | 推送状态→成功 | 无额外变化 | 金蝶接收结果 |
| 金蝶推送失败 | 推送状态→失败；业务仍已审核 | 不回滚 | 自动重试3次；仍失败则在系统集成中心重推 |
| 库存校验不通过 | 保留异常，不记账 | 不减少库存、不消耗预占 | 不推送；修复后处理原记录 |

## 11. 异常与一致性

### 11.1 并发操作

| 场景 | 业务处理结果 |
| --- | --- |
| 同一申请重复回传触发生成 | 只允许一张有效出库单；重复触达幂等，不重复记账、不重复消耗预占 |
| 记账同时可用量被其他业务占用 | 以服务端最新库存为准重新校验，将为负则阻断本次记账 |
| 同一出库单同时被列表查看与推送作业触达 | 已审核为终态，审核维度不变、推送维度按R10推进 |
| 人工确认与自动回传同时到达 | 只允许一张有效结果单；先到者成立，后到者按重复处理 |

### 11.2 幂等与重复处理

| 操作 | 幂等规则 |
| --- | --- |
| 回传触发生成 | 同一来源不得重复生成出库单或重复减少库存 |
| 预占消耗与释放 | 同一部分不能既消耗又释放，也不能重复释放（《预占与冻结主PRD》R09） |
| 金蝶重推 | 同一出库单重复推送不得重复减少库存与重复回写 |
| 重复回传 | 不重复生成单据、不重复回写数量；幂等标识与部分成功恢复留接口设计（《单据分层设计》§8.5） |

### 11.3 与上下游单据一致性

| 场景 | 处理方式 |
| --- | --- |
| 申请单已有关联出库单 | 不可再自动生成 |
| 推送失败 | 库存、预占消耗与回写保持；自动重试3次；仍失败则在系统集成中心重推原单 |
| 取消中到达实际结果 | 按真实结果完成（申请单侧R19），结果单正常记账与推送 |
| 已取消后迟到回传 | 进入异常处理，修复后处理原记录 |
| 结果错误或重复 | 结果单差异不设常规业务更正流程，由技术介入或按双方线下约定处理；冲销更正规则待确认（Q02） |
