> 用途：定义ERP库存查询页展示即时、预占、冻结、可用数量的口径，以及仓储运营手工冻结、解冻的操作规则，作为研发实现和测试验收的依据。

> 不写什么：不写预占的来源单据、占用、消耗与释放规则（见[《预占与冻结主PRD》](../预占与冻结/预占与冻结主PRD.md)）；不写库存流水（见[《库存流水主PRD》](../库存流水/库存流水主PRD.md)）；不写库存比对、其他出入库、直接调拨与分步式调拨等对象；不写系统权限、接口报文与数据库设计。

库存查询是即时库存视图：每行一个「逻辑仓＋商品」，展示即时、预占、冻结和可用数量。可用库存＝即时库存−预占库存−冻结库存。预占由来源业务单据审核产生，冻结由仓储运营在库存查询页手工办理；「预占库存」列可查看产生预占的来源单据行，行内可跳转库存流水核对执行与释放，不新增独立预占明细页；每次冻结、解冻生成一条库存流水。页面只查看和查询，不提供新增、编辑、删除和导入；导出按导出中心。

## 二、需求背景与范围

采购、销售、仓储运营和数据分析都需要知道某个逻辑仓、某个商品还有多少能用。即时库存只说明ERP账上有多少实物，不能直接回答还能承诺多少；没有统一口径时，可用量会被重复承诺，或者被异常处理长期占用。库存查询把即时、预占、冻结和可用放在一处，让各业务按同一口径判断，并给仓储运营提供手工冻结、解冻的入口。

| 范围 | 说明 |
| --- | --- |
| 本期要做 | 按逻辑仓、实体仓、商品、库存状态查询库存；商品编码与条码的批量查询；展示即时、预占、冻结、可用；「展示为0的库存数据」勾选框；预占来源查看与行内跳转库存流水；仓储运营手工冻结、解冻；导出按导出中心 |
| 本期不做 | 库存编辑与手工调整、库存初始化、预占手工新增或修改、预占明细独立页面（预占来源查看走库存流水）、库存比对、库存预警与消息提醒、采购未入库数量展示 |
| 适用对象 | 全部逻辑仓（含已禁用逻辑仓的存量）与商品；虚拟在途仓按普通行统计（在途数量即即时库存）；数量按商品基本单位，一期不做单位换算 |

## 三、方案总览与功能清单

库存查询把ERP库存账上每个「逻辑仓＋商品」的即时、预占、冻结数量集中展示，可用数量按公式实时算出；仓储运营对有需要的人工控制或异常处理，直接从行内冻结可用量，处理完再解冻。预占不能在库存查询里手工增改，只能由销售、采购退货、分步式调拨、其他出库等来源单据审核产生，并按各域规则消耗或释放；预占的来源不单独建页，行内「查看来源」列出产生预占的来源单据行，并可跳到该「逻辑仓＋商品」的库存流水核对执行与释放。冻结、解冻各生成一条库存流水，操作人与时间随流水留存。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 数量口径 | 可用库存＝即时库存−预占库存−冻结库存。即时库存是ERP库存账上的实物数量；预占、冻结只锁定数量，不直接减少即时库存 | 页面按ERP账口径展示，不保证任意时刻与仓库现场实物一致；与仓库的差异比对见库存比对对象，不自动改账（INV-FR01、INV-FR08） |
| R02 | 行口径 | 每行＝逻辑仓＋商品；同一实体仓可建多个相同库存状态的逻辑仓，行不合并、不按实体仓汇总 | 采购未入库数量不记录、不展示（INV-FR01）；《库存与仓储业务设计》§5.1 |
| R03 | 数量格式 | 数量为整数，按商品基本单位展示；0是有效值按0展示，未填写展示 `-`；一期不做单位换算 | QTY_INT；《6.强盛ERP的编码规则和通用字段规则》Q16 |
| R04 | 查询规则 | 查询条件之间按AND匹配；逻辑仓、库存状态多选时按OR匹配；商品编码、商品条码支持批量查询，一次输入多个值（换行或逗号分隔），任一值命中即返回；未选条件等同全部；「展示为0的库存数据」不勾选时过滤掉即时、预占、冻结、可用均为0的行，默认不勾选 | INV-FR01；批量查询与勾选框为本模块设计（勾选框2026-09-23确认） |
| R05 | 排序 | 默认按逻辑仓编码升序，同一逻辑仓内按商品编码升序；即时、预占、冻结、可用数量列支持排序 | 本模块定义；价目表按最近更新排序，库存余额按仓、商品排序更便于核对 |
| R06 | 冻结规则 | 冻结只能从可用量中占用；冻结数量必须大于0且不超过当前可用库存；不重复冻结已经预占或已经冻结的部分；冻结原因必填；超量或非法数量阻断本次操作；每次冻结生成一条库存流水（事件类型：冻结） | INV-FR05、INV-AC05、INV-AC15；原因必填与流水记录为2026-09-23确认 |
| R07 | 解冻规则 | 解冻只能针对已冻结数量；解冻数量必须大于0且不超过当前冻结库存；解冻后这部分重新计入可用量；解冻原因必填；每次解冻生成一条库存流水（事件类型：解冻） | 《库存与仓储业务设计》§4.6、INV-AC15；原因必填与流水记录为2026-09-23确认 |
| R08 | 更新时机 | 数量随已审核结果单记账和冻结、解冻操作变化；采购订单、收货通知下发本身不增加库存；页面读取当前库存账，冻结、解冻成功后刷新当前行；冻结、解冻按记账生效时间写入库存流水 | INV-FR01；《实体对象关系》§八“结果单是唯一记账依据”；流水见[《库存流水主PRD》](../库存流水/库存流水主PRD.md) |
| R09 | 只读边界 | 查询类页面不做编辑：不提供新增、编辑、删除和导入；预占不能手工新增、修改或释放，只能由来源业务单据审核、消耗和释放；预占来源通过「查看来源」列出来源单据行并可跳转库存流水核对，不新增独立预占明细页 | 《库存与仓储需求分析》§七；《实体对象关系》§八“数量状态不是对象”；预占规则见[《预占与冻结主PRD》](../预占与冻结/预占与冻结主PRD.md)；来源查看方式为2026-09-23确认 |
| R10 | 导出 | 导出按导出中心，范围可选全部／当前筛选／已勾选，异步任务；导出列与列表列一致；空值不写入 `-` | 《4.强盛ERP全局业务规则与约束》§五；导出中心PRD另行交付 |
| R11 | 预占来源查看 | 「预占库存」列提供「查看来源」入口，列出产生该行预占的来源单据行（来源单号、行号）；来源单据行可跳转该「逻辑仓＋商品」的库存流水，核对预占的执行与释放；不新增独立预占明细页 | 2026-09-23确认；占用、消耗与释放规则见[《预占与冻结主PRD》](../预占与冻结/预占与冻结主PRD.md)F01、F02；流水口径见[《库存流水主PRD》](../库存流水/库存流水主PRD.md) |
| R12 | 跳转库存流水 | 行内「查看流水」以当前行逻辑仓、商品为必要条件，连同查询区已选条件（所属实体仓、库存状态等）跳转库存流水查询页并预填 | 一期提供（2026-09-23确认）；库存流水页面见[《库存流水主PRD》](../库存流水/库存流水主PRD.md) |

### 4.2 F01 库存查询列表

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 采购、销售、仓储运营、数据分析人员查询某个逻辑仓、某个商品还有多少即时、预占、冻结和可用数量。 |
| 操作与处理 | 按逻辑仓、所属实体仓、商品编码、商品名称、商品条码、库存状态查询；商品编码和条码可批量输入多个值；查询区提供「展示为0的库存数据」勾选框，默认不勾选；列表默认按逻辑仓编码、商品编码升序；数量列可排序；预占库存列提供「查看来源」，行内提供「查看流水」；导出按导出中心。 |
| 功能规则 | 可用库存按R01实时计算；0库存行默认不展示，勾选「展示为0的库存数据」后展示；已禁用逻辑仓仍可查询存量（禁用只影响新单选用，不阻断既有库存业务）；已禁用逻辑仓的存量行只要有库存就可以冻结、解冻（按自身库存状态与可用量校验）；虚拟在途仓按普通行统计：即时＝在途数量，预占、冻结按实际，可用＝即时−预占−冻结，行内冻结、解冻按普通行校验；其他入库、其他出库申请单可选虚拟在途仓，调拨仓位仍按调拨规则限制；库存统计侧不做特殊口径；预占来源查看见R11，跳转流水见R12；页面不提供库存调整入口。 |
| 成功结果 | 列表返回匹配的「逻辑仓＋商品」行，展示即时、预占、冻结、可用和最后更新时间；有预占的行可查看来源单据行，并可跳转该仓＋商品的库存流水。 |
| 异常与恢复 | 查询无结果时展示空状态，不自动创建库存记录；查询失败提示后保留查询条件；数量为0按0展示，不展示为 `-`；0库存行在勾选后按0展示，不展示为 `-`。 |

### 4.3 F02 冻结

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 仓储运营对某部分库存做人工控制或异常处理，需要暂时限制这部分数量被业务占用。 |
| 操作与处理 | 在库存查询行内点「冻结」打开冻结弹窗；弹窗展示当前可用库存和冻结库存，录入冻结数量和冻结原因（必填）；确认后冻结即时生效，可用库存减少、冻结库存增加，即时库存和预占库存不变。 |
| 功能规则 | 冻结只能从可用量中取（R06）；冻结数量大于0且不超过当前可用库存；不重复冻结已预占或已冻结的部分；原因必填；一期由仓储运营手工办理，不做异常自动冻结；每次冻结生成一条库存流水。 |
| 成功结果 | 该行冻结库存增加、可用库存减少；冻结原因按输入保留；本次操作生成一条冻结流水（事件类型：冻结，来源单号为空，记录操作人与时间，见[《库存流水主PRD》](../库存流水/库存流水主PRD.md)R01、R04）。 |
| 异常与恢复 | 冻结数量为空、为0、为负或超过当前可用库存时阻断并提示，库存不变；并发下可用量已被其他操作占用时按最新可用量重新校验，不通过则阻断（不记负数）；以服务端最新可用量为准，重复提交同一入参不得二次增减。 |

### 4.4 F03 解冻

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 人工控制或异常处理结束后，仓储运营恢复被冻结数量的使用。 |
| 操作与处理 | 在库存查询行内点「解冻」打开解冻弹窗；弹窗展示当前冻结库存和可用库存，录入解冻数量和原因（必填）；确认后解冻即时生效，冻结库存减少、可用库存增加。 |
| 功能规则 | 解冻数量大于0且不超过当前冻结库存（R07）；解冻后这部分重新计入可用量，可被正常业务占用；原因必填；每次解冻生成一条库存流水。 |
| 成功结果 | 该行冻结库存减少、可用库存增加；解冻原因按输入保留；本次操作生成一条解冻流水（事件类型：解冻，来源单号为空，记录操作人与时间，见[《库存流水主PRD》](../库存流水/库存流水主PRD.md)R01、R04）。 |
| 异常与恢复 | 解冻数量为空、为0、为负或超过当前冻结库存时阻断并提示，库存不变；并发下按最新冻结量与可用量重新校验，不通过则阻断；以服务端最新冻结量为准，重复提交同一入参不得二次增减。 |

### 4.5 状态与动作

库存查询是即时视图，没有审核状态和业务状态，也不发生状态流转。预占与冻结都是挂在逻辑仓库存上的数量状态，不单独成单（《实体对象关系》§八）；冻结、解冻是即时操作，操作成功后立即改变可用库存，不产生独立单据编号；每次冻结、解冻生成一条库存流水（见[《库存流水主PRD》](../库存流水/库存流水主PRD.md)），操作人、操作时间与原因随流水和系统记录留存（《4.强盛ERP全局业务规则与约束》§五“必要处理记录必须保留”）。

能不能执行查询、导出、冻结和解冻按RBAC：具备菜单与按钮权限的角色即可操作，没有对应权限时界面不展示该操作；页面文档不描述角色与数据范围（2026-09-23确认）；权限不替代业务校验，可用量不足、数量非法仍然阻断（《单据与状态流转》§八）。权限规则引用[《公共能力与系统管理需求分析》](../../../../../02-需求调研和分析/08-公共能力与系统管理/公共能力与系统管理需求分析.md) COM-FR01、COM-FR02。
