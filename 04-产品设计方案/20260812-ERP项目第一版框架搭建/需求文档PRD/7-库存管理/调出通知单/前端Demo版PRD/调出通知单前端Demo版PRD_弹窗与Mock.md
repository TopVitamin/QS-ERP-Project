### 1.1 本模块不提供的弹窗

本期不提供以下弹窗：

| 弹窗 | 说明 |
| :--- | :--- |
| 新增 / 编辑弹窗 | 通知单由主单审核后系统自动生成，本模块无新增、编辑入口（主PRD §3.4） |
| 手工推送确认框 | 创建后由系统自动推送，不提供人工触发推送（主PRD R03） |
| 补发确认框 | 已发货为终态，不往原通知补发；需要再调拨另建主单（主PRD R04） |
| 主单取消联动确认框 | 取消成功后主单如何收口待确认（主PRD Q03），本模块不提供联动主单的取消确认 |
| 手工调整预占 | 预占不能手工增改，只能由审核占用、实出消耗、未发与取消释放（[《预占与冻结主PRD》](../../预占与冻结/预占与冻结主PRD.md) §二） |

自动重试（正式环境）：推送明确失败后系统自动重试，**最多3次**；间隔由技术配置。3次仍失败则保持「推送失败」，可人工重试（F07）。

```
调出通知单列表 / 详情
         │
    用户查找重试入口
         │
         ▼
   单据状态=推送失败？
   ├─否─> 无重试按钮（推送中/取消中/终态）
   └─是─> [重试推送] → 确认弹窗 → 推送中
```

## 2. 确认弹窗

### 2.1 取消（待推送/推送失败）

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 列表或详情「取消」（待推送；或推送失败且已确认仓库未接收） |
| 标题 | 取消调出通知单 |
| 正文 | 取消后本单不再执行，不可撤销；未执行部分的预占在取消成功后释放。推送失败时请先确认仓库未接收。 |
| 表单 | 取消原因（必填，`REMARK_500`） |
| 主按钮 | 确认取消 |
| 次按钮 | 取消 |
| 失败处理 | 推送结果不确定时阻断并提示「请先核实仓库是否已接收，再决定取消或重试」 |

### 2.2 取消（待发货）

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 列表或详情「取消」（待发货） |
| 标题 | 取消调出通知单 |
| 正文 | 调出仓已接收本指令，取消需等待仓库回执，不能单方面认定；取消中仍会处理到达的实际调出结果。 |
| 表单 | 取消原因（必填，`REMARK_500`） |
| 主按钮 | 确认取消 |
| 次按钮 | 取消 |
| 结果 | 单据状态→取消中；仓库同意→已取消并释放未执行预占；仓库拒绝→恢复待发货 |

### 2.3 重试推送

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 列表或详情「重试推送」（推送失败） |
| 标题 | 重试推送调出仓 |
| 正文 | 将对本通知单重新发送调出仓，不重新审核、不重复预占。发送结果不确定时请先核实仓库是否已接收。 |
| 主按钮 | 确认重试 |
| 次按钮 | 取消 |
| 结果 | 单据状态→推送中；推送失败原因保留历史 |

## 3. Demo Mock：调出仓回传实出（F08）

### 3.1 正式规则（必读）

正式环境中，调出仓执行一次调出并回传实际调出数量：实出必须大于0且不超过通知调出数量，超量整次拒绝；校验通过后通知变为已发货，系统生成调出端直接调拨单（调出仓减、在途加），消耗实出对应预占、释放未发部分，并按实际调出量生成调入通知单推送接收仓。实出为0时，来源分步式调拨单按零出取消，本通知单按取消结束，不生成后续单据。

本节 Mock **仅用于 Demo 原型串联展示**，不属于主PRD AC01～AC13 的正式验收项（主PRD F08）。

### 3.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 调出通知单详情（待发货）「模拟仓库回传(Mock)」 | 打开 §3.3 弹窗，录入实际调出数量；确认后按 §3.4 本地生成 |
| 分步式调拨单详情的调出仓回传 Mock | 由主单侧统一触发，本模块不重复定义（见[《分步式调拨单前端Demo版PRD_弹窗与Mock》](../../分步式调拨单/前端Demo版PRD/分步式调拨单前端Demo版PRD_弹窗与Mock.md) §3） |

```
调出通知单详情（待发货）
      │
  Mock 回传
      │
      ▼
 实出 >0 ？ ──否──> 主单按零出取消
      │              本通知单已取消，不生成后续单据
      是
      ▼
 实出 ≤ 通知调出数量 ？ ──否──> 整次拒绝，提示超量
      │
      是
      ▼
 §3.4 本地生成
 通知单已发货
 调出端直接调拨单（已审核）
 调出仓 −90、在途 +90
 调入通知单（待收货）
```

### 3.3 引导弹窗

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 模拟仓库回传（Demo） |
| 正文 | 按实际调出数量生成演示用调出端直接调拨单与调入通知单；正式流程以仓库回传为准。 |
| 表单项 | 实际调出数量 |
| 主按钮 | 确认回传 |
| 次按钮 | 取消 |
| 关闭图标 | 关闭后不生成任何数据 |

### 3.4 生成规则（本地 Mock）

| 项目 | Mock 规则 |
| :--- | :--- |
| 生成条件 | 通知单处于待发货；实际调出为正整数、大于0、不超过通知调出数量 |
| 通知单 | 单据状态=已发货；回写实际调出与未发数量；最终发货确认时间=当前时间 |
| 调出端直接调拨单 | 来源类型=分步式调出端；来源逻辑仓=调出仓；目标逻辑仓=虚拟在途仓；审核状态=已审核；金蝶推送状态从未推送开始 |
| 库存与预占 | 调出仓即时库存减、在途加；写两条库存流水；消耗实出预占、释放未发预占（Demo 可在库存查询页核对） |
| 回写主单 | 主单累计实际调出、未调出数量与在途数量更新 |
| 调入通知单 | 按实际调出量生成，状态=待收货 |
| 单号 | 调出端结果按 ZJDB、调入通知按 DRTZ 编码规则生成 fictitious 编号 |
| 超量分支 | 实出大于通知调出数量时：整次拒绝并提示「回传数量超过通知数量，已整次拒绝」；不记账、不生成单据 |
| 零调出分支 | 实出=0时：主单业务状态=已取消、本通知单=已取消；不生成后续单据、不改变库存、释放未执行预占 |
| 负库存分支 | 记账后调出仓即时或可用库存将为负时：阻断并提示「库存不足，不允许负库存」 |

界面标注「演示数据」或「Mock」角标，与正式回传生成的结果单区分。

### 3.5 不做的事

- 不代替正式接口校验与映射
- 不在 Mock 中自动执行金蝶正式推送
- 不在 Mock 中制造负库存
- 不生成零数量的结果单

## 4. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| Mock 回传（发足） | 通知100件，Mock 回传100 | 通知单已发货、未发0；生成调出端直接调拨单与调入通知单 |
| Mock 回传（少发） | 通知100件，Mock 回传90 | 通知单已发货、未发10；消耗预占90、释放10 |
| Mock 回传（零调出） | Mock 回传0 | 主单已取消、通知单已取消；不生成后续单据、不改变库存 |
| Mock 超量 | Mock 回传110（通知100） | 整次拒绝并提示；不记账、不生成单据 |
| Mock 负库存 | 回传数量超过调出仓可用 | 阻断并提示不允许负库存 |
| 无新增/编辑弹窗 | 在列表与详情查找新增、编辑入口 | 无入口、无对应弹窗 |
| 重试入口 | 推送失败单 | 展示「重试推送」；确认后状态=推送中 |
| 无取消入口 | 推送中、取消中、已发货、已取消单 | 无取消按钮、无取消弹窗 |

Demo 验证 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。**本章 Mock 仅 Demo，非正式验收。**
