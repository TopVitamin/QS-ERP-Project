预占与冻结是挂在逻辑仓库存上的数量状态，不单独成单（《实体对象关系》§八），也不单独建页面：预占由来源业务单据审核时产生，冻结、解冻由仓储运营在库存查询页手工办理；预占的来源在库存查询「查看来源」中查看，并可跳转库存流水核对，不新增独立预占明细页；每次冻结、解冻生成一条库存流水。本PRD定义这两个数量状态的模型与规则，页面、字段和弹窗见《库存查询主PRD》与字段清单。

## 二、需求背景与范围

即时库存说明账上有多少实物，但不能直接承诺给业务：同一批货可能同时被多张订单、退货或多笔调拨看中，先承诺的没有锁住数量，后面的就会超卖。预占解决正常出库业务的预留：审核时占住可用量，实际出库时消耗对应部分；冻结解决人工控制和异常处理：仓储运营把暂时不能动的数量锁住，处理完再解冻。两者都只限制可用量，不减少即时库存；预占的占用与释放不记流水，冻结、解冻各生成一条库存流水。

| 范围 | 说明 |
| --- | --- |
| 本期要做 | 预占的来源清单与占用时机；预占的消耗与释放；手工冻结、解冻；可用库存公式；负库存阻断；跨模块校验接口点 |
| 本期不做 | 异常自动冻结、按正常品／待检品／残次品限制业务用途、品质处理期间的临时冻结、手工新增或修改预占、预占与冻结的独立单据、独立页面与报表；预占来源查看走库存查询「查看来源」与库存流水，不新增独立预占明细页 |
| 适用对象 | 采购退货、B2B销售、独立站、分步式调拨、其他出库等产生预占的业务；全部逻辑仓库存的出库与冻结校验；一期不区分库存状态限制用途（INV-FR05） |

## 三、方案总览与功能清单

预占和冻结共同维护“可用量不能重复承诺”：可用库存＝即时库存−预占库存−冻结库存，任何会减少可用量的动作（审核占库、冻结、结果记账）都要先校验，处理后会变成负数的一律阻止。预占随来源业务的执行而消耗，随取消、关闭或执行结束按所属业务规则释放；释放和消耗不能重复扣减。

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 可用库存公式 | 可用库存＝即时库存−预占库存−冻结库存；预占、冻结只锁定数量，不直接减少即时库存 | INV-FR01；《4.强盛ERP全局业务规则与约束》§二 |
| R02 | 不重复锁定 | 已经预占或已经冻结的数量不能被再次冻结，也不能被另一笔业务再次预占；冻结只能使用剩余可用量 | INV-FR05、INV-AC05 |
| R03 | 通知不重复占库 | 订单、退货单审核时占用可用量；下游通知下发不再次占库，推送失败、等待执行、取消中都不提前释放 | INV-FR05；《单据与状态流转》§六 |
| R04 | 仓库已完成结果不补预占 | 仓库主动回传、外部ToC已经完成的实际结果，经商品、归属和库存校验后直接记账，不补做事前预占 | INV-FR04；SAL-FR09 |
| R05 | 直接调拨不涉及预占 | 直接调拨单只在ERP内部一减一增，不预占、不分批；分步式调拨审核时预占调出仓 | INV-FR07、INV-FR03 |
| R06 | 一期不按库存状态限制用途 | 只要有足够的可用库存，就允许办理相应出库；不额外设置品质处理期间的临时冻结 | INV-FR05；《库存与仓储业务设计》§6.3 |
| R07 | 数量状态不是单据 | 预占、冻结挂在具体逻辑仓库存上，不单独成单、不单独编号；冻结、解冻是即时操作 | 《实体对象关系》§八；《库存与仓储业务设计》§5.2 |
| R08 | 校验时机 | 审核预占、冻结、结果记账三个时点统一校验；处理后即时库存或可用库存为负时，阻止本次生效并报错，不先记负数 | INV-FR09、INV-AC09 |
| R09 | 消耗与释放不重复 | 实际出库消耗对应预占，取消、关闭或执行结束释放未执行部分；同一部分不能既消耗又释放，也不能重复释放 | 《单据与状态流转》§六示例（1,000−580 不能算成420） |
| R10 | 冻结不做异常自动处理 | 一期由仓储运营手工冻结、解冻，不做异常自动冻结；冻结、解冻不改变即时库存和预占库存，每次冻结、解冻生成一条库存流水（事件类型：冻结、解冻） | INV-FR05；[《库存流水主PRD》](../库存流水/库存流水主PRD.md)R01、R12；冻结、解冻记流水为2026-09-23确认 |
| R11 | 切换期初始化 | 上线切换时不初始化冻结与预占：期初冻结、预占为0，切换后从0开始累计；期初数量、截点与迁移随上线切换方案另行实施 | 2026-09-23确认；INV-FR02；与《库存查询主PRD》§七上线准备同一批 |

### 4.2 F01 预占占用

来源业务在审核时按可用量占用对应逻辑仓库存；可用不足时不能审核占库（INV-FR05）。占用对象是「逻辑仓＋商品」上的预占数量，占用结果跟随来源单据，直到消耗或释放。

| 来源业务 | 占用时机与对象 | 依据 |
| --- | --- | --- |
| B2B销售订单 | 审核通过时按整单占用发货仓可用量 | SAL-FR03；《单据与状态流转》§二 |
| 独立站订单 | 审核时占库，整单履约、不拆单缺量发货 | SAL-FR07、SAL-FR08 |
| 采购退货单 | 审核通过时占用退货出库仓可用量；关联原入库的退货仍受原入库数量控制 | PUR-FR04；《单据与状态流转》§二 |
| 分步式调拨单 | 审核通过时预占调出仓库存 | INV-FR03 |
| 其他出库申请单 | 审核通过时预占；其他入库申请不占库 | INV-FR06 |

### 4.3 F02 预占消耗与释放

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 来源业务实际出库、取消、关闭或执行结束时，处理已占用的预占。 |
| 操作与处理 | 实际出库时，即时库存和该业务对应的预占同时扣减，页面展示的可用量同步反映预占消耗；取消、关闭、执行结束时，按所属业务规则释放未执行部分；其他出库缺量时消耗实际数量并释放差额。 |
| 功能规则 | 计算时要同步反映对应预占的消耗，不能把正常已经预占的出库误判成库存不足；没有对应预占的结果（如盘亏）不能自动挪用其他订单的预占；消耗与释放不重复（R09）。 |
| 成功结果 | 即时库存和预占按实际结果同减；未执行部分恢复可用量。 |
| 异常与恢复 | 记账结果为负时按R08阻止，不自动释放已有预占（INV-AC09）；结果错误或重复的冲销更正规则仍在待确认范围（《库存与仓储业务设计》§七）。 |

示例（标明为示例）：某销售订单审核预占95；即时库存100，可用5。实际出库95时，即时减95、预占消耗95，结果即时5、预占0、可用5；不能按“预占95没释放”再报库存不足。订单再取消时不产生释放，因为预占已经消耗完。

业务效果对照表：

| 业务 | 消耗时机 | 释放时机 |
| --- | --- | --- |
| B2B销售 | 销售出库单审核记账 | 订单关闭释放未安排部分；取消按销售规则释放 |
| 独立站 | 销售出库单审核记账 | 整单零执行按取消释放；取消审核按销售规则处理 |
| 采购退货 | 采退出库单审核记账 | 退货单关闭释放未下推部分；取消按采购规则释放 |
| 分步式调拨 | 调出端直接调拨单记账（消耗实出、释放未发） | 零调出按取消释放未执行预占 |
| 其他出库 | 其他出库单审核记账（实出部分） | 缺量差额释放；未推送取消直接释放，已推送等实际结果或仓库取消成功 |

### 4.4 F03 冻结

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 仓储运营对某部分库存做人工控制或异常处理，暂时限制这部分数量被业务占用。 |
| 操作与处理 | 在库存查询页行内点「冻结」打开弹窗，录入冻结数量和原因（必填）；确认后冻结即时生效，可用库存减少、冻结库存增加。 |
| 功能规则 | 冻结只能从可用量中取，数量必须大于0且不超过当前可用库存；不重复冻结已预占或已冻结的部分（R02）；原因必填；一期由仓储运营手工办理，不做异常自动冻结；每次冻结生成一条库存流水。 |
| 成功结果 | 冻结库存增加、可用库存减少；即时库存、预占库存不变；生成一条冻结流水（事件类型：冻结，来源单号为空，记录操作人与时间）。 |
| 异常与恢复 | 超量或非法数量阻断并提示，库存不变；并发下按最新可用量重新校验，不通过则阻断。 |

示例（标明为示例）：即时100、预占60、冻结10时，可用30，最多还能新增冻结30；再冻31被阻止（INV-AC05）。

### 4.5 F04 解冻

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 人工控制或异常处理结束后，恢复被冻结数量的使用。 |
| 操作与处理 | 在库存查询页行内点「解冻」打开弹窗，录入解冻数量和原因（必填）；确认后冻结库存减少、可用库存增加。 |
| 功能规则 | 解冻数量必须大于0且不超过当前冻结库存；解冻后这部分重新计入可用量，可被正常业务占用；原因必填；每次解冻生成一条库存流水。 |
| 成功结果 | 冻结库存减少、可用库存增加；即时库存、预占库存不变；生成一条解冻流水（事件类型：解冻，来源单号为空，记录操作人与时间）。 |
| 异常与恢复 | 超量或非法数量阻断并提示，库存不变。 |

### 4.6 F05 负库存阻断

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 审核预占、冻结，以及结果记账时统一做库存校验。 |
| 操作与处理 | 处理后即时库存或可用库存将会为负时，本次操作不生效并报错；提示按业务场景给出原因（可用不足、超量等）。 |
| 功能规则 | 不允许出现负库存，不采用先记负数再处理的方案；不自动释放已有订单的预占，不自动挪用在途或其他订单的预占。 |
| 成功结果 | 操作被阻止，库存、预占、冻结保持不变，异常原因可由业务人员查明后另行处理。 |
| 异常与恢复 | 恢复方式待详细设计（INV-FR09“异常修复和重新处理的方式，待详细设计”）；外部ToC异常继续引用SAL-FR12。 |

示例（标明为示例）：即时100、预占95，收到盘亏10后，如果记账会变成即时90、可用−5，此时必须阻止，不自动释放已有订单的预占（INV-AC09）。

### 4.7 状态与动作

预占与冻结没有审核状态和业务状态，不参与状态流转；预占数量由来源单据的占用、消耗、释放规则驱动，冻结与解冻是即时操作，各生成一条库存流水。能不能执行冻结、解冻按RBAC：具备菜单与按钮权限的角色即可操作，没有对应权限时界面不展示该操作，页面文档不描述角色与数据范围（2026-09-23确认），权限不替代数量校验（《单据与状态流转》§八）；权限规则引用COM-FR01、COM-FR02。
