# 系统集成交付清单

> 清单版本：V0.1｜更新日期：2026-09-24｜状态：初稿，待评审。
>
> 本套件覆盖系统集成一期两个页面：**业财结果单据**和**推送异常**。业财结果单据展示七类已审核结果单的推送财务ERP情况，推送失败可针对原单重推，推送成功后异常由技术运维重新推送；推送异常按推送对象分五个页签（推送财务ERP、推送外部仓库、推送电商平台、主数据分发、结果处理）集中查看外部推送失败与结果处理失败，含必要的处理记录。业务规则以[《系统集成需求分析》](../../../../02-需求调研和分析/07-系统集成/系统集成需求分析.md)和[《集成协作与人工补充》](../../../../03-业务分析和设计/07-集成协作与人工补充.md)为准；字段与取值以`字段清单合集/集成相关`为准；状态以[《单据与状态流转》](../../系统架构和流程/03-单据与状态流转.md)§四和[《单据分层设计》](../../../../01-全局背景信息/5.强盛ERP的单据分层设计.md)为准。

## 本轮范围决定（2026-09-24）

系统集成菜单按使用需要收口为两个页面；本轮调整已确认，相关上游文档同步见“上游同步清单”：

| 事项 | 决定 | 说明 |
| --- | --- | --- |
| 人工补充页 | 去掉；人工确认入口回到各业务单据页面 | 接口拿不到接单、执行结束或取消结果时，在通知单、申请单详情页人工确认，原型用Mock模拟回传；Shopify未覆盖订单导入归独立站订单页面；无原单补录一期不做页面入口，接口失败先线下兜底；不再由系统集成中心统一承接 |
| 外部映射页 | 去掉；映射在基础资料维护 | 商品映射在商品资料模块的独立页面按「平台＋店铺」维护多条外部编码，修改权限按角色；仓库映射（对接方式／系统、第三方仓库编码、货主标识）随实体仓创建、编辑维护；不单独设系统集成-外部映射页 |
| 推送异常 | 按推送对象分页签 | 推送财务ERP、推送外部仓库、推送电商平台、主数据分发、结果处理；财务ERP失败可跳转业财结果单据重推，本页不重复入口 |

保留的**人工确认业务规则**（谁确认、确认什么、不能替代虚拟入出库、不能无来源新建采购入库单）继续以[《系统集成需求分析》](../../../../02-需求调研和分析/07-系统集成/系统集成需求分析.md) INT-FR06 和[《集成协作与人工补充》](../../../../03-业务分析和设计/07-集成协作与人工补充.md)§4.4为准；各业务单据页面的人工确认交互随对应模块PRD下一轮修订补充。

## 本轮设计边界

### 业财结果单据

- 页面是推送财务ERP结果的查看口和重推口，不是改单口：不修改原单业务信息，不展示财务ERP单号，不另建业务单（主PRD R01）。
- 数据范围为七类已审核结果单；草稿、待审核结果单与订单、申请、通知、调拨主单不进入本页（R02）。
- 推送明确失败后自动重试最多3次，间隔由技术配置；仍失败保持推送失败，行内出现「重推」（R03、R04）。
- 推送成功后异常由技术运维执行「异常运维重推」，先财务ERP删单、再重推原单；权限与操作方式随运维方案（R05、Q02）。
- 推送记录保留每次推送的时间、结果、原因、触发方式与操作人；一期不做完整操作日志，推送记录必须保留（R06）。

### 推送异常

- 页面只读：不重试、不取消、不改单、不维护映射、不人工关闭异常；重试与修复在各自入口办理（R01、R06）。
- 五个页签按推送对象拆分；切换页签回到第一页、清空勾选，查询区与列表列随页签切换（R03）。
- 处理状态只有待处理、已处理：重试成功、原单取消或修复后原记录处理成功时自动置为已处理，保留记录可查（R04）。
- 处理记录保留处理时间、处理方式（系统自动重试／人工重试／重推／修复恢复）、处理结果、操作人与说明（R05）。
- 推送财务ERP页签与业财结果单据同源：可看处理记录、可跳转重推，不在本页重复重推入口（F01、F04）。

## 已定结论与后续事项

| 事项 | 结论与处理 |
| --- | --- |
| 人工确认入口 | 已改（2026-09-24）：入口回到各业务单据页面，在通知单、申请单详情页提供「人工确认」，原型用Mock模拟回传；Shopify未覆盖订单导入归独立站订单页面；无原单补录一期不做页面入口，接口失败先线下兜底；人工确认规则不变。上游同步见下表 |
| 外部映射维护位置 | 已定（2026-09-24）：在基础资料维护；商品映射在商品资料模块的独立页面按「平台＋店铺」维护多条外部编码，修改权限按角色；仓库映射与货主标识随实体仓创建、编辑维护；不设系统集成-外部映射页 |
| 推送异常页签划分 | 已定（2026-09-24）：推送财务ERP、推送外部仓库、推送电商平台、主数据分发、结果处理 |
| 财务ERP失败重推入口 | 已定：统一在业财结果单据；推送异常页签只跳转，不重复入口；重推与异常运维重推按角色权限控制（RBAC） |
| 自动重试次数 | 已定（2026-09-24）：仓库推送（通知单、申请单、独立站订单）、推送财务ERP、电商平台回写、主数据分发均为最多3次，间隔由技术配置 |
| 记录保留与人工关闭 | 已定（2026-09-24）：推送记录与异常记录全部保留、不清理；一期不做人工关闭，只按重试成功、原单取消、原记录处理成功自动置「已处理」 |
| 电商平台回写范围 | 已定（2026-09-24）：一期发货结果与运单、取消结果；退货回写等接口确认后再加 |
| 主数据分发范围 | 已定（2026-09-24）：商品SKU分发到第三方仓／WMS、金蝶云·星空、聚水潭、领星 |
| 结果处理异常恢复 | 已定（2026-09-24）：修复基础数据后由系统按接口机制自动重试处理原记录；技术运维只处理接口与数据问题；本页保持只读 |
| 财务ERP返回内容 | 已定（2026-09-24）：推送记录记录财务ERP返回内容（错误码、报文摘要等），字段随接口设计扩展 |
| 财务ERP接口成功判定、失败原因与报文协议 | 待接口设计（业财结果单据Q01）；本期先用Mock表达流程 |
| 初始化与历史切换 | 已定（2026-09-24）：暂不纳入本模块方案，后续需要时另议 |
| 原型实现差异 | 09原型已接入两个页面（2026-09-24）；实现差异、演示造数与边界登记09《待改项》，不用原型替代业务规则 |
