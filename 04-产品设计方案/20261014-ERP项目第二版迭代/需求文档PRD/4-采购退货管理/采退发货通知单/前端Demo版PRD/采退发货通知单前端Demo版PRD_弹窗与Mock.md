## 2. 取消通知单（F05）

**触发入口**：列表、详情「取消」；可用条件为**待推送**或**推送失败**（主 PRD §6.4）。

```
列表 / 详情
     │
点「取消」（待推送 / 推送失败）
     ▼
┌──────────────────────────────────────────┐
│  取消采退发货通知单                  [×] │
│  取消后通知不再执行，不可撤销…           │
│  推送失败时追加：请确认仓库尚未接收…     │
│  取消原因* [多行文本]                    │
│                    [取消] [确认取消]      │
└──────────────────────────────────────────┘
         │ 取消              │ 确认
         ▼                   ▼
    关闭弹窗，停留      已取消 + 释放占用
                        Toast「已取消」
```

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 取消采退发货通知单 |
| 正文 | 取消后通知不再执行，不可撤销，并释放退货单可下推量。 |
| 推送失败补充 | 推送失败时追加：「请确认仓库尚未接收本通知。」 |
| 必填项 | 取消原因（多行） |
| 确认按钮 | 确认取消 |
| 取消按钮 | 取消 |
| 确认后 | 单据状态→已取消；记录取消原因、取消时间、取消操作人；释放全部通知占用；采购退货单仍开放则回补可下推量，已关闭则不恢复下推资格（R08）；Toast「采退发货通知单已取消」 |

```
列表 / 详情
     │
点「取消」（待发货）
     ▼
┌──────────────────────────────────────────┐

│  取消原因* [多行文本]                    │
│                    [取消] [确认取消]      │

                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              仓库同意              仓库拒绝
              已取消                待发货
```

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 取消采退发货通知单 |
| 正文 | 单据已推送仓库，取消需等待仓库回执。取消期间通知仍占用退货单可下推量。 |
| 必填项 | 取消原因（多行） |
| 确认按钮 | 确认取消 |

| 回执 | 结果状态 | 提示 |
| :--- | :--- | :--- |
| 仓库同意 | 已取消 | 采退发货通知单已取消 |
| 仓库拒绝 | 待发货 | 仓库拒绝取消，请继续等待发货 |

## 4. 重试推送（F07）

**触发入口**：列表、详情「重试推送」；可用条件为**推送失败**（主 PRD §6.4）；正式环境须已自动重试满3次仍失败（R14）。

```
列表 / 详情
     │
点「重试推送」（推送失败）
     ▼
┌──────────────────────────────────────────┐
│  重试推送仓库                        [×] │
│  将重新向仓库发送本通知，请确认失败原因已处理。│
│                    [取消] [确认重试]      │
└──────────────────────────────────────────┘
         │ 取消              │ 确认
         ▼                   ▼
    关闭弹窗，停留      推送中 + Toast
                        「已重新推送仓库」
```

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 重试推送仓库 |
| 正文 | 将重新向仓库发送本通知，请确认失败原因已处理。 |
| 必填项 | 无 |
| 确认按钮 | 确认重试 |
| 取消按钮 | 取消 |
| 确认后 | 单据状态→推送中；Toast「已重新推送仓库」 |

正式环境：推送明确失败后系统自动重试，**最多3次**；3次仍失败才保持「推送失败」并出现本按钮。间隔本期不定秒数，由技术配置。Demo 可直接把单据置于推送失败，便于演示人工重试，不模拟间隔。

**推送失败去向（二版补充）**：推送失败不回滚业务，通知仍占用退货单额度。失败记录在系统集成中心「推送异常－推送外部仓库」页签只读展示（原单、推送状态、失败原因与必要的处理记录），页签本身不提供重试；修复后回到本通知重试推送（F07），不另建通知（INT-FR05）。

## 5. Demo Mock：模拟仓库出库回传（F08）

### 5.1 正式规则

正式环境中，仓库通过WMS接口回传实出数量与结束标记；零出按 PUR-FR04 取消通知，不生成采退出库单；有实出则由系统生成采退出库单并自动审核、扣减库存并消耗预占。自营仓由 ERP 直连作业系统；**电商仓经聚水潭（国内）、领星（跨境）中转**，SaaS 把通知原样转达其对接仓库、把结果原样回传，仍只执行一次退货出库，不额外创建执行（02/07 §五）。重复回传按「来源系统＋来源单号＋执行标识」识别，已成功处理的不重复记账。

本节 Mock **仅用于 Demo 原型串联展示**，不属于 AC01～AC16 的正式验收项（主PRD F08）。

### 5.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 详情页「模拟仓库出库回传」 | 单据状态为待发货（可配置 Demo 开关，默认开启） |
| 创建后自动推送 | Demo 可配置在数秒后自动将待推送→待发货，便于演示 |

```
详情页「模拟仓库出库回传」（待发货）
         │
         ▼
┌─ 模拟仓库出库回传（Demo）──────────────────┐
│  各行实出 ≤ 通知数量；可勾选零出            │
│  明细表：通知数量只读，实出可填             │
│              [取消] [确认回传]              │
└────────────────────────────────────────────┘
         │ 取消              │ 确认
         ▼                   ▼
     关闭弹窗            有实出 → 已发货 + 生成出库单
                         零出 → 已取消，不生成出库单
                         缺量 → 已发货 + 缺出展示 + 退货单回补
```

### 5.3 Mock 回传弹窗

| 项目 | 内容 |
| :--- | :--- |
| 标题 | 模拟仓库出库回传（Demo） |
| 正文 | 各行实出数量不能超过通知数量；超过将自动调整为通知数量并提示。实出少于通知量按缺量结束本次执行。勾选零出则整单按取消结束。 |
| 明细展示 | 表格列：行号、商品编码、商品条码、商品名称、通知数量（只读）、实出数量（可填，默认=通知数量） |
| 输入 | 每行实出数量；零出勾选框 |
| 主按钮 | 确认回传 |
| 次按钮 | 取消 |

### 5.4 Mock 回传规则（演示数据）

| 项目 | Mock 规则 |
| :--- | :--- |
| 有实出 | 各行实出≤通知量，且至少一行实出>0；状态→已发货；回写明细实出、缺出=通知量−实出；本地生成演示用采退出库单 |
| 缺量 | 实出<通知量且未勾选零出：按缺量结束，缺出回补退货单可下推量 |
| 零出 | 状态→已取消；实出均为0；释放全部占用；不生成出库单 |
| 超量输入 | 实出>通知量时自动调整为通知量，并提示「实出数量不能超过通知数量，已自动调整为通知数量」 |
| 负值 | 实出<0时阻断并提示「实出数量不能为负数」 |
| 退货单联动 | 同步更新来源采购退货单累计实出、可下推量、在途通知数量 |

Mock 数据在界面标注「演示数据」或「Mock」角标。

## 6. 人工确认（F10）

**触发入口**：详情页「人工确认」；可用条件为**已交给仓库**且接口拿不到结果的状态（主 PRD §6.4）：推送中（确认接单）、待发货（确认执行结束或零出）、取消中（确认取消结果）。

```
详情页「人工确认」（推送中 / 待发货 / 取消中）
         │
         ▼
┌─ 人工确认（补记仓库实际结果）──────────────┐
│  确认类型：按当前状态给出可选项            │
│   推送中 → 确认接单                        │
│   待发货 → 确认执行结束（逐行填实出）／零出 │
│   取消中 → 确认取消结果（同意／拒绝）       │
│              [取消] [确认]                 │
└────────────────────────────────────────────┘
         │ 取消              │ 确认
         ▼                   ▼
    关闭抽屉            推送中 → 待发货
                        待发货 → 已发货 + 生成出库单（草稿→待审核）
                        待发货 + 零出 → 已取消
                        取消中 → 已取消 / 待发货
```

### 6.1 弹窗（抽屉）结构

| 项目 | 内容 |
| :--- | :--- |
| 标题 | 人工确认 |
| 正文 | 只用于已交给仓库、接口拿不到结果的通知；确认前请先与仓库核实实际结果。 |
| 确认类型 | 按当前状态给出可选项：推送中＝确认接单；待发货＝确认执行结束／零出；取消中＝仓库同意取消／仓库拒绝取消 |
| 执行结束明细 | 表格列：行号、商品编码、商品条码、商品名称、通知数量（只读）、实出数量（可填，默认=通知数量）；另有「零出（整单按取消结束）」勾选框 |
| 留痕 | 提交后记录人工确认人、人工确认时间与人工确认内容（确认类型与实际数量摘要）；本次确认明细写入操作日志 |
| 主按钮 | 确认 |
| 次按钮 | 取消 |

### 6.2 校验与阻断

| 校验对象 | 条件 | 阻断 | 文案 |
| :--- | :--- | :---: | :--- |
| 状态 | 推送中／待发货／取消中之一 | 是 | 当前状态不可人工确认 |
| 确认类型 | 必选，且与当前状态匹配 | 是 | 请选择确认类型 |
| 实出数量（确认执行结束时） | 0～通知数量 | 是 | 第 N 行实出数量不能超过通知数量 |
| 实出数量（确认执行结束时） | 至少一行大于 0（零出除外） | 是 | 请填写至少一行实出数量 |
| 零出 | 须确认本次执行已结束 | 是 | 请确认仓库本次执行已结束 |
| 商品与归属 | 商品、出库仓库须与来源通知和退货单行一致 | 是 | 商品或出库仓库与来源通知不一致，请核对 |
| 取消结果 | 须已取得仓库明确回复，二选一 | 是 | 请选择仓库的取消回复 |

### 6.3 确认后表现

| 确认类型 | 单据状态 | 结果单 | 库存与业财 |
| :--- | :--- | :--- | :--- |
| 确认接单 | 推送中 → 待发货 | 不生成 | 无 |
| 确认执行结束（有实出） | 待发货 → 已发货；回写实出、缺出 | 生成采退出库单，走草稿 → 待审核 | 出库单审核通过后扣减逻辑仓库存、消耗本次预占并推送财务ERP |
| 零出 | 待发货 → 已取消 | 不生成 | 释放全部占用 |
| 确认取消结果（同意／拒绝） | 取消中 → 已取消／待发货 | 不生成 | 同意时释放占用并按 R08 回补退货单可下推量 |

### 6.4 边界（必读）

- 人工确认只用于**已交给仓库、接口拿不到结果**的情形；待推送、推送失败先推送或重试，不能用人工确认代替推送。
- **不能替代通知单上事先选择的虚拟出库**：虚拟出库仍按 R13 创建后直接生成已审核出库单，不走人工确认。
- **不能无来源新建采退出库单**：确认结果必须沿本通知（及来源退货行）形成结果单。
- 确认接单、确认取消结果只更新执行情况，不生成出入库结果单；确认实际出库形成的结果单，审核通过才扣减库存并进入财务交接。
- ERP 里的「取消申请」不等于仓库已取消；人工确认取消结果是把已取得的仓库回复补录进系统。
- 留痕：人工确认人、人工确认时间与人工确认内容记入单据字段，每次确认的明细进操作日志；不做无记录的确认。

| 提交 | 本地更新状态与数量，按 §6.3 联动；生成出库单时按[《采退出库单前端Demo版PRD_弹窗与Mock》](../../采退出库单/前端Demo版PRD/采退出库单前端Demo版PRD_弹窗与Mock.md) §2 的本地生成规则演示（含「草稿→待审核」的演示态） |
| 与 Mock 回传的关系 | 「模拟仓库出库回传（Demo）」演示接口自动回传；「人工确认」演示接口拿不到结果时补记，二者互斥使用，同一次执行只成立一个结果 |
| 标注 | 界面标注「演示数据」或「Mock」角标；Mock 不代表正式接口或审核行为 |

## 7. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| 取消 | 待推送点取消，填原因 | 已取消，退货单占用释放并回补可下推量 |
| 推送失败取消 | 推送失败点取消 | 正文含仓库未接收提示；已取消 |
| 待发货取消 | 待发货点取消 | 取消中，等待回执 |
| 拒绝回执 | 取消中收到仓库拒绝 | 恢复待发货；Toast 仓库拒绝取消，请继续等待发货 |
| 重试 | 推送失败点重试 | 推送中 |
| 自动重试说明 | 查看推送失败单据 | 正式规则为自动重试3次后才出现人工重试；Demo 可直接模拟失败 |
| Mock回传 | 待发货保持实出=通知量并确认 | 已发货，缺出0，退货单数量联动 |
| Mock缺量 | 实出改小于通知量后确认 | 已发货；缺出=差额；退货单可下推量回补缺量 |
| Mock零出 | 勾选零出 | 已取消，不生成出库单 |
| 超量调整 | 实出填超过通知量 | 自动调整为通知量并提示 |
| 离开未保存 | 下推创建有修改后取消 | 弹出离开确认 |
| 人工确认接单 | 推送中点人工确认，选确认接单 | 待发货；不生成结果单；展示人工确认人、时间与内容 |
| 人工确认执行结束 | 待发货点人工确认，逐行填实出并提交 | 已发货；回写实出、缺出；生成演示出库单（草稿→待审核） |
| 人工确认零出 | 待发货点人工确认，勾选零出 | 已取消；释放占用；不生成出库单 |
| 人工确认取消结果 | 取消中点人工确认，选仓库同意／拒绝 | 分别为已取消、待发货 |
| 人工确认阻断 | 待推送单或已发货单查看入口；用人工确认替代虚拟出库 | 不提供入口／阻断并提示；不生成无来源结果单 |
| 电商仓中转 | 电商仓单据：Mock 出库回传 | 状态待发货→已发货；生成演示出库单并可查看来源标识演示值 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。
