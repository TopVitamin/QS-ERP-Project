## 2. 需求背景与范围

一期已确认采用RBAC权限控制：有相应权限就可以提交、审核，允许本人审核本人创建的数据；审核为单级流程；权限不替代模块已有的状态、库存和金额校验。账号来源、账号建立与禁用、具体角色和数据权限留到设计阶段（COM-FR01；《公共能力与系统管理需求分析》§一、§五、§七）。二版在系统设置下补齐用户与权限套件：给账号、角色、数据权限落字段与页面，并把"各模块权限段统一引用本套件"的口径定下来。

| 范围 | 说明 |

| 本期要做 | 账号新建、编辑、重置密码、启用与停用；角色新建、编辑、删除、启用与停用；功能权限点目录（覆盖一期七个一级菜单）与角色勾选配置；数据权限配置框架（一期不启用过滤，结构预留，见 §6.2）；菜单与按钮按权限展示、提交与审核权限判断、允许本人审核本人创建的数据（收口 COM-FR01）；导入不绕过对象审核的权限侧口径（收口 COM-FR02）；各模块权限段统一引用本套件的引用口径（§4.8） |

## 3. 方案总览与功能清单

用户与权限按RBAC三段组织：账号（谁在用）→角色（能做什么）→权限点（菜单与操作）。账号与角色多对多：一个账号可分配多个角色，有效权限为所属启用角色权限点的并集；权限保存即生效，不做审核。数据权限在角色上预留配置框架，回答"同一功能权限下能看到和操作哪些数据"；一期不启用数据权限过滤，结构保留为预留。提交与审核按权限判断：有提交权限即可提交、有审核权限即可审核，允许本人审核本人创建的数据；权限只决定入口与动作是否可用，不替代状态、库存和金额校验。单级审核的状态与流转沿用[《单据与状态流转》](../../../../20260812-ERP项目第一版框架搭建/系统架构和流程/03-单据与状态流转.md)，本套件不改状态机。

| 编号 | 功能/位置 | 本次内容 | 关联对象 | 需求来源 |
| --- | --- | --- | --- | --- |
| F01 | 账号管理（用户与权限-账号页签） | 账号新建、编辑、重置密码、启用与停用；账号分配角色 | 账号、角色 | COM-FR01；《公共能力与系统管理需求分析》§七 |

## 4. 功能需求说明

### 4.1 共用规则

| 规则编号 | 适用条件 | 规则与结果 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 权限模型 | RBAC：账号→角色→权限点；账号可分配多个角色，有效权限为所属启用角色权限点的并集；角色权限保存即生效，不做审核 | 不提供按账号直接授权；角色停用后其权限对已分配账号立即失效，账号保留分配关系，重新启用恢复 |
| R02 | 账号标识 | 登录账号全系统唯一，保存后不可修改；系统内引用账号处（创建人、审核人等）展示姓名，不拼接账号 | 《6.强盛ERP的编码规则和通用字段规则》Q19；更换登录名按新建账号并停用旧账号处理 |
| R03 | 提交与审核 | 有提交权限即可提交，有审核权限即可审核；允许本人审核本人创建的数据，不强制制单与审核分离 | COM-FR01；审核状态与流转仍按《单据与状态流转》与各模块主PRD，权限模块不改状态机 |
| R04 | 权限不替代业务校验 | 权限只决定入口与动作是否可用；状态、库存、金额等校验仍按所属模块规则执行，不因有权限而跳过 | COM-FR01；《4.强盛ERP全局业务规则与约束》§五 |
| R05 | 入口展示 | 无菜单权限不显示菜单；无操作权限不显示按钮与行内入口，不采用"先展示再弹窗阻断" | 项目现行口径（库存查询等主PRD"按钮按权限展示"）；权限点见 §4.4 |
| R06 | 权限点粒度 | 权限点＝二级菜单（对象）＋操作；勾选任一业务操作自动带出该菜单的查看权限，取消查看联动取消该菜单全部操作；一级菜单在其下至少一个二级菜单可查看时显示 | 权限点目录见 §4.4；页内页签（如推送异常按推送对象分页签）不单独拆权限点 |
| R07 | 数据权限 | 数据权限回答同一功能权限下可见与可操作的数据范围，以角色为单位配置；一期不启用数据权限过滤，结构保留为预留（Q01、Q02 已定，2026-10-15） | 一期所有具备功能权限的用户可见全部数据；启用时点后续单议；数据权限只限制范围，不放大功能权限 |
| R08 | 账号密码 | 新增账号与重置密码由管理员设置初始密码并线下告知；用户登录后经个人中心修改密码；密码不出现在列表、详情和导出中 | 个人中心为一期功能（COM-FR06）；密码强度与首次登录修改要求待确认（Q04） |
| R09 | 删除与引用 | 账号不提供删除，用停用代替，保留历史留痕；角色未被任何账号引用时可删除，被引用的角色只能停用；预置「系统管理员」角色不可删除、不可停用 | 角色删除受引用控制；账号姓名保留在历史单据的创建人、审核人等记录中 |
| R10 | 导入与审核 | 业务对象的导入执行受对应「导入」权限点控制；导入不改变对象的审核要求：原本要审核的仍需提交审核，原本不审核的不增加审核 | COM-FR02；导入对象范围与错误处理按各对象PRD与导入中心 |
| R11 | 与个人中心分工 | 用户与权限维护账号、角色与权限；用户修改本人密码、维护基本资料在个人中心完成 | COM-FR06 |
| R12 | 字段与展示 | 展示与命名遵循《6.强盛ERP的编码规则和通用字段规则》：系统记录字段用创建人、创建时间、最后更新人、最后更新时间；空值展示`-`；角色引用展示按Code-Name（`{编码} {名称}`） | 账号与角色均不设审核状态，保存即生效 |

### 4.2 F01 账号管理

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 管理员为新使用人建立账号、调整角色或权限；人员离职或不再使用时停用账号。 |
| 操作与处理 | 账号页签按登录账号、姓名、角色、使用状态查询；新增账号填写登录账号、姓名、手机号、邮箱，分配至少一个角色并设置初始密码，使用状态默认启用；支持编辑（登录账号只读）、重置密码、启用与停用；点击登录账号可查看只读弹窗。 |
| 功能规则 | 登录账号唯一且保存后不可改（R02）；角色至少一个、可多选，只可新选启用中的角色，已分配后停用的角色保留展示（R01）；停用后不能登录；不提供删除（R09）。 |
| 成功结果 | 账号建立完成，按所属角色的权限点展示菜单与按钮；停用账号立即不能登录，历史记录不受影响。 |
| 异常与恢复 | 登录账号重复、姓名或角色为空时阻止保存并保留已填内容；密码遗忘由管理员重置；停用后需要恢复的重新启用。 |
| 关联影响 | 停用账号在历史单据的创建人、审核人等记录中仍显示姓名；审核中的单据不因提交人停用而转移，由仍有审核权限的账号处理。 |

### 4.3 F02 角色管理

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 管理员按实际职责建立角色、配置功能权限与数据权限，并分配给账号。 |
| 操作与处理 | 角色页签按角色编码、角色名称、使用状态查询；新增角色填写角色编码、角色名称、使用状态（默认启用）、备注；行内支持配置功能权限、编辑、启用与停用、删除；点击角色名称可查看只读弹窗。 |
| 功能规则 | 角色编码、角色名称唯一，编码保存后不可改；预置「系统管理员」角色拥有全部权限点且权限点不可修改，不可停用、不可删除，用于保证系统始终有可管理人员（R09）；其余角色由管理员按职责建立，不预置业务岗位角色，不按组织架构自动生成。 |
| 成功结果 | 角色保存即生效；分配给账号后，账号的菜单与按钮随角色权限点变化。 |
| 异常与恢复 | 编码或名称重复时阻止保存；被账号引用的角色不能删除，只能停用；尝试停用或删除系统管理员角色时阻止并提示。 |
| 关联影响 | 角色停用后已分配账号立即失去该角色权限；重新启用后恢复；角色改名后账号列表按最新名称展示。 |

### 4.4 F03 功能权限配置与权限点目录

权限点由系统预置并随菜单与模块动作维护，管理员不能新增、删除或改名权限点；角色通过「配置功能权限」勾选树配置，保存即生效。权限点结构为：一级菜单（7 个）→二级菜单（对象）→操作；「查看」为所有二级菜单的统一权限点；提供导出入口的菜单另设「导出」统一权限点；两者单独勾选。勾选任一业务操作自动带出该菜单的查看权限，取消查看联动取消该菜单全部操作（R06）。操作名称沿用各模块已有叫法（提交、审核、驳回、撤回等），不因权限模块另造叫法（《单据与状态流转》§八）。

下面的目录覆盖一期七个一级菜单的全部二级菜单，逐菜单核对：

| 一级菜单 | 二级菜单 | 业务操作权限点（「查看」「导出」为通用权限点，不在此列重复；不提供导出入口的菜单不配置「导出」） |

### 4.5 F04 数据权限

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 管理员希望同一功能权限下的不同角色只看到和操作各自负责的数据时。一期不启用数据权限过滤，页签保留为预留结构。 |
| 操作与处理 | 数据权限页签按角色展示配置记录（一期为预留占位，不可编辑、不提供保存）；行内「配置数据权限」打开配置弹窗；一条记录归属一个角色，一个角色可配置一条或多条规则（按受控范围拆分，启用时确认）。 |
| 功能规则 | 以角色为单位配置（R07）；一期不启用数据权限过滤：所有具备功能权限的用户可见全部数据，不做范围过滤（Q02 已定）；控制维度（按仓库、按渠道、按业务线等）、受控对象与取值方式保留为预留，随启用时点单议（Q01）。 |
| 成功结果 | 启用后：账号在功能权限之上按角色数据权限看到对应范围的数据，按钮与动作可用性不变。 |
| 异常与恢复 | 一期页面与弹窗按「一期不启用（预留）」占位展示；启用时按最终规则补配置项并更新本文、骨架与Demo PRD。 |
| 关联影响 | 数据权限只限制数据范围，不放大功能权限：不会因数据权限获得未勾选的功能操作。 |

### 4.6 F05 权限校验、提交审核与自审

- 菜单可见性：登录后按账号所属启用角色的权限点展示菜单；一级菜单在其下至少一个二级菜单可查看时显示（R06）。
- 按钮与入口可见性：无对应操作权限时不显示按钮与行内入口；不采用"先展示再弹窗阻断"（R05）。状态不允许的操作同样不展示，按各模块主PRD的状态矩阵执行。
- 提交与审核：有提交权限即可提交，有审核权限即可审核；允许本人审核本人创建的数据，不强制制单与审核分离（R03，COM-FR01）。单级审核状态与流转沿用《单据与状态流转》§一、§五：草稿提交；有已驳回态的对象用审核通过／驳回，无已驳回态的业务单据用审核／撤回。
- 权限与业务校验的关系：权限通过后仍走模块校验；状态、库存、金额不满足时阻断并提示原因（R04）。
- 实现边界：真实实现须在服务端复核权限与业务条件，页面隐藏只作表现层处理；本期原型不接真实权限模型，演示边界见《用户与权限前端Demo版PRD_弹窗与Mock》。

### 4.8 收口口径与各模块引用方式

- 本套件是"谁能提交、谁能审核、按钮怎么显示"的统一维护位置，收口 COM-FR01、COM-FR02 的权限侧：提交与审核权限、允许自审、导入不绕过审核、权限不替代业务校验；数据权限一期不启用过滤（Q01、Q02 已定，2026-10-15）。
- 各模块主PRD权限段与「角色与数据范围」未决问题统一改为引用本套件，建议口径句：

  > 查看与操作按RBAC：具备菜单与按钮权限的角色即可操作，没有对应权限时界面不展示该操作；权限不替代本模块业务校验。提交与审核允许本人审核本人创建的数据（COM-FR01）。权限配置见《用户与权限主PRD》（二版路径：`需求文档PRD/9-系统设置/用户与权限/用户与权限主PRD.md`）。

  引用为文字引用，相对链接按所在文件位置换算；各模块「角色与数据范围」按「具备功能权限即可查看全部数据、不做范围过滤」收口（Q01、Q02 已定，2026-10-15），数据权限启用时再统一回填。
- 本轮不逐模块回改；需回改的位置（各模块权限段、未决问题、上线准备项、一版《单据与状态流转》§八的引用）由批次报告与《二版交付清单》（B6）登记，随各模块套件修订或收尾批次统一执行。
