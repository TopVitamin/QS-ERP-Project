> 清单版本：V0.1｜更新日期：2026-10-15｜状态：初稿，待评审（未纳入B10①评审范围）。
> 二版说明：本模块三个对象中，销退入库单按 B5 重建、销退收货通知单按 B7 重建（主PRD、页面骨架、Demo、字段清单出二版；列表页、新增编辑页等未变文件继续引用一版）；销售退货单二版未修订，继续引用一版文件。二版变化与一版文件去向登记见[《二版交付清单》](../../二版交付清单.md)§二。销售正向三个对象与订单三件套见[《销售管理交付清单》](../3-销售管理/销售管理交付清单.md)。

本套件覆盖销售退货管理一期三个对象：销售退货单、销退收货通知单、销退入库单。销售退货单是业务安排，审核时占用原出库可退额度（溯源）或无来源退货额度；销退收货通知单是执行指令，负责仓库收货或虚拟入库；销退入库单是实际结果，自动审核后记账并推送财务ERP，并承接国内/跨境电商退货结果归集。业务规则以[《销售与履约需求分析》](../../../../02-需求调研和分析/04-销售与履约/销售与履约需求分析.md)和[《销售与履约业务设计》](../../../../03-业务分析和设计/02-销售与履约业务设计.md)为准；字段与取值以`字段清单合集/销售相关`为准；状态以[《单据与状态流转》（一版）](../../../20260812-ERP项目第一版框架搭建/系统架构和流程/03-单据与状态流转.md)第二、三、四节为准（二版未修改，继续引用）。

## 已定结论与后续事项

| 事项 | 结论与处理 |
| --- | --- |
| 来源「分两张」（B5） | 销退入库单路径二来源拆为「来源国内电商订单」「来源跨境电商订单」两个互斥字段（可筛选、详情可跳转）；平台/渠道单号留在订单对象、不重复设在入库单；去重按「来源系统＋来源单号＋执行标识」 |
| 自动审核与异常（二版） | 渠道退货入库结果回传→校验通过→自动生成已审核销退入库单→记库存→排队推金蝶；匹配失败、重复回传不记账、不推财务ERP，修复后处理原记录；已完结结果保护沿用SAL-FR12 |
| 人工确认（销退收货通知单，B7） | 详情页入口（推送中／待收货／取消中）：确认接单、执行结束（含零收）、取消结果、实际收货数量；确认执行结束形成的销退入库单走草稿→待审核；留痕「人工确认人／人工确认时间／人工确认内容」；不得替代虚拟入库、不得无来源新建销退入库单（《集成协作与人工补充》§4.4、INT-FR06） |
| 销售退货单（一版结论，未变） | 审核时占用原出库可退额度（溯源）或无来源额度；无来源每行大于0；退货截止日期后T+2自动关闭（全部退足不自动关闭）；已实出只能关闭余量；审核后只能调整截止日期 |
| 虚拟入库 | 不推仓库、创建后按通知数量直接生成结果单并自动审核（一版口径，二版不变） |
| 接口与渠道产品名 | 渠道侧产品名与字段待联调核验，文件内标「待确认」；商品外部映射与SKU分发暂缓（00 §五） |
| 原型演示数据 | 销退入库单溯源退货联动机制已实现，但演示种子无「独立站出库单→溯源退货」数据（空态），如需演示可补 1 条种子（09《待改项》） |
| 原型实现差异 | 见09[《待改项》](../../../../09-产品原型/待改项.md)；本清单只记录入口，不用原型替代业务规则 |
