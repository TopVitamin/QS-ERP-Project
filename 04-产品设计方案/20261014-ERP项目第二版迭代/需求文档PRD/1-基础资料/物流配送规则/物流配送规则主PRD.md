# 物流配送规则主PRD

> 用途：定义基础资料「物流配送规则」的建档、启停与匹配口径，作为研发实现和测试验收的依据；业务单据侧按规则自动带出物流服务产品的行为在消费方 PRD 展开（本期仅维护规则档案）。
> 定位：应用设计层文档。字段与页面投影以[《物流配送规则（详细稿）》](../../../字段清单合集/基础资料/物流配送规则/物流配送规则（详细稿）.tsv)为准（初稿留档）；物流服务产品档案规则继续引用一版[《物流资料主PRD》](../../../../20260812-ERP项目第一版框架搭建/需求文档PRD/1-基础资料/物流资料/物流资料主PRD.md)。页面交互见[《物流配送规则前端Demo版PRD》](物流配送规则前端Demo版PRD.md)；配销侧消费见[《配销订单-物流服务产品自动带出衔接说明》](../../3-销售管理/配销订单（规划）/配销订单-物流服务产品自动带出衔接说明.md)。
> 不写什么：不写运费计算、物流商直连与面单；不写配销订单页面与状态机（对象未交付）；不替代销售订单、独立站订单现有的人工选物流流程。

## 一、文档概要

需求类型：二版增量（基础资料-物流配送规则）。

关联资料：

- 业务背景：门店配货／配销场景需按「从哪里发、发到哪」预选物流服务产品（课程与规划见项目内配销模块材料；ERP 配销订单对象尚未交付）。
- 主数据：[《主数据准备》](../../../../../03-业务分析和设计/05-主数据准备.md)（物流商、物流服务产品）、一版[《物流资料主PRD》](../../../../20260812-ERP项目第一版框架搭建/需求文档PRD/1-基础资料/物流资料/物流资料主PRD.md)
- 应用设计：[《系统与模块地图（V2）》](../../../系统架构和流程/00-系统与模块地图.md)、[《实体对象关系（V2）》](../../../系统架构和流程/02-实体对象关系.md)

## 二、需求背景与范围

总部向门店配货时，承运方式往往与线路相关：同一发货仓发往省内、省外或不同城市，默认的物流服务产品不同。若每次在配销订单上手工挑选，容易选错且难以统一治理。本期在基础资料预先维护「发件省、发件市、收件省、收件市 → 物流服务产品」的映射，供后续配销订单在选定发货仓与收货门店后自动带出默认物流服务产品（可人工改选）。

| 范围 | 说明 |
| --- | --- |
| 本期要做 | 物流配送规则列表、新增／编辑、启用／禁用；省、市联动录入；唯一性校验；关联启用的物流服务产品；权限与菜单登记 |
| 本期不做 | 配销订单（及发货通知单）上的自动匹配落库与验收；批量导入；B2B 销售订单、独立站订单改用本规则自动选物流；海外地址规则；运费与时效 |
| 适用对象 | **仅中国大陆**省、市字典（2026-10-20 确认：不含港澳、海外门店/仓）；与客户、实体仓地址一致的字典口径；业务侧发件省、市由所选**发货逻辑仓**解析为其归属**实体仓**地址的省、市；收件侧未来取自国内门店收货地址的省、市（消费方 PRD 固化字段来源） |

### 2.1 维护对象与引用关系

| 对象 | 用途 | 数据来源 | 由哪里维护 | 被哪些业务引用 |
| --- | --- | --- | --- | --- |
| 物流配送规则 | 按发件／收件省、市映射默认物流服务产品 | 人工建档 | 主数据维护人员；菜单：基础资料-物流配送规则 | 规划：配销订单（未交付）；本期无业务消费 |

## 三、方案总览与功能清单

先维护启用的物流服务产品档案，再维护物流配送规则。规则保存后供业务侧按省、市查询；禁用规则不参与匹配。

| 编号 | 功能/位置 | 本次内容 | 需求来源 |
| --- | --- | --- | --- |
| F01 | 物流配送规则列表 | 查询、列展示、进入新增／编辑／详情 | 用户确认（2026-10-20） |
| F02 | 新增／编辑 | 维护路由条件与物流服务产品、备注、使用状态 | 同上 |
| F03 | 启用／禁用 | 禁用后不参与匹配 | 同上 |
| F04 | 匹配服务（系统能力，无单独菜单） | 按发件省、市与收件省、市解析默认物流服务产品；供后续配销订单调用 | 同上；消费方待交付 |

## 四、功能需求说明

### 4.1 共用规则

| 规则编号 | 主题 | 规则 | 边界或例外 |
| --- | --- | --- | --- |
| R01 | 规则名称 | 不设单独业务编码字段；**规则名称**必填且在物流配送规则对象内唯一；允许编辑改名，保存时校验不与其它记录重名 | 列表、筛选、详情以规则名称识别；系统内部可用技术主键存储，不对用户展示、不要求维护 |
| R02 | 不审核 | 无草稿、提交、审核；新建保存后默认启用 | 与物流商、物流服务产品一致 |
| R03 | 省、市录入 | 发件省份、收件省份必填；城市通过地区字典联动所选省份；发件城市、收件城市**允许留空，表示该省下全部城市（全省）**（2026-10-20 确认） | 仅中国大陆字典（Q04 已确认）；港澳、海外地址不参与本规则表与 F04 |
| R04 | 物流服务产品 | 须选择启用状态的物流服务产品；所属物流商禁用不阻止已启用产品被引用（与《物流资料主PRD》R03 一致） | 不自提、不创建「由仓库指定」类虚拟档案 |
| R05 | 启用规则唯一性 | 对「启用」状态的规则，发件省＋发件市（空视为通配）＋收件省＋收件市（空视为通配）组合不可重复；保存时校验并阻止 | 禁用规则可与启用规则组合相同；启用时若与另一条启用规则冲突则阻止 |
| R06 | 匹配优先级（运行时） | 多条启用规则均可命中时，优先命中「城市越具体」的规则：双方市均填 > 仅一方填市 > 双方市均空；仍有多条同级命中时取**最后更新时间最新**的一条（2026-10-20 确认，不设显式优先级字段） | 配销订单 PRD 引用本规则编号 |
| R07 | 无匹配 | 业务侧调用匹配服务且无启用规则命中时，不自动填充物流服务产品，由用户手工选择 | 不阻断建单 |
| R08 | 删除 | 物流配送规则不提供删除，仅禁用；避免历史审计无法对应 | 若后续要求物理删除，单独评审 |
| R09 | 发件地址来源（业务侧） | 配销等消费方以**发货逻辑仓**为输入；系统读取该逻辑仓归属实体仓地址的省、市作为发件省、市参与 R06 匹配 | 逻辑仓未维护实体仓或实体仓地址缺省省、市时，不推断发件地，按 R07 处理；不在规则表上单独维护逻辑仓 |

### 4.2 F01 列表

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 查询、浏览已维护线路与默认物流产品。 |
| 操作与处理 | 按规则名称、发件省份、收件省份、物流服务产品、使用状态筛选；默认按最后更新时间倒序。 |
| 功能规则 | 列表默认列、筛选项以[详细稿](../../../字段清单合集/基础资料/物流配送规则/物流配送规则（详细稿）.tsv)及[页面骨架](物流配送规则页面骨架.md)为准；发件／收件省、市在列表合成展示。 |
| 成功结果 | 可进入新增、编辑或只读详情。 |

### 4.3 F02 新增／编辑

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 新开通线路默认物流、或调整既有线路的默认产品。 |
| 操作与处理 | 填写规则名称、发件省／市、收件省／市、物流服务产品、备注；维护使用状态。 |
| 功能规则 | R01、R03～R05、R04；市留空时界面提供「全省（不选具体城市）」选项，备注与占位文案见[Demo PRD](物流配送规则前端Demo版PRD.md)。 |
| 成功结果 | 保存后列表可见；启用规则可被匹配服务读取。 |
| 异常与恢复 | 名称重复、组合重复、未选启用产品、市与省不联动时阻止保存并定位字段。 |

### 4.4 F03 启用／禁用

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 线路停用或临时下线某条默认映射。 |
| 操作与处理 | 列表或表单切换使用状态。 |
| 功能规则 | 启用时执行 R05；禁用不参与 R06、R07。 |
| 成功结果 | 状态立即生效；已保存业务单据上的物流快照不变。 |

### 4.5 F04 匹配服务（供后续配销订单）

| 内容 | 说明 |
| --- | --- |
| 使用场景 | 配销订单（规划）选定发货逻辑仓与收货门店后，系统解析发件省、市与收件省、市并带出默认物流服务产品。 |
| 操作与处理 | 输入：发货逻辑仓（系统按 R09 解析发件省、市）、收件省、收件市（门店收货地址，名称与规则表一致）；输出：物流服务产品编码或空。 |
| 功能规则 | 仅查询启用规则；按 R06 解析；输出产品须仍为启用状态，否则视为无匹配（R07）。 |
| 成功结果 | 仅当配销单头「物流服务产品」**为空**时预填 F04 结果；用户可改选其他启用产品，或在 ERP 中主动选择「由仓库指定」（2026-10-20 确认 Q05）。单头已有取值（含系统预填、手工改选、由仓库指定）后，改发货逻辑仓或收货门店**不自动重算**（PQ01）。 |
| 异常与恢复 | 发件侧按 R09；收件省、市取自门店默认收货地址；任一侧省、市不完整或地址非大陆字典时走 R07，不阻断建单。 |
