### 1.1 本模块不提供的弹窗

本期不提供以下弹窗：

| 弹窗 | 说明 |
| :--- | :--- |
| 新增 / 编辑弹窗 | 通知单由调出端结果单生成后系统自动生成，本模块无新增、编辑入口（主PRD §3.4） |
| 取消确认框 | **本期不提供取消入口**：货已实际发出，取消接收指令会让在途失去归属（主PRD §6.4、Q02） |
| 零收取消确认框 | 零调入属异常，不按零收取消通知单，只拒绝整次回传并保持等待（主PRD R05） |
| 手工推送确认框 | 创建后由系统自动推送，不提供人工触发推送（主PRD R03） |
| 补收确认框 | 已收货为终态，不往原通知补收；少收差异用其他出库从在途扣减（主PRD R07） |
| 手工调整预占 | 预占不能手工增改，只能由审核占用、实出消耗、未发与取消释放（[《预占与冻结主PRD》](../../../../../20260812-ERP项目第一版框架搭建/需求文档PRD/7-库存管理/预占与冻结/预占与冻结主PRD.md)（一版未变） §二） |

自动重试（正式环境）：推送明确失败后系统自动重试，**最多3次**；间隔由技术配置。3次仍失败则保持「推送失败」，可人工重试（F05）。

```
调入通知单列表 / 详情
         │
    用户查找操作入口
         │
    ┌────┴─────────────────┐
    │                      │
 单据状态=推送失败？     其他状态
    │                      │
   是                      ▼
    ▼                仅查看；无取消、无重试
 [重试推送] → 确认弹窗 → 推送中
```

| 项目 | 内容 |

| 触发 | 列表或详情「重试推送」（推送失败） |
| 标题 | 重试推送接收仓 |
| 正文 | 将对本通知单重新发送接收仓，不重新生成、不重复回写。发送结果不确定时请先核实仓库是否已接收。 |
| 主按钮 | 确认重试 |
| 次按钮 | 取消 |

## 3. 零调入异常提示（F06）

零调入不是确认弹窗，而是回传被拒绝后的**提示条与 Toast**。

| 项目 | 内容 |
| :--- | :--- |
| 触发 | 接收仓回传实际调入为0（正式为接口回传；Demo 见 §4.4 零调入分支） |
| 提示条位置 | 详情页商品明细上方 |
| 提示条文案 | 回传实际调入为0已被拒绝，请仓库改为大于0后重新回传；本单不按零收取消。 |
| Toast 文案 | 实际调入必须大于0，回传已被拒绝，请改为大于0后重新回传 |
| 状态表现 | 单据状态保持「待收货」；在途、接收仓与来源主单状态均不变 |
| 人工处理 | 页面提示「如长期无法回传，请联系管理员人工处理」；责任方待Q03、Q04确认后回填 |

不提供「按零收取消」按钮，也不提供「关闭通知单」入口。

## 4. Demo Mock：接收仓回传实收与主单完结（F07）

### 4.1 正式规则（必读）

正式环境中，接收仓执行一次接收并回传实际接收数量：实收必须大于0且不超过通知调入数量，超量整次拒绝；实收为0属异常，拒绝整次回传并报错，通知单保持等待。实收大于0时通知变为已收货，系统生成调入端直接调拨单（在途减、接收仓加），回写来源主单累计实际调入与在途数量，主单自动完结（业务状态=已关闭、页面展示「已完结」）。少收差额继续留在途，不自动抹平。

本节 Mock **仅用于 Demo 原型串联展示**，不属于主PRD AC01～AC12 的正式验收项（主PRD F07）。

### 4.2 触发时机

| 时机 | 行为 |
| :--- | :--- |
| 调入通知单详情（待收货）「模拟接收仓回传(Mock)」 | 打开 §4.3 弹窗，录入实际调入数量；确认后按 §4.4 本地生成 |
| 分步式调拨单详情的接收仓回传 Mock | 由主单侧统一触发，本模块不重复定义（见[《分步式调拨单前端Demo版PRD_弹窗与Mock》](../../../../../20260812-ERP项目第一版框架搭建/需求文档PRD/7-库存管理/分步式调拨单/前端Demo版PRD/分步式调拨单前端Demo版PRD_弹窗与Mock.md)（一版未变） §4） |

```
调入通知单详情（待收货）
      │
  Mock 回传
      │
      ▼
 实收 =0 ？ ──是──> 拒绝整次回传
      │              通知单保持待收货（§3 提示条）
      否
      ▼
 实收 ≤ 通知调入数量 ？ ──否──> 整次拒绝，提示超量
      │
      是
      ▼
 §4.4 本地生成
 通知单已收货
 调入端直接调拨单（已审核）
 在途 −88、接收仓 +88
 主单已完结（在途剩 2）
```

### 4.3 引导弹窗

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 模拟接收仓回传（Demo） |
| 正文 | 按实际调入数量生成演示用调入端直接调拨单并触发主单完结；正式流程以仓库回传为准。 |
| 表单项 | 实际调入数量 |
| 主按钮 | 确认回传 |
| 次按钮 | 取消 |
| 关闭图标 | 关闭后不生成任何数据 |

### 4.4 生成规则（本地 Mock）

| 项目 | Mock 规则 |
| :--- | :--- |
| 生成条件 | 通知单处于待收货；实际调入为正整数、大于0、不超过通知调入数量 |
| 通知单 | 单据状态=已收货；回写实际调入与少收数量；最终收货确认时间=当前时间 |
| 调入端直接调拨单 | 来源类型=分步式调入端；来源逻辑仓=虚拟在途仓；目标逻辑仓=接收仓；审核状态=已审核；推送财务ERP状态从未推送开始 |
| 库存 | 在途减、接收仓即时库存加；写两条库存流水；少收差额留在途（Demo 可在库存查询页核对） |
| 回写主单 | 主单累计实际调入、在途数量更新；主单业务状态=已关闭（页面展示「已完结」）；关闭方式=两端执行完成自动完结 |
| 单号 | 调入端结果按 ZJDB 编码规则生成 fictitious 编号 |
| 超量分支 | 实收大于通知调入数量时：整次拒绝并提示「回传数量超过通知数量，已整次拒绝」 |
| 零调入分支 | 实收=0时：拒绝整次回传并按 §3 展示提示条；通知单保持待收货，主单保持已审核+正常 |
| 少收分支 | 实收小于通知调入数量时：主单在途数量保留差额；详情提示「少收差额留在途，不自动抹平，后续用其他出库从在途逻辑仓扣减」 |

界面标注「演示数据」或「Mock」角标，与正式回传生成的结果单区分。

### 4.5 不做的事

- 不代替正式接口校验与映射
- 不在 Mock 中自动抹平在途差异
- 不在 Mock 中制造负库存
- 不把 Mock 推送当作财务ERP正式验收
- 不在 Mock 中替代人工确认；人工确认见 §5

## 5. 人工确认（F08）

**触发入口**：详情页「人工确认」；可用条件为**已交给仓库**的状态（推送中、待收货；主 PRD §6.4）。本期无取消入口，不涉及取消结果确认。

### 5.1 正式规则（必读）

接口拿不到接单或执行结果时，操作人在详情页「人工确认」按实际发生情况填写：确认接单（推送中→待收货）、确认执行结束（待收货→已收货，逐行填实际调入数量）。只适用于已交给仓库的通知；必须过业务校验（商品、接收仓、数量按来源主单行回写）与适用审核；确认执行结束形成的调入端直接调拨单走草稿→待审核，审核通过后在途减、接收仓加，回写主单并自动完结（主 PRD R08、[《集成协作与人工补充》](../../../../../../03-业务分析和设计/07-集成协作与人工补充.md) §4.4、[《系统集成需求分析》](../../../../../../02-需求调研和分析/07-系统集成/系统集成需求分析.md) INT-FR06）。

```
详情（推送中/待收货）
     │
点「人工确认」
     ▼
┌──────────────────────────────────────────┐
│  人工确认（补记仓库实际结果）        [×] │
│  确认类型按当前状态给可选项…             │
│  确认执行结束：逐行填实际调入数量        │
│  提示：实际调入必须大于0；回传0属         │
│  零调入异常，不通过人工确认收口。         │
│                    [取消] [确认]          │
└──────────────────────────────────────────┘
```

### 5.2 弹窗规格

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 人工确认（补记仓库实际结果） |
| 正文 | 只用于已交给仓库、接口拿不到结果的通知；确认前请先与仓库核实实际结果。 |
| 确认类型 | 按当前状态给出可选项：推送中—确认接单；待收货—确认执行结束 |
| 执行结束时 | 逐行填写实际调入数量（必须大于0且不超过通知调入数量） |
| 确认按钮 | 确认 |
| 取消按钮 | 取消 |
| 确认后 | 记录人工确认人、人工确认时间与人工确认内容；状态按确认结果更新；确认执行结束且校验通过时，形成调入端直接调拨单并提交审核（待审核） |
| 失败处理 | 实际调入为0时阻断并提示按零调入异常处理（见 §3）；超通知调入数量、未核实等校验不通过时阻断并提示；状态不匹配时 Toast「当前单据状态为{状态}，不可执行人工确认」 |

### 5.3 Demo 本地行为

| 场景 | Demo 行为 |
| :--- | :--- |
| 确认接单 | 单据状态→待收货；不生成结果单 |
| 确认执行结束 | 复用 §4.4 本地生成规则形成演示调入端直接调拨单并触发主单完结，结果单状态按正式口径为**待审核**（草稿→待审核）并标注「演示数据」；回写实际调入与少收 |
| 实际调入填0 | 阻断并提示按零调入异常处理；状态保持待收货 |

### 5.4 不做的事

- 不代替正式接口回传与校验
- 不无来源建通知单；不通过人工确认收口零调入异常
- 不把 Mock 结果当作财务ERP正式验收
- Demo 中的「模拟接收仓回传」保留用于演示接口回传链路，与本弹窗不重复触发同一张单的生成

## 6. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| Mock 回传（收足） | 通知90件，Mock 回传90 | 通知单已收货、少收0；生成调入端直接调拨单；主单已完结 |
| Mock 回传（少收） | 通知90件，Mock 回传88 | 通知单已收货、少收2；在途剩2；主单已完结 |
| Mock 回传（零调入） | Mock 回传0 | 拒绝整次回传并展示提示条；通知单保持待收货；主单保持已审核+正常 |
| Mock 超量 | Mock 回传100（通知90） | 整次拒绝并提示；不记账、不生成单据 |
| 无取消弹窗 | 在列表与详情查找取消入口 | 无取消按钮、无取消确认弹窗 |
| 无新增/编辑弹窗 | 在列表与详情查找新增、编辑入口 | 无入口、无对应弹窗 |
| 重试入口 | 推送失败单 | 展示「重试推送」；确认后状态=推送中 |
| 人工确认接单 | 推送中单点人工确认并确认接单 | 待收货；记录人工确认人／时间／内容 |
| 人工确认执行结束 | 待收货单确认执行结束，实际调入88（通知90） | 已收货；少收2；形成演示调入端结果单（待审核） |
| 人工确认填0 | 实际调入填0并确认 | 阻断并提示按零调入异常处理；状态保持待收货 |

Demo 验证 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。**本章 Mock 仅 Demo，非正式验收。**
