## 2. 选仓选物流与提交相关弹窗（F04、F05）

**触发入口**：列表行内「编辑」、批量操作栏「批量选仓选物流」、详情页头「编辑」；可用条件为**单据状态=待提交**（主 PRD §6.4）。

### 2.1 选仓选物流

**单张编辑**：

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 选仓选物流 · {单号} |
| 正文 | 一单一仓、整单履约，提交审核前须选定仓库与物流。 |
| 字段 | 发货仓库*（`select`，审核通过且启用的逻辑仓，Code-Name）；物流服务产品*（`select`，启用的物流服务产品 + 「由仓库指定」）；备注（`textarea`，`REMARK_500`，选填） |
| 必填项 | 发货仓库、物流服务产品 |
| 确认按钮 | 保存 |
| 取消按钮 | 取消 |
| 确认后 | 更新发货仓库、物流服务产品及名称快照；记录操作日志；Toast「独立站订单已保存」；刷新当前页 |

**批量设置**（勾选≥1张待提交订单后触发）：

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 批量选仓选物流 |
| 正文 | 将对已选 {N} 张待提交订单统一设置发货仓库与物流服务产品；不含备注。 |
| 字段 | 发货仓库*；物流服务产品*（不含备注） |
| 必填项 | 发货仓库、物流服务产品 |
| 确认按钮 | 保存 |
| 取消按钮 | 取消 |
| 确认后 | 逐单更新仓库、物流与快照；不改变单据状态；Toast「已更新 N 张订单的发货仓库与物流服务产品」 |
| 阻断 | 勾选含非待提交订单时，不进弹窗，Toast「批量选仓选物流仅支持待提交状态的订单，请调整勾选」 |

**图中省略**：选项过滤（禁用档案不可选）、保存校验、失败恢复；校验失败定位字段并停留弹窗。

### 2.2 提交确认（F05）

**校验前置**：打开提交弹窗前按主 PRD R10 校验当前单据；未通过则 Toast 阻断，**不进入**弹窗。

| 校验对象 | 条件 | 错误位置 | 阻断 | 文案 |
| :--- | :--- | :--- | :---: | :--- |
| 单据状态 | =待提交 | Toast | 是 | 当前单据状态为{状态}，不可提交 |
| 发货仓库 | 已选 | Toast / 字段提示 | 是 | 请先选定发货仓库 |
| 物流服务产品 | 已选 | Toast / 字段提示 | 是 | 请先选定物流服务产品 |
| 来源内容 | Shopify来源单号、商品、订购数量、收货信息完整 | Toast | 是 | 单据来源内容不完整，请处理后重试 |

**提交确认弹窗**：

| 项目 | 内容 |
| :--- | :--- |
| 弹窗标题 | 确认提交独立站订单？ |
| 正文 | 提交后进入待审核状态；审核通过后系统自动推送仓库，不需要人工推送。审核前仍可撤回修改。 |
| 确认按钮 | 确认提交 |
| 取消按钮 | 取消 |
| 确认后 | 单据状态→待审核；Toast「独立站订单已提交」；刷新当前页或列表 |

## 3. 状态变更弹窗（F05～F10）

下列弹窗均在**二次确认**后执行。入口可用条件见主 PRD §6.4 与各页页头/行内矩阵；条件不满足时**不展示按钮**，无需弹窗阻断。

**阻断类失败**（不满足业务规则、未进入成功流）：审核库存不足、取消审核条件不符、批量含非待提交等直接 Toast 阻断，示例见列表 Demo PRD §8。

## 4. 人工确认（F11，B7边界）

### 4.1 正式规则

已交给仓库、接口拿不到接单、执行结束或取消结果时，按实际发生情况人工确认；确认仍过业务校验与适用审核，并留痕确认人、确认时间、确认内容（主 PRD R23）。**不得替代虚拟入出库（本对象本期不提供虚拟出库）；不得脱离本单无来源新建销售出库单。**

### 4.2 触发与可用

| 项目 | 内容 |
| :--- | :--- |
| 触发入口 | 详情页头「人工确认」 |
| 可用条件 | 已审核（确认接单）／待发货（执行结束）／取消中（取消结果）；确认类型按状态限定，其余选项不展示 |
| 弹窗标题 | 人工确认 · {单号} |
| 提示文案 | 用于已交给仓库、接口拿不到结果的场景；确认仍过业务校验。 |

**确认类型与表单（动态展示）**：

| 确认类型 | 可用状态 | 表单项 | 校验 | 确认后 |
| :--- | :--- | :--- | :--- | :--- |
| 确认接单 | 已审核 | 无额外字段 | 状态=已审核 | 视同仓库已接收：状态→待发货；不生成结果单；留痕 |
| 执行结束 | 待发货 | 明细表（商品编码、商品名称、订购数量、实际发货数量*）、运单号* | 各行实际发货数量=订购数量（整单发出），或整单为0（零执行）；非整单数量阻断；整单发出时运单号必填 | 整单发出：生成销售出库单草稿（沿来源本单、金额沿用），提示提交审核；审核通过后→已发货、回写Shopify。整单为0：按零出取消（R16），不生成零数量出库单 |
| 取消结果 | 取消中 | 仓库结果*（单选：仓库同意取消／仓库拒绝取消） | 状态=取消中 | 同意：按原取消用途落已取消或待提交；拒绝：恢复待发货；仅更新执行情况，不生成结果单；按 §5.3 回写取消结果 |

**必填项**：按确认类型动态必填；**确认按钮**：确认；**取消按钮**：取消。

**留痕**：人工确认人、人工确认时间、人工确认内容（最近一次）写入操作信息；逐条记录追加到操作日志（操作类型=人工确认，说明含确认类型与要点）。

### 4.3 Demo Mock 边界

- 原型以 Mock 模拟「回传」取得结果，**不代表接口已验证**（INT-FR06、03/07 §4.4）；弹窗与结果标注「演示数据」。
- 执行结束生成的销售出库单在本地 Mock 存储创建（草稿，来源=本单）；其提交、审核与记账演示按销售出库单页面当前实现串联，不在本模块内实现。
- 不模拟真实权限校验：按钮可见性仅按状态与规则判断。

## 5. Demo Mock：推送、回传、回写与导入（F02、F03、F12）

### 5.1 正式规则

- 审核通过后系统自动推送仓库，不需要人工推送；推送明确失败自动重试最多3次，仍失败可人工重试（R13）；
- 仓库整单回传后自动生成已审核销售出库单并回写Shopify；整单零执行按零出取消（R15、R16）；
- 回写失败的记录进系统集成中心「推送异常-推送电商平台」页签，本单提供重新回写（R18）；
- 拉取与人工导入按「来源系统＋来源单号」识别、去重与匹配（R02～R05）。

本节 Mock **仅用于 Demo 原型串联**，不属于 AC01～AC17 的正式验收项；接口字段、协议与调用方式随接口设计（主 PRD Q01、Q02）。

### 5.2 推送与仓库回传 Mock

```text
[审核成功] -> [Demo开关(默认开)]
                 | 关闭 -> [停留已审核；由「模拟推送成功(Mock)」入口手动推进]
                 | 开启 -> [约1秒后模拟推送成功] -> 状态=待发货
[待发货] -> [详情/列表提供演示用「模拟仓库回传」入口(Mock角标)]
                 | 整单发出 -> [生成已审核销售出库单，状态=已发货，累计实际发货数量回写，接§5.3回写]
                 | 整单零执行 -> [按零出取消：状态=已取消、实发0、差额=订购数量、无出库单，接§5.3回写取消结果]
[取消中] -> [模拟仓库回执] -> [同意：已取消或待提交；拒绝：恢复待发货]
```

| 项目 | 规则 |
| :--- | :--- |
| 推送成功触发 | 审核成功后约1秒（可配置）自动模拟推送成功；开关关闭时不自动推进，由演示用「模拟推送成功（Mock）」入口手动触发；记录推送时间、最近处理时间 |
| 推送失败分支 | 演示可选：首次推送失败→推送失败（原因=演示用「仓库接口超时」）→自动重试 3 次演示不逐步播放，人工重试后成功 |
| 模拟回传入口 | 待发货/取消中单据的详情与列表提供「模拟仓库回传（Mock）」入口，不进入正式行操作矩阵 |
| 回传数据 | 整单发出：各明细实际发货数量=订购数量、运单号（示例 `SF1234567890`）；零执行：各明细实际发货数量=0 |
| 生成出库单 | 本地 Mock 创建已审核销售出库单（来源=本单、金额沿用）；零执行不创建 |
| 角标 | 所有Mock触发入口与生成单据标注「演示数据」 |

### 5.3 Shopify回写 Mock

| 项目 | 规则 |
| :--- | :--- |
| 触发时机 | 整单发出后（回写内容=发货结果与运单）；取消生效后（回写内容=取消结果） |
| 成功分支 | 回写状态=已回写；记录回写时间、回写内容 |
| 失败分支 | 演示开关控制：回写状态=回写失败、记录原因（演示用「Shopify接口超时」），并派生一条推送异常「推送电商平台」记录（单据编号=本单号、推送内容=对应内容、状态=待处理） |
| 重新回写 | 详情/列表「重新回写」按钮（回写失败时展示）：演示开关返回成功→回写状态=已回写，同步推送异常记录置「已处理」；返回失败→保持并更新原因 |
| 不得提前 | 取消结果仅在取消生效后回写；仓库拒绝不写取消成功 |

### 5.4 导入向导 Mock（F03）

| 场景 | 文案或表现 |
| :--- | :--- |
| 向导内提示 | 仅用于接口未覆盖的Shopify订单，导入后仍需提交审核 |
| 步骤 | 1 下载模板（Mock）→ 2 上传 .xlsx → 3 校验预览（成功/失败行数，按来源单号分组，任一行失败整组不导入）→ 4 导入 |
| 生成规则 | 生成 2～3 张待提交草稿：获取方式=人工导入、来源单号示例 `#2001`～`#2003`、金额/商品/收货信息取演示模板；创建人=当前演示用户 |

### 5.5 不做的事

- 不调用真实Shopify与仓库接口；不代表接口已验证；
- 不在 Mock 中自动审核人工确认形成的销售出库单；
- 不把 Mock 行为写入主 PRD 验收标准（AC01～AC17）；
- 不提供无来源建单与虚拟出库能力。

## 6. 验收场景

| 场景 | 操作 | 预期 |
| :--- | :--- | :--- |
| 选仓选物流 | 待提交单选仓库物流保存 | 快照更新；操作日志记录 |
| 批量设置 | 勾选3张待提交批量设置 | 3单统一更新；状态不变 |
| 批量阻断 | 勾选含待审核单 | Toast 阻断，不进入弹窗 |
| 提交阻断 | 未选仓库提交 | Toast 阻断，不进入待审核 |
| 提交流 | 完整单据提交 | 校验通过→确认→待审核 |
| 审核成功 | 库存充足审核 | 已审核并占库；Mock 开启时约1秒后待发货 |
| 审核失败 | 库存不足审核 | Toast 展示逻辑仓与各不足 SKU 数量明细，不占库 |
| 撤回 | 待审核撤回 | 必填意见→待提交 |
| 取消审核 | 已审核选终止/调整 | 已取消 / 待提交；占库释放 |
| 申请取消 | 待发货申请 | 取消中；仓库拒绝恢复待发货 |
| 人工确认接单 | 已审核确认接单 | 转待发货，无结果单 |
| 人工确认执行结束 | 待发货整单发出 | 生成出库单草稿；审核通过后已发货 |
| 人工确认零执行 | 待发货实发为0 | 已取消、实发0、差额=订购数量 |
| 复制新单 | 已取消复制 | 新草稿、同来源单号；原单不变 |
| 重试推送 | 推送失败重试 | 演示成功转待发货 |
| 回写失败与重写 | 演示开关回写失败→重新回写 | 回写状态与推送异常记录联动更新 |
| 导入演示 | 列表点导入 | 向导完成后生成演示草稿并标注「演示数据」 |
| Mock 关闭 | Demo 配置关闭 | 审核成功后不自动推进状态；由演示入口手动触发推送/回传/回写，文案与联动同开关开启 |

Demo 验证弹窗文案、必填项与 Mock 本地数据联动；不代表生产接口、并发或后端事务行为。
