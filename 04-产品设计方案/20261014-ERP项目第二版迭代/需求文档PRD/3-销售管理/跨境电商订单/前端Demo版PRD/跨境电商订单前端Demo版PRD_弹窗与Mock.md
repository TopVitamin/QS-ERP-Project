## 2. 弹窗清单与边界

**本模块没有确认弹窗、表单弹窗与Mock引导弹窗。** 原因：

- 订单由渠道回传自动生成，页面上没有新增、编辑、提交、审核、取消、关闭、删除、重试等业务动作，不需要二次确认（主PRD §6.4、R02）；
- 导出走导出中心，导出向导属于公共能力，不在本模块维护；
- 关联结果单跳转与异常回传记录查看都是纯跳转／只读展示，不做确认拦截；
- FBA消费者订单不进本对象，页面不出现FBA相关弹窗或入口（主PRD §7.6、R12）。

因此：行内与页头不发生「按钮不满足条件时隐藏还是置灰」的弹窗判定——本模块行内无按钮，页头只有`返回列表`。若后续接口设计为订单补充人工处理入口（本期不做，见主PRD §5.1），弹窗在此文件新增章节维护。

相关动作的弹窗归属：

| 相关动作 | 弹窗归属 |
| :--- | :--- |
| 结果回传的匹配、校验与异常处理 | 系统集成中心-推送异常（见[《推送异常主PRD》](../../../../../20260812-ERP项目第一版框架搭建/需求文档PRD/8-系统集成/推送异常/推送异常主PRD.md)），本模块不设弹窗 |
| 商品外部映射维护 | 商品资料（按平台＋店铺维护，INT-FR04），本模块不设弹窗 |
| FBA相关处理 | 领星侧，强盛不设入口（主PRD §7.6） |
| 导出向导 | 导出中心（公共能力），本模块不设弹窗 |

## 3. 共享 Mock 数据集

### 3.1 数据范围与结构

一套Mock数据同时服务列表页与详情页，并通过订单编号与结果单单号建立关联：

```text
跨境电商订单（列表6张以上）
   ├── 订单基础信息（单头）
   ├── 订单行快照（数组：一行一条）
   ├── 关联结果单
   │      ├── 销售出库单（0..N，单号、业务日期、数量、审核状态、推送财务ERP状态、创建时间）
   │      └── 销退入库单（0..N，同结构，数量列为实际退回数量）
   └── 异常回传记录（0..N：执行标识、异常环节、失败时间、失败原因、处理状态、关联结果单）
```

### 3.2 订单与订单行 Mock

| 项目 | 要求 |
| :--- | :--- |
| 数量 | 订单不少于6张；单张订单行数1～5行 |
| 覆盖 | 待归集、部分归集、已归集、异常各至少1张；至少1张两个关联Tab为空（空态）；至少1张含未匹配订单行 |
| 编号 | 订单编号示例按已定前缀 KJDS 书写（2026-10-15 用户确认）；渠道单号、平台单号为虚构值 |
| 平台与店铺 | 至少2个店铺；平台取值以「（待确认）」占位，不预填具体平台名称（主PRD Q03） |
| 币别 | 至少覆盖美元与人民币各1张，用于验证币别「编码 名称」展示 |
| 金额 | 行与单头金额沿用Mock的渠道金额；至少1张退货金额为0，至少1张大于0；至少1张金额未回传用于核对空值展示 |
| 数量 | 订购数量、累计实际出库数量、累计实际退回数量为整数；累计数量与关联结果单数量之和一致，保证页面可连续核对 |
| 范围 | 不生成FBA消费者订单、FBA备货相关Mock（主PRD §7.6） |

### 3.3 关联结果单 Mock

| 项目 | 要求 |
| :--- | :--- |
| 销售出库单 | 至少含一张订单关联2张销售出库单（对照SAL-AC15同一订单两次实际出库）；审核状态为已审核；推送财务ERP状态覆盖推送成功／推送中 |
| 销退入库单 | 至少1张订单关联1张销退入库单，用于退货Tab与退货金额展示 |
| 数量一致 | 订单行的累计实际出库数量＝该订单关联销售出库单数量合计；累计实际退回数量＝销退入库单数量合计 |
| 跳转 | 结果单单号在原型内可跳转到对应的结果单页（详情或列表定位）；原型未实现时以Toast或占位说明，不改变Mock数据 |

### 3.4 异常回传记录 Mock

| 项目 | 要求 |
| :--- | :--- |
| 待处理 | 至少1条处理状态为待处理，异常环节为商品匹配（对应未匹配订单行），失败原因为虚构文案「平台商品编码未匹配到ERP商品」 |
| 已处理 | 至少1条处理状态为已处理，并填写关联结果单（可跳转）；异常环节为库存校验或归属识别 |
| 执行标识 | 记录带执行标识，用于说明同一来源单的多次执行（INT-FR02） |
| 只读 | 页面不提供重试与修复按钮；Mock不模拟修复动作（修复在系统集成中心） |

### 3.5 存储与重置

| 项目 | 规则 |
| :--- | :--- |
| 存储 | 本地演示数据（`localStorage`）；刷新保留，重置演示数据后恢复初始值 |
| 只读一致性 | Mock数据为静态展示数据，不因页面操作改变（本模块无业务操作）；列表与详情读取同一份数据 |
| 标注 | 页面标注「演示数据」或「Mock」角标，与正式能力区分 |

### 3.6 不做的事

- 不模拟结果回传、自动审核、库存记账与推送财务ERP（真实链路在渠道与集成侧）；
- 不模拟订单的建单、编辑、取消、关闭与人工处理；
- 不模拟FBA消费者订单、FBA备货与领星侧的销售链路；
- 不把Mock数据写入主PRD验收标准；Demo验证不代表真实接口、并发或后端事务已验证。

## 4. 跨页跳转与演示边界

| 跳转 | 起点 | 终点 | 保留状态 |
| :--- | :--- | :--- | :--- |
| 进详情 | 列表订单编号 | 跨境电商订单详情 | 返回列表保留查询条件与页码 |
| 看结果单 | 详情销售出库单／销退入库单Tab单号、异常回传记录的关联结果单 | 对应结果单详情 | 返回本页保留查询条件与页码 |
| 导出 | 列表页头 | 导出中心 | 不适用（异步任务） |

演示边界：订单页只展示渠道已经发生的结果，页面上不出现占库、下推仓、发货指令与任何写操作，也不出现FBA入口；结果单页由对应套件实现，本模块只约定跳转关系。

## 5. 验收场景

| 场景 | 前置 | 操作 | 预期 |
| :--- | :--- | :--- | :--- |
| 无弹窗 | 任意订单 | 在列表与详情尝试触发弹窗动作 | 无二次确认、无表单弹窗；仅跳转与只读展示 |
| 数据一致 | Mock含一张订单两次出库 | 对照订单行累计数量与销售出库单Tab合计 | 两者一致；行数不因两次出库增加 |
| 空态 | Mock含无关联结果的订单 | 打开详情 | 两个Tab展示空态文案；无异常记录时不展示异常卡片 |
| 异常只读 | Mock含未处理异常 | 打开详情异常回传记录 | 只读展示；无处理按钮 |
| 无FBA入口 | 任意订单 | 查看列表、查询区与详情 | 无FBA筛选、字段与入口；Mock中无FBA数据 |
| 跳转闭环 | 有两次出库关联的订单 | 点Tab单号再返回 | 目标页打开；返回本页保留查询条件与页码 |
| 刷新保留 | 任意订单 | 刷新页面 | 数据保持一致（localStorage） |

Demo 验证Mock数据、页面呈现与跳转；不代表生产接口、并发或后端事务行为。
