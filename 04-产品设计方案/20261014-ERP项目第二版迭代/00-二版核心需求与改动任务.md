## 一、迭代目标（一句话）

把 **B2C 电商仓 + 聚水潭/领星** 的采购执行与销售结果归集做成可设计、可验收的完整链路：国内/跨境两套集成映射，订单侧用「国内电商订单」「跨境电商订单」承接追溯，库存与业财仍由 **采购入库单、销售出库单、销退入库单** 等结果单承载；同时补齐第一版欠账——**独立站订单、国内电商订单、跨境电商订单**三套订单对象（含详情页）与相关 PRD 套件、用户与权限、初稿评审与交付清单收尾纳入本轮。

## 二、已确认的核心需求

### 2.1 集成与映射

| 项 | 结论 |
| --- | --- |
| 聚水潭 vs 领星 | **两套**独立接口与映射（国内一套、跨境一套），不共用一套「电商 ERP」抽象配置 |
| 采购出站（仅 B2C 电商仓） | 强盛 **采购收货通知单** → 映射为渠道侧 **采购/入库类执行单据**（产品侧常称采购单/入库指令）→ 渠道下推其对接仓库 → 仓内实收 |
| 采购入站 | 渠道 **入库结果** 回传强盛 → 匹配通知/订单行 → 生成（或完成）**采购入库单** → 增加对应 **逻辑仓** 库存 → 已审核结果 **推金蝶** |
| 采退出站/入站（仅 B2C 电商仓） | 强盛 **采退发货通知单** → 映射为渠道侧出库类执行单据 → 渠道下推其对接仓库 → 仓内实际出库 → 渠道 **出库结果** 回传强盛 → 生成（或完成）**采退出库单** → 扣减对应 **逻辑仓** 库存 → 已审核结果 **推金蝶** |
| 销售履约主控 | 平台订单在 **聚水潭/领星** 抓单、占库、打单、下推仓；强盛 **不下发发货指令**，避免二次发货 |
| 销售入站 | 渠道 **出库/退货入库结果** 回传强盛 → 校验通过 → **已审核销售出库单 / 销退入库单** → 记库存 → 推金蝶 |

### 2.2 仓库与渠道路径（谁走哪条链）

| 场景 | 路径 |
| --- | --- |
| B2C **电商仓**（实体仓经聚水潭/领星衔接） | 采购：**通知 → 渠道采购/入库指令 → 仓 → 回传 → 采购入库单**；采退同链路（**发货通知 → 渠道执行 → 回传出库结果 → 采退出库单**）；销售：平台 → 渠道 → 仓 → 渠道 → 强盛结果单 |
| **自营仓 + 直连 WMS** | 维持第一版：**通知/订单直推 WMS**，**不**生成渠道采购单 |
| **Shopify 独立站** | 维持第一版特殊：**ERP 拉单、审核、直推自营 WMS**；**不走**「通知 → 渠道采购单」；采购收货若进自营仓仍走直连 WMS |

### 2.3 订单对象（替代「外部原始订单」）

| 对象 | 范围 | 说明 |
| --- | --- | --- |
| **国内电商订单** | 聚水潭、国内平台 **自发货** | 承接平台/渠道单号、店铺、行与金额快照、履约状态；关联 N 张销售出库单 / 销退入库单 |
| **跨境电商订单** | 领星、跨境 **自发货 only** | 同上；**不包含 FBA 消费者订单** |
| **FBA** | 不进入上述两单归集链 | **不驱动**强盛逻辑仓增减（与消费者段相关的销售出库不在此迭代）；头程备货仍按调拨/在途（第一版库存规则），不在此重复定义 |
| **外部原始订单** | **取消作为正式单据类型/菜单名** | 平台单号、渠道单号等为 **国内/跨境电商订单上的字段**；结果单关联按**分两张**处理（来源国内电商订单 / 来源跨境电商订单），不采用「来源电商订单 + 国内/跨境类型」的合并写法（2026-10-14 确认） |

独立站订单对象与菜单 **不变**（第一版「独立站订单」），与国内/跨境电商订单并列，不合并。

### 2.4 结果处理与业财

| 项 | 结论 |
| --- | --- |
| 自动审核 | 渠道回传出库/退货结果 → 商品、逻辑仓、库存校验 **通过** → **自动生成已审核** 销售出库单 / 销退入库单 → 记库存 → 排队推金蝶 |
| 异常 | 匹配失败、库存不足、重复回传等 → **不记账、不推财务** → 「结果处理」类异常 → 修复后 **处理原记录**（不重复履约、不另造业务） |
| 业财范围 | 仍仅 **七类已审核结果单** 推金蝶；不因新增订单对象增加第八类 |

### 2.5 与第一版/课件口径的差异（须在 01/02/03 修订时写清）

| 主题 | 第一版/番外已写 | 第二版增量 |
| --- | --- | --- |
| 向 SaaS 推采购 **入库结果**（虚拟库存） | 一期 **不推** | 仍 **不推**「已完成采购入库单」做渠道加库存；改为 **推收货通知 → 渠道执行 → 收回入库结果** |
| Amazon FBA 消费者销售 | 业务设计曾写 FBA 消费者销售归集 | 本迭代 **跨境电商订单不含 FBA**，FBA **不影响**强盛库存；须在 03 销售与履约 **修订** |
| 外部 ToC 统称 | 「外部电商」+ 外部原始订单 | 拆为 **国内电商订单 / 跨境电商订单**，去掉外部原始订单类型名 |

## 四、设计时须遵守的约束（防重做）

1. **一套实物作业只驱动一次**：强盛通知与渠道指令不能导致仓收两次货；映射层写清幂等与取消边界。  
2. **强盛采购订单**仍是商务主数据；渠道侧单据仅为 **执行映射**，不是第二份采购合同。  
3. **库存唯一入账点**：逻辑仓增减只发生在强盛 **结果单** 生效时，不在「电商订单」上直接改库存。  
4. **Shopify、自营直连、B2C 电商仓** 三条路径在文档与导航上必须可一眼区分。  
5. 接口字段与渠道产品名 **待联调核验** 的，在 PRD 中标「待确认」，本表结论不变。
