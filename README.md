# 强盛科技自研 ERP 项目

这是一个基于“强盛科技”虚拟企业发展史的供应链ERP产品设计与前端原型项目。

故事从阶段4开始：2020年下半年，前台完成领星、聚水潭切换后，后台主链条仍断在金蝶与各仓储节点之间。公司决定从0到1自研ERP，作为衔接外部SaaS与金蝶的**后台业务中枢**。

这个仓库记录的重点，不只是一个ERP页面长什么样，而是**一个企业为什么需要自研ERP，以及如何从业务问题一步步落到系统设计和可交互原型**。

> 项目中的强盛科技、时间、规模、财务指标和业务数据均为课程演练设计的虚拟内容，不代表任何真实企业的公开资料或经营数据。

## 怎么读这个项目

README只说明**目录分工和阅读方法**，不维护具体文件清单。新增或调整文档时，放进对应目录即可，**不必改README**。

首次了解项目时按下列层级阅读；局部任务先读直接依据，缺少背景或发现冲突时再向上追溯：

| 层级 | 目录 | 回答什么 | 怎么找 |
| --- | --- | --- | --- |
| 1. 立项背景 | `01-全局背景信息/` | 公司什么样、为什么做、系统怎么衔接、跨模块规则怎么约束 | 按文件名序号读：`1.`–`3.` 讲公司与系统分工，`4.` 是全局业务规则，`5.` 是单据分层，`6.` 是编码与通用字段规则 |
| 2. 模块需求 | `02-需求调研和分析/` | 某个业务模块做什么、有哪些单据 | 进入对应模块子目录 |
| 3. 业务设计 | `03-业务分析和设计/` | 各业务域如何协作、规则如何闭环 | 从业务蓝图进入对应模块设计 |
| 4. 产品设计 | `04-产品设计方案/` | 字段、PRD、流程图 | 按模块或版本子目录查找 |
| 5. 可交互原型 | `09-产品原型/` | 页面长什么样、能点什么 | 看 `src/config/implementedPages.js` 的 `IMPLEMENTED_PAGE_IDS`（真正开放的页面）；`src/config/pages.js` 会给未实现菜单自动挂占位页 |

资料按事项分工：背景与全局约束看01，需求范围与验收看02，业务运行规则看03，字段及目标系统行为看04，当前实现看09代码；`00-草稿对话` 是历史素材，仅供人工回看，AI 不主动读取。实现不自动覆盖已确认设计；冲突处理见[根AGENTS.md](AGENTS.md)。文内标记“待确认”的，不算最终方案。

## 这个仓库适合学习什么

1. **ERP相关知识**：ERP、WMS、渠道SaaS、财务系统如何分工，数据如何在系统间流转。
2. **产品设计知识**：从业务背景到需求调研、单据、字段、PRD、原型的逐层拆解。
3. **AI产品经理工作流**：用AI辅助整理与分析；业务取舍仍由产品经理判断。

## 本地运行

```bash
cd 09-产品原型
npm install
npm run dev
```

默认地址：<http://localhost:5180>。技术栈：React、Vite、Tailwind CSS。

构建说明：`npm run build` 还会执行 `scripts/prepare-sites-build.mjs`（生成 Sites 产物），要求本地存在 `.openai/hosting.json`（该文件不随仓库分发，已被 .gitignore 忽略）；CI（`.github/workflows/deploy.yml`）使用 `npx vite build`，只发布 `dist/client`，与本地构建链路不同。
