# 强盛科技自研 ERP 项目

这是一个基于“强盛科技”虚拟企业发展史的供应链 ERP 产品设计与前端原型项目。

故事从强盛科技发展到阶段 4 开始：业务规模扩大，销售渠道、仓储节点和外部系统越来越多，原有的 Excel、金蝶以及渠道 SaaS 已经无法独立承接后台业务。公司因此决定从 0 到 1 建设自己的 ERP，并逐步梳理业务流程、系统边界、单据关系、字段口径和产品原型。

这个仓库记录的重点，不只是一个 ERP 页面长什么样，而是**一个企业为什么需要自研 ERP，以及如何从业务问题一步步落到系统设计和可交互原型**。

> 项目中的强盛科技、时间、规模、财务指标和业务数据均为课程演练设计的虚拟内容，不代表任何真实企业的公开资料或经营数据。

## 这个仓库适合学习什么

这个项目会持续迭代，适合产品经理结合一个连续发展的业务案例，学习下面几类内容：

1. ERP 相关知识：从企业背景、业务流程和系统边界出发，理解 ERP、WMS、SRM、渠道系统和财务系统如何分工，以及业务数据和单据如何在系统之间流转。
2. 产品设计知识：学习如何拆解业务对象、角色、流程、单据、状态、字段、PRD、页面骨架和交互原型，并沉淀可以复用的通用产品知识组件。
3. AI 产品经理工作流：观察如何把 AI 用在资料整理、需求分析、字段候选发现、跨文档一致性检查、PRD 编写、原型迭代和结果验证等环节。AI 可以提高整理和分析效率，但业务事实、规则取舍和最终验收仍然需要产品经理判断。

项目会随着内容和原型的推进逐步补充，不保证每个学习主题在当前版本都已经完整展开。

## 内容的时效性与阅读方式

这个项目不是一次性写完的静态资料，而是一个持续迭代的产品设计项目。README 主要承担长期入口、项目定位和资料导航的职责，不保证随着每一次字段、流程或页面调整同步更新。

| 内容类型 | 典型内容 | 阅读时的处理方式 |
| --- | --- | --- |
| 长期基线（相对稳定） | 项目定位、学习目标、资料目录、文档职责和基本业务背景 | 可以作为理解项目的稳定入口，但项目方向发生变化时也会调整 |
| 当前设计（随版本变化） | 当前模块范围、业务规则、字段清单、PRD、页面范围和原型实现 | 具有版本时效性，具体问题应回到对应文档或当前代码核对 |
| 临时、待确认或时效性内容 | `Mock` 数据、演示指标、页面数量、构建设置信息、规划项，以及标记为“待确认”“示意”“规划中”的内容 | 不代表最终业务事实，可能在后续迭代中被修改、替换或删除 |

遇到内容不一致时，按下面的顺序判断：

1. 项目“是什么、为什么做、如何阅读”，以 README 为长期入口。
2. 业务边界、规则、流程和单据关系，以对应的全局背景、需求调研、PRD 和字段清单为准。
3. 字段名称、类型、枚举和页面投影，以当前字段清单为准；页面实际能做什么，以 `09-产品原型/src/` 当前代码为准。
4. 标记为“待确认”“示意”“Mock”或“规划中”的内容，只能作为当前讨论或演示材料阅读，不能直接当作最终方案。

因此，README 中的“当前状态”“当前原型范围”和技术版本都属于快照信息。后续即使 README 没有同步更新，也应优先查看具体文件的最新内容、原型代码和 Git 提交记录。

## 当前已经明确的业务边界

目前文档已经把以下边界写清楚：

1. 强盛科技采购和销售的主要对象是成品 SKU，不在本项目中建设生产制造、BOM 和 MRP。
2. 商品模块负责成品 SKU 主数据，包括编码、名称、品类、单位、条码、物理属性、规格说明和供应来源信息。
3. 采购模块负责供应商档案、采购申请、采购订单、采购入库，并为采购付款、采购退货和供应商协同预留后续设计空间。
4. 采购订单记录采购约定，本身不直接增加逻辑库存；实际入库确认后，才更新库存和供应商应付等后续结果。
5. 国内仓的实物收货、质检和上架由第三方 WMS 执行，ERP 负责业务单据和逻辑结果的承接。
6. 领星、聚水潭和金蝶不会因为建设自研 ERP 就被简单替换，项目会逐项明确各系统的职责边界和数据交互方向。

这些内容仍然会随着后续走查和模块设计继续细化。背景文档、需求调研、字段清单、PRD 和原型之间存在明确的职责分工，阅读时应以对应层级的文档为准。

## 本地运行原型

需要 Node.js 环境。在仓库根目录执行：

```bash
cd 09-产品原型
npm install
npm run dev
```

开发服务器默认地址为：<http://localhost:5180>

原型使用的主要技术：

- React 19
- Vite 6
- Tailwind CSS 3
- Radix UI 部分组件
- `lucide-react` 图标
- 浏览器 `localStorage` Mock 数据持久化

## 当前状态

这是一个持续演进中的产品设计项目，不是已经上线运行的完整 ERP。项目会继续补充业务资料、产品设计和前端原型。以当前仓库状态为例，已经具备：

- ERP 项目全局背景和基础边界；
- 商品、采购模块的需求调研；
- 商品资料字段清单；
- 可在线访问的采购订单与采购入库前端原型。

尚未全部完成的内容包括完整的销售、库存、仓储、财务、外部系统集成模块，以及与这些模块对应的全套 PRD、字段清单、状态机、接口规范和前端页面。后续会继续按“业务背景 → 需求调研 → 流程与单据 → 字段与 PRD → 原型 → 走查”的顺序补齐。
