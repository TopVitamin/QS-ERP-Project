## 一、公司概况

### 1.1 基本信息

| 维度 | 说明 |
| --- | --- |
| 公司全称 | 深圳市强盛科技有限公司（QS-Tech） |
| 公司性质 | 有限公司，还没启动股份制改造 |
| 成立时间 | 2016 年正式注册 |
| 总部 | 中国深圳 |
| 创始人 / CEO | 林强 |
| 企业定位 | 品牌商和供应链链主：自己做研发设计和品牌运营，生产交给代工厂，不自建重资产工厂 |
| 经营模式 | 向代工厂 / 供应商买成品，再卖到各渠道 |
| 销售渠道 | Amazon、天猫、京东、Shopify 独立站、国内 B2B 批发，线上为主 |

### 1.2 规模

| 维度 | 说明 |
| --- | --- |
| 营收 | 约 3 亿元 |
| 员工 | 从近百人接着往上扩 |
| 活跃 SKU | 大约 3,500，低效品已经砍过一轮，走大单品精品 |
| 供应商 | 200 多家成品供应商，其中参股 3 家核心代工厂（线材、充电头、充电宝） |
| 仓储 | 深圳自营主仓、东莞第三方电商仓、Amazon FBA、第三方海外仓 |
| 跨境占比 | 营收一半以上 |

### 1.3 眼下在干什么

卖的是 GaN 充电器、数据线、移动电源这类成品。产品中心定款、做设计，生产委托代工厂。

货主要卖到 Amazon 欧美站，天猫和京东，Shopify 独立站，以及国内 30 多家代理商和大客户。

货从 200 多家供应商进来，核心产能绑在 3 家参股代工厂上。成品先入国内仓，再按渠道备到 FBA 或第三方海外仓。

现在要做的事，是从 0 到 1 建设一套自研 ERP，逐步承接公司确认过的采购、销售和相关业务单据。领星、聚水潭继续承担电商侧履约，金蝶继续承担其现有工作。具体单据范围以后续确认的项目文件为准。

## 二、四条业务线

| 业务线 | 渠道与客户 | 履约 | 结算 | 业务特点 |
| --- | --- | --- | --- | --- |
| 跨境 B2C | Amazon 欧美站 | 国内头程 → FBA 上架 → 亚马逊派送；从国内备货到 FBA 可用大约 75–105 天 | 大约 14 天回款，扣佣金和 FBA 费 | 履约链路长，订单和履约结果涉及领星 |
| 海外独立站 | Shopify 品牌官网 | 多半从深圳仓直发，一部分走第三方海外仓 | 支付通道实时或 T+2 | 订单可直接接入自研 ERP |
| 国内 B2C 电商 | 天猫旗舰店、京东 | 东莞第三方电商仓发货，大约 48 小时履约 | 平台按账期结算 | 订单和履约主要在聚水潭侧完成 |
| 国内 B2B 批发 | 30 多家代理商 + 企业大客户 | 深圳仓整车出库或自提 | 赊销月结，卡授信 | 订单直接在自研 ERP 产生 |

| 节点 | 实物谁管 | 当前业务用途 |

| FBA | 亚马逊托管，领星提供相关信息 | 跨境官方派送 |
| 第三方海外仓 | 3PL | 独立站部分海外订单的本地履约 |

## 五、业务怎么转

### 5.1 电商 ToC

```plain
Amazon / 天猫 / 京东订单
    → 进入领星 / 聚水潭
    → 在领星 / 聚水潭完成履约
    → 履约结果单据同步一份到自研 ERP
    → 自研 ERP 推送给金蝶
```

### 5.2 B2B 和直接接入自研 ERP 的订单

```plain
B2B / 直接接入自研 ERP 的订单
    → 自研 ERP 生成销售订单
    → 自研 ERP 生成销售发货通知单
    → 自研 ERP 生成销售出库单等业务单据
    → 自研 ERP 推送给金蝶
```

### 5.3 采购

```plain
向供应商 / 代工厂采购成品
    → 当前先确认采购订单
```

采购订单之外的采购单据和处理规则，暂不在本文展开。

几件背景事实需要先认清：

- 买的、卖的都是成品，没有生产环节。代工厂车间和 BOM 不进强盛系统。
- 公司同时使用领星、聚水潭和金蝶，另外还有深圳仓现场、东莞仓作业系统、Excel 和微信等现有工作方式。
- 1 号文件只说明公司背景，不定义库存、状态、调拨、退货或其他未确认业务规则。

## 六、为什么要立项

体量上来之后，公司需要把分散在不同系统和线下工作方式中的业务信息逐步收拢。当前可见的问题包括：

| 问题 | 背景表现 |
| --- | --- |
| 跨境与国内履约节奏不同 | 跨境链路较长，国内电商履约时效较快 |
| 供应商交付信息分散 | 采购沟通和交期信息依赖线下方式 |
| 多渠道业务并行 | Amazon、国内电商、独立站和 B2B 同时经营 |
| 多个仓储节点并存 | 自营仓、第三方电商仓、FBA 和第三方海外仓各有执行方 |
| 业务与财务信息分散 | 订单、采购及其他业务资料分布在不同系统和线下文件中 |

以上内容用于说明项目背景，不代表已经确认的一期功能范围。

## 七、现有系统

| 系统 | 当前承担的工作 |
| --- | --- |
| 金蝶云·星空 | 财务核算，以及部分现有业务工作 |
| 领星 | Amazon 运营、FBA 相关工作、跨境侧履约 |
| 聚水潭 | 天猫 / 京东抓单和电商侧履约 |
| 深圳仓现场 | 收货、拣货、装柜等现场工作 |
| 东莞仓作业系统 | 国内电商仓内作业 |
| Excel / 微信 | 采购跟踪、批发开单、供应商沟通等线下工作 |
| 自研 ERP | 待从 0 到 1 建设，具体功能以确认后的项目文件为准 |

当前各渠道和仓储节点各自承担一部分业务，项目目标是逐步建立自研 ERP，并明确它与领星、聚水潭、金蝶之间的业务单据交互关系。
