## 二、从哪来：阶段 3 到阶段 4 的关键变化

阶段3（2016–2018）靠“金蝶云·星空 + 店小秘 + 旺店通 + Excel”跑通了约1.2亿元规模。跨入阶段4后，三条变化把原有模式顶到了上限：

| 变化 | 具体表现 |
| --- | --- |
| 体量跃升 | 营收从约1.2亿跨入3亿区间，SKU精简至约3,500，走GaN等精品路线 |
| 供应链周期割裂 | 跨境补货完整周期约75–105天（代工厂生产30–45天 + 海运头程45–60天），国内电商要求48小时履约，长短周期交织 |
| 渠道扩张 | 2020年下半年新增京东店铺（强盛自主经营），Shopify独立站由试水转为正式业务线；eBay、淘宝店等资源向主渠道集中 |

### 前台先升级，后台仍接不住

2020年下半年，公司先把前台渠道SaaS做了升级：**领星**替换店小秘承接Amazon运营与跨境履约，**聚水潭**替换旺店通承接天猫、京东的高并发打单发货。这一步解决了各自渠道内的运营和履约问题。

但跑了几个月后，领星、聚水潭与财务ERP之间仍缺自动贯通：采购交期协同、跨仓库存视图、独立站订单、业财单据归集等关键链路，仍要靠人工导出、Excel台账和微信补齐。**没有一个系统能横跨领星、聚水潭、财务ERP和多个仓储节点，把后台主链条串起来。**

因此公司决定从零自研ERP，定位不是替换领星或聚水潭，而是作为**衔接外部三方SaaS和财务底座的业务中枢**。

## 三、四条业务线

| 业务线 | 渠道与客户 | 履约链路 | 结算 | 供应链压力 |
| --- | --- | --- | --- | --- |
| 跨境B2C | Amazon欧美站 | 国内头程 → FBA上架 → 亚马逊派送；补货完整周期约75–105天 | 约14天回款，扣佣金和FBA费 | 营收占比超50%；头程在途长，断货和滞销风险并存；订单和履约在领星 |
| 国内B2C电商 | 天猫旗舰店 + 京东店铺（强盛自主经营） | 东莞菜鸟仓发货，约48小时履约 | 平台按账期结算 | 大促脉冲强，和跨境共享库存时容易抢货、超卖；订单和履约在聚水潭 |

| 国内B2B批发 | 30多家代理商 + 企业大客户 | 深圳仓整车出库或自提 | 赊销月结为主 | 单笔货值大、场景非标：常临时改量改价、分批发货、现场提车；当时财务ERP的标准开单方式未覆盖这些灵活场景 |

## 四、仓在哪、各管什么

东莞地处珠三角制造带，紧邻深圳总部与代工厂集中区，是国内电商发货枢纽。

```plain
                               ┌── 深圳自营主仓（约 5,000㎡）── B2B 批发、跨境头程集货装柜、独立站直发
                               │   还没有专业 WMS，收发靠财务ERP简易仓储模块和现场工具
公司现有仓储节点 ─────────────┼── 东莞第三方电商仓（菜鸟仓）── 天猫 / 京东订单履约
                               ├── Amazon FBA 仓 ──────────── 跨境官方派送
                               └── 第三方海外仓（3PL）─────── 独立站部分海外单本地履约
```

| 节点 | 实物谁管 | 当前业务用途 | 系统连接情况 |
| --- | --- | --- | --- |
| 深圳自营主仓 | 仓管现场作业 | B2B出库、跨境头程集货、独立站直发 | 财务ERP简易仓储 + 现场纸单；与领星、聚水潭无自动库存联动 |
| 东莞第三方电商仓 | 仓方作业系统 | 天猫 / 京东电商履约 | 聚水潭对接打单发货；与深圳仓、FBA库存视图割裂 |
| FBA | 亚马逊托管 | 跨境B2C官方派送 | 领星提供FBA库存和货件信息；与国内仓不互通 |
| 第三方海外仓 | 3PL | 独立站部分海外订单本地履约 | 由跨境侧分别管理，未纳入统一库存视图 |

## 六、立项时业务怎么跑

以下描述的是**立项当时已在运行的业务方式**，不是自研ERP建成后的目标态。

### 6.1 电商 ToC（领星 / 聚水潭各管一段）

```plain
Amazon 订单 → 领星抓单、FBA 履约、运营分析
天猫 / 京东订单 → 聚水潭抓单、东莞菜鸟仓打单发货

履约完成后 → 部分结果进入财务ERP；与采购、B2B、其他仓的库存和单据未打通
```

### 6.2 B2B 批发、采购、独立站（财务ERP管基础进销存，关键链路仍断）

阶段3起，B2B销售和采购入库就在金蝶云·星空里跑。立项时的问题不是“没用财务ERP”，而是当时财务ERP的部署和使用方式只覆盖了基础单据，尚未贯通多渠道、多仓和供应商协同：

```plain
B2B 批发
    → 财务ERP能录标准销售订单、做出库过账
    → 实际业务更灵活：大单临时调价、分批发货、客户现场提车、账期结算方式各异
    → 业务员往往先微信 / 电话谈妥，再事后补单，或用 Excel 记变通，系统里只有「标准版」
    → 缺一个专门承接 B2B 灵活场景的模块，而不是在财务ERP上硬套固定模板

采购
    → 财务ERP下采购订单、做采购入库
    → 交期跟进、代工厂进度、物料齐套靠采购员微信问、Excel 记台账
    → 备货量靠人工从领星 / 聚水潭 / 财务ERP各自导出销量和在途后估算，没有统一计划模型

Shopify 独立站
    → 订单未接入财务ERP或领星 / 聚水潭，发货靠人工协调深圳仓或海外仓
```

### 6.3 业务和财务怎么汇总

```plain
月末财务（阿兰）→ 从领星导出跨境账单、从聚水潭导出国内发货明细、从财务ERP导出成本账
                → 三套系统 SKU 编码不一致，靠 Excel 映射表手工拼
                → 月结关账约 7 天，单品和渠道真实毛利算不清
```

## 七、现有系统

| 系统 | 当前承担的工作 | 当时尚未覆盖或贯通的工作 |
| --- | --- | --- |
| 领星 | Amazon运营、PPC广告、FBA货件与跨境侧履约 | 国内电商、B2B、采购主链条、统一库存视图 |
| 聚水潭 | 天猫 / 京东多店铺抓单、电子面单、大促批量发货 | 跨境FBA、B2B灵活批发、采购协同、业财中枢 |
| 金蝶云·星空 | 财务核算、B2B销售与采购的基础进销存、深圳仓简易仓储 | 电商履约、代工厂协同、跨渠道库存防超卖、与领星 / 聚水潭自动贯通 |
| 深圳仓现场 | 收货、拣货、装柜等实物作业 | 库位管理、批次追溯、与前台系统库存联动 |
| 东莞仓作业系统 | 国内电商仓内作业 | 与深圳仓、FBA的统一调度 |
| Excel / 微信 | 采购交期台账、供应商沟通、月末多系统对账拼表 | 无法替代业务系统，也形不成可追溯的单据链 |
| 自研ERP | **尚未建设**；公司已决定从零搭建，作为衔接中枢 | — |

上述缺口是公司决定自研ERP的直接背景，描述的是本项目立项时的部署和使用情况，不是对外部产品全部能力的判断。
