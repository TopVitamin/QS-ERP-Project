## 三、业务怎么转（一条链路看懂）

```plain
选品上架（定 SKU）
    ↓
向供应商采购成品（下单 → 到货）
    ↓
入库（第三方 WMS 管国内仓 / 领星管 FBA 仓）
    ↓
各渠道销售（跨境 / 国内电商 / B2B 批发）
    ↓
发货出库 → 对账 → 金蝶入账
```

**三个关键事实**：

1. **采购和销售的都是成品**，没有生产环节。
2. **库存分散在多个系统**：国内仓在第三方 WMS，FBA 在领星，国内电商在聚水潭——互不相通。
3. **后台靠 Excel 补洞**：商品资料、采购单、批发单散落在金蝶和 Excel 里，越来越乱。

## 四、当前痛点（为什么需要 ERP）

### 4.1 业务痛点

| 痛点 | 通俗说法 |
| --- | --- |
| **采购交期不清楚** | 问供应商「货什么时候到」，只能靠微信问，经常耽误上市 |
| **渠道抢库存** | 天猫卖超了，亚马逊还在卖，同一批货没人统一调度 |
| **大促容易乱** | 双十一订单暴涨，发货出错、超卖时有发生 |
| **对账对不上** | 月底财务要对好几个系统的数据，经常对不齐 |

### 4.2 系统痛点

| 痛点 | 通俗说法 |
| --- | --- |
| **商品资料乱** | 金蝶、Excel、领星、聚水潭各维护一套 SKU，经常不一致 |
| **后台太弱** | 采购、批发等核心流程还在 Excel 里跑，撑不住业务体量 |
| **库存看不全** | 第三方 WMS、领星、聚水潭各管一段，没有全局库存视图 |
| **业财断裂** | 业务在多个系统跑，财务只在月末人肉汇总推金蝶 |

## 五、现有系统（一张表看懂）

| 系统 | 干什么 | 问题 |
| --- | --- | --- |
| **金蝶云·星空** | 财务记账 | 只管钱，不管货；商品和采购能力弱 |
| **第三方 WMS** | 国内仓入库、出库、管库存 | 和渠道系统没打通 |
| **领星** | 亚马逊订单 + FBA 库存 | 只管跨境，和国内仓割裂 |
| **聚水潭** | 天猫 / 京东打单发货 | 只管国内电商，和跨境割裂 |
| **Excel / 微信** | 供应商对账、临时记账 | 靠人工，容易出错 |
| **自研 ERP** | 商品、采购、销售、库存、对账中枢 | **还没建，本项目要做的事** |

**一句话总结**：渠道和仓库各用各的系统，后台靠 Excel 撑着——**需要建一个 ERP 把后台收回来，把库存和订单拉通**。
