# 强盛ERP全局业务规则与约束

> 更新日期：2026-09-20。依据本轮需求调研与分析中的已确认结论整理。三层通知单的仓库执行与虚拟入出库见[单据分层设计](5.强盛ERP的单据分层设计.md) §5.10。
>
> 本文面向产品、研发、测试及AI，集中说明一期跨模块业务规则、强约束及适用边界，不是AI工作指令。项目范围见第2篇，系统链路见第3篇；详细规则仍由对应模块维护，本文不新增业务决策，也不替代模块中的待决策事项。

## 一、业务对象与归属

| 对象 | 已确认规则与约束 | 原文依据 |
| --- | --- | --- |
| 商品 | 只管理成品SKU，不建立SPU，不管理原材料、BOM、MRP和生产物料。初始供应商用于初始采购价格归属，不建立商品与供应商供货关系，也不强制SKU只能对应一家供应商。建档后初始供应商和初始价格不能改，变价走价格调整单 | [主数据分析](../02-需求调研和分析/01-商品与主数据/商品与主数据需求分析.md) §一、MD-FR09；[采购分析](../02-需求调研和分析/02-采购业务管理/采购业务管理需求分析.md) §一 |
| 实体仓与逻辑仓 | 实体仓表示实际仓储节点，逻辑仓由人工划分，选择正常品、残次品或待检品；同一库存状态可有多个逻辑仓。逻辑仓不等于物理库位 | [主数据分析](../02-需求调研和分析/01-商品与主数据/商品与主数据需求分析.md)“仓库结构与单据链路确认” |
| 库存结果归属 | 有ERP原单时沿用原单指定逻辑仓；无原单时依据来源信息和映射判断。不能仅因回传由仓库主动发起就重新分仓；归属依据不足不得任意选仓记账 | [主数据分析](../02-需求调研和分析/01-商品与主数据/商品与主数据需求分析.md)“仓库结构与单据链路确认” |
| ToC客户 | 国内电商、跨境电商分别使用通用2C客户，独立站使用跨境电商2C通用客户；不按消费者逐一建客户档案，不将消费者资料逐条追加到通用档案 | [主数据分析](../02-需求调研和分析/01-商品与主数据/商品与主数据需求分析.md)“客户设计确认补充” |

档案资格不采用一条笼统的“父级一禁，全部禁用”规则。实体仓禁用只限制新增逻辑仓关联，既有逻辑仓按自身资格使用；物流商禁用不影响既有启用服务产品；上级商品分类禁用不级联下级。逻辑仓自身可以禁用，有库存或未完成单据不阻断；新单不能再选，已有业务继续。具体引用和删除条件分别见主数据及[辅助资料分析](../02-需求调研和分析/09-辅助资料/辅助资料需求分析.md) AUX-FR04。

## 二、库存记账与数量控制

| 规则 | 适用范围与限制 | 原文依据 |
| --- | --- | --- |
| 可用库存＝即时库存－预占库存－冻结库存 | 即时库存是ERP账上实物数量口径，不保证任意时刻均与仓库实物一致；预占、冻结只限制可用量 | [库存分析](../02-需求调研和分析/03-库存与仓储/库存与仓储需求分析.md) INV-FR01 |
| 库存流水 | 一期提供流水查询，按逻辑仓、商品、时间查，能点进对应结果单 | 库存分析INV-FR01 |
| 入库依据实际结果 | 采购订单、入库申请或通知不增加库存；采购未入库数量不在库存模块记录或展示 | 库存分析INV-FR01、INV-FR06 |
| 审核预占，实际出库消耗对应预占 | 适用于ERP主动承接的销售、采购退货、分步式调拨及其他出库等正常业务。通知下发不重复占库；实际出库同时减少即时库存及对应预占 | 库存分析INV-FR05 |
| 仓库已完成结果不补做预占 | 仓库主动回传的其他实际变动通过校验后形成结果单；外部ToC实际结果按销售规则处理，不套用ERP主动履约的事前审核占库流程 | 库存分析INV-FR04；[销售分析](../02-需求调研和分析/04-销售与履约/销售与履约需求分析.md) SAL-FR09 |
| 不允许负库存 | 审核预占、冻结及结果记账均需校验；处理后即时库存或可用库存为负，阻止本次生效并报错，不先记负数，也不自动释放其他订单预占 | 库存分析INV-FR09 |
| 冻结只能使用可用数量 | 不重复冻结已经预占或冻结的数量。一期由仓储运营手工冻结、解冻，不做异常自动冻结 | 库存分析INV-FR05 |
| ToC实际结果也记ERP库存 | 出库、退货入库通过匹配及库存等校验后，自动审核、生效并增减对应逻辑仓；第三方仓出库不重复扣自营仓 | 销售分析SAL-FR09 |
| 调拨只用于库存转移 | 不能用调拨替代买卖；FBA备货属于库存转移，不是消费者销售，不由此扩展头程物流管理 | 库存分析INV-FR03、INV-FR07 |
| 在途差异不自动抹平 | 分步式调拨按实际调出量通知接收；少收差异保留在途，人工后续处理。主单执行结束不代表差异已经清理 | 库存分析INV-FR03 |
| 调拨零调出按取消处理 | 分步式调拨实际调出为0时取消该分步式调拨单，不生成在途、调入通知或调出对应的直接调拨单，不改变库存、不推进主单；取消后释放未执行预占 | 库存分析INV-FR03、INV-AC13 |
| 比对不自动改账 | ERP按实体仓、SKU、库存状态汇总即时库存后与仓库比较，不用可用量、不逐个逻辑仓比较、不纳入虚拟在途；每天自动比对一次，具体钟点由技术配置。共仓的多个外部货主与本公司仓库的对应仍需核验 | 库存分析INV-FR08 |

一期不按正常品、待检品、残次品限制业务用途，有足够可用库存即可办理相应出库；品质变化通过逻辑仓间调整处理，不额外设定一套未确认的品质拦截或临时冻结规则。销售退货仍先按指定逻辑仓收货，后续品质变化再调拨。依据：库存分析INV-FR05、INV-FR07，销售分析SAL-FR05。

## 三、单据执行不能一概而论

订单或申请表达业务安排；执行指令通常由通知单承担，也可由订单、申请单直接承担；结果单记录实际发生的业务。处理方式写在通知单上：仓库收货／仓库发货时，通知单创建后由系统自动推送仓库，不需要人工逐单触发推送；虚拟入库／虚拟出库时不推仓库，创建后按通知数量直接生成结果单并自动审核，通知变为已收货／已发货。直接承担指令的订单或申请单（独立站、其他出入库）本期仍在来源单审核后自动发送仓库，不增加虚拟入出库。不允许因为不经仓库，就由订单或退货单直接生成入出库单。不同来源不一定都补齐这三层：仓库已执行后回传的其他出入库结果，不补申请、通知；外部ToC原订单用于追溯，不重新驱动履约。单据分层的完整模型、层数判断口径、场景映射及一次回传、超量拒绝、结果单审核、虚拟入出库等共用规则见[单据分层设计](5.强盛ERP的单据分层设计.md)。

### 3.1 分批、缺量与结束

| 场景 | 已确认边界 | 原文依据 |
| --- | --- | --- |
| 采购及采购退货 | 支持分批通知与执行、缺量回补；关闭后不能新增通知或反关单，关闭前已有通知继续执行与回传 | [采购分析](../02-需求调研和分析/02-采购业务管理/采购业务管理需求分析.md) PUR-FR02～PUR-FR05 |
| B2B正向及销售退货 | 支持分批；B2B出库通知一次执行结束，少出回补可下推额度，补发另建通知；全部发货后立即自动关单；关闭后不再下推，不能把额度回补理解为重复占库 | [销售分析](../02-需求调研和分析/04-销售与履约/销售与履约需求分析.md) SAL-FR02、SAL-FR03、SAL-FR06 |
| Shopify独立站 | 一期人工批量选仓、选物流并审核占库，审核通过后自动推送仓库，整单履约，不拆单缺量发货；订单直接承担执行指令，不再生成发货通知单；不套用B2B到期自动关单规则 | 销售分析SAL-FR07、SAL-FR08 |
| ERP发起的其他出入库 | 申请审核后直接推送仓库（不再生成通知单）；不分批，允许缺量，按实际数量一次结束，不回补余量再次执行；不提供手动关闭，收到仓库回传的一次结果后自动完结，要中止只能取消，不设置到期自动关单 | [库存分析](../02-需求调研和分析/03-库存与仓储/库存与仓储需求分析.md) INV-FR06 |
| 直接及分步式调拨 | 直接调拨仅在ERP内部处理，不推送外部执行系统，审核后直接记账；分步式不分批、允许大于0的缺量，每端一次执行结束，未发预占释放，调入通知收到最终回传并生成第二张直接调拨单后主单自动完结，少收仍保留在途 | 库存分析INV-FR03、INV-FR07 |

### 3.2 修改、关闭与取消

- **已审核不等于可以随意改原交易。** 采购已审核订单保留原数量和价格，不做变更单；B2B已审核订单不改量改价，可按规则调整交期。不能据此统一推导全部单据的反审核、修改或冲销机制。依据：采购分析PUR-FR01、PUR-FR03，销售分析SAL-FR01。
- **ERP关闭不等于仓库取消成功。** 已通知仓库的执行部分不能因ERP关闭直接释放；收到实际结果或仓库取消成功反馈后，按对应模块规则处理。销售通知申请取消时需等待仓库确认，不能提前认定成功。依据：采购分析PUR-FR03、PUR-FR05，销售分析SAL-FR03、SAL-FR04，库存分析INV-FR06。
- **关闭、取消、执行结束的业务效果不同。** 各模块的剩余数量、占库释放和后续可操作范围分别按原文处理，不统一套用一个状态流程。未确认的状态命名、到期时点及并发处理留到详细设计。
- **零收零出统一按取消处理。** 采购通知、两层订单／申请实际数量为0时取消该执行单；分步式调拨实际调出为0时取消该分步式调拨单（主单），不是调出通知单。均不生成零数量结果单、不改变库存，取消后按各模块规则释放占用；等待执行期间不提前按零收／零出结束。依据：采购分析PUR-FR02、销售分析SAL-FR07、库存分析INV-FR03，细则见[单据分层设计](5.强盛ERP的单据分层设计.md) §5.3、§6.4、§9。

## 四、价格、业财与系统异常

| 主题 | 已确认规则与强约束 | 原文依据 |
| --- | --- | --- |
| 当前价格与成交价格 | 商品建档初始化采购价与销售基准价，后续变价通过采购／销售价格调整单；业务单据保留自身价格与税率快照，后续调价不改历史成交。一期不做价目禁用，错价用新调整单覆盖当前价 | [价格分析](../02-需求调研和分析/06-价格管理/价格管理需求分析.md) §一、§二、PRI-FR06 |
| 外部ToC金额 | 沿用SaaS成交优惠后金额及退货金额，不用ERP价目表重算；缺必要金额按异常处理，不自行补价 | [销售分析](../02-需求调研和分析/04-销售与履约/销售与履约需求分析.md) SAL-FR10 |
| 金蝶推送范围 | 仅采购入库单、采退出库单、销售出库单、销退入库单、其他入库单、其他出库单、直接调拨单，在ERP生成且已审核后自动逐单推送；不汇总，不增加财务二次审核 | [业财分析](../02-需求调研和分析/05-结算与业财/结算与业财需求分析.md) FIN-FR01 |
| 非推送对象 | 订单、申请、通知、草稿、未审核结果及分步式调拨主单不推送；分步式两端实际生成的直接调拨单分别推送 | 业财分析 §一；[库存分析](../02-需求调研和分析/03-库存与仓储/库存与仓储需求分析.md) INV-FR10 |
| 财务核算归属 | ERP不建应收应付、收付款、预收预付、核销、凭证、总账及财务对账台账。其他出入库、直接调拨不传成本价格；存货成本由金蝶核算 | 业财分析FIN-FR02、FIN-FR04 |
| 平台结算 | 平台账单、收退款、佣金、仓储履约费及回款由财务线下处理并在金蝶记账；仅退款不生成供应链单据、不影响库存 | 业财分析FIN-FR04；销售分析SAL-FR09 |
| 金蝶推送失败 | 不回滚ERP已生效结果或库存；保留失败记录，修复后在系统集成中心针对原结果单重推，不另建业务单，也不在采购入库单等业务列表提供重推按钮。成功后异常更正属于技术运维场景，不建设为普通业务用户随意改单重推的入口 | 业财分析FIN-FR03 |
| 外部ToC异常与重复结果 | 映射或库存校验失败时不记库存、不推金蝶；修复后继续原记录。已成功结果不得重复记账，已完结结果不跟随来源直接更新；不能因ERP重试再次触发已完成的仓库履约 | 销售分析SAL-FR12 |
| 人工补充结果 | 无法自动取得仓库接单、执行结束或取消结果时可人工确认实际结果；Shopify未覆盖订单可人工导入，仍须遵守业务校验及适用的提交审核 | [集成分析](../02-需求调研和分析/07-系统集成/系统集成需求分析.md) INT-FR06 |

外部ToC已确认的完结保护不自动构成所有模块的冲销更正规则；其他业务异常保存、部分成功恢复、取消并发等未逐项定义的内容，仍按模块待决策事项处理。

## 五、权限与审核边界

依据：[公共能力分析](../02-需求调研和分析/08-公共能力与系统管理/公共能力与系统管理需求分析.md) COM-FR01～COM-FR04，以及各主数据对象的专属规则。

- 一期采用RBAC，有对应权限才能提交或审核，允许本人审核本人创建的数据；权限不能绕过库存、金额和状态校验。公司组织架构不直接决定角色或审批节点。审核为单级流程：草稿提交，待审核时审核通过或驳回（主数据、价格调整单等有独立已驳回态的对象），或审核或撤回（业务安排单、结果单等无已驳回态的对象，撤回回到草稿）。操作命名见[《单据与状态流转》](../04-产品设计方案/20260812-ERP项目第一版框架搭建/系统架构和流程/03-单据与状态流转.md)。不建设多级审批、会签或条件审批流；附件/文档与单据打印／导出是否纳入一期仍待确认，见[公共能力分析](../02-需求调研和分析/08-公共能力与系统管理/公共能力与系统管理需求分析.md) §七。
- 原本需要提交审核的对象，导入后仍走原流程；物流、辅助资料等原本不审核的对象，不因导入增加审核。
- 外部ToC实际结果通过校验后自动审核，不增加常规人工审核。
- 主数据审核状态与启用／禁用状态分开，按各对象资格使用；不能把所有档案都套成同一个审核和禁用流程。
- 完整操作日志不列为一期必做，待办与消息提醒后置；已确认的集成异常、推送结果和必要处理记录必须保留。业务参数暂由技术支持／运维维护代码配置文件。

## 六、一期限制与后续确认边界

完整范围见[项目背景](2.强盛科技ERP项目的背景信息.md) §三、§四；系统分工见[上下游链路](3.强盛ERP的定义和上下游链路.md)。以下几组边界容易混淆：

| 已纳入或必须安排 | 不因此纳入或尚待确认 |
| --- | --- |
| 自营及第三方逻辑仓库存、ToC实际结果记账 | 全量库存双向同步、跨渠道配额及统一调度不纳入一期 |
| ERP发起仓间调拨、FBA备货在途 | 不扩展头程物流管理或多主体之间的购销方案 |
| 仓库盘盈盘亏结果接收 | 不建设ERP盘点单，不接管仓内作业，不自研WMS |
| 商品批次、序列号、保质期及预警配置 | 执行和采集规则仍待细化，不能仅凭配置字段认为完整追溯能力已经确定 |
| 外部映射、通知和实际结果交换 | 实际接口覆盖、字段、协议及联调仍待核验，Mock不代表真实接口已验证 |
| 上线前建立库存起点 | 初始化数量、截点、迁移及切换校验另行实施，不能按零库存直接累计上线后的结果 |
| 公共权限和审核原则 | 账号来源、具体角色、数据范围及完整状态机留到详细设计 |
