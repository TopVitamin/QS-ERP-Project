# 强盛ERP的编码规则和通用字段规则

> 更新日期：2026-09-23。依据本轮编码与通用字段规则讨论确认，结合《4.强盛ERP全局业务规则与约束》《5.强盛ERP的单据分层设计》以及需求调研与产品设计各模块文档整理。
>
> 本文是ERP一期编码和通用字段的统一规范。02《公共能力与系统管理需求分析》COM-FR03要求编码后续统一形成规范；基础资料各PRD的Q01（编码如何生成、唯一范围如何界定、建档后能否修改）在本轮按本文收口，字段清单的编码生成方式与取值说明同步指向本文。
>
> 本文只写产品和业务规则，数据库类型、索引、接口错误码和具体实现由技术设计负责。原型、Demo PRD和Mock里的编码只是演示值，不作为正式规则；本文定稿后由09原型单独一轮对齐。文中标“待确认”的条目不是最终规则，统一在第五节登记跟踪。已确认项：用户引用展示姓名；一期数量不允许小数；单价4位、金额和税额2位、尾差进税额；税率允许0%；商品默认销售税率允许为空；金额页面展示千分位、录入不带；条码全系统唯一；价目按基本单位、一期不做单位换算；主数据编码一经保存不可改；导入允许指定编码；附件单文件10MB、单次20个；银行账号不脱敏；录入导入转半角；默认标记每类最多一个；系统自动关闭时关闭原因留空；自动生成的结果单创建人、最后更新人显示「系统」；安排单和通知单列表按创建时间倒序，结果单按业务日期倒序。

## 一、单据编号规则

### 1.1 编号格式与生成规则

单据编号格式为 `{单据前缀}-{YYYYMMDD}-{序号}`，例如 `CGDD-20260818-0001`，表示2026年8月18日创建的第1张采购订单。

- 前缀取单据中文名的拼音首字母，2至8位大写字母，同一类型固定不变，对照表见1.2；尽量短，能表意即可。
- 以项目内正式单据名为准；单据名已简称的，前缀跟随简称。对照表已列明的以对照表为准；尚未列入对照表的新单据类型，按本规则拟定前缀，确认后补入对照表。
- 日期取单据创建日期，格式YYYYMMDD。
- 序号在同类型、同一天内从0001起自增，默认4位、不足补0；同类型同一天超过9999张时自动扩为5位（如10000、10001），继续自增。
- 单号在保存草稿时生成：草稿保存前须通过字段校验，校验通过后分配单号；无草稿态的单据（通知单、自动生成的结果单）在创建生成时分配；用户不可编辑，生成后不可修改。
- 作废、取消、删除后单号不重用。
- 单据之间的关联用单据上的来源单号字段表达，不把来源单号拼进编号；通知单、结果单各自独立编号。

### 1.3 外部来源单据

- 外部原始订单及结果（Shopify订单、天猫和京东经聚水潭、领星回传等）按「来源系统+来源单号」识别，不生成ERP单号。
- 独立站订单在ERP内是业务安排兼执行指令，需要ERP单号，与B2B销售订单共用前缀 XSDD。
- 平台单号、运单号等外部标识按普通字段保存，套用第四节的外部单号模板。

## 二、主数据编码规则

### 2.1 通用规则

- 编码由固定字母前缀加数字序号组成（商品和商品分类另有规则，见2.2），长度固定（币别除外，使用币别代码），不用中文、年月日和空格。
- 默认由系统自动生成；供应商、客户、实体仓、逻辑仓、物流商、物流服务产品、商品允许手工录入；辅助资料仅币别类型允许手工录入币别代码，其余类型系统生成。
- 唯一范围按对象区分：商品、供应商、客户、实体仓、逻辑仓、物流商、物流服务产品的编码各自唯一；辅助资料按「资料类型+资料编码」唯一；商品分类编码唯一。依据《实体对象关系》。
- 修改规则：编码一经保存不可修改。新建时可以由系统生成，也可以手工录入；保存后新建页和编辑页都不能再改。需要换编码时按新建处理，原编码不改、作废禁用删除后不重用。
- 作废、禁用、删除后的编码不重用。
- 导入允许指定编码，空着由系统按规则生成；按编码匹配新增或更新，校验与手工录入一致；失败返回行号、字段名和原因。依据COM-FR02和基础资料各PRD的导入规则。
- 带编码的主数据引用统一按 **Code-Name** 格式展示，规则见 **2.3**。
- 第三方仓库编码、外部SKU映射和财务ERP历史编码迁移不在本文定义，见《商品与主数据需求分析》第七节和系统集成相关文档。

### 2.2 各对象编码

### 2.3 主数据引用展示规则（Code-Name）

引用带编码的主数据时，页面展示层统一用 **Code-Name** 格式拼接：**`{编码} {名称}`**。用户在任何场景下都能同时看到编码和名称，便于识别、筛选和对照。

**格式说明**

| 项目 | 规则 |
| --- | --- |
| 格式名称 | Code-Name（编码 名称） |
| 拼接规则 | 编码与名称之间用一个空格连接 |
| 示例 | 供应商 `SUP000001 深圳示例电子有限公司`；逻辑仓 `LWH000001 华东正品仓` |

**适用对象（一期）**

供应商、客户、实体仓、逻辑仓、商品、物流商、物流服务产品，以及辅助资料中带独立编码的字典项（如品牌、基本单位等）。币别统一按「编码 名称」展示（如 CNY 人民币）；单价、金额等数值列只展示数值，不再前缀币别。

**适用场景**

列表列、详情只读区、下拉选项、选择器列表、筛选区已选展示、搜索结果、导出 Excel 的展示列。接口传参和存储仍传编码或内部 ID，不在传参层拼接名称。

**搜索与筛选**

可按编码、名称分别匹配；展示结果统一为 Code-Name，让用户知道命中的是哪条档案。下拉选项同样展示 Code-Name，不能只显示名称或只显示编码。

**例外**

- 主数据档案自有列表页若分列展示「编码」「名称」，各列原样展示，不强行合并为一列。
- 单据明细若字段清单将编码、条码、名称拆成独立列（如采购订单商品明细的商品编码、商品条码、商品名称），按字段清单分列展示，不另加「商品」汇总列。
- 字段清单或模块 PRD 写明只展示编码或只展示名称的，以字段清单和备注为准。

模块字段清单、页面骨架、Demo PRD 和原型引用主数据时默认遵循本节；有例外须在备注写明依据。

## 三、通用字段默认规则

以下规则对所有模块的字段默认生效，模块字段清单只需要写例外。

| 规则 | 默认要求 | 说明 |
| --- | --- | --- |
| 语言与时区 | 仅简体中文、北京时间（UTC+8） | 不做多语言、多时区切换 |
| 币别 | 币别字段保留，取值来自辅助资料的币别字典，按币别代码和名称展示 | 不做跨币别汇率换算；一期实际启用的币别由初始化确认（待确认） |
| 前后空格 | 用户输入的文本默认去掉首尾空格 | 备注类字段允许保留行内换行，首尾仍去掉 |
| 空字符串 | 去空格后为空按未填写处理 | 必填字段报错；选填字段存空值，不存空字符串 |
| 0与空值 | 数量和金额的0是有效值，按0展示 | 只有未填写才展示 `-` |
| 大小写 | 编码类字段区分大小写 | `SP001`与`sp001`视为不同编码，唯一性校验不折叠大小写 |
| 特殊字符 | 编码、电话等机器识别字段用白名单 | 名称、备注等展示字段可宽松，但禁止HTML和脚本 |
| 全角与特殊空白 | 电话、邮箱、编码、条码在录入和导入时统一转半角，去掉不换行空格等特殊空白 | 手工录入和导入都转，转完再校验 |
| HTML/script | 所有非富文本字段禁止保存 | 备注字段也不做富文本 |
| emoji | 编码类字段禁止；名称、地址、附件名默认禁止 | 备注字段可按模块配置 |
| 导入校验 | 与手工录入一致；失败返回行号、字段名和原因 | 依据COM-FR02；编码、账号、条码类字段按文本读取，防止科学计数法和前导零丢失 |
| 展示规则 | 页面空值统一展示英文连字符 `-`，不用中文破折号 `—`；带编码的主数据引用按 Code-Name 展示 `{编码} {名称}`，见2.3 | 导出Excel或接口传参为空时直接留空，不写入 `-`；金额、单价页面按千分位展示，录入不带千分位符号，存库为数字。业务单据列表默认排序：安排单和通知单按创建时间倒序，结果单按业务日期倒序 |
| 价税字段命名 | 含税单据明细默认顺序：含税单价→税率→不含税单价→价税合计→税额→金额；金额指不含税金额，价税合计指含税总额 | 单头汇总字段同名；不再使用「金额合计」指含税总额；精度见Q14已确认口径 |
| 超长输入 | 按最大长度阻止继续输入并显示字数 | 粘贴超长内容不静默截断，提示已达上限 |
| 枚举来源 | 字段清单是枚举唯一来源 | 所有枚举值逐字来自模块字段清单；Demo PRD和Mock不另行发明 |
| 状态筛选 | 业务单据列表的并列状态维度（审核状态、业务状态、收货/发货状态等）筛选项默认多选；未选等同全部，选中多项 OR 匹配 | 见《UI布局公共说明》；主数据用页内 Tab 切审核状态时查询区不重复该字段 |
| 系统计算字段 | 只读，不参与手工输入校验 | 价税合计、税额、金额、不含税单价、累计数量、可下推数量等 |
| 默认标记 | 是否默认地址、默认联系人、默认账户等 | 同一对象下每类最多一个默认；新开默认时自动取消同类其他行 |
| 引用禁用 | 禁用档案不可新选，已有引用和历史展示保留 | 依据《4.强盛ERP全局业务规则与约束》的档案资格规则 |
| 系统记录字段命名 | 页面与字段清单统一用：**创建人**、**创建时间**、**最后更新人**、**最后更新时间** | 不用「更新人」「更新时间」；指最近一次保存或系统写入的修改人与时间。数据字段键 `creator`、`createdAt`、`updater`、`updatedAt` 不变 |
| 技术实现 | 本文只写产品和业务规则 | 数据库类型、索引、接口错误码由技术设计负责 |

| `BARCODE` | 文本 | 商品条码（每个条码值） | 1~20字符；仅数字和字母；禁止空格和中文；全系统唯一，重复不能保存；录入和导入转半角、去特殊空白 | 逐条展示 | 商品条码是多值字段，每个值套本模板；同一商品可有多条，任意两条之间、跨商品均不可重复 |
| `NAME_100` | 文本 | 商品名称、客户名称、供应商名称、仓库名称、物流商名称、资料名称、分类名称、联系人姓名、账户名称 | 1~100字符；去首尾空格；禁止HTML、脚本、emoji和连续空格 | 原样展示 | 需要更长的名称由字段清单单独放长，如备注最长500字符（见REMARK_500） |
| `SNAPSHOT_TEXT` | 文本 | 商品名称快照、客户名称快照、收货地址快照 | 长度按来源字段；生成单据时从来源带出并固化 | 与来源字段同款展示 | 历史单据不随主数据变更；字段清单要写清快照来源和取值时点 |
| `REMARK_500` | 多行文本 | 单据备注、驳回意见、撤回意见、关闭原因、取消原因、推送失败原因 | 0~500字符；去首尾空格；允许换行；禁止HTML和富文本 | 详情页跨列展示 | 有已驳回态的对象用驳回意见（一期主数据不录入意见），无已驳回态的业务单据用撤回意见；异常日志可按模块放宽长度。手工关闭必填关闭原因；系统自动关闭时关闭原因留空，用关闭方式区分 |
| `MULTI_VALUE` | 多行文本 | 商品条码等多值字段 | 一行一条；去首尾空格；逐条校验 | 列表合并展示，详情逐条展示 | 逐条唯一性和格式由具体字段的模板决定 |
| `BOOL_YN` | 布尔 | 是否启用、是否赠品、是否默认地址、是否批次管理 | 布尔值；必填时必须明确默认值；禁止自由文本 | 页面展示 `是`、`否` | 涉及状态流转的不用布尔替代状态字段；默认标记的唯一性见第三节 |
| `QTY_INT` | 数值 | 订购数量、通知数量、实收数量、实出数量、累计数量、可下推数量、库存预警数量 | 整数；手工录入默认大于0；一期不允许小数 | 按基本单位展示 | 盘盈盘亏、退货等负数场景由模块规则显式说明；一期不做单位换算 |
| `NUMBER` | 数值 | 净重、长宽高、外箱尺寸、装箱数量、保质期天数、单位换算数量、分类级别 | 数值；小数位和单位由字段清单写明 | 带单位展示，如kg、cm、天 | 精度待确认；数量类字段优先用QTY_INT |
| `UOM` | 关联选择 | 基本单位、辅助计量单位 | 引用辅助资料的基本单位字典项；每种商品只绑一个基本单位 | 优先 Code-Name `{编码} {名称}`；仅名称足够时可只展示名称 | 一期不做单位换算和阶梯价；价目和单据数量按基本单位；辅助计量单位一期保留可填，不参与换算 |
| `DICTIONARY_REF` | 关联选择 | 商品分类、品牌、币别、客户等级、结算方式、付款条件、收款条件 | 必须引用存在且启用的字典项；禁用项不可新选 | 展示字典项名称；币别按「编码 名称」展示 | 字典类型和字典项由辅助资料维护 |
| `MONEY_2` | 金额 | 金额、税额、价税合计、折让金额、退款金额 | 数字；保留2位小数；行内税额＝价税合计−金额，吸收尾差 | 页面按千分位展示；录入不带千分位 | 币别不限人民币；负数场景由模块规则说明；存库为数字 |
| `PRICE_4` | 金额 | 含税单价、不含税单价、采购价、批发价、零售价 | 数字；保留4位小数；不含税单价由系统计算 | 页面按千分位展示；录入不带千分位 | 开单按含税单价录入；价格来源、改价权限和取价失败处理由模块PRD定义；价目按基本单位 |
| `PCT_4` | 数值 | 税率、折扣率 | 页面按百分比录入，最多2位小数，允许0 | 展示百分比，如13%、0% | 商品默认销售税率允许为空，开单时再填；开单后可从商品带出、可手工覆盖；税率为0时税额为0，价税合计等于金额 |
| `DATETIME_SEC` | 日期时间 | 创建时间、最后更新时间、审核时间、推送时间、取消时间 | 系统记录；格式 `YYYY-MM-DD HH:mm:ss`；只读 | 统一按北京时间展示 | 只支持UTC+8；维护类字段展示名见第三节「系统记录字段命名」 |
| `DATE_ONLY` | 日期 | 业务日期、单据日期、承诺交期、预计到货日期 | 格式 `YYYY-MM-DD`；按日历日期处理 | 统一按北京时间展示 | 不做时区换算；账龄和报表归属按业务日期 |
| `EFFECTIVE_DATE` | 日期 | 生效、失效日期类字段 | 格式 `YYYY-MM-DD` | 按日期展示 | 预留模板，一期字段清单暂未使用；价目表不设生效起止日期、价格长期有效 |
| `PHONE_11` | 文本 | 手机号码、固定电话、联系电话、注册电话 | 1~20字符；去首尾空格；录入和导入转半角、去特殊空白；仅数字、`+`、`-`和空格 | 原样展示 | 选填；格式不符时报错 |
| `EMAIL` | 文本 | 电子邮箱 | 1~100字符；去首尾空格；录入和导入转半角、去特殊空白；自动转小写；标准邮箱格式 | 原样展示 | 不做系统级唯一约束；多邮箱拆子表维护 |
| `ADDRESS_200` | 文本 | 联系地址、详细地址、注册地址、仓库地址 | 1~200字符；去首尾空格；允许换行；禁止HTML、脚本和emoji | 原样展示 | 代发场景使用结构化字段，不塞进备注 |
| `POSTAL_CODE` | 文本 | 邮政编码 | 1~20字符；允许字母、数字、空格和 `-` | 原样展示 | 一期字段清单已使用：供应商资料、客户资料地址明细的邮政编码 |
| `URL_500` | 文本 | 商品链接、外部地址 | 1~500字符；URL格式校验；支持http和https | 原样展示 | 预留模板，一期字段清单暂未使用 |
| `REFERENCE` | 关联选择 | 供应商、客户、商品、仓库、物流商 | 必须引用存在且可用的主数据；禁用数据不可新选 | 按 Code-Name 展示 `{编码} {名称}`，见2.3 | 具体引用范围由模块字段清单定义 |
| `USER_REF` | 用户引用 | 业务员、创建人、审核人、最后更新人、取消操作人、关闭操作人 | 引用存在且启用的账号 | 页面展示姓名，不拼接账号或简称 | 系统记录类只读；系统自动关闭时关闭操作人留空，关闭原因也留空，用关闭方式表达，不写「系统」字符串；系统自动生成的结果单（仓库回传、虚拟入出库、外部来源），创建人和最后更新人显示「系统」 |
| `STATUS_ENUM` | 枚举 | 审核状态、单据状态、业务状态、执行状态、推送财务ERP状态 | 取值必须来自字段清单定义的枚举；禁止自由输入 | 展示枚举文字 | 不做全系统统一状态枚举 |
| `ENUM_REF` | 枚举 | 客户类型、仓库类型、物流类型、运输类型、地址类型 | 取值必须逐字来自字段清单定义的枚举；Demo PRD和Mock不另行发明 | 展示枚举文字 | 状态用STATUS_ENUM，布尔用BOOL_YN，字典类用DICTIONARY_REF |
| `SORT_NO` | 数值 | 明细排序、展示顺序、行号 | 整数；大于等于0；不允许小数 | 按序展示或不展示 | 排序影响业务优先级时须在PRD说明 |
| `ATTACHMENT` | 图片 | 商品图片（7个视图位）、导入文件、合同附件 | 图片jpg/png/webp，附件pdf/xls/xlsx；单文件不超过10MB，单次不超过20个 | 图片显示缩略图，附件显示文件名 | 商品七个视图位各自上传，仍受单文件和单次上限约束 |

### 4.2 字段类型与模板映射

字段清单的字段类型是闭集，各类型默认套用以下模板，字段清单按字段用途选择并在备注写明。

| 04字段类型 | 默认模板 |
| --- | --- |
| 文本 | MASTER_CODE、BILL_NO、CODE_50、EXTERNAL_NO、OFFICIAL_CODE、BANK_ACCOUNT、BARCODE、NAME_100、SNAPSHOT_TEXT、ADDRESS_200、PHONE_11、EMAIL、POSTAL_CODE、URL_500 |
| 数值 | QTY_INT（数量）、NUMBER（通用数值）、PCT_4（税率类）、SORT_NO（排序） |
| 金额 | MONEY_2（金额）、PRICE_4（单价） |
| 日期 | DATE_ONLY；EFFECTIVE_DATE（生效、失效日期类） |
| 日期时间 | DATETIME_SEC |
| 枚举 | ENUM_REF；状态类用STATUS_ENUM |
| 布尔 | BOOL_YN |
| 关联选择 | REFERENCE、DICTIONARY_REF、UOM、USER_REF |
| 关联明细 | 不套模板，由所属对象说明 |
| 多行文本 | REMARK_500、MULTI_VALUE |
| 图片 | ATTACHMENT |
| 用户引用 | USER_REF |
| 系统记录 | 只读；时间用DATETIME_SEC，人用USER_REF |
