## 一、为什么要把单据分层

一笔业务在现实中通常包含三件不同的事：先谈好"要做什么"，再安排仓库"这一次怎么做"，最后记录"实际做成了什么"。这三件事由不同的人在不同时间完成，还可能反复发生：供应商分批发货、客户取消某一次发货、仓库实际只收到一部分。

如果把这些压在一张单据上，会出现三类问题：

- **契约和执行互相牵制**：分批发货、单独取消某一次执行，没有地方安放；
- **计划被当成事实**：订单数量、通知数量直接进库存，造成账实不符；
- **历史被覆盖**：仓库回传直接改写已审核的业务约定，追溯断链。

分成三层之后：

1. **执行可以分批、可以独立跟踪**：一张订单对应多张通知单，每张通知单有自己的数量、状态和取消流程；
2. **约定保持稳定**：实际结果只回写到对应层级，差额按各模块规则回补额度或另建单据，不篡改原约定；
3. **记账口径唯一**：库存只按实际结果变化；订单、通知和申请本身不增加或扣减即时库存（销售、采购退货等审核时的预占只锁定可用量）。

## 二、三个角色（层）是什么

| 层级 | 角色 | 回答什么 | 本质 | 典型单据 |
| --- | --- | --- | --- | --- |
| 第一层 | 业务安排 | 我要做什么 | 与供应商、客户或内部确认的业务约定 | 采购订单、采购退货单、销售订单、销售退货单、其他入库申请单、其他出库申请单、分步式调拨单 |
| 第二层 | 执行指令 | 这一次让仓库做什么 | 一次具体执行的指令，可以分批下发 | 采购收货通知单、采退发货通知单、销售发货通知单、销退收货通知单、调出通知单、调入通知单；也可由订单、申请单直接承担 |
| 第三层 | 实际结果 | 实际发生了什么 | 实际发生的事实，库存记账和业财推送的唯一依据 | 采购入库单、采退出库单、销售出库单、销退入库单、其他入库单、其他出库单、直接调拨单 |

两个必须记住的认识：

- **角色 ≠ 单据**。本项目两层链路把业务安排与执行指令合并到订单／申请单上，实际结果仍由独立结果单记录。一层表示 ERP 只登记实际结果或办理账内调整，不表示外部业务没有安排和执行过程。
- **结果单的定义**。结果单记录实际发生的事情：由仓库或下游回传自动生成，或由人工确认实际结果后形成。订单和通知的数量不能当作库存事实——这正是"库存只按实际结果记账、只把结果推给金蝶"能成立的原因。

以采购为例：采购订单审核后（第一层），采购按供应商线下发货反馈代录采购收货通知单，由系统自动推送仓库（第二层）；仓库回传一次实际收货结果（允许缺量），校验通过后系统更新通知单及采购订单累计收货数量，有实际入库时生成采购入库单（第三层，自动审核；零收见 §5.3）；采购入库单再逐单推送金蝶。

## 三、层数怎么定（判断口径）

设计或评审单据时，先看业务安排与执行任务的关系，再决定建几类单据：

1. **有没有需要 ERP 管理的独立业务安排？** 有采购、销售或内部收发需求，就保留安排单；ERP 只登记已经发生的事实时，不补造安排单。
2. **一张安排是否需要多个独立执行任务？** 分批履约需要多张通知分别跟踪；调拨虽不分批，但调出、调入有先后依赖，也需要独立指令。如果一次只有一个有效执行任务，订单／申请可以直接承担指令。
3. **实际结果如何保存？** 本项目以独立结果单承接实际库存变化和金蝶推送。安排数量与实收数量是否接近，不作为合并指令与结果的依据；零收／零出按取消执行单处理、不生成结果单，见 §5.3、§6.4。

取消、重试本身不决定层数。独立站取消旧仓执行后换仓重发，仍可采用两层，因为同一时刻只保留一个有效执行任务，并保留前次执行历史。

| 形态 | 什么时候用 | 本项目链路 |
| --- | --- | --- |
| 3 层（安排→指令→结果） | 一张安排分批执行，或多个任务有先后依赖，需要分别跟踪 | 采购、B2B 销售、退货、分步式调拨 |
| 2 层（安排兼指令→结果） | 一次只有一个有效执行任务，业务单据本身能指挥仓库 | 独立站正向、其他出入库 |
| 1 层（只有结果） | ERP 办理账内调整，或接收外部已经完成的事实 | 一步式直接调拨、仓库主动回传、外部 ToC |

**规则跟着角色走，不跟着单据名走**：一次回传及缺量、超量校验，约束的是"承担执行指令角色的单据"（可能是通知单，也可能是直接推送的订单或申请单）与其回传之间；结果单的自动审核和金蝶推送，针对的是第三层。

**什么时候升级层数**：独立站开放拆单分批发货、其他出入库开放分批执行时，再增加独立指令层。采购类链路因分批保留三层，分步式调拨因两端执行依赖保留三层，不要求所有业务统一为相同层数。

**升级保留历史**：新业务按新链路执行，旧单据按原规则完成；既有订单、执行记录、结果及来源关系保留，不把历史记录重新拼成另一条链路。当前先保证这些关系可追溯，不提前建设通用状态机配置平台或展开迁移程序设计。

**状态字段为什么不完全统一**：三层主单需要同时表达审核、是否继续安排、累计执行进度，关闭时下游仍可能执行，因此采用多个状态维度。两层订单／申请一次执行，可以用一个状态字段贯穿审核、发送和完成。统一的是动作含义与联动规则，不是字段数量；审核历史不会因为页面合并状态而丢失。

## 四、各业务链路的分层

| 业务链路 | 层数 | 结构 | 为什么这么定 |
| --- | --- | --- | --- |
| 采购入库 | 3 | 采购订单 → 采购收货通知单 → 采购入库单 | 供应商分批发货，每批一次通知、一次回传；PUR-FR01～FR03 |
| 采购退货 | 3 | 采购退货单 → 采退发货通知单 → 采退出库单 | 支持分批出库、缺量回补；PUR-FR04、FR05 |
| B2B 销售 | 3 | 销售订单 → 销售发货通知单 → 销售出库单 | 分批通知、可自提、取消需等仓库确认；SAL-FR02、FR03 |
| 销售退货 | 3 | 销售退货单 → 销退收货通知单 → 销退入库单 | 支持分批收货、按额度控制；SAL-FR05、FR06 |
| 分步式调拨 | 3 | 分步式调拨单 → 调出通知单（按实际调出生成调入通知单）→ 直接调拨单×2 | 两端执行，第二段指令按实出量生成；INV-FR03 |
| 独立站正向 | 2 | 销售订单（审核后直接推送仓库）→ 销售出库单 | 一单一仓、整单履约、不分批，订单即执行指令；SAL-FR07、FR08 |
| 其他入库 | 2 | 其他入库申请单（审核后直接推送仓库）→ 其他入库单 | 一期不分批、一次执行，申请即指令；INV-FR06 |
| 其他出库 | 2 | 其他出库申请单（审核后直接推送仓库）→ 其他出库单 | 同上；出库申请审核时预占；INV-FR06 |
| 一步式直接调拨 | 1 | 直接调拨单 | ERP 内部转库存、不推送仓库或外部执行系统，审核后直接记一减一增；INV-FR07 |
| 仓库主动回传 | 1 | 其他入库单、其他出库单、直接调拨单 | 仓库已经完成，ERP 只接收结果，不补造安排与指令；INV-FR04、INV-FR07 |
| 外部 ToC 正/反向 | 1 | 销售出库单、销退入库单 | 履约在 SaaS 完成；平台原订单仅作来源追溯，不驱动履约；SAL-FR09 |

## 五、三层单据的状态机与联动

> 本节用采购链举例说明三层的职责划分；状态枚举是示例，具体取值和操作条件以应用设计为准。

本节依据本轮讨论，定义三层单据的共用状态设计，以“采购订单 → 采购收货通知单 → 采购入库单”完整说明。采购、B2B 销售及退货链复用相同的职责划分，收货、发货名称按业务替换；分步式调拨另保留两端执行及在途规则。两层状态机见 §六，一层直接复用结果单模型，见 §七。

本轮新增确认的状态枚举、采购取消、零收／零出取消、独立站取消审核回草稿等规则，已同步到对应模块文档。本文不因此改动各模块已有的预占、退货额度、分批限制或自动关单条件。

### 5.1 三层各管什么，单据如何关联

| 层级 | 管理重点 | 采购示例 |
| --- | --- | --- |
| 业务安排 | 总共采购多少、是否审核、是否继续办理、累计收到多少 | 采购订单 |
| 执行指令 | 这一批是否交给仓库、是否完成收货、是否取消 | 采购收货通知单 |
| 实际结果 | 实际收到多少、是否生效记账、是否推送金蝶 | 采购入库单 |

一张采购订单可以分批生成多张通知单；一张通知最多生成一张有效采购入库单。未执行、已取消或零收的通知没有入库单。通知只接收一次最终收货结果，需要补收就另建通知。

通知明细关联来源订单明细，入库明细关联来源通知明细，并能追溯到订单。数量按来源行累计，不同 SKU 不能互相抵用。订单可查看全部通知和入库单，通知可查看来源订单及对应入库单，入库单可向上追溯。

### 5.2 采购订单：三个状态字段

| 状态字段 | 枚举值 | 用途 |
| --- | --- | --- |
| 审核状态 | 草稿、待审核、已审核 | 控制编辑、审核和下推资格 |
| 业务状态 | 正常、已取消、已关闭 | 控制是否继续办理，不另设作废状态 |
| 收货状态 | 未收货、部分收货、全部收货 | 按各行累计实际入库数量自动计算 |

三个字段分别记录不同信息。一张订单可以同时为“已审核＋部分收货＋已关闭”。“正常”表示没有取消或关闭，不表示尚未完成；全部收足后可以保持“正常＋全部收货”，不再增加重复的已完成状态。

```plain
审核：草稿 → 提交 → 待审核 → 审核通过 → 已审核
       ↑              │
       └──审核退回─────┘

业务：正常 → 取消 → 已取消
         └→ 手工关闭／到期自动关闭 → 已关闭

收货：未收货 → 部分收货 → 全部收货
         └────一次收足────→ 全部收货
```

审核退回后回到草稿，保留退回意见。取消、关闭保留原审核状态及操作历史，不把已审核订单退回草稿。已取消、已关闭不再编辑、提交、审核或新增通知；已关闭订单仍可接收已有通知的实际结果。

| 条件 | 主要功能及限制 |
| --- | --- |
| 草稿＋正常 | 编辑、提交、取消；删除仅作为清理草稿的可选功能 |
| 待审核＋正常 | 审核通过、退回、取消；取消同时终止待审核流程，不允许删除 |
| 已审核＋正常 | 调整交期、关闭；满足取消条件时可取消，不允许删除；价格和数量不可修改 |
| 已审核＋正常＋有可下推数量 | 创建采购收货通知单，支持分批 |
| 已取消 | 查看历史，不再办理 |
| 已关闭 | 查看、追溯；已有有效通知继续办理，不新增通知，不可反关单 |

**取消和关闭的分工：**取消表示整张订单不再执行；关闭表示不再安排剩余采购，已有通知继续执行。订单无实际入库，且没有仍需执行的通知时允许取消；待推送或明确推送失败的通知可以随订单一起取消。存在推送中、待收货或取消中的通知时，不直接取消订单，先处理通知并取得必要的仓库确认。已有实际入库不能取消整单，可以关闭余量。

**关闭不按触发方式拆状态。** 手工关闭与到期自动关闭都落为“已关闭”，另记录关闭方式（手动关闭、到期自动关闭）、关闭原因、关闭时间、关闭操作人（用户或系统）。未关闭时这些信息留空。采购到期关闭的宽限参数仍按模块待确认事项处理。

### 5.3 采购收货通知单：一个状态字段

通知单将推送和执行串成一个“单据状态”，不再拆独立的推送状态、执行状态或取消状态。通知单的首次发送由系统自动执行，创建后由系统自动推送仓库，不需要人工再点一次推送；由来源单审核后才生成的通知单，在生成时自动发送。

| 枚举值 | 含义 | 主要功能 |
| --- | --- | --- |
| 待推送 | 已创建，等待系统自动发送仓库 | 取消 |
| 推送中 | 正在发送，结果尚未确定 | 等待结果，不重复发送或直接取消 |
| 推送失败 | 本次发送明确失败 | 重试、取消 |
| 待收货 | 仓库已接收通知，等待最终收货结果 | 接收回传、申请取消 |
| 取消中 | 已申请取消，等待仓库确认 | 等待确认，仍需处理可能到达的实际结果 |
| 已取消 | 通知已取消，不再执行 | 查看历史 |
| 已收货 | 最终收货结果已确认，本批执行结束 | 查看实收、缺收及关联入库单 |

```plain
待推送 → 推送中 → 待收货 → 已收货
            │
            └→ 推送失败 → 重试 → 推送中

待推送／推送失败 → 已取消
待收货 → 取消中 → 仓库同意 → 已取消
                  └→ 仓库拒绝 → 待收货
待收货 → 回传零收 → 已取消
```

“待收货”表示 ERP 等待最终结果，不表示仓库一定尚未开始作业。“已收货”表示本批收货结果已确认，不表示全部收足；实收为 0 时不按已收货处理，按零收取消通知单。通知不设“部分收货”状态，已收货后不能往原通知追加收货。

| 通知数量 | 实收数量 | 缺收数量 | 状态及结果 |
| --- | --- | --- | --- |
| 100 | 100 | 0 | 已收货，生成 100 的采购入库单 |
| 100 | 80 | 20 | 已收货，生成 80 的采购入库单，释放 20 的通知占用额度 |
| 100 | 0 | 100 | 零收：通知单取消，显示“实收 0／整批未收”；不生成零数量入库单，释放全部通知占用额度 |

以上均指收到并确认最终结果之后；等待回传时不能把实收未知当作零收处理。缺收数量在收货完成后计算，缺量通过数量、标签和筛选呈现，不增加流程状态。零收按取消处理并保留最终回传及确认记录，供追溯。

### 5.4 采购入库单：审核与金蝶推送分别记录

| 状态字段 | 枚举值 | 用途 |
| --- | --- | --- |
| 审核状态 | 草稿、待审核、已审核 | 人工形成结果时走审核，正常回传校验通过后自动审核 |
| 金蝶推送状态 | 未推送、推送中、推送成功、推送失败 | 跟踪实际结果传递给金蝶的情况 |

```plain
自动：最终收货结果 → 校验通过 → 生成入库单并自动审核
人工：草稿 → 待审核 → 已审核（退回则回草稿）
                         ↓
       库存生效、回写实收数量、通知变为已收货
                         ↓
金蝶：未推送 → 推送中 → 推送成功
                  └→ 推送失败 → 重试
```

零收按 §5.3 取消通知，不经过入库单流程。人工确认同一批实际结果也要沿来源通知回写，不能因为人工办理而重复记账。

入库单草稿可编辑、提交，待审核可审核或退回；已审核后查看来源、库存结果及推送记录，不直接改写已生效结果。它不需要另设待收货、部分收货或已完成状态。只有已审核结果才记账和推送金蝶；推送失败不撤销入库、不回滚库存，处理后重试原单。

### 5.5 行明细：维护数量，不设关闭状态

一期按整单取消、整单关闭，不另设行审核、行取消、行关闭状态。行收货进度根据订购与累计实收数量计算展示即可；只有后续确实需要“停止某一个 SKU 的余量，其他行继续”时，才增加行关闭能力。

采购、采购退货、B2B 销售及销售退货等支持分批的三层链路，按来源行维护：

**可下推数量＝安排数量－累计实际执行数量－未结束有效通知占用数量。**

- 创建有效通知即占用额度；推送失败、待收货、取消中仍占用，不因发送失败或申请取消提前释放。
- 通知取消成功后释放额度；收货完成后以实际数量替代原通知占用，缺量回补。
- 订单关闭后保留原数量和剩余数量，不清零；余量不代表仍有下推资格。
- 订单各行都收足才显示全部收货；全无实收显示未收货，其余显示部分收货，不用不同 SKU 的数量互相抵消。
- 下推额度不是库存。采购订单、通知不增加即时库存；涉及销售、采购退货等出库业务时，额度回补也不等于重新预占，预占释放沿用各模块规则。

### 5.6 用一张采购订单串联分批收货

以下为一个 SKU 采购 100 件的演示：

| 步骤 | 采购订单 | 收货通知单 | 采购入库及库存 |
| --- | --- | --- | --- |
| 订单审核通过 | 已审核、正常、未收货；可下推 100 | 无 | 无，不增加库存 |
| 创建 A：60，并推送成功 | 可下推 40，仍未收货 | A 待收货 | 无，不增加库存 |
| A 最终实收 50 | 部分收货，累计实收 50，可下推 50 | A 已收货，缺收 10 | 入库单 A：50，自动审核，库存＋50 |
| 创建 B：50，并推送成功 | 可下推 0，仍部分收货 | B 待收货 | 保留入库单 A |
| B 最终实收 50 | 全部收货，累计实收 100 | B 已收货 | 入库单 B：50，自动审核，库存再＋50 |

```plain
采购订单：100
├─ 收货通知 A：60 → 采购入库单 A：50
└─ 收货通知 B：50 → 采购入库单 B：50
```

A 缺收的 10 已释放，故通知累计数量可以为 110，实际入库仍不超过订单 100。两张入库单分别推送金蝶。

如果创建 B 后关闭订单，B 仍继续收货。B 若最终只收 40，订单为“已审核＋已关闭＋部分收货”，累计实收 90，剩余 10 不再下推。如果订单仍正常而 B 取消成功，可下推恢复 50，可以另建通知 C。

### 5.7 取消、关闭及异常如何收口

| 场景 | 处理结果 |
| --- | --- |
| 订单关闭时存在通知 | 关闭前已有的有效通知继续办理，包括推送、重试和收货；关闭本身不自动取消通知 |
| 通知取消成功 | 释放通知占用额度，不生成结果单、不改变即时库存；订单正常才可重新下推 |
| 通知取消被拒绝 | 恢复待收货，保留占用额度，继续执行 |
| 取消中收到实际收货结果 | 校验通过后按真实结果收货，不再把通知落成已取消 |
| 回传零收 | 通知单取消，不生成结果单、不改变库存，释放全部通知占用额度；订单仍开放时可重新下推 |
| 回传校验失败 | 保留异常，暂不完成通知、不增加库存、不回写累计实收；修复后处理同一份结果 |
| 推送结果不确定 | 先核实原请求结果，不能直接当明确失败而重复发送或释放额度 |
| 重试、重复回传 | 不重复生成单据、不重复回写数量、不重复记账；具体幂等标识与恢复机制留接口设计 |
| 金蝶推送失败 | 不回滚库存和已审核入库单，修复后重试原结果单 |

### 5.8 页面需要呈现的关键数据

本表规定主要业务信息，不代替各模块完整字段清单。

| 单据 | 单头重点 | 行明细重点 |
| --- | --- | --- |
| 采购订单 | 单号、采购组织、供应商、收货仓库、承诺交期、币别、金额、三个状态 | SKU、订购数量、累计实收数量、未结束通知占用数量、可下推数量、单价与金额 |
| 收货通知单 | 单号、来源订单、收货仓库、单据状态、创建时间、推送时间、最终收货确认时间 | 来源订单行、SKU、通知数量、实收数量、缺收数量 |
| 采购入库单 | 单号、来源通知及订单、入库仓库、实际入库时间、审核状态、金蝶推送状态 | 来源通知行、SKU、实际入库数量、来源交易价格与金额 |

同时呈现取消／关闭原因、操作人及时间，关闭方式，推送或处理失败原因、最近处理时间，以及上下游单据入口。推送日志放在关联记录中，不再给通知单增加一套并列推送状态。

### 5.9 其他三层链路如何复用

| 链路 | 复用方式 | 必须保留的业务差异 |
| --- | --- | --- |
| 采购入库、销售退货 | 主单采用审核、业务、收货三个维度；收货通知采用待收货／已收货 | 销售退货还要控制原出库单可退额度，取消／关闭时按销售规则处理额度 |
| B2B 销售、采购退货 | 收货进度替换为发货进度：未发货、部分发货、全部发货；通知对应待发货／已发货 | 审核预占，实际出库消耗预占；关闭和取消按模块释放，不能把下推额度与预占混为一谈 |
| 分步式调拨 | 复用审核、业务控制、通知推送／取消以及结果单审核／推送职责；调出、调入分别跟踪 | 每端一次执行、不分批；调入通知按实际调出生成，收到接收回传并生成第二张直接调拨单后主单自动完结；少收留在途，不能套用分批补下推公式。实际调出必须大于 0；仓库回传 0 时按零出取消该分步式调拨单，不生成零数量后续单据。实际调入也必须大于 0，回传 0 属于异常，通知单无法关闭，需人工处理 |

共用的是状态职责与操作含义，不是把采购所有功能原样复制。销售与退货的关单日期、占库和额度规则仍按对应模块；零收／零出统一按取消执行单处理，采购零收、两层整单零执行与分步式调拨零调出均不生成零数量结果单，取消后按各模块规则释放占用。两层状态机见 §六；一层状态机见 §七。


## 六、两层单据的状态机与数量

> 本节用独立站和其他出入库举例；同样属于示例，落地取值见应用设计。

两层由订单／申请单同时承担业务安排和执行指令，审核后自动推送仓库，不再生成通知单。实际执行结果形成第二张单据。本轮确认以下状态与数量口径。

### 6.1 适用链路

| 链路 | 订单／申请单 → 结果单 | 执行规则 |
| --- | --- | --- |
| 独立站正向 | 销售订单 → 销售出库单 | 一单一仓，不分批、不缺量 |
| ERP 发起的其他入库 | 其他入库申请单 → 其他入库单 | 不分批，允许缺量，一次结束 |
| ERP 发起的其他出库 | 其他出库申请单 → 其他出库单 | 不分批，允许缺量，一次结束 |

独立站退货仍走三层；仓库主动回传的其他出入库属于一层。此次将独立站“审核后人工批量推送”调整为“审核后自动推送”，其他出入库申请不再提供手动关闭，统一用取消停止业务。这两项结论已回填至 01 的系统链路与全局规则，以及销售、库存模块文档。

### 6.2 订单／申请单：一个单据状态字段

不再并列维护审核状态、业务状态、关闭状态；审核人、审核时间及操作记录仍保留。

| 枚举值 | 含义及操作 |
| --- | --- |
| 草稿／待提交 | 编辑、提交；同一草稿状态可根据来源流程在页面显示为“待提交” |
| 待审核 | 等待审核；通过后进入已审核，退回则回草稿 |
| 已审核 | 审核通过，自动推送仓库，尚未取得确定结果 |
| 推送失败 | 已审核，但发送明确失败，可重试 |
| 待收货／待发货 | 仓库已成功接收，等待最终实际结果；可申请取消 |
| 取消中 | 等待仓库确认取消，不能提前释放预占 |
| 已取消 | 本次业务取消，不再执行 |
| 已收货／已发货 | 最终执行结果已确认，本次结束，不在原单追加执行 |

其他入库使用“待收货、已收货”；独立站销售及其他出库使用“待发货、已发货”。不另设推送中或推送成功状态，具体发送过程保留在推送记录中。

```plain
草稿／待提交 → 待审核 → 已审核 ──自动推送成功──→ 待收货／待发货
                │       │                          │
                │       └──推送失败──→ 推送失败     ↓
                │                         │    已收货／已发货
                └→ 退回草稿               └──重试→ 已审核

已审核／推送失败 ──取消审核（终止订单）──→ 已取消
                  └─取消审核（调整重执行）→ 草稿／待提交

待收货／待发货 → 取消中 ──仓库取消成功（终止订单）──→ 已取消
                         ├─仓库取消成功（调整重执行）→ 草稿／待提交
                         └─仓库拒绝取消────────────→ 待收货／待发货

待收货／待发货 → 零收／零出回传 → 已取消（终止本次执行）
```

重试返回已审核只是等待新的发送结果，不重新审核、不重复预占。已审核且发送结果不确定时，先核实仓库是否接收，不重复发送或直接认定取消成功。

### 6.3 取消、调整与实际结果

- 草稿、待审核可直接取消；明确推送失败且确认仓库未接收时可取消，释放适用预占。
- 仓库已接收后，从待收货／待发货进入取消中；仓库同意时，终止订单的进入已取消，调整后重新执行的回到草稿／待提交。两者均在仓库确认取消成功后释放适用预占；仓库拒绝则恢复待收货／待发货，继续执行。
- 取消中仍须处理到达的实际结果；校验通过后按真实结果完成，不能再将已执行业务落成已取消。回传校验失败保留异常，修复后处理原记录，不能重复记账。
- 独立站换仓或换物流时，保留原订单：未发送可直接取消审核、释放预占，回到草稿／待提交修改；已经发送须先获仓库取消本次执行成功，再释放预占并回草稿／待提交修改。记录取消用途是“终止订单”还是“调整后重新执行”；终止订单不回草稿，调整后重新执行才可继续编辑。不新增状态枚举，也不抹掉前次执行记录。
- 独立站修改仓库或物流并重新提交审核后，作为新的仓库执行并生成新的执行标识；旧执行记录、取消用途及回执继续保留，迟到回传只能关联旧执行，不能推进新执行。
- 独立站不足量时整单不发，保持待发货及预占，不生成出库单；收到仓库明确、最终的整单零执行结果时，按零出取消订单并释放占库。其他出入库允许缺量，最终结果确认即已收货／已发货；零收／零出时申请单取消，实际数量为 0，原申请不回补余量供再次执行。
- 其他入库审核不增加库存，实际入库才增加；其他出库及独立站审核预占，实际出库扣即时库存并消耗对应预占。其他出库缺发的剩余预占在最终执行结束后释放。

结果单复用 §5.4：审核状态为草稿、待审核、已审核，金蝶推送状态为未推送、推送中、推送成功、推送失败；正常回传校验通过后自动审核。结果明细直接关联订单／申请明细，回写实际数量；金蝶失败只重试原结果单，不回滚已生效库存。

**两层保留可关联回传的执行历史。** 每次仓库执行都要能识别其来源订单、目标仓库、发送与取消结果，以及是否为当前有效执行；回传必须关联到对应执行，不能仅凭订单当前状态处理。发送失败后的重试仍属同一次执行，取消成功后换仓重发属于新的执行，旧执行记录不覆盖。

例如先发 A 仓、取消成功后改发 B 仓，A 仓迟到的反馈仍关联 A 仓那次执行，不能推进 B 仓的状态或直接按当前仓库记账；与已取消结论冲突的实际结果进入异常处理。这些关联是系统处理依据，不只是文字日志，不要求新增通知单、业务页面或状态枚举。重新审核生成新的执行标识，具体编码及接口机制留详细设计。

### 6.4 明细只关注三个数量

| 业务单据 | 计划数量 | 实际数量 | 差额数量 |
| --- | --- | --- | --- |
| 独立站销售订单 | 订购数量 | 实发数量 | 未发数量 |
| 其他入库申请单 | 申请入库数量 | 实收数量 | 未收数量 |
| 其他出库申请单 | 申请出库数量 | 实出数量 | 未出数量 |

**未收／未出／未发数量＝对应订购或申请数量－实际数量。** 实际数量由已生效结果按来源行回写；最终结果尚未确认时，实际数量可显示“—”，差额按尚未执行的计划数量展示，不能把它误读为最终缺量。仓库最终确认整单零执行时，原订单／申请按零收／零出取消，实际数量显示 0，差额等于计划数量；不生成零数量结果单、不改变库存、不推金蝶，释放未执行占用，保留最终回传及确认记录。独立站正常的“无法足量、整单不发、继续占库”仍保持待发货，只有收到明确的最终零执行结果时才按此取消。

例如其他入库申请 A 商品 100、实收 80、未收 20；B 商品 50、实收 50、未收 0。单据统一为已收货，A 可显示缺收标签，原申请不能再补收 20。独立站不允许缺量发货，正常完成时各行实发等于订购数量，未发为 0。

- 不增加已下推、未下推、可下推数量。订单／申请本身就是指令，整单推送的数量就是计划数量；重试不是新下推，不累加数量。
- 不设行关闭、行取消或独立收发状态机。未收、收足、缺收等提示按数量及单据阶段计算即可。
- 已取消仍保留计划数量及实际记录，余量不再执行；已收货／已发货的差额表示本次最终未执行数量，不代表还有补收、补发资格。
- 结果单重点记录实际入出库数量；计划和差额主要在来源订单／申请查看，不重复维护。


## 七、一层单据：直接复用结果单状态

> 本节说明一层结果单的职责；枚举是示例。

一层没有 ERP 内的前置安排单和通知单，直接按结果单处理，不另建一套状态机。适用于一步式直接调拨，以及仓库主动回传、外部 ToC 实际结果形成的其他入库单、其他出库单、直接调拨单、销售出库单和销退入库单；来源范围沿用 §四。

### 7.1 两个状态字段

| 状态字段 | 枚举值 | 用途 |
| --- | --- | --- |
| 审核状态 | 草稿、待审核、已审核 | 控制实际结果是否生效；人工创建走审核，外部回传校验通过后自动审核 |
| 金蝶推送状态 | 未推送、推送中、推送成功、推送失败 | 跟踪已审核结果传递给金蝶的情况 |

不增加待收货、待发货、取消或关闭状态。人工结果在审核前可以编辑、提交、审核或退回；已审核结果不直接改写，更正沿用 §8.5。

### 7.2 来源与流转

```plain
人工创建：草稿 → 待审核 → 已审核
            ↑      │         │
            └─退回─┘         ↓
外部回传：实际结果 → 校验通过、生成并自动审核
                             ↓
                          库存生效
                             ↓
金蝶推送：未推送 → 推送中 → 推送成功
                     └→ 推送失败 → 重试原单
```

人工创建的直接调拨单审核后直接记账，不推送仓库、不预占。仓库／外部系统回传已经发生的事实，匹配及库存等校验通过后自动审核、生效；校验失败保留异常，修复后继续处理原记录，不提前记账或推送金蝶。

不同单据的区别在库存记账方式：入库增加、出库减少，直接调拨在同一库存组织内一减一增。明细以实际数量为依据，不需要下推数量或待执行余量。外部来源及原订单关联保留用于追溯，不重新触发履约。

金蝶推送失败不回滚已生效库存；重复回传或推送重试不重复生成结果、记账。审核与推送共用规则沿用 §8.3。一层状态已明确，不因分步式调拨的两端专用规则而留为待定。

## 八、各层共用规则（按角色表述）

### 8.1 一次回传

承担执行指令角色的单据只接受一次回传，回传即结束；仓库内部如何分批作业、拆分成多少任务，不进入系统口径。结束后需要补发、补收的，另建单据。

### 8.2 缺量与超量

- 允许缺量的链路：回传数量少于指令数量时按实际结果记账；少收、少发部分是否回补下推数量按各模块规则（采购、销售支持回补，其他出入库不回补原单余量）。独立站正向不允许缺量，缺货保持待发货，见 §6.3。
- 不允许超量：回传数量超过指令数量时，系统直接拒绝本次回传并报错。需要接收超出部分时，按各模块规则另建单据（采购超出通知仍在原订单可下推额度内另建通知单，超过订单数量另建采购订单），不改变回传层面的拒绝规则。

### 8.3 结果单与审核

- 由仓库或下游回传、校验通过后系统自动生成的结果单，默认自动审核，不经人工审核。零收／零出按 §5.3、§6.4 取消原通知／订单／申请，不生成零数量结果单。
- 人工形成的结果单（人工确认实际结果、人工创建的直接调拨单），按提交审核流程处理。
- 结果单在 ERP 已生成且已审核后逐单推送金蝶；订单、申请、通知和分步式调拨主单不推送。推送范围与失败处理沿用 FIN-FR01～FIN-FR03。
- 结果单推送金蝶后由金蝶按其核算规则处理；金蝶内部的暂估应付、应付、付款及凭证流程不属于 ERP，也不在本文范围。

### 8.4 执行回执

执行指令层的实际结果用于形成结果单，零收／零出按取消处理、不生成结果单。申请取消后的仓库确认或拒绝等回执不生成结果单、不改变即时库存；取消成功后按规则释放下推额度，涉及预占或可退额度时沿用各模块规则。采购通知状态流转见 §5.3，销售取消规则见 SAL-FR04、SAL-FR08。

### 8.5 结果单的完结与更正

结果单记录实际发生，不接受第二次回传，也不跟随来源直接改写已完结结果。回传后发现少收、错收等差异，不设计常规业务更正流程，由技术介入修数据，或按双方线下约定处理；外部 ToC 的完结保护继续沿用 SAL-FR12。

业务上一次回传与接口去重是两件事：来源重复回传、幂等标识及部分成功恢复仍属接口设计待确认项，不因本模型视为已解决。

### 8.6 不设换货单、补发单

换货按"销售退货链 + 新建销售订单"处理；补发在销售按原订单另建单据或新订单，采购超出部分按 §8.2 的补救规则处理。不新增换货单、补发单。

## 九、边界场景

以下情况明确不进单据分层模型：

- 拒收：仓库现场拒收按缺量回传处理；入库后的不合格品走采购退货链，不新增单据。
- 自提：B2B 现场提车仍需订单与通知单，只是不选物流，层数不变。
- 在途差异：分步式调拨少收差异保留在途，后续通过再次调拨或其他出库清理，不自动抹平（INV-FR03）。
- 整单零执行：采购通知、两层订单／申请在最终确认数量为 0 时按零收／零出取消该执行单，不生成零数量结果单；等待执行期间不提前按零收／零出结束。分步式调拨实际调出为 0 时同样按零出取消该分步式调拨单，不生成后续单据并释放未执行预占。
- 库存比对差异：只展示与比较，不自动改账、不生成单据（INV-FR08）。
- 库存初始化：由上线切换方案安排，不属于日常单据链（INV-FR02）。
- 跨组织调拨：属于买卖，方案另行确认，不并入同组织调拨链路。
- FBA、海外仓等外部来源的丢件、破损与平台调整：一期接口能力待核验，不预设单据链路。

## 十、适用范围与后续维护

- 当前已说明采购类三层主链、两层链路及一层结果单状态。销售、退货按 §5.9 保留各自额度与占库差异；分步式调拨主单在调入通知收到最终回传并生成第二张直接调拨单后自动完结，少收差异仍按在途单独处理。
- 分步式调拨实际调出必须大于 0；仓库回传 0 时按零出取消该分步式调拨单，不生成在途、调入通知或第二张直接调拨单，不改变库存、不推进主单，取消后释放未执行预占。实际调入同样必须大于 0；回传 0 属于异常，不按零收取消通知单，通知单无法关闭，需要人工处理。
- 本文维护分层、状态职责及跨层联动，各模块维护特有业务规则。独立站自动推送与取消审核调整、其他出入库取消替代关闭、采购取消、零收／零出取消、分步式调拨主单完结、零调出取消及零调入异常处理规则均已回填到对应模块。
- 后续设计或 AI 实现应同时读取本文与对应模块；尚未确认的局部差异不得用通用惯例补齐。
- 状态枚举和操作条件以应用设计和 PRD 为准；本文与它们不一致时，按“越靠近实现越有解释权”处理：先确认是不是模型本身要改，不是的话改本文的示例。
- 共用规则集中在 §八，§五至§七说明各自的操作、数量和差异；维护时同步检查相关引用，避免同一规则在不同章节出现不同结论。
