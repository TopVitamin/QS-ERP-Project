## 一、自研 ERP 指什么

自研 ERP 是强盛科技从 0 到 1 建设的**后台业务中枢**，一期承担以下职责：

| 职责 | 说明 |
| --- | --- |
| 基础资料 | 维护成品 SKU、供应商、仓库、客户、物流与辅助资料 |
| 价格 | 维护采购、销售价目表，通过各自价格调整单变价；业务单据保留交易快照 |
| 采购 | 承接成品采购、采购退货的订单、通知和实际结果链路 |
| 销售 | ERP 承接 B2B、Shopify 独立站及退货；外部 ToC 保留原订单与实际结果关联 |
| 库存 | 维护自营及第三方仓对应的逻辑仓库存，支持预占冻结、其他出入库、仓间调拨、在途及库存比对 |
| 业财推送 | 将七类已审核结果单自动逐单推送金蝶，不建立财务核算台账 |
| 公共能力与集成 | RBAC、适用的提交审核、导入与技术参数配置；外部映射、数据交换及必要异常记录 |

**不由自研 ERP 承担的工作：**

- 领星／聚水潭承接的 ToC 抓单、打单及履约执行。
- 仓内收发、拣货、上架与盘点执行；ERP 不建盘点单，但接收盘盈盘亏结果。
- 应收应付、收付款、核销、凭证、总账与存货成本核算，由金蝶负责。
- 自研 WMS、自研 SRM、中央 OMS，以及全量库存双向同步、跨渠道配额与统一调度。

## 二、各系统分工

```plain
外部 ToC 平台 → 领星／聚水潭 → 对应仓库履约
                      │ 原订单及实际结果
                      ↓
Shopify 已付款订单 → 自研 ERP → 七类已审核结果单 → 金蝶
                      ↑                           │
                      └───────────────────────────┘

ERP → 仓储通知 → 自营仓 WMS（直连）／第三方仓（可经 SaaS 中转）
ERP ← 实际结果、物流及库存信息 ← 仓库／SaaS
ERP → 商品 SKU 分发 → WMS、金蝶
```

图中 Shopify、SaaS 和仓库的返回数据范围见 §四。以下是本项目分工，不是外部产品完整能力清单。

| 系统 | 一期承担的工作 | 与 ERP 的职责交界 |
| --- | --- | --- |
| 领星 | Amazon FBA 相关运营与履约衔接，适用仓储单据中转 | 提供原订单及实际结果；不替代 ERP 的采购、库存与业财主链 |
| 聚水潭 | 国内平台店铺订单与履约，第三方仓储单据中转 | 提供原订单及实际结果；可中转 ERP 通知与仓库结果 |
| Shopify | 独立站订单来源 | ERP 拉取已付款订单，人工选仓、选物流与审核后自动推送仓库，并回写履约结果 |
| 第三方 WMS／仓库作业系统 | 收货、上架、拣货、出库和盘点等实物作业 | 接收 ERP 通知或直接推送的订单、申请单并回传实际结果，不承担 ERP 业务审批及财务核算 |
| 金蝶云·星空 | 财务核算 | 采购、销售业务入口逐步迁入 ERP；接收实际结果单 |
| 自研 ERP | 基础资料、价格、采购、销售、逻辑仓库存、集成与业财推送 | 不接管 SaaS 履约、仓内作业和财务引擎 |

深圳自营仓直连仓库作业系统，东莞电商仓经聚水潭衔接；FBA、第三方海外仓的路径与单据映射按实际来源核验。SaaS 中转采购通知不表示额外创建一次仓库执行。具体接口能力尚未验证，需求阶段可用 Mock 表达流程。

## 三、业务链路

### 3.1 采购与入库

采购部门人工测算后直接创建采购订单，不设置采购申请。供应商通过邮件、微信等线下反馈，采购人员代录 ERP。

```plain
采购订单（ERP）→ 采购收货通知单 → 仓库执行
    → 实际入库回传 → 采购入库单 → 对应逻辑仓库存增加

采购退货单（ERP）→ 采退发货通知单 → 仓库执行
    → 实际出库回传 → 采退出库单 → 对应逻辑仓库存减少
```

采购及退货支持分批执行。采购订单、收货通知本身不增加库存；采购退货审核预占，实际出库消耗对应预占。仓储交互可直连或经 SaaS 中转。进入金蝶的是已审核的采购入库单、采退出库单，订单和通知不推送；预付定金、预付款继续在线下处理。

### 3.2 库存

ERP 按逻辑仓维护库存，逻辑仓归属实体仓。同一实体仓可有多个逻辑仓。

**可用库存＝即时库存－预占库存－冻结库存。** 实际出入库改变即时库存；预占和冻结限制可用数量，不直接减少即时库存。不允许负库存。

```plain
采购入库、销退入库、其他入库 → 对应逻辑仓增加
销售出库、采退出库、其他出库 → 对应逻辑仓减少
外部 ToC 实际出入库结果     → 同样按归属逻辑仓记账

ERP 其他入库申请（审核后直接推送仓库）→ 实际结果 → 其他入库单
ERP 其他出库申请（审核后直接推送仓库）→ 实际结果 → 其他出库单
仓库已完成的其他变动       → 校验通过后直接形成其他出入库结果单
```

盘盈、盘亏由仓库执行后回传，分别形成其他入库、其他出库；不补建 ERP 盘点单。已有 ERP 原单时沿用原单逻辑仓，无原单按来源及映射判断；依据不足不任意选仓记账。

仓间调拨包含直接调拨和分步式调拨。深圳向东莞、FBA、海外仓备货属于库存转移，不是消费者销售，也不因此纳入头程物流管理。

```plain
直接调拨：实际调整 → 来源逻辑仓减少、目标逻辑仓增加

分步式调拨单 → 调出通知 → 实际调出
    → 直接调拨单：调出仓减少、虚拟在途仓增加
    → 按实出数量生成调入通知 → 实际接收
    → 直接调拨单：在途仓减少、接收仓增加
```

调拨由 ERP 发起和调度。分步式调拨每端一次执行，少收差异留在途，由人工后续处理，不自动抹平。

库存比对按实体仓、SKU、库存状态汇总 ERP 即时库存，与仓库数量比较；不自动分摊差异或改账。上线需要库存初始化，具体截点、数量及迁移方案另行安排。

### 3.3 B2B 销售

```plain
销售订单（ERP）→ 审核占库 → 销售发货通知单 → 仓库执行
    → 销售出库单 → 扣减即时库存及对应预占

销售退货单（ERP）→ 销退收货通知单 → 仓库收货
    → 销退入库单 → 对应逻辑仓库存增加
```

支持分批通知、分批执行和自提。已审核订单不改量改价，可按已确认规则调整交期；信用控制一期只提醒，不限制发货。取消、关闭与仓库执行有各自边界，不能把 ERP 关闭视为仓库已经取消。

### 3.4 电商 ToC

这里指领星、聚水潭承接的外部 ToC，Shopify 独立站见 §3.5。

```plain
平台订单 → 领星／聚水潭抓单与履约 → 实际出库或退货入库
    → ERP 保留原始订单、实际结果及关联
    → 匹配和库存等校验通过 → 结果单自动审核、生效
    → 对应逻辑仓库存增减 → 已审核结果单逐单推送金蝶
```

原订单用于追溯，不因此提前接单占库或再次触发履约；实际结果归属第三方逻辑仓时，不重复扣自营仓。售后按 SaaS 实际拆分接收，不补造来源中不存在的关联。仅退款不生成供应链单据、不改变库存，财务线下处理后在金蝶记账。

国内平台按强盛经营店铺、面向消费者销售处理，“自营”不表示向京东批量供货。Amazon 暂仅覆盖 FBA；送仓备货与消费者销售分别处理。

商品或逻辑仓匹配失败、库存不足时阻止记账及推送，保留异常；修复后继续原记录，不重复履约或记账。已完结结果不跟随来源直接改写，具体异常和接口机制见销售与集成分析。

### 3.5 独立站与直接接入订单

本轮明确的直接接入渠道为 Shopify，不据此扩展其他渠道承诺。

```plain
Shopify 已付款订单 → ERP 自研接口拉取
    → 人工批量选仓、选物流 → 审核占库
    → 订单审核后自动推送仓库执行
    → 深圳仓／海外仓实际发货 → 销售出库单及库存扣减
    → 向 Shopify 回写履约与运单等结果；向金蝶推送已审核销售出库单
```

独立站一单一仓，订单与本次执行一一对应，审核后直接作为执行指令推送仓库，不再单独生成销售发货通知单；一期整单履约、不拆单缺量发货；退货按销售退货链路处理，ERP 不执行退款。接口未覆盖的 Shopify 订单支持人工导入，仍遵守对应业务校验及适用的提交审核流程。完整自动选仓、选物流及自动履约后置，取消需遵守仓库确认边界。

### 3.6 主数据

```plain
商品、供应商、仓库、客户、物流（ERP 维护）
    → 采购／销售／库存等模块引用
    → 商品 SKU 异步分发至金蝶、第三方 WMS
    → 外部 SKU 编码或映射用于识别领星／聚水潭结果

辅助资料 → 提供分类、品牌、单位、币别、结算方式及收付款条件等选项
商品初始价格 → 建档时生成采购价和销售基准价 → 后续通过采购／销售价格调整单变价
```

一期不全量推送商品资料到领星、聚水潭，不管理商品与供应商供货关系。金蝶其他历史主数据迁移范围仍待确认。外部 ToC 交易金额沿用来源，不用 ERP 价目表重算。

### 3.7 业财推送

```plain
采购入库单、采退出库单、销售出库单、销退入库单、
其他入库单、其他出库单、直接调拨单
    → 在 ERP 生成且已审核 → 自动逐单推送金蝶
    → 金蝶按其核算规则处理
```

不按日期、客户、供应商或店铺汇总；订单、申请、通知、分步式调拨主单不推送。分步式调拨两端产生的直接调拨单分别推送。

采购销售结果带来源交易信息；其他出入库和直接调拨不传成本价格，由金蝶核算存货成本。ERP 不维护应收应付、收付款、核销和财务对账台账。平台账单、费用及最终回款由财务线下处理并在金蝶记账。

推送失败不回滚已生效业务或库存，修复后处理原结果单；必要推送记录由系统集成中心承接。金蝶目标单据、字段和核算映射仍需核验。

## 四、数据流转方向

| 方向 | 传什么 | 说明 |
| --- | --- | --- |
| 领星／聚水潭 → ERP | 原始平台订单及实际出入库等结果 | 保留关联，校验后记入对应逻辑仓；不重新履约 |
| ERP → 仓库（直连或 SaaS 中转） | 适用通知，或直接推送的订单、申请单（独立站、其他出入库） | 下游单据名称和映射待核验，不重复驱动执行 |
| 仓库／SaaS → ERP | 实际结果、物流结果及适用库存快照 | 结果支撑业务记账；快照用于库存比对，不自动改账 |
| Shopify → ERP | 已付款订单及相关业务信息 | 自研接口接入；未覆盖订单支持人工导入 |
| ERP → Shopify | 履约、运单等结果 | 具体回写及取消协议待接口设计 |
| ERP → 金蝶 | 七类已审核结果单 | 自动逐单推送，具体目标单据与字段待核验 |
| ERP → 金蝶／WMS | 商品 SKU | 异步分发，失败进入集成异常处理 |

无法自动取得仓库接单、执行结束或取消结果时，支持人工确认实际结果，不绕过业务校验。数据回传记账、库存快照比对不等于 ERP 与各外部系统全量库存双向同步。
