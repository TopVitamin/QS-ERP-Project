## 一、为什么做

### 1.1 到了哪一步

营收大约 3 亿，跨境、国内电商、独立站、B2B 四条线一起跑。自己做研发和品牌，成品外协，核心产能绑着 3 家参股代工厂。

领星和聚水潭能够承担各自渠道侧的订单和履约工作，但公司的采购、B2B、独立站以及不同系统之间的业务单据仍然分散。公司希望从 0 到 1 建设一套自研 ERP，逐步形成自己的业务单据体系。

### 1.2 项目背景中的主要问题

以下内容用于说明立项背景，不代表已经确认的一期功能范围。

| 问题场景 | 当前表现 |
| --- | --- |
| 跨境与国内履约节奏不同 | 跨境链路较长，国内电商履约时效较快，相关信息分布在不同系统 |
| 供应商交付信息分散 | 采购沟通和交期信息依赖线下方式 |
| 多渠道业务并行 | Amazon、国内电商、独立站和 B2B 同时经营 |
| 多个仓储节点并存 | 自营仓、第三方电商仓、FBA 和第三方海外仓各有执行方 |
| 业务与财务信息分散 | 订单、采购和其他业务资料分布在不同系统和线下文件中 |

### 1.3 为什么自研，而不是再买一套

公司此前根据业务需要分别使用过不同系统。现在需要明确的是：领星和聚水潭继续承担渠道侧履约，金蝶继续承担其现有工作，自研 ERP 负责承接本项目确认的业务单据和系统交互。

因此，本项目的重点不是替换现有系统，而是从 0 到 1 建立自研 ERP，并逐步明确它与领星、聚水潭、金蝶之间的边界。

### 1.4 立项时系统长什么样

```plain
电商 ToC 订单
    → 领星 / 聚水潭
    → 在领星 / 聚水潭完成履约
    → 履约结果单据同步到自研 ERP
    → 自研 ERP 推送给金蝶

B2B / 直接接入自研 ERP 的订单
    → 自研 ERP 生成销售订单
    → 自研 ERP 生成销售发货通知单
    → 自研 ERP 生成销售出库单等业务单据
    → 自研 ERP 推送给金蝶

自研 ERP
    ← 部分数据拉取 ── 金蝶
```

## 二、这个项目是什么

项目名称：强盛科技自研 ERP 建设项目（一期）

从零新建。不是升级旧 ERP，也不替换领星、聚水潭或金蝶。本项目当前只固化下面几类已经确认的关系：

| 业务方向 | 当前确认的内容 |
| --- | --- |
| 采购 | 当前先确认采购订单，采购计划和采购申请暂不写入本项目背景 |
| 电商 ToC | 订单先进入领星 / 聚水潭，在外部系统完成履约；履约结果单据再同步一份到自研 ERP |
| B2B | 订单直接在自研 ERP 生成销售订单、销售发货通知单、销售出库单等业务单据 |
| 直接接入自研 ERP 的订单 | 按自研 ERP 内生成业务单据的方式处理，具体订单类型后续确认 |
| ERP 与金蝶 | 业务单据从自研 ERP 推送给金蝶；自研 ERP 也可能从金蝶拉取部分数据 |

除上述关系外，库存、单据状态、调拨、退货、采购订单后续单据以及其他业务规则，暂不在本文定义。

## 三、从 0 到 1 的建设边界

本项目当前关注的是：先把已经确认的业务对象、订单来源、业务单据生成方式和 ERP—金蝶交互关系搭起来。

本轮不展开：

- 具体库存规则；
- 单据状态和状态流转；
- 补货建议、采购计划和采购申请；
- 调拨、退货及其他逆向业务；
- 项目切换、并行运行和期初迁移；
- WMS、SRM、中央 OMS、POS、BI 等后续系统。

这些内容后续按走查结果逐项确认，不从现有背景材料中推导。

## 四、已确认的系统关系

| 系统或对象 | 当前关系 |
| --- | --- |
| 领星 / 聚水潭 | 电商 ToC 订单先进入对应系统，并在对应系统完成履约 |
| 自研 ERP | 接收 ToC 履约结果单据；生成 B2B 和直接接入订单的业务单据 |
| 金蝶 | 接收自研 ERP 推送的业务单据；自研 ERP 也可能从金蝶拉取部分数据 |
| 组织架构 | 用于理解业务参与方，不直接映射 ERP 角色、权限或审批配置 |

## 五、一期先做什么

当前只列已经确认的建设对象：

| 建设对象 | 已确认范围 |
| --- | --- |
| 采购订单 | 自研 ERP 中先承接采购订单 |
| B2B 销售单据 | 自研 ERP 生成销售订单、销售发货通知单、销售出库单等 |
| 直接接入订单 | 自研 ERP 生成相应销售业务单据 |
| ToC 履约结果 | 从领星 / 聚水潭同步履约结果单据到自研 ERP |
| 金蝶交互 | 自研 ERP 向金蝶推送业务单据，并预留从金蝶拉取部分数据的关系 |

## 六、项目协同

本项目会涉及供应链、采购、各渠道、仓储、财务、产品和数字化等业务参与方。组织架构用于帮助理解这些业务关系，具体系统角色和审批方式后续单独确认。

领星、聚水潭、金蝶与自研 ERP 的接口范围，也按已经确认的数据关系逐项补充，不在本文提前扩展。
