## 一、为什么做这个项目（项目缘起）

### 1.1 业务背景：公司到了什么关口

强盛科技当前处于 **供应链深耕期（第四阶段）**——营收向 5–7 亿迈进，员工 300+ 人，活跃 SKU 2,000+，日均订单 8,000+ 单。

经过前几个阶段的扩张，公司已经完成了从「华强北档口」到「全球化品牌运营商」的蜕变：亚马逊、Shopify 独立站做跨境主力，天猫、京东成为国内增量，B2B 经销覆盖全球代理商。经营模式是 **向供应商采购成品、向各渠道销售成品**，产品线从数据线、充电器扩展至氮化镓充电头、移动电源等品类，SKU 数量快速增长。

**但有一个结构性矛盾越来越突出：前台渠道跑得太快，后台主链条跟不上了。**

领星、聚水潭每天在处理海量订单，生意越做越大；但采购、主数据、批发、库存调度等后台能力，仍然散落在金蝶和 Excel 里，靠人工协调。业务体量已经从 1 亿级跳到了 5–7 亿级，**后台系统却还停在 3 亿级时代**。

2021 年亚马逊封号潮进一步加剧了这种焦虑——单一平台风险暴露，国内电商投入加大，多渠道并行抢货成为常态。**公司意识到：如果不把后台主链条收回来，渠道多元化只会让更多系统烟囱竖起来，问题更大。**

### 1.2 至暗时刻：几个逼出项目的真实场景

| 场景 | 发生了什么 | 暴露的问题 |
| --- | --- | --- |
| **大促超卖** | 去年双十一，天猫聚水潭侧把一批氮化镓充电头卖超了，亚马逊端还在正常接单，最后只能紧急砍单、赔付，账号评分受损 | 跨渠道库存不统一，没有全局调度 |
| **新品上市崩盘** | 一款移动电源新品定了上市日，销售预热已铺开，到交货日采购打电话问供应商才知道「货还没备好」，上市计划推迟一个月 | 采购交期不可见，与供应商协同靠电话 |
| **月末对账噩梦** | 财务阿兰月末对账：第三方 WMS 的库存成本与领星、聚水潭导出的发货数据对不上，平台佣金、广告费、汇率损益分散在各处，一笔烂账对了一整晚 | 业财链路断裂，多系统数据不一致 |
| **商品资料混乱** | 产品中心同时推进 5 款新品，金蝶和 Excel 里各维护一套商品信息，条码、规格、价格经常对不上，同步到领星 / 聚水潭时频频出错 | 商品主数据无唯一来源，各系统口径不一致 |
| **质量追溯受阻** | 一批移动电源海外退货率异常，想查是哪个供应商、哪次采购入库、哪批出库——翻了三四个系统，花了两天才拼出链路 | 成品批次追溯链路不完整 |

这些场景的共同点是：**不是某一个 SaaS 不好用，而是没有一个系统能串起「成品采购 → 库存 → 多渠道订单 → 财务」整条链路。**

### 1.3 项目原因：业务痛点与建设诉求

| 业务痛点（来自《业务背景信息》） | 根因 | 本项目要解决的 |
| --- | --- | --- |
| **采购交期不可见** | 向供应商采购成品，协同靠微信 / 电话，无系统化跟踪 | ERP 采购模块跑通基础流程，预留后续 SRM 接口 |
| **备货不合理** | 各渠道各自备货，缺少统一的成品库存视角，容易造成积压或断货 | ERP 库存中心建立逻辑库存，支撑跨渠道调度 |
| **渠道争抢库存** | 领星（FBA）、聚水潭、第三方 WMS 各管一段库存，无全局视角 | ERP 订单中心 + 库存中心，统一归集与调度 |
| **后台主链条太弱** | 采购、批发、主数据散落在金蝶和 Excel | ERP 收回后台供应链主链条 |
| **业财对账靠人肉** | 业务数据分散，金蝶只承接部分结果 | ERP 结算中心统一推送应记账结果至金蝶 |
| **质量追溯难** | 供应商、批次、出入库记录分散 | ERP 主数据 + 采购 / 入库单据链路可追溯 |
| **仓储与库存割裂** | 国内仓实物库存在第三方 WMS，FBA 在领星，国内电商在聚水潭，三套库存互不联通 | ERP 从各系统同步实物库存，建立逻辑库存层；自研 WMS 后续另建 |

### 1.4 为什么是自研，而不是继续买 SaaS

强盛科技的信息化路径一直是 **「痛点驱动，买一个 SaaS 顶一下」**：

```plain
管家婆 → 金蝶 + 店小秘 + 旺店通 → 金蝶 + 领星 + 聚水潭
```

每一轮采购 SaaS 都解决了一个具体问题，但也多竖了一根烟囱。到第四阶段，公司已经同时拥有：

+ **金蝶云·星空**——财务核算底座，不管实物库存；成品主数据、跨渠道调度能力不足
+ **第三方 WMS**——国内仓实物库存与仓内执行（入库、出库、库位），但与渠道系统未深度打通
+ **领星**——跨境执行 + FBA 库存，但只管亚马逊侧
+ **聚水潭**——国内电商打单发货，但与跨境 / 第三方 WMS 库存割裂

**继续买 SaaS 的问题**：

+ 没有一个 SaaS 能同时承接「后台供应链主链条 + 跨渠道订单调度 + 与现有系统深度对接」。
+ 公司业务流程已经高度定制化（成品多渠道并行、跨系统库存调度），通用 SaaS 适配成本不比自研低。
+ 商品主数据、采购与销售单据是公司的核心经营数据，不宜长期散落在外部系统中。

**决策结论**：林强和数字化中心达成共识——**自研 ERP，把后台主链条收回来**；金蝶、第三方 WMS、领星、聚水潭继续在各自场景使用，通过 ERP 中枢拉通。自研 WMS、SRM 排在 ERP 之后，不在本期建设。

### 1.5 信息化现状与差距

**当前系统版图**：

| 系统 | 类型 | 当前承担职责 | 局限性 |
| --- | --- | --- | --- |
| **金蝶云·星空** | SaaS | 财务总账、成本核算 | 不管实物库存；成品主数据、跨渠道调度能力不足 |
| **第三方 WMS** | SaaS | 国内仓实物库存、入库 / 出库、库位管理 | 与领星、聚水潭、ERP 未打通，无法全局调度 |
| **领星 ERP** | SaaS | 亚马逊广告、FBA 库存、跨境订单执行 | FBA 库存与国内仓 / 国内电商库存割裂 |
| **聚水潭** | SaaS | 天猫 / 京东打单发货 | 只管国内电商执行，与跨境 / 第三方 WMS 库存割裂 |
| **供应商协同** | 人工 | 微信、邮件、Excel 跟踪 300 家供应商 | 无 SRM，交期与对账效率低 |

**关键差距**：

```plain
  领星(FBA) ──┐
  聚水潭 ─────┤   各系统各自管库存，互不联通
  第三方WMS ──┤
  ToB/Excel ──┘
              ↓  缺口：缺少自研 ERP
         【自研 ERP】← 本项目
              ↓
         金蝶（财务底座，不管库存）
              ↓
    实物库存：第三方WMS + FBA/领星 + 聚水潭（→ 未来自研WMS统一）
    供应商：微信 + Excel（→ 未来自研SRM）
```

### 1.6 项目的定义

**项目名称**：强盛科技自研 ERP 建设项目

**项目性质**：**从零新建**。不是升级旧 ERP，也不是替换某一个 SaaS，而是在现有 SaaS 之上 **新建一层后台主链条 + 跨渠道调度中枢**。

**一句话定义**：

> 从零搭建自研 ERP，收回商品主数据、成品采购、批发等后台能力，建设订单中心与库存中心实现跨渠道统一调度，通过结算中心将业务结果推送金蝶，让「前台渠道强、后台主链条弱」的局面得到根本改善。

**项目发起**：

+ **发起人**：CEO 林强
+ **执行部门**：数字化中心（正在组建中）
+ **协同部门**：供应链中心、跨境 / 国内电商事业部、职能中心（财务）

**项目边界**：

| 纳入本项目 | 不纳入（沿用或后续另建） |
| --- | --- |
| 自研 ERP 从零搭建（商品主数据、成品采购、批发、订单 / 库存 / 结算中心） | 自研 WMS（后续项目，现阶段沿用第三方 WMS） |
| 与金蝶、第三方 WMS、领星、聚水潭的接口与调度规则 | 自研 SRM（后续项目） |
| 逻辑库存、渠道预留、基础分仓路由 | 金蝶财务核算规则（财务主导） |
| 应记账结果推送金蝶 | 第三方 WMS 仓内执行（沿用，不自研） |
| ToB 批发、内部结算等后台业务单据 | 领星广告 / ASIN 利润核算等垂直能力 |
| — | **生产制造、BOM、物料、MRP、生产计划**（本练习不涉及） |

**建设顺序**：**先 ERP → 再自研 WMS → 再自研 SRM**（第三方 WMS 现阶段沿用）。

## 二、项目的方向和目标

### 2.1 建设方向

本项目的核心逻辑是 **「后台收回来，前台接起来」**：

1. **后台主链条收回**：商品主数据、成品采购、ToB 批发从金蝶 + Excel 迁入自研 ERP，成为唯一管理入口。
2. **跨渠道调度拉通**：领星（跨境）、聚水潭（国内电商）、ToB 批发订单统一入 ERP，由 ERP 做归集、拆单、锁库。
3. **逻辑库存先行**：ERP 从第三方 WMS、领星（FBA）、聚水潭同步实物库存，建立逻辑库存层，解决跨渠道抢货和超卖。
4. **业财链路打通**：业务动作在 ERP 沉淀，应记账结果推送金蝶，减少月末人工对账。
5. **SaaS 各司其职**：金蝶做财务、第三方 WMS 做国内仓执行、领星做跨境 + FBA、聚水潭做国内电商打单，ERP 做中枢调度。
6. **为后续留接口**：架构预留自研 WMS / SRM 对接能力，但不在本期建设。

### 2.2 核心目标

| 目标维度 | 目标描述 | 对应痛点 |
| --- | --- | --- |
| **后台主链条上线** | 商品主数据、成品采购、ToB 批发在 ERP 内闭环 | 后台主链条太弱 |
| **跨渠道订单归集** | 领星、聚水潭、ToB 订单统一入 ERP | 渠道争抢库存 |
| **逻辑库存统一** | 全渠道可承诺库存可见，基础锁库与渠道预留 | 跨渠道超卖 |
| **业财链路建立** | 核心场景应记账自动推送金蝶，单据可追溯 | 业财对账靠人肉 |
| **商品主数据统一** | 成品 SKU 唯一维护入口，自动分发至各系统 | 商品资料混乱 |

### 2.3 建设原则

+ **先 ERP、后自研 WMS / SRM**：本期只建 ERP，国内仓继续用第三方 WMS，供应商协同后续再系统化。
+ **后台优先、调度跟进**：一期先收回主数据和采购，再拉通订单归集与逻辑库存。
+ **对接而非替换**：金蝶、第三方 WMS、领星、聚水潭继续用，ERP 通过接口拉通。
+ **中枢不替代执行**：ERP 管规则与调度，第三方 WMS 管国内仓执行，领星 / 聚水潭管渠道打单，金蝶管财务核算。
+ **主数据单一来源**：商品（成品 SKU）、条码只在 ERP 维护，向各系统分发。
+ **分阶段切换**：与金蝶并行运行，分模块切流，保留回退方案。

### 2.4 预期成效（12 个月）

| 指标 | 当前基线 | 目标 | 对应痛点 |
| --- | --- | --- | --- |
| 商品主数据维护 | 多系统重复维护 | ERP 唯一来源，自动分发 | 主数据混乱 |
| 采购 / 批发流程 | 金蝶 + Excel 散落 | ERP 内闭环 | 后台主链条太弱 |
| 跨渠道订单归集 | 各 SaaS 独立，人工核对 | 主链路统一入 ERP | 渠道争抢库存 |
| 跨渠道超卖率 | 大促偶发 | 显著下降 | 大促超卖 |
| 月末业财对账 | 大量人工核对 | 核心场景自动推送金蝶 | 业财对账靠人肉 |
| 质量问题追溯耗时 | 以天计 | 以小时计（单据链路可追溯） | 质量追溯难 |

## 四、项目的范围与蓝图规划

### 4.1 一期：后台主链条 + 跨渠道调度打底

**目标**：ERP 从无到有上线，跑通「商品主数据 → 成品采购 → 订单归集 → 逻辑库存 → 推送金蝶」。

| 建设模块 | 范围 |
| --- | --- |
| **商品主数据** | 成品 SKU、条码、规格维护；向金蝶 / 领星 / 聚水潭 / 第三方 WMS 分发 |
| **成品采购** | 采购申请 / 订单、到货入库回写 |
| **ToB 批发** | 批发开单、信用额度、发货 |
| **订单中心** | 对接聚水潭、领星；订单归集、拆单、状态回传 |
| **库存中心** | 逻辑库存模型；从第三方 WMS / 领星 / 聚水潭同步实物库存；渠道预留与基础锁库 |
| **结算中心** | 采购入库、销售发货、ToB 出库等核心场景推送金蝶 |
| **接口** | ERP ↔ 金蝶、ERP ↔ 第三方 WMS、ERP ↔ 聚水潭、ERP ↔ 领星 |

**一期交付价值**：

+ 后台主链条从金蝶 + Excel 收回，主数据有唯一来源。
+ 跨境 + 国内电商订单统一入 ERP，跨渠道抢货问题初步缓解。
+ 核心业财场景自动推送金蝶，月末对账效率提升。

### 4.2 二期：能力深化 + 复杂场景

**目标**：多仓调度、大促保障、采购备货优化，ERP 中枢能力趋于完整。

| 建设模块 | 范围 |
| --- | --- |
| **采购增强** | 安全库存预警、补货建议（基于销售与库存数据，非 MRP） |
| **库存中心增强** | 多仓路由、跨仓调拨单据、大促锁库策略 |
| **订单中心增强** | 异常处理、退换货、大促峰值保障 |
| **结算中心增强** | ToC 多渠道结算、退货 / 调拨、凭证模板完善 |

**二期交付价值**：

+ 多仓调拨系统化，大促超卖率进一步下降。
+ 成品备货更有依据，减少盲目采购。
+ 业财覆盖场景扩大，质量问题追溯链路完善。

### 4.3 远期扩展（后续独立项目）

| 方向 | 说明 | 与 ERP 的关系 |
| --- | --- | --- |
| **自研 WMS** | PDA 扫码、库位、波次、FIFO；统一国内仓实物库存主账 | 替代 / 整合第三方 WMS，ERP 管逻辑库存 |

| **新渠道接入** | TikTok Shop 等 | ERP 订单中心提供 API |

## 五、关键协同与风险

### 5.1 关键协同方

| 协同方 | 协同内容 |
| --- | --- |
| **供应链中心** | 成品采购流程、库存策略、分仓调拨 |
| **产品中心** | 商品主数据维护规范、新品上市节奏 |
| **跨境 / 国内电商事业部** | 渠道接入、订单异常规则、大促保障 |
| **财务** | 结算规则、凭证模板、金蝶对接、并行期对账 |
| **金蝶 / 第三方 WMS / 领星 / 聚水潭** | 接口对接、联调、库存同步与历史数据迁移 |

### 5.2 主要风险

| 风险 | 应对思路 |
| --- | --- |
| **从零搭建，团队刚组建** | 分模块迭代，一期聚焦主链路，控制范围 |
| **与金蝶并行期冲突** | 分模块切换，财务人工复核兜底 |
| **多 SaaS 接口联调复杂** | 明确边界，一期只接三条主链路 |
| **多源库存同步复杂** | 第三方 WMS、领星（FBA）、聚水潭三套库存，ERP 需统一同步与对账 |
| **业务方抵触改变习惯** | 管理层推动，配套培训，保留并行期 |
| **供应商协同仍靠人工** | ERP 先跑通成品采购流程；深度协同等 SRM 项目 |
