## 前端规范

- 含税类单据明细的价税字段默认顺序：含税单价、税率、不含税单价、价税合计、税额、金额；其中**金额指不含税金额**，**价税合计指含税总额**；单头汇总字段同名，见《6.强盛ERP的编码规则和通用字段规则》第三节「价税字段命名」。

- 字体与对比度：正文和控件保持 12px 紧凑型（compact），不放大字号解决对比度。可读文本统一用深墨蓝 `text-erp-text`（正文、表头、表单标签、批量操作按钮、首页卡片正文），灰色（`text-erp-text-muted`）只用于分页计数、占位等次要信息；语义色文字已加暗到 ≥4.5:1，亮色只用于填充、边框、圆点和图表，新增颜色按实际背景实测。禁用态文字用 `text-erp-disabled`，不复用 `text-erp-text-muted`。
- 空值占位：列表、详情、明细表等未填写字段统一显示 `-`（英文连字符），不用中文破折号 `—`；统一用 `lib/format.js` 的 `EMPTY_PLACEHOLDER` / `formatEmpty`。数量、金额的 `0` 按有效值展示。
- 多条码展示：列表、明细等合并展示为一行，用英文分号 `;` 连接（如 `6901001001;6901001991`）；商品资料档案页仍逐条展示。
- 系统记录字段展示名：创建人、创建时间、**最后更新人**、**最后更新时间**（不用「更新人」「更新时间」）；见《6.强盛ERP的编码规则和通用字段规则》第三节。制单信息用 `buildCreateMetaFields`。
- 主题：`data-theme` 挂 `documentElement`，弹层／下拉／弹窗／Toast 才能跟随主题；顶栏用 `--erp-header-gradient` 渐变（随主题微调）；左侧菜单固定近黑中性色（`--erp-sidebar-solid: #1f232e`，hover／边框／弹出层从它混出，不随主题换底），只有选中项 `--erp-sidebar-active-solid` 跟主题主色（配白字）；主按钮用主题主色（默认精工蓝，不用金蝶的绿色）；主题清单在 `styles/tokens.js`，新增主题在 `styles.css` 补 brand／hover／selected／active-solid／表头渐变并实测对比度（文字 ≥4.5:1、选中块与侧栏底 ≥2:1、hover 与底 ≥1.4:1）；图表等装饰色走 `rgb(var(--erp-brand-500))`，不硬编码。
- 控件样式：业务字段用仅保留底边框的底线样式；明细表格内输入框和下拉用完整边框；分页页码与条数选择器保留完整边框；禁用控件不用灰背景。
- 明细与栅格：合计行紧凑、汇总值落在对应列下、金额适度加粗；基础信息普通字段占 1 列、备注占 3 列且单行高度；数字输入框隐藏原生步进器。**单价（含税／不含税）统一 4 位小数**（`LineItemTable` 自动走 `formatUnitPrice` / `calculateNetUnitPrice4`，单价输入框 `step="0.0001"`）；金额、税额、价税合计仍 2 位（`formatAmount`）。
- 价格调整单、采购/销售订单与退货单的税率属于 `PCT_4` 数值字段，`LineItemTable` 用 `editorOptions.taxRateControl: 'number'` 显示百分比数值输入（`min="0"`、`step="0.01"`），允许0%、最多2位小数。采购税率由采购人员结合供应商纳税人类型手动填写，不从商品带出；采购取价命中税率为空的初始价时保留空值。销售税率可按商品税务信息预填并允许用户修改；有来源的退货沿用原单税率。各单据提交时校验必填，格式由共享 `validation.js` 校验。
- 采购订单和采购退货按供应商+SKU+币别查询当前采购价；销售订单和无来源销售退货按具体客户价→客户等级价→所有客户基准价查询当前销售价。无匹配价时保留空价供手工录入；选品弹窗不展示与当前业务维度无关的通用SKU参考采购价。
- `SkuSelectionDialog` 用 `DialogDescription` 提供筛选与确认操作说明；如说明不适合视觉展示，可使用 `sr-only` 保留屏幕阅读器可读信息。
- 查询区：筛选项统一走 `FilterControl`（`ListPageHeader` 接线）；`type` 取值与下方「查询区通用规则」一致。Demo PRD 写查询条件时直接用原型 `type`，不要另造控件名。
- 下拉弹层：宽度按内容自适应（`SelectContent` 已统一）——最窄对齐触发器、最宽 560px 且不出屏、选项单行；不要写死成触发器宽度。
- 列表交互：重置只还原筛选和选中，不改列显隐；页码可清空编辑，失焦或越界回合法页；操作列宽按当前页各行可见按钮文案估算（无「更多」时不预留更多位），表头与行内按钮左对齐，按钮 `px-1`、`gap-1.5`；配置 `rowActionsMaxVisible: 3` 时最多直出 3 个按钮，其余进「更多」下拉；表格横向滚动条用 `.table-scroll` 细滚动条（6px），不用全局粗滚动条；列表默认不限日期，保证新单保存后可见。列表页内 Tab 用 `InnerTabs` 默认 `underline` 变体（下划线、40px 行高），位置在表格卡片顶部、批量操作栏之上；用了 Tab 就不再在筛选区重复放同一状态字段。详情页卡片内切换用 `InnerTabs` 的 `pill` 变体（胶囊），见「详情页标准接线」。
- 批量操作栏：左侧默认只展示「已选中 N 条」；导入导出放页头（`ImportExportActions`），导出可选全部／当前筛选／已勾选。主数据列表一期提供批量提交审核、批量审核通过、批量驳回、批量删除（2026-09-23确认，覆盖仓库、供应商、客户等有审核状态的主数据）：提交／审核通过／驳回要求所选记录审核状态一致且满足动作前置状态（草稿或已驳回可提交，待审核可通过/驳回），状态不一致时提示后阻止；批量删除逐个校验引用，存在被引用记录时整批阻止并说明原因，删除不受审核状态限制。业务单据列表一期以行内操作为主，批量栏不放删除、取消、关闭等——状态与校验因单而异，取消关闭还须逐单填原因。
- 排序：只给日期、金额、数量这类可比较的列开排序，文本列（单号、供应商等）不排序；排序图标同族，未排序显示上下两个箭头，升／降序显示单个箭头（`DataTable` 已统一）。
- 列设置：面板支持搜索列名、勾选显隐、拖动排序、图钉固定左侧、恢复默认（`ColumnSettings` 已统一）；固定列吸附在勾选列之后，右侧操作列保持固定；列宽拖拽和右键自适应留在表头。
- 配色基线（对齐金蝶 tf.jdy.com 实测）：画布 `#EBEDF1`、表头 `#F6F6FB`、数据行 `#FFFFFF`（不做斑马纹）、行线 `#D2D0E4`、列线 `#E8E9EB`；可读文字（含 Tab 未选中）`#07073F`，次级灰 `#66667F`（顶栏浅色渐变上按最深处实测 ≥4.5:1），输入占位 `#555871`，禁用 `#787A94`。语义色色相向金蝶靠（橙 `#B85700`、绿 `#2A8003`、红 `#D42626`），但必须保持 ≥4.5:1。
- 列表框架尺寸：页面标题行 48px；表格卡片内 Tab 行 40px、批量操作行 48px、分页行 48px（`InnerTabs`／`BulkActionBar`／`PaginationBar` 已统一）。Tab（`px-3`）选中态只用加粗文字 + 2px 下划线，不加背景色；下划线要压在 Tab 行底线上：底线用容器的 inset box-shadow（`shadow-[inset_0_-1px_0_rgb(var(--erp-border-default))]`）画并给容器留 `pb-px`，让按钮不占满底线、hover 背景盖不到线，指示线用 `-bottom-px` 探出按钮盖住底线；Tab 行用 `px-1 gap-3`，首项文字与下方批量操作栏的「已选中」左对齐。批量操作用纯文字按钮（12px、常规字重、无图标、不加边框，默认次级文字色、悬停出浅底，危险操作用红色文字），按钮之间用 12px 高的 `bg-erp-border-light` 浅色竖线分隔（`已选中 X 条` 之后也要有分隔线）；行内操作保持文字链接。注意 erp 颜色里默认边框的类名是 `border-erp-border`，没有 `border-default` 后缀。
- 表单：所有输入都要有可访问名称（`FormControl` 管基础信息、`LineItemTable` 管明细）；拒绝负数单价（`lib/validation.js` 的 `hasNegativePrice`）；字段默认值不得与列表默认筛选冲突。**新增/创建页页头不展示流程状态标签**（`DocumentFormPage` 默认已拦截）。**表单校验**见下方「表单页标准接线」与[《UI布局公共说明》](../05-常用模板/02-模块设计交付/UI布局公共说明.md)。
- 主数据：供应商、仓库、员工、部门、SKU 等选项只从 `src/data/masterData.js` 取，页面和筛选不另建。供应商、客户、仓库、商品等带编码主数据的展示与下拉选项统一用 Code-Name（`{编码} {名称}`），见《6.强盛ERP的编码规则和通用字段规则》2.3。
- Mock 数据：写入 `localStorage`，刷新保留；单据间的关联选项从本地 Mock 集合读取。

### 查询区通用规则

列表查询区由 `ListPageHeader` + `FilterControl` 统一承载；模块 Demo PRD **只列筛选项、顺序、匹配方式与模块联动**，不重复写布局与通用交互。

| 项目 | 规则 |
| --- | --- |
| 字段布局 | 6 列栅格（`grid-cols-6`），标签在上、控件在下；按 Demo PRD / TSV 顺序从左到右、从上到下填充，满 6 个换行 |
| 默认/更多筛选 | **不支持**按字段分「基础筛选 / 更多筛选」；所有筛选项同屏排在栅格内 |
| 整块折叠 | 仅支持**整块查询区**展开/收起（页头「展开过滤」、查询区底「收起过滤」）；收起后筛选值保留 |
| 查询触发 | 点「查询」后执行 `filterRows`；改条件不自动查询 |
| 重置 | 「重置」清空筛选初值与表格勾选，**不改**列设置 |
| 空条件 | 条件全空时返回全量数据；日期类筛选项默认「不限」，保证新单保存后可见 |
| 查询后分页 | 点「查询」或「重置」后回到第一页 |
| 状态多选 | 审核状态、业务状态、收货/发货状态等并列维度用 `multi-select`；初值 `[]`、placeholder「全部」、未选等同全部；过滤用 `matchesMultiSelect`（`lib/listFilters.js`） |
| 主数据下拉 | 供应商、仓库等选项从 `masterData.js` 取；选项与已选展示 Code-Name（`{编码} {名称}`） |
| 文本搜索 | `search` 为纯输入框，不加放大镜图标；有值后 hover 出现清除按钮 |
| 模块联动 | 前置未满足时禁用/占位等**模块差异**写在各 Demo PRD；无通用 `type` 时在页面用条件渲染，不另造全局控件名 |

操作组顺序：查询区底行左侧「收起过滤」；右侧「重置」→「查询」。

### FilterControl 控件 type

`filterFields` 每项的 `type` 必须与下表一致（实现见 `src/components/erp/FilterControl.jsx`）。Demo PRD 查询区表的「type」列照抄此表取值。

| type | 用途 | 初值 / 值结构 | 备注 |
| --- | --- | --- | --- |
| `search` | 单号、商品编码等模糊搜索 | `''` | 走 `ClearableInput`；`placeholder` 写「请输入…」 |
| `select` | 枚举单选、主数据单选（选项不多时） | `''` | 第一项常为 `{ value: '', label: '全部…' }`；用 `SelectField` |
| `searchable-select` | 选项较多、需下拉内搜索的主数据 | `''` | 用 `Combobox`；选项仍 Code-Name |
| `multi-select` | 并列状态等多选枚举 | `[]` | 未选等同全部；OR 匹配 |
| `date-range` | 单据日期、创建时间等日期范围 | `{ from: '', to: '' }` | 按日期比较 |
| `datetime-range` | 需要精确到秒的时间范围（如库存流水「变动时间」） | `{ from: '', to: '' }`（`'YYYY-MM-DD HH:mm:ss'`） | 用 `DateTimeRangePicker`：日历选日期范围 + 起止时/分/秒；只选日期时起始补 `00:00:00`、结束补 `23:59:59`；过滤用 `matchesDateTimeRange` |
| `checkbox` | 单个勾选项（如库存查询「展示为0的库存数据」） | `false` | 用 `Checkbox`；标签由查询区栅格提供 |
| `date` | 单日筛选（少用） | `''` | `yyyy-MM-dd` 字符串 |
| `radio` | 少量平铺选项（少用） | `''` | 横向单选组 |

**样板**：`PurchaseOrderListPage.jsx` 的 `filterFields` / `initialFilters`（`date-range` + `search` + `select` + `multi-select`）。

并列状态字段可用 `statusMultiSelectField(key, label, labelsMap)` 生成配置（`lib/listFilters.js`）。

### 列表列通用呈现规则

`DataTable` 列配置与模块 Demo PRD 的列表表对齐；**通用规则写在本节，模块 PRD 只列本页列清单与差异**（如本模块状态 tone、币别列位置）。

| 项目 | 规则 |
| --- | --- |
| 对齐 | 文本、日期、状态、链接默认**左对齐**；数量、金额、税率等数值列 **`align: 'right'`** |
| 排序 | 仅日期、数量、金额等可比较列开 `sortable: true`；单号、供应商、状态、备注等文本列**不排序**（见上文「排序」） |
| 默认排序 | 模块 Demo PRD 写明默认字段与方向；业务单据安排单/通知单类通常 **创建时间降序** |
| 空值 | 未填写显示 `-`（`EMPTY_PLACEHOLDER`）；数量/金额的 **`0` 为有效值**，显示 `0` 或 `0.00` |
| 金额 | 页面 **千分位 + 2 位小数**（`formatAmount`）；录入不带千分位；见《6.强盛ERP的编码规则和通用字段规则》 |
| 币别与金额分列 | 列表有币别列时，金额列**只展示数值**，不再前缀 `¥` 或币别编码；币别列按辅助资料 **编码+名称** 展示（如 `CNY 人民币`） |
| 主数据列 | 供应商、仓库等 Code-Name：`{编码} {名称}`（`resolveOptionLabel`） |
| 列表状态列 | 用列配置 `tone` 渲染**语义色文字**（如 `text-erp-success`），**不用** `StatusBadge` 胶囊 |
| 详情/页头状态 | 用 `StatusBadge` 胶囊；tone 与列表状态列语义一致；tone 只传语义键（success／warning／danger／info／neutral），不要传 `text-erp-*` 类名（未命中会回落橙色） |
| 链接列 | 主色文字 + hover 下划线；点击进入详情（列表行内不设「查看」）；`link: true` 整列可点，`link: (row) => 条件` 可按行判断（空值不提供占位链接） |
| 长文本 | 默认 `ellipsis: true`；过长省略，hover 可看全文（`EllipsisCell`） |
| 固定列 | 勾选列 + 业务主键列（通常单号）固定左侧；操作列固定右侧 |
| 页头按钮 icon | 页头主操作（如「新增」）**可有**图标；批量操作栏、行内操作**不加**图标 |
| 行内操作 | 纯文字链接；最多直出 3 个 +「更多」；不满足 `visibleWhen` 时**隐藏** |

## 详情页标准接线

走 `DocumentDetailPage` 的单据详情页，优先**配置**已有分组与底部卡片，不要在页面里重复画胶囊 Tab、内嵌简表和操作日志。

## 导入导出与消息

- 导入导出对象统一注册在 `lib/transferTargets.js`（字段、必填、枚举、keyField、storageKey）；页面入口用 `ImportExportActions`，流程走 `ImportWizardDialog`／`ExportWizardDialog`，不要在页面里另写导入导出。
- 导入规则：按 `keyField` 匹配，已存在更新非空字段、不存在新增，导入后统一回 `auditStatus: draft` 等人工审核；新对象接入前核对02/03的业务处理原则，以及04字段清单与主PRD中的字段和校验设计。`importable: false` 的对象不进导入中心、列表默认不展示导入按钮；Demo 需要保留导入向导时加 `demoImport: true`，按钮和向导标明 Mock。
- 单据级分组导入（采购退货单、销售退货单）：模板按「单据序号」把多行归并为一张单据，任一行失败则整批不导入。target 上另挂 `documentImportFields`（模板列）、`validateDocumentImport(target, headers, rows)`（逐行校验 + 归并成单，返回 `items/summary/headerErrors`，`summary.documentCount` 为拟生成张数）与 `commitDocumentImport(target, { fileName, validation })`（整批落库或整批失败）；`ImportWizardDialog` 检测到这两个钩子就走分组流程，未挂钩子的对象仍走原单表流程。校验与落库函数放各模块的 `lib/*Import.js`，不在页面里另写。
- 所有导出都是异步任务，写入 `lib/taskStore.js`（`qs-erp:transfer-tasks:v1`），完成时推 `transfer` 类消息；导入导出中心两页共用 `TransferCenterPage`。
- 消息统一走 `lib/notificationStore.js` + `hooks/useNotifications.js`（分类：待办／业务／导入导出／系统），偏好走 `lib/preferences.js`；文件解析与生成统一用 `lib/spreadsheet.js`（xlsx 按需加载，csv/tsv 自解析）。
