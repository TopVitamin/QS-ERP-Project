## 1. 这套项目在做什么

从这一节开始，正式进入ERP项目。

和进销存项目一样，后面整套ERP课会同时存在两条线：

- **竞品拆解线**：研究金蝶、领星、聚水潭等成熟ERP产品，看它们怎么组织模块、怎么解决业务问题
- **项目实战线**：回到强盛科技的真实发展阶段，做产品设计取舍

两条线的配合方式和进销存项目一致：**先看成熟竞品，再回到强盛科技做判断，最后收成自己的方案。** 拆竞品时先以竞品本身为准，不要一上来就用强盛科技的背景硬套。

但ERP项目比进销存复杂得多——因为**ERP本身就是一个宏大且边界模糊的概念**。进销存很清晰：采购、销售、库存，三条主链路，基本不会有歧义。但ERP不一样——你去问10家公司"你们的ERP包含什么"，可能会得到10个不同的答案。

所以这套课的第一步，不是直接进入模块设计，而是先建立一个对ERP的**全局认知框架**。

## 2. ERP到底是什么

### 2.1 ERP的三大类

ERP（Enterprise Resource Planning，企业资源计划）这个概念最早起源于制造业，但到今天，"ERP"这个词在不同场景下指代的东西已经完全不同。

最常见的ERP大致可以分成三类：

| 类型          | 定位                                       | 核心模块侧重                            | 代表产品                             |
| ----------- | ---------------------------------------- | --------------------------------- | -------------------------------- |
| **传统ERP**   | 以财务、生产、人力资源为核心的企业级资源计划系统                 | MRP/BOM、生产排产、质量管理、成本核算、总账、HR      | SAP、Oracle（NetSuite）、Infor、金蝶、用友 |
| **电商ERP**   | 围绕电商订单履约业务设计的服务支撑系统，是商家与平台之间的桥梁          | 订单管理、仓储管理、物流对接、商品管理、采购、财务对账       | 聚水潭、旺店通、领星、店小秘、马帮、万里牛            |
| **公司内部ERP** | 企业自己的后台管理系统，功能丰富但边界模糊，有时不知道怎么定义就统一叫"ERP" | 采购、销售、库存、仓库、物流、商品——按业务需要长出来什么就做什么 | 各企业自研系统                          |


**这三类的差别很大：**

- **传统ERP**模块最全（财务+人力+生产+供应链），但通常不直接对接电商平台
- **电商ERP**主要服务商家，核心是帮商家在多平台上高效履约（拉单、打单、发货、库存同步），是典型的"服务支撑类系统"
- **公司内部ERP**最灵活也最难定义——它的模块范围完全取决于企业自身的业务需要

**强盛科技的自研ERP属于第三类。** 但它的设计思路会大量借鉴前两类：从传统ERP借鉴主数据体系和业财协同，从电商ERP借鉴平台集成和订单履约。

### 2.2 电商ERP生态——国内和跨境

因为强盛科技同时做国内电商和跨境电商，所以需要对这两个方向的ERP产品都有了解。

**国内电商ERP**——主要服务国内电商平台（天猫/京东/抖音/拼多多）的商家：

| 产品       | 市场定位                                                          | 核心能力                                                           |
| -------- | ------------------------------------------------------------- | -------------------------------------------------------------- |
| **聚水潭**  | 国内电商SaaS ERP头部厂商；多份招股书与行业研究按**收入**计市场份额领先 | 多平台订单、WMS/仓配、采购与库存、财务对账；平台与物流对接面广，偏中大商家复杂履约                    |
| **旺店通**  | 慧策（北京掌上先机）旗下主力品牌，与聚水潭同属国内电商ERP**第一梯队** | 订单与全渠道履约；产品线含极速版/企业版/旗舰版及独立WMS，旗舰版侧重OMS+WMS与仓内智能化作业（以官网版本划分为准） |
| **万里牛**  | 电商+跨境+门店等一体化SaaS，适合“国内+跨境+线下”多形态并存                            | 多业态模块覆盖；官网对多款产品提供**免费试用**，适合上手摸底（不等同于全功能长期免费）                  |
| **超级店长** | 偏中小商家的工具型SaaS                                                 | 光云科技旗下，功能相对轻量，常与打单、上货等单点工具组合使用                                 |
| **吉客云**  | 一站式经营数字化                                                      | 帮助中心/手册颗粒度细，适合当“说明书式”自学材料                                      |


**跨境电商ERP**——主要服务跨境电商平台（亚马逊/eBay/沃尔玛/Shopee/Lazada）的商家：

| 产品      | 市场定位                                                                                      | 核心能力                                                                  |
| ------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **领星**  | 以亚马逊深度场景为主，并向多平台延伸；亚马逊侧官方合作资质（如SPN、广告等）较全                                                 | Listing/广告/库存/FBA、利润与成本核算、业财一体化；卖家侧渗透与口碑讨论度较高 |
| **店小秘** | 跨境ERP头部厂商之一；沙利文等第三方报告近年常给出**市占率领先**表述（口径以报告为准）；**D轮融资发生在2022年**（约1.1亿美元量级新闻多见） | 多平台刊登与订单处理；ERP+赛狐、BigSeller、17TRACK等**产品矩阵广**；“集成最全”随平台迭代变化，以当期对接清单为准 |
| **马帮**  | 成立较早的多平台跨境ERP                                                                             | 刊登、订单、采购仓储等常规链路；华东等区域卖家基础较深                                           |
| **易仓**  | 跨境数字化**矩阵型**厂商（ERP、海外仓WMS、TMS等并列演进），并非“只做ERP后补WMS”单线故事                                    | 市场认知上**海外仓/WMS**声量常高于单点“ERP”；适合理解“业务中枢ERP + 仓配执行WMS”的分工与集成            |
| **积加**  | 聚焦亚马逊精品/品牌卖家，与领星等有客群重叠                                                                    | 运营看板、利润与经营分析                                                          |


> **说明**：市场份额、排名、融资阶段等会随统计口径与时间变化；上表用于建立**品类地图**，实际选型以各产品当期官网、对接平台清单与试用为准。

**电商ERP的核心业务场景**可以从三个角度理解：

```mermaid
flowchart LR
    A["平台<br/>（天猫/亚马逊等）"] <-->|"拉单/推送库存/同步状态"| B["电商ERP<br/>（商家与平台的桥梁）"]
    B <-->|"下发执行指令/回传结果"| C["商家<br/>（采购/仓储/物流/财务）"]
```

电商ERP是**商家与平台之间的桥梁**——它不直接增加销售额，但它决定了订单能不能快速审核、库存能不能准确同步、物流能不能高效发运、财务能不能按时对账。

**电商ERP的高频业务场景包括：**

| 场景类型  | 具体内容                                |
| ----- | ----------------------------------- |
| 订单处理  | 多平台拉单、订单审核（仓库/物流/库存分配）、拆单/合单、异常订单拦截 |
| 仓储与履约 | 采购→入库→库存管理→分波拣货→复核→出库发货             |
| 库存管理  | 库存查询、库存流水、调拨、盘点、加工（组装/拆卸）、库存预警      |
| 财务对账  | 平台回款核算、利润核算、采购对账、多币种结算              |
| 平台集成  | 多店铺管理、刊登、物流渠道对接、售后处理                |


> 其中**订单审核规则**是电商ERP的灵魂——自动化的审核规则可以释放人力、提升履约时效。常见的审核子项包括：分配仓库规则、分配物流规则、拆合单规则、地址校验规则、赠品规则等。

### 2.3 不同类型ERP的功能模块横向对比

把和强盛科技业务相关的几款ERP拿出来横向对比，能更直观地看到差异：


| 功能模块    | 金蝶云·星辰 （中小零售/小微，现多称金蝶AI星辰）                                 | 金蝶云·星空 （中大型，现多称金蝶AI星空）                                          | 领星ERP （跨境电商）                                | 聚水潭 （国内电商）                    |
| ------- | ---------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------- | ----------------------------- |
| 商品主数据   | ✅ 零售/商贸商品档案为主；**制造扩展包**下支持生产向BOM（深度通常弱于星空）                 | ✅ 多规格+BOM+品类/组织体系                                               | ✅ 平台SKU/Listing映射                           | ✅ 电商SPU/SKU                   |
| 供应商管理   | ✅ 基础档案+账期                                                  | ✅ 供应商+采购协同                                                      | ⚠️ 有供应商与价格体系；**较金蝶缺多组织SRM/复杂协同**            | ⚠️ 够用为主；非传统SRM深度              |
| 采购管理    | ✅ 采购订单→入库→对账                                               | ✅ 采购全链路+审批                                                      | ✅ 采购单链路+智能补货/FBA补货等                         | ⚠️ 电商采购/1688协同等够用；弱于金蝶全链路业财采购 |
| 库存管理    | ✅ 多仓+调拨+盘点                                                 | ✅ 多组织多仓+批次                                                      | ✅ FBA库存+海外仓                                 | ✅ 电商库存                        |
| 销售/订单管理 | ✅ 批发+零售                                                    | ✅ 多渠道销售                                                         | ✅ 多平台订单+审核规则                                | ✅ 多平台订单+审核规则                  |
| 门店管理    | ✅ 连锁门店+POS                                                 | ✅ 门店+配货                                                         | ❌                                           | ❌                             |
| 财务协同    | ✅ 业财一体                                                     | ✅ 总账+成本+合并报表                                                    | ⚠️ 利润核算                                     | ⚠️ 基础对账                       |
| WMS/仓储  | ⚠️ 基础仓储                                                    | ✅ WMS对接                                                         | ✅ FBA/海外仓对接                                 | ✅ 仓储对接                        |
| 生产/BOM  | ⚠️ **简易生产+BOM**（常随版本/增值包开通；非大型MRP工厂套件）                     | ✅ MRP+排产等制造深度                                                   | ❌                                           | ❌                             |
| 多平台集成   | ⚠️ **非**聚水潭式「国内电商全平台订单中台」开箱套件；网店+门店可走**零售/全渠道方案**，深度对接常需集成 | ⚠️ **OpenAPI/连接器+生态**；天猫京东等电商订单常见与**管易云·奇门、iPaaS或专业电商ERP**并存/对接 | ✅ **亚马逊能力最深**，并已扩展**多跨境平台**（以官网「已对接平台」清单为准） | ✅ 国内电商平台集成深                   |


> ✅ = 重点覆盖　⚠️ = 基础支持　❌ = 不覆盖  
> 金蝶产品线名称近年有「云星辰/云星空 → AI星辰/AI星空」升级，**能力以当期官方模块说明为准**；本表侧重「和强盛叙事相关的差异」，不是厂商完整功能清单。

**从这张表可以看出3个关键事实**：

1. **没有一款ERP覆盖所有场景**——金蝶**并非**不能做平台对接，但**默认强项**在组织、制造、总账与开放集成；**开箱形态**通常不等同于聚水潭式「国内电商全平台订单中台」。领星不做门店，聚水潭不做金蝶式**多组织SRM/复杂采购协同**。
2. **同一功能在不同产品里的深度完全不同**——同样是「采购管理」，金蝶星空强调**多组织+审批+业财闭环**；领星、聚水潭更贴近**跨境/电商补货与履约**链路。
3. **每款产品都有自己的「核心战场」**——领星：**跨境多平台**（亚马逊仍常是能力最深的一极）+业财运营一体化；聚水潭：**国内电商订单履约与仓配**；金蝶星辰：**中小零售/小微业财税与门店**；金蝶星空：**中大型制造与集团化管控**。

### 2.4 ERP的共性到底是什么

虽然差异很大，但如果把传统ERP、电商ERP、公司内部ERP放在一起看，有一组能力是**几乎所有ERP都会包含的**：


| 共性模块        | 为什么几乎所有ERP都有                 |
| ----------- | ---------------------------- |
| **主数据管理**   | 没有统一的商品、客户、供应商数据，后面所有业务都无法运转 |
| **采购管理**    | 企业总要买东西，采购→到货→入库→应付是最基础的链路   |
| **库存管理**    | 企业总要管库存，进多少、出多少、还剩多少         |
| **销售/订单管理** | 企业总要卖东西，订单→出库→应收是最基础的链路      |
| **财务协同**    | 业务最终要进财务账，不管是自动生成凭证还是手动对接    |


差异主要出现在：


| 差异维度             | 取决于什么                  |
| ---------------- | ---------------------- |
| 是否包含生产/BOM       | 是否是制造型企业               |
| 是否包含门店/POS       | 是否有线下零售                |
| 是否包含多平台集成和订单审核规则 | 是否做电商/跨境               |
| 是否包含多组织管控        | 企业规模和组织复杂度             |
| 库存管理的深度          | 单仓 vs 多仓 vs 逻辑仓 vs 全渠道 |
| 财务协同的深度          | 基础对账 vs 业财一体 vs 集团合并报表 |


**这就是为什么学ERP不能只看一款产品。** 只看金蝶会以为ERP一定包含门店管理，只看领星会以为ERP核心是平台对接，只看SAP会以为ERP必须有生产模块。

## 3. ERP应该怎么学

### 3.1 学习方法：从多产品对比中找共性，再回到场景做设计

正确的学习路径是：

```mermaid
flowchart LR
    A["对比多款ERP产品<br/>（金蝶/领星/聚水潭等）"] --> B["提炼出ERP的共性模块<br/>和通用设计思路"]
    B --> C["回到强盛科技的<br/>具体业务场景"]
    C --> D["判断SaaS能不能解决<br/>→不能→自研要做什么"]
    D --> E["输出自己的<br/>产品设计方案"]
```



**不是背功能列表，而是理解"场景→需求→方案"的映射关系。**

### 3.2 学完要能做什么

这套课学完，你至少要能做到以下5件事：


| #   | 能力                           | 面试时怎么用                                      |
| --- | ---------------------------- | ------------------------------------------- |
| 1   | 能说清ERP在企业信息化体系中的定位和边界        | 回答"你对ERP怎么理解"——不是背定义，而是用系统演进过程来讲            |
| 2   | 能拆一款ERP产品，识别它的核心模块、系统边界和设计取舍 | 回答"你拆过哪些竞品"——不是列功能，而是讲场景-功能映射               |
| 3   | 能结合业务背景做模块设计和优先级判断           | 回答"你做过什么项目"——不是说"我做了采购模块"，而是讲业务痛点→设计决策→取舍原因 |
| 4   | 能输出关键模块的PRD（含流程图、字段表、异常处理）   | 展示作品集——有具体产出物                               |
| 5   | 能讲清ERP和WMS、金蝶等系统的分工          | 回答"你们系统和其他系统怎么协同"——讲数据流和职责边界                |


## 4. 强盛科技的ERP演进：每个阶段的业务诉求和解题思路

### 4.1 阶段3：品牌出海期（2016-2018）——「后台归口 + 前台分治」

这个阶段强盛科技同时跑跨境（Amazon/eBay为主）、国内电商（天猫/淘宝）和国内B2B批发。最现实的诉求不是先做一套自研大而全的ERP，而是先把两件事跑通：一是后台库存与财务要有企业级归口，二是两条电商前台要能快速拉单、审单、履约。于是形成「金蝶做底座，店小秘管跨境、旺店通管国内电商」的典型分治格局。

阶段3在叙事里的系统组合如下。

| 架构角色 | 系统 | 当时的核心诉求 |
| --- | --- | --- |
| 后台底座 | 金蝶云·星空 | 采购、库存、总库存主账、仓库基础管理、国内B2B批发、应收应付与财务总账 |
| 跨境前台执行 | 店小秘ERP | 平台订单与刊登、FBA与头程、读取金蝶同步的可用库存与商品资料，发货结果回传 |
| 国内电商前台执行 | 旺店通OMS | 天猫/淘宝订单审核、规则、打单发货与仓配执行，读取金蝶同步资料，结果回传 |

这套组合为什么当时能成立？因为：

- 相比阶段2，库存与财务有了统一归口（金蝶），批发主链路也落在同一后台。
- 店小秘、旺店通分别承接两条电商前台的高频操作，比强行用一套「哪条线都勉强」的系统更现实。

为什么很快又不够？矛盾不在「没有主系统」。金蝶已经是后台主系统，真正痛的是主账归口之后，协同仍然断裂。

- 同步与预占：店小秘、旺店通依赖与金蝶的同步；同步不是绝对实时，预占、锁库、回传时点一旦不一致，就容易放大超卖、抢货、错账。
- 仓储形态：金蝶能管基础仓储与实物库存，但还不是独立意义上的强WMS，库位、扫码防错、波次、路径等能力弱，现场仍大量靠人。
- 业财粒度：月结总账在金蝶能做，但平台佣金、广告、FBA、退款等仍分散在前台与报表里，SKU级真实净利仍难算清，月末常靠Excel汇总再导入凭证。

---

请思考：如果当时「只买一款SaaS」，能不能替代上述三分工？

| 场景 | 若只上金蝶云·星辰（偏小微零售/业财税） | 若只上领星ERP（偏跨境） |
| --- | --- | --- |
| 跨境平台深度对接 | 通常不是「跨境订单中台开箱形态」 | 强项 |
| 国内淘系高并发履约 | 不等同聚水潭/旺店通式订单中台开箱 | 不覆盖国内电商主链路 |
| 线下B2B批发主链 | 有商贸/批发向能力，但与星空组织深度不同 | 不覆盖 |
| 财务总账与业财一体 | 业财税一体化是主线之一 | 偏经营利润与对账，不等于企业总账闭环 |

在课程设定的阶段3里，企业是主动选择「底座 + 双前台」分工，而不是先买一款SaaS再被动发现不够。现实里也很难指望一款现成SaaS，同时以第一梯队深度覆盖跨境中台、国内电商履约中台、中大型批发与总账，再加一套强WMS。

### 4.2 阶段4：供应链深耕期（2019-2022）——后台主链条自研化，前台渠道继续分治


到了阶段4之后，强盛科技的业务进一步复杂化。研产销一体化（参股工厂）、SKU走精品策略，库存形态覆盖原料、半成品、国内成品与FBA，ToB批发与多条ToC渠道并存。痛点也从「有没有系统」，升级到生产黑盒、牛鞭效应、质量追溯、全局库存调度这类供应链纵深问题。

阶段3已经证明：只靠「金蝶做库存与财务底座 + 店小秘/旺店通做前台」仍不够。阶段4的建设思路，是把采购、计划、库存、仓储、供应商协同等后台核心链条逐步收回到自研体系，同时继续用前台垂直SaaS处理各自擅长的渠道执行。金蝶云·星空从「库存 + 财务底座」退回到以财务归口为主（总账、成本、多币种等），供应链业务侧的主系统改由自研ERP承接。

阶段4在叙事里的系统组合如下。

| 系统 | 定位（与发家史一致） | 相对阶段3的关键变化 |
| --- | --- | --- |
| 自研ERP | 后台主干：主数据、BOM、MRP、采购、批发、逻辑仓与逻辑库存、内部结算、业务单据中枢 | 接管原由金蝶承担的供应链业务侧主链条，并补齐通用模块不够深的部分 |
| 自研WMS | 仓内执行（库位、波次、PDA、FIFO等） | 不再只靠ERP轻仓储加人工补位 |
| 自研SRM | 供应商在线协同（接单、交期、送货、标签/箱码） | 把阶段3里微信、电话、纸单为主的协同搬进系统 |
| 领星ERP | 亚马逊专项（广告、FBA、ASIN利润等） | 替代店小秘，渠道侧更深，但仍不承担企业后台主链条 |
| 聚水潭 | 天猫/京东等高并发订单审核、打单发货 | 替代旺店通，角色仍是国内电商前台履约 |
| 金蝶云·星空 | 财务底座（总账、成本、凭证归口等） | 供应链业务单据与结果由自研ERP/WMS归集后推送应记账结果 |

---

请思考：如果阶段4坚持不外采自研后台，仍只靠通用ERP加渠道SaaS叠罗汉，能不能撑住？

| 业务诉求 | 金蝶云·星空（继续扛「全公司供应链业务主账」） | 领星/聚水潭 |
| --- | --- | --- |
| 物料/BOM/MRP、原料与半成品、委外与计划协同 | ⚠️ 通用ERP有模块边界；深度垂直场景往往走向大量二开或外挂，响应未必跟得上业务迭代 | ❌ 不承担企业物料与制造计划主数据主链条 |
| 逻辑仓、逻辑库存与多渠道预留、内部结算口径 | ⚠️ 理论上可定制，但与多条前台系统的锁库、回传时点协同复杂度高 | ❌ 各自输出本渠道履约所需视图，不是全局调度中枢 |
| 总仓实物执行（扫码防错、波次、路径） | ⚠️ 不等于独立WMS；阶段3叙事里已强调轻仓储天花板 | ❌ FBA、打单是渠道履约视角，不能替代企业总仓的WMS级执行系统 |
| 供应商门户化协同（ASN、标签、预约送货） | ⚠️ 采购模块不等于SRM门户化协同的全套体验 | ❌ |
| 财务总账与合规月结 | ✅ 财务底座仍是金蝶强项 | ⚠️ 输出渠道经营明细；总账闭环仍在金蝶或企业财务系统 |

金蝶在阶段4仍然重要，但角色更应聚焦财务归口。若继续要求它同时扮演全公司供应链业务主系统、深WMS、渠道一体化，就和阶段4设定的演进方向拧着来。领星、聚水潭在阶段4仍是合理的前台选择，但它们不覆盖BOM/MRP、总仓WMS、SRM、ToB批发后台主链与逻辑库存中枢，这些由自研ERP、WMS、SRM承接。

自研ERP（V1）的核心定位，是供应链垂直领域里的后台业务中枢，而不是再造一个天猫打单工具。

| 自研ERP（V1）要收口的能力 | 为何难以用「纯SaaS拼」替代（教学归纳） |
| --- | --- |
| 统一主数据与业务规则（物料/成品/BOM/组织/仓网/渠道口径） | 多SaaS各有自己的商品与映射模型，企业要的是一套可随业务演进的唯一真相 |
| 采购、批发、逻辑库存、内部结算在同一中枢编排 | 领星偏亚马逊前台、聚水潭偏国内履约，二者相加仍不等于企业级ToB+ToC后台主单据中枢 |
| 向WMS、SRM、金蝶稳定下发与回传 | 接口面、单据状态机、幂等与追溯要能自主掌控迭代节奏 |
| 逻辑库存向前台输出可售、锁定、预留视图 | 阶段4也留了一手：后台做强之后，仍可能缺全局订单与库存调度，那是阶段5的题；阶段4先把后台主链与仓配执行专业化 |

容易踩的坑，是把「自研」理解成「不用领星/聚水潭」。阶段4的标准叙事是烟囱林立的最佳实践组合：自研ERP、WMS、SRM与领星、聚水潭、金蝶并存。自研收后台主链与执行，垂直SaaS继续做渠道前台，金蝶做财务底座。

### 4.3 阶段5：IPO冲刺与新零售期（2023-2026）——ERP中枢化 + 主数据与分析平台


进入阶段5，强盛科技面临Pre-IPO合规压力、全渠道一盘货（Amazon、独立站、天猫、京东、抖音、门店、B2B并行）、新零售O2O（线上下单门店取、门店缺货云仓发、会员一体），以及全球多仓履约和「小单快返」下的计划协同。阶段4已经把后台主链条自研化做扎实，但领星、聚水潭、自研ERP、WMS、SRM、门店POS之间仍缺统一的全局调度视角。典型矛盾是：亚马逊缺货、天猫仓有货、门店也有货，却没有一个站在集团视角的总调度。

本阶段建设思路，是把自研ERP继续做大、做中枢化，补齐主数据与经营分析平台、补齐门店POS与新零售入口，应记账结果继续统一推金蝶，满足业财一体与审计要求。

| 系统层级 | 系统（课程设定） | 核心职责 |
| --- | --- | --- |
| 财务底座 | 金蝶云·星空（沿用深化） | 多系统应记账结果汇入、凭证与审计归口 |
| ERP中枢 | 自研数智化全渠道零售ERP（相对V1的升级形态，课内可称V2） | 订单中心：全渠道接入、清洗、拆合单、路由与异常；库存中心：在WMS实物库存之上管理逻辑库存、锁库、共享与渠道预留、防超卖、跨仓与门店路由；结算中心：把业务动作标准化为结算结果再推金蝶，并归集ToB、ToC与内部经营 |
| 主数据与分析 | 主数据与指标口径平台、观远BI | 主数据分发；GMV、毛利、周转等统一指标定义与经营驾驶舱 |
| 新零售 | 自研POS、小程序 | 门店收银、会员、扫码下单、就近仓履约协同 |
| 仓储/供应 | 自研WMS（持续升级）、自研SRM | WMS管实物执行与库存主账，由ERP调度；SRM承接采购前段与供应商协同 |
| 渠道垂类 | 领星、聚水潭（保留） | 亚马逊专项、国内电商高并发履约；不再承担集团中枢，订单与库存承诺以ERP规则为准 |

阶段4解决的是「后台主链条自研化」；阶段5在此基础上解决「ERP中枢化、全渠道统一调度与统一口径」。系统不是简单变多，而是ERP更集中、更大、更中枢化。

| 诉求/痛点（阶段5归纳） | 阶段4自研ERP（V1）为何仍不够 | 阶段5（V2）怎么升级 |
| --- | --- | --- |
| 全渠道一盘货与全局调度 | 各系统局部都强，但缺少集团视角的订单、库存路由与配额引擎，容易出现有货却发错仓、承诺不一致 | 订单中心与库存中心联动：共享库存池、渠道预留、安全库存、重分配与调拨建议 |
| 新零售O2O、门店履约 | 门店尚未作为与总仓、电商同一套锁库与路由规则下的履约节点纳入闭环 | POS加小程序：门店直售、云仓代发；ERP基于WMS主账与逻辑库存判断最近履约点 |
| 主数据与经营语言统一 | 业务主数据已在ERP收敛，跨系统指标口径与看板仍易各说各话 | 主数据与指标口径平台分发，观远BI统一经营视图 |
| IPO业财可追溯 | 有单据与日志，全链路可审计、可对穿的成本仍高 | 结算结果统一推金蝶，追溯、一致性校验、数据血缘与复核机制加固 |

阶段4的ERP是后台业务主链条与单据中枢；阶段5的ERP升级为订单、库存、结算一体化的全渠道业务中枢，并与主数据与指标口径平台、观远BI、POS、WMS、SRM、金蝶形成全域协同，与课程总纲里强盛科技阶段5的叙事一致。

### 4.4 总结：强盛科技的ERP在阶段3–5各属于什么类型

回到前面「三大类ERP」框架，把阶段3、4、5对齐成一张总表，口径与发家史各阶段一致。

| 阶段     | 用的ERP类型                              | 具体产品                      | ERP在这个阶段的定义                        |
| ------ | ------------------------------------ | ------------------------- | ---------------------------------- |
| 阶段3 | 传统ERP底座 + 电商前台SaaS（分治架构） | 金蝶云·星空（后台库存/采购/B2B/财务总账）+ 店小秘ERP（跨境）+ 旺店通OMS（国内电商） | 后台主账与主链条在金蝶，渠道高频执行在店小秘、旺店通；矛盾集中在同步、轻仓储与业财粒度 |
| 阶段4 | 公司内部ERP（自研）+ 渠道SaaS + 财务底座 | 自研ERP + WMS + SRM；领星（亚马逊专项）+ 聚水潭（国内履约）；金蝶退回财务归口 | 自研ERP承担后台业务主链条与单据中枢（主数据、BOM、MRP、采购、批发、逻辑库存、内部结算），业财结果推金蝶 |
| 阶段5 | 公司内部ERP（自研V2）中枢化 + 平台与垂类协同 | 自研数智化全渠道零售ERP（订单/库存/结算中枢）+ WMS、SRM、POS + 主数据与指标口径平台 + 观远BI；金蝶（财务深化）；领星、聚水潭（保留渠道执行，非中枢） | ERP是全渠道业务中枢（订单中心、库存中心、结算中心），并作为主数据与经营口径的关键源头；审计与总账仍归口金蝶 |

同一家公司，在不同发展阶段对ERP的定义完全不同。你面试的公司可能处在阶段3（金蝶底座加双前台分治），也可能处在阶段4（自研收后台主链、前台仍用垂直SaaS），也可能处在阶段5（订单、库存、结算中枢化，叠加主数据与BI、新零售门店、IPO口径）。能判断对方处在哪一阶段，才谈得上给出合理的产品设计方案。

## 5. ERP的系统定位与边界

### 5.1 进销存和ERP的本质区别


| 维度       | 进销存              | ERP                     |
| -------- | ---------------- | ----------------------- |
| 解决什么     | 单店/单仓的采购-销售-库存闭环 | 多渠道、多仓、多组织的后台统一主链条      |
| 库存口径     | 即时库存基本够用         | 需要区分逻辑库存、可售库存、锁定库存、在途库存 |
| 主数据定位    | 够用就行             | 必须是唯一来源，所有系统围绕它运行       |
| 和其他系统的关系 | 基本独立运行           | 必须和WMS、金蝶、前台渠道系统协同      |
| 财务要求     | 先把业务账跑起来         | 口径统一、单据关联、日志留痕、凭证追溯     |


**ERP不是"更大一点的进销存"。** 进销存之后走到ERP，不是因为ERP更高级，而是因为企业开始需要一个统一主数据、统一业务单据、统一库存口径、统一财务协同入口的后台中枢。

### 5.2 ERP和其他系统的分工

ERP不是"什么都管"，它和其他系统有明确的边界：


| 系统      | 核心职责                               | 不重点负责什么            |
| ------- | ---------------------------------- | ------------------ |
| **ERP** | 主数据、采购、批发销售、逻辑库存、可售与锁定口径、结算协同、财务接口 | 仓内精细执行、平台深度运营、财务总账 |
| WMS     | 库位、上架、拣货、波次、复核、发运、实物库存             | 主数据归口、采购主链路、渠道经营口径 |
| SRM     | 供应商协同、对账、供货、质量反馈                   | 内部库存主账、渠道销售        |
| POS     | 门店收银、前台交易、现场成交                     | 后台采购、主数据归口、全局库存总账  |
| 金蝶云·星空  | 财务总账、凭证、成本、结账、审计口径                 | 后台业务主链路            |
| 领星/聚水潭  | 渠道专项执行、平台集成                        | 统一主数据、统一后台主链路      |


**最容易混淆的一条边界——实物库存 vs 逻辑库存：**

- **实物库存主账偏WMS**：货到底在不在、在哪个库位、是否已拣走
- **逻辑库存/可售库存/锁定库存偏ERP**：哪些货能承诺、哪些被哪个渠道锁了

WMS更像"实物执行真相"，ERP更像"经营分配真相"。与此相关的一个概念是**逻辑仓**——ERP里经常出现一些"不是真实仓库、但必须存在"的仓，比如"跨境锁定仓""FBA在途仓""门店待配仓"，它们描述的不是"货放在哪"，而是"这批货当前属于什么经营状态"。这个概念会在第4讲展开。

## 7. 小结

读到这里，建立5个认知：

1. **ERP是一个宏大且边界模糊的概念**——传统ERP、电商ERP、公司内部ERP差异很大，同一家公司在不同阶段对ERP的定义也完全不同
2. **学ERP的方法是从多产品对比中找共性**——先看金蝶怎么做、领星怎么做、聚水潭怎么做，提炼出共性模块和通用设计思路，再回到业务场景做设计
3. **强盛科技不是一开始就做自研ERP**——阶段3用金蝶底座加店小秘、旺店通分治解决执行效率，阶段4起才把后台主链条收回自研
4. **阶段4偏"后台主链条系统"，阶段5偏"全渠道业务中枢"**——这不是同一次升级，而是被不同阶段的业务矛盾逼出来的两代产品
5. **学完不是为了背功能列表**——而是要能拆竞品、能做设计取舍、能输出作品集、能在面试中讲清楚决策过程
